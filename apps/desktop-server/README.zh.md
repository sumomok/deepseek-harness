# @deepseek-ai/dsh-desktop-server

[English](README.md) | 中文

桌面应用内嵌服务器的纯依赖 deploy root:`@deepseek-ai/dsh` 闭包了整个 `dsh web` 运行时(bundle、host 插件、client 产物与已构建的 web 前端 dist)。vendor 框架三件(`cordis`、`cosmokit`、`schemastery`)显式列出,因为 pnpm 的 deployer 会跳过 `link:` 覆盖的包,只有作为直接依赖才能被暂存步骤恢复——python/sdk-runtime 列出它们是同一个原因。它们旁边另有那些作用域外的插件包,各自钉死在与本清单放在一起提交的 `vendor/` 下的一个 tarball 上,而那也是它们唯一的到达渠道:`@haoran` 那几个插件哪里都没发布,`@sumomok/dsh-balance` 与 `@sumomok/dsh-quote-message` 走在作者发布到 npm 的版本之前:npm 上 `@sumomok/dsh-balance` 止于 0.4.0,`@sumomok/dsh-quote-message` 止于 0.3.1。pnpm 为 `file:` tarball 记录 `integrity` 哈希,与注册表版本完全一样,这正是 `pnpm deploy` 对它物化的每一条 lockfile 条目的要求。它们是桌面客户端的内置插件,正是本清单把它们放进载荷,供壳播种到 `desktop-shell` profile。这里列出、而服务端自己从不导入的工作区包,是某个插件 peer 依赖的那一个:`@deepseek-ai/dsh-mcp-client` 在此,是因为 `@haoran/dsh-mcp-servers` 导入它,而 peer 是对着运行中安装目录自己的闭包解析、不是装在插件旁边,所以清单漏掉这个名字会让该插件加载失败。插件只为类型声明为可选 peer 的包也列在这里:`@deepseek-ai/dsh-cmdline` 与 `@deepseek-ai/dsh-workspace` 是为 `@haoran/dsh-crash-resume` 列的,因为清单漏掉的可选 peer 会被 pnpm 从注册表装一份,这第二份会进入载荷。组合行点名、而 `@deepseek-ai/dsh` 并不依赖的工作区包,由点名那一行的 bundle 自己声明,不列在这里,因为运行时解析器只读安装包的依赖闭包和每个选中 bundle 自己的依赖闭包,从不读这份清单:`@deepseek-ai/dsh-desktop-app` 为它的 `tool-session-query` 行声明了 `@deepseek-ai/dsh-tool-session-query`,那个包的每个必需 peer 都列在这里,因为 deploy 不安装任何 peer。`apps/desktop-shell/scripts/package.ts` 对本清单执行 `pnpm deploy`,把物化后的树作为 Electron 应用的 `resources/server` 随包分发,由捆绑的 Node 运行时启动。此处没有任何代码;见 [apps/desktop-shell](../desktop-shell/README.zh.md)。
