# @deepseek-ai/dsh-desktop-server

English | [中文](README.zh.md)

Dependency-only deploy root for the desktop app's embedded server: `@deepseek-ai/dsh` closes over the whole `dsh web` runtime (bundles, host plugins, client bundles, and the built web frontend dist). The vendored framework trio (`cordis`, `cosmokit`, `schemastery`) is listed explicitly because pnpm's deployer skips `link:`-overridden packages unless they are direct dependencies the staging step can restore — the same reason python/sdk-runtime lists them. The out-of-scope plugin packages are listed beside them, each pinned to a tarball committed beside this manifest under `vendor/`, which is the only channel any of them arrives by: the `@haoran` plugins are published nowhere, `@sumomok/dsh-balance`'s archive is its published release byte for byte, `@sumomok/dsh-quote-message` and `dsh-at-file` run ahead of their authors' newest published releases. pnpm records a `file:` tarball with an `integrity` hash exactly as it records a registry version, which is what `pnpm deploy` requires of every lockfile entry it materializes. They are the desktop client's built-in plugins, and this manifest is what puts them in the payload for the shell to seed into the `desktop-shell` profile. A workspace package listed here that the server itself never imports is one such a plugin peers on: `@deepseek-ai/dsh-mcp-client` is here because `@haoran/dsh-mcp-servers` imports it, and a peer resolves against the running installation's own closure rather than beside the plugin, so a name the manifest omits would fail the plugin's load. `apps/desktop-shell/scripts/package.ts` runs `pnpm deploy` against this manifest and ships the materialized tree as the Electron app's `resources/server`, launched with a bundled Node runtime. Nothing here is code; see [apps/desktop-shell](../desktop-shell/README.md).
