# @deepseek-ai/dsh-desktop-app

English | [中文](README.zh.md)

The desktop application's own composition layer. `@deepseek-ai/dsh-base` and `@deepseek-ai/dsh-web-app` are the shipped bundles every `dsh web` deployment shares, and both deliberately leave some rows at the value that suits no deployment in particular; this package is where the desktop app makes those choices for itself. Its patch is `cordis.patch.yml`, named by the `dsh.bundle.patch` manifest field, which `loadProfile` reads without importing anything; its code is the browser half behind the `desktop-brand` row and the logger exporter behind the `desktop-server-log` row, both described below. `apps/desktop-server` lists it as a dependency, which puts it in the payload `pnpm deploy` materializes, and `apps/desktop-shell/src/profile-seed.ts` names it last in `BUILTIN_WEB_BUNDLES`, which puts it after dsh-base, dsh-web-app, and every built-in plugin layer in the desktop profile's `dsh.profile.bundles`, on a fresh profile and on an upgraded one alike. Last there is last as of that seeding rather than for good: a plugin migrated from the `web` profile, or installed from the Plugins page, is appended after it. Three user layers apply later still — the profile's own `cordis.patch.yml`, then `$DSH_HOME/cordis.patch.yml`, then any `--patch` overlay — so a row here is a deployment default the user can replace, not one they are stuck with. Its rows are described here by the id each one patches. `session-query-sqlite` turns on full-text search over conversation content (`openAt: first-search` over a durable derived index), which the shipped bundles leave off. `llm-deepseek` raises `retryPolicy.backoff.maxDelayMs` from ten seconds to five minutes, which is the longest `Retry-After` a rate-limited request will wait out before the turn fails; the ceiling lives on the provider because `@deepseek-ai/dsh-llm-retry`, the plugin that executes the wait, takes no configuration of its own and rejects a `retryPolicy` key with a message saying so. That ceiling bounds one wait and a step retries at most five times, so a step sits for 25 minutes at worst and 2.5 to 10 minutes across the windows this is for, with every wait ending the moment the user stops the turn and counted down in the transcript while it runs; the [Agent Note](../../.agents/notes/implemented/feature/2026-09-06-desktop-composition-layer-content-search.md) carries the arithmetic. That row restates the model catalog a built-in plugin layer below sets on the same id, since a patch replaces the whole `config`. That catalog is one row, `deepseek-flash`, and `@deepseek-ai/dsh-llm-deepseek` now ships a row for that id itself, so the restatement repeats the shipped row field for field and names only the label and the line under it: a whole-table replacement drops every field it does not repeat, and `systemPromptUpdate: in-history` is the one that costs a warm prefix cache when it goes missing. `vision-switch` names the model an image sent on a model without vision moves the session to, the one sessions start on. `llm-permission-gateway` names the model the permission gateway's reviews run on, and adds `plugin_manager` to the calls the gateway always puts to a person, restating the gateway's own `browser_auth` entry because `alwaysAsk` replaces the default map. `plugin-manager` points upstream's plugin installer at the pnpm launcher the shell names in `DSH_DESKTOP_PNPM`, falling back to `pnpm` on `PATH` in a development launch. `office-to-pdf` is disabled, because the payload carries no LibreOffice engine. `ui-chat` starts work details compact. The layer inserts two rows rather than patching one. `desktop-brand` mounts this package, whose empty Host apply gives the Loader a row and whose browser half occupies `sidebar.brand.name` with 北冥 (Beiming in English) at 18px and no version, and `sidebar.brand.mark` with the fish logo at 1.25 times the size ui-sidebar asks for, 30px wide and 22px tall for its 24, in the expanded brand row and the collapsed rail alike. The same half registers an empty entry under the `current-version` id of `settings.general.item` at priority -1, which shadows ui-settings-general's row because the lowest priority of entries sharing a list id renders, so Settings → General shows no version; the desktop's release version is on the update settings page. `desktop-server-log` mounts `@deepseek-ai/dsh-desktop-app/server-log` (`src/server-log.ts`): an exporter on the root logger service, shared by every context in the tree, that appends each record at or below `level: 2` to the file the shell names in `DSH_DESKTOP_SERVER_LOG`, which is `dsh-server.log`. cordis orders ERROR 0 < INFO 1 < WARN 2 < DEBUG 3, so that threshold keeps errors, info, and warnings and drops debug. The shell sets the variable for the server child alone, and the packaging run's staged boot sets it as well so the row mounts there and its module has to resolve from the payload; a boot started by hand without it leaves the row off. The exporter writes the file itself, one append per record starting `[server-log]`, rather than printing, because the shell scans the server's stdout and stderr for its readiness line and copies both into the same file. On mount it first appends the records the logger's own buffer holds within the threshold; that buffer keeps records at INFO, so a warning logged during boot before the row mounted is lost. `build.ts` bundles both halves and the exporter with esbuild (`pnpm --filter @deepseek-ai/dsh-desktop-app run bundle`), the exporter to `lib/server-log.js` with `@deepseek-ai/cordis` and `@deepseek-ai/schemastery` left as imports, so it shares the server's one cordis instead of carrying a second. The root build does not, because its client pass covers `packages/*/*` only, so the desktop package runs the bundle after `pnpm run build` and its title check (`apps/desktop-shell/scripts/client-build.ts`); the browser half reads no build-time value. `tests/brand.client.spec.tsx` applies the source half on the production slot and locale runtimes, and `tests/server-log.spec.ts` runs the exporter in a real cordis context. `apps/desktop-shell/tests/desktop-composition-layer.spec.ts` composes the real layers, asserts the values the desktop profile ends up with, compares that restated catalog against the one below it, and compares the row against the shipped adapter's own key by key, so a field upstream adds fails there. See [apps/desktop-shell](../desktop-shell/README.md) for the shell and [apps/desktop-server](../desktop-server/README.md) for the payload.
