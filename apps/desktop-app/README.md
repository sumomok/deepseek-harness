# @deepseek-ai/dsh-desktop-app

English | [中文](README.zh.md)

The desktop application's own composition layer. `@deepseek-ai/dsh-base` and `@deepseek-ai/dsh-web-app` are the shipped bundles every `dsh web` deployment shares, and both deliberately leave some rows at the value that suits no deployment in particular; this package is where the desktop app makes those choices for itself. It carries no code: the whole package is `cordis.patch.yml` plus the `dsh.bundle.patch` manifest field that names it, so `loadProfile` reads the layer without importing anything. `apps/desktop-server` lists it as a dependency, which puts it in the payload `pnpm deploy` materializes, and `apps/desktop-shell/src/profile-seed.ts` names it last in `BUILTIN_WEB_BUNDLES`, which puts it after dsh-base, dsh-web-app, and every built-in plugin layer in the desktop profile's `dsh.profile.bundles`, on a fresh profile and on an upgraded one alike. Last there is last as of that seeding rather than for good: a plugin migrated from the `web` profile, or re-enabled afterwards, is appended after it. Three user layers apply later still — the profile's own `cordis.patch.yml`, then `$DSH_HOME/cordis.patch.yml`, then any `--patch` overlay — so a row here is a deployment default the user can replace, not one they are stuck with. It carries two rows today. `session-query-sqlite` turns on full-text search over conversation content (`openAt: first-search` over a durable derived index), which the shipped bundles leave off. `llm-deepseek` raises `retryPolicy.backoff.maxDelayMs` from ten seconds to five minutes, which is the longest `Retry-After` a rate-limited request will wait out before the turn fails; the ceiling lives on the provider because `@deepseek-ai/dsh-llm-retry`, the plugin that executes the wait, takes no configuration of its own and rejects a `retryPolicy` key with a message saying so. That ceiling bounds one wait and a step retries at most five times, so a step sits for 25 minutes at worst and 2.5 to 10 minutes across the windows this is for, with every wait ending the moment the user stops the turn and counted down in the transcript while it runs; the [Agent Note](../../.agents/notes/implemented/feature/2026-09-06-desktop-composition-layer-content-search.md) carries the arithmetic. That row restates the model catalog a built-in plugin layer below sets on the same id, since a patch replaces the whole `config`. That catalog is one row, `deepseek-flash`, and `@deepseek-ai/dsh-llm-deepseek` now ships a row for that id itself, so the restatement repeats the shipped row field for field and names only the label and the line under it: a whole-table replacement drops every field it does not repeat, and `systemPromptUpdate: in-history` is the one that costs a warm prefix cache when it goes missing. `apps/desktop-shell/tests/desktop-composition-layer.spec.ts` composes the real layers, asserts the values the desktop profile ends up with, compares that restated catalog against the one below it, and compares the row against the shipped adapter's own key by key, so a field upstream adds fails there. See [apps/desktop-shell](../desktop-shell/README.md) for the shell and [apps/desktop-server](../desktop-server/README.md) for the payload.
