# @deepseek-ai/dsh-desktop-app

English | [中文](README.zh.md)

The desktop application's own composition layer. `@deepseek-ai/dsh-base` and `@deepseek-ai/dsh-web-app` are the shipped bundles every `dsh web` deployment shares, and both deliberately leave some rows at the value that suits no deployment in particular; this package is where the desktop app makes those choices for itself. Its patch is `cordis.patch.yml`, named by the `dsh.bundle.patch` manifest field, which `loadProfile` reads without importing anything; its code is the Host half and the browser half behind the `desktop-brand` row and the logger exporter behind the `desktop-server-log` row, all described below. `apps/desktop-server` lists it as a dependency, which puts it in the payload `pnpm deploy` materializes, and `apps/desktop-shell/src/profile-seed.ts` names it last in `BUILTIN_WEB_BUNDLES`, which puts it after dsh-base, dsh-web-app, and every built-in plugin layer in the desktop profile's `dsh.profile.bundles`, on a fresh profile and on an upgraded one alike. Last there is last as of that seeding rather than for good: a plugin migrated from the `web` profile, or installed from the Plugins page, is appended after it. Three user layers apply later still — the profile's own `cordis.patch.yml`, then `$DSH_HOME/cordis.patch.yml`, then any `--patch` overlay — so a row here is a deployment default the user can replace, not one they are stuck with. Its rows are described here by the id each one patches. `session-query-sqlite` turns on full-text search over conversation content (`openAt: first-search` over a durable derived index), which the shipped bundles leave off. `llm-deepseek` raises `retryPolicy.backoff.maxDelayMs` from ten seconds to five minutes, which is the longest `Retry-After` a rate-limited request will wait out before the turn fails; the ceiling lives on the provider because `@deepseek-ai/dsh-llm-retry`, the plugin that executes the wait, takes no configuration of its own and rejects a `retryPolicy` key with a message saying so. That ceiling bounds one wait and a step retries at most five times, so a step sits for 25 minutes at worst and 2.5 to 10 minutes across the windows this is for, with every wait ending the moment the user stops the turn and counted down in the transcript while it runs; the [Agent Note](../../.agents/notes/implemented/feature/2026-09-06-desktop-composition-layer-content-search.md) carries the arithmetic. That row sets no model catalog, so the picker lists `@deepseek-ai/dsh-llm-deepseek`'s own `DEFAULT_MODELS`, as upstream ships it. `vision-switch` names the model an image sent on a model without vision moves the session to, the one sessions start on. `llm-permission-gateway` names the model the permission gateway's reviews run on, and adds `plugin_manager` to the calls the gateway always puts to a person, restating the gateway's own `browser_auth` entry because `alwaysAsk` replaces the default map. `plugin-manager` points upstream's plugin installer at the pnpm launcher the shell names in `DSH_DESKTOP_PNPM`, falling back to `pnpm` on `PATH` in a development launch, and names `@haoran/dsh-crash-resume` in `requiredModules`, so the service refuses to switch off or remove that plugin and the Plugins page shows its switches locked with 应用必需，不能停用或卸载; the list equals `REQUIRED_WEB_BUNDLES` in `apps/desktop-shell/src/profile-seed.ts`, whose seed puts that bundle back on at every launch. `office-to-pdf` has no row: the shipped row stays on, and the shell downloads its LibreOffice engine into the data directory when the person asks for it (see the desktop shell's "Office engine service"). `ui-chat` has no row either, so work details start at the Chat form's own default, which is `detailed` in this shell because it defines no `dshDesktop` global. `desktop-product-telemetry` and `product-analytics`, dsh-web-app's two product-analytics rows, which its expressions keep off under any profile not named `desktop`, are set `disabled: true` outright, so neither a change to those expressions nor a profile rename turns reporting to DeepSeek on; `otel`, which the Host row reports through, already ships disabled in dsh-base. The layer inserts three rows rather than patching one. `desktop-brand` mounts this package. Its Host half (`src/index.ts`) registers the global system-prompt section `desktop:protected-directories`, as literal text at the `DEPLOYMENT_PERSONA_SUFFIX` order, where equal orders sort by name, so the text ends the system prompt of every session, whichever preset it runs and whether or not it is a delegated in-process subagent; a persona with `complete: true`, which the `minimal` preset uses, replaces the whole prompt and drops it, a known limitation the sandbox protection covers later. The line is `protectedDirsPrompt`, which must contain exactly `{directories}` and `{skillsDir}`. `{directories}` becomes one clause from `directoryClauses` per directory the launch knows, in a fixed order, joined with `directorySeparator` and, before the last, `directoryLastSeparator`; each clause must contain exactly its own placeholder. `installDir` comes from `DSH_DESKTOP_INSTALL_DIR`, which the shell sets for a packaged launch; `appDataDir`, `logDir`, and `updateCacheDir` come from `DSH_DESKTOP_USER_DATA_DIR`, `DSH_DESKTOP_LOG_DIR`, and `DSH_DESKTOP_UPDATE_CACHE_DIR`, the shell's Electron `userData`, log directory, and update download cache. The logs have their own clause because on macOS they sit under `~/Library/Logs`, outside `userData`; on Windows and Linux the logs folder is listed inside the settings folder. `{dataDir}`, always listed, is the harness home `resolveDshHome()` resolves (`$DSH_HOME`, else `~/.dsh`), the resolver the server's own plugins use, and `{skillsDir}` is its `skills` folder, the root `@deepseek-ai/dsh-skill-filesystem` reads user skills from, which the line exempts so the agent can keep writing skills there. A development launch of the shell lists no installation directory, and `dsh --profile desktop-shell` started by hand lists the data directory alone. A template with a missing or unknown placeholder refuses to mount, and a layer that patches the row by id must restate every key. Each path is inserted in backticks. The [Agent Note](../../.agents/notes/implemented/feature/2026-09-28-desktop-protected-directories-prompt.md) records why the line is worth its context cost. The system prompt reaches the session log as `system/message`, so the line and its paths are recorded with every prompt that carries it. Its browser half occupies `sidebar.brand.name` with 北冥 (Beiming in English) at 18px and no version, and `sidebar.brand.mark` with the fish logo at 1.25 times the size ui-sidebar asks for, 30px wide and 22px tall for its 24, in the expanded brand row and the collapsed rail alike. The same half registers an empty entry under the `current-version` id of `settings.general.item` at priority -1, which shadows ui-settings-general's row because the lowest priority of entries sharing a list id renders, so Settings → General shows no version; the desktop's release version is on the update settings page. It registers a second empty entry, under the `create-plugin` id of `plugins.add.actions` at priority -1, which shadows ui-agent-preset's action in the Plugins page's add-plugin menu the same way, so that menu offers no 让 Agent 创建插件 (Let the agent create a plugin) item; Creator mode stays reachable from Settings → Agent presets and from the preset chip of a new session. `desktop-server-log` mounts `@deepseek-ai/dsh-desktop-app/server-log` (`src/server-log.ts`): an exporter on the root logger service, shared by every context in the tree, that appends each record at or below `level: 2` to the file the shell names in `DSH_DESKTOP_SERVER_LOG`, which is `dsh-server.log`. cordis orders ERROR 0 < INFO 1 < WARN 2 < DEBUG 3, so that threshold keeps errors, info, and warnings and drops debug. The shell sets the variable for the server child alone, and the packaging run's staged boot sets it as well so the row mounts there and its module has to resolve from the payload; a boot started by hand without it leaves the row off. The exporter writes the file itself, one append per record starting `[server-log]`, rather than printing, because the shell scans the server's stdout and stderr for its readiness line and copies both into the same file. On mount it first appends the records the logger's own buffer holds within the threshold; that buffer keeps records at INFO, so a warning logged during boot before the row mounted is lost. `tool-session-query` mounts upstream's `@deepseek-ai/dsh-tool-session-query`, which dsh-base and dsh-web-app leave unmounted: five read-only tools, `session_search`, `session_event_search`, `session_trace`, `session_event_trace`, and `session_event_read`, and one prior-history system-prompt section, so the model can look up in the session logs the details compaction summarized or pruned, in its own session and in the other sessions of the same workspace; a target session is readable only when its `cwd` is exactly the caller's. It is a Host row, as the package's own mount reference is. Every service it injects is a Host row dsh-web-app leaves on, so the tools register in the tool registry's global layer and every agent scope inherits them: a `standard`, `ptc`, `cordis`, or `minimal` session, and a child it delegates to unless the delegation's tool allow-list leaves them out. A row inside a preset would mean restating that preset's whole `config.plugins` here, because no id-targeted patch reaches a preset's own rows. A `minimal` session's `complete` persona drops the prompt section, and its model still sees the five schemas. The row carries no `config`, so a search returns at most the package's default 100 hits, and dsh-base's `spill-policy` row bounds a long trace or event read inline. `@deepseek-ai/dsh` does not depend on the package, so this package lists it in `dependencies`: the runtime resolver supplies a row's module only from the installation's dependency closure and from each selected bundle's own. `build.ts` bundles both halves and the exporter with esbuild (`pnpm --filter @deepseek-ai/dsh-desktop-app run bundle`), the Host half to `lib/index.js` and the exporter to `lib/server-log.js`, both with `@deepseek-ai/cordis` and `@deepseek-ai/schemastery` left as imports, so they share the server's one cordis instead of carrying a second. The root build does not, because its client pass covers `packages/*/*` only, so the desktop package runs the bundle after `pnpm run build` and its title check (`apps/desktop-shell/scripts/client-build.ts`); the browser half reads no build-time value. `tests/brand.client.spec.tsx` applies the browser half on the production slot and locale runtimes, `tests/protected-directories.spec.ts` mounts the Host half on a real prompt registry and loads a skill from the folder it exempts through the skill provider, `tests/server-log.spec.ts` runs the exporter in a real cordis context, and `tests/host-build.spec.ts` builds both Host bundles with the options `build.ts` uses. `apps/desktop-shell/tests/desktop-composition-layer.spec.ts` composes the real layers, asserts the values the desktop profile ends up with, checks that the composed `llm-deepseek` row resolves to the adapter's own catalog and that sessions start on dsh-base's own default model; it also renders the system prompt of a `standard`, `ptc`, `cordis`, and `minimal` session and of a delegated child from the composed rows, and it mounts the composed `tool-session-query` row on real tool and prompt registries and checks that each of those sessions and a delegated child see the five session tools. [`snapshots/desktop`](../../snapshots/desktop/README.md) replays one recorded turn through `dsh --profile acp` with this package's `cordis.patch.yml` as the base patch, so the five session tools are pinned as a model request carries them and the session log records a `session_event_read` call and its result. See [apps/desktop-shell](../desktop-shell/README.md) for the shell and [apps/desktop-server](../desktop-server/README.md) for the payload.
