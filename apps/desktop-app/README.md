# @deepseek-ai/dsh-desktop-app

English | [中文](README.zh.md)

The desktop application's own composition layer. `@deepseek-ai/dsh-base` and `@deepseek-ai/dsh-web-app` are the shipped bundles every `dsh web` deployment shares, and both deliberately leave some rows at the value that suits no deployment in particular; this package is where the desktop app makes those choices for itself. Its patch is `cordis.patch.yml`, named by the `dsh.bundle.patch` manifest field, which `loadProfile` reads without importing anything; its only code is the browser half behind the `desktop-brand` row described below. `apps/desktop-server` lists it as a dependency, which puts it in the payload `pnpm deploy` materializes, and `apps/desktop-shell/src/profile-seed.ts` names it last in `BUILTIN_WEB_BUNDLES`, which puts it after dsh-base, dsh-web-app, and every built-in plugin layer in the desktop profile's `dsh.profile.bundles`, on a fresh profile and on an upgraded one alike. Last there is last as of that seeding rather than for good: a plugin migrated from the `web` profile, or installed from the Plugins page, is appended after it. Three user layers apply later still — the profile's own `cordis.patch.yml`, then `$DSH_HOME/cordis.patch.yml`, then any `--patch` overlay — so a row here is a deployment default the user can replace, not one they are stuck with. Its rows are described here by the id each one patches. `session-query-sqlite` turns on full-text search over conversation content (`openAt: first-search` over a durable derived index), which the shipped bundles leave off. `llm-deepseek` raises `retryPolicy.backoff.maxDelayMs` from ten seconds to five minutes, which is the longest `Retry-After` a rate-limited request will wait out before the turn fails; the ceiling lives on the provider because `@deepseek-ai/dsh-llm-retry`, the plugin that executes the wait, takes no configuration of its own and rejects a `retryPolicy` key with a message saying so. That ceiling bounds one wait and a step retries at most five times, so a step sits for 25 minutes at worst and 2.5 to 10 minutes across the windows this is for, with every wait ending the moment the user stops the turn and counted down in the transcript while it runs; the [Agent Note](../../.agents/notes/implemented/feature/2026-09-06-desktop-composition-layer-content-search.md) carries the arithmetic. That row restates the model catalog a built-in plugin layer below sets on the same id, since a patch replaces the whole `config`. That catalog is one row, `deepseek-flash`, and `@deepseek-ai/dsh-llm-deepseek` now ships a row for that id itself, so the restatement repeats the shipped row field for field and names only the label and the line under it: a whole-table replacement drops every field it does not repeat, and `systemPromptUpdate: in-history` is the one that costs a warm prefix cache when it goes missing. `vision-switch` names the model an image sent on a model without vision moves the session to, the one sessions start on. `llm-permission-gateway` names the model the permission gateway's reviews run on, and adds `plugin_manager` to the calls the gateway always puts to a person, restating the gateway's own `browser_auth` entry because `alwaysAsk` replaces the default map. `plugin-manager` points upstream's plugin installer at the pnpm launcher the shell names in `DSH_DESKTOP_PNPM`, falling back to `pnpm` on `PATH` in a development launch. `office-to-pdf` is disabled, because the payload carries no LibreOffice engine. `ui-chat` starts work details compact. `desktop-brand` is the one row this layer inserts rather than patches: it mounts this package, whose empty Host apply gives the Loader a row and whose browser half occupies `sidebar.brand.name` with 北冥 (Beiming in English) and, under it, the client build's `DSH_CLIENT_VERSION`, the repository version; the sidebar mark stays on its fallback. The same half registers an empty entry under the `current-version` id of `settings.general.item` at priority -1, which shadows ui-settings-general's row because the lowest priority of entries sharing a list id renders, so Settings → General shows no version; the desktop's release version is on the update settings page. `build.ts` bundles both halves with esbuild (`pnpm --filter @deepseek-ai/dsh-desktop-app run bundle`). The root build does not, because its client pass covers `packages/*/*` only, so the desktop package runs the bundle after `pnpm run build` with the client values the build record names (`apps/desktop-shell/scripts/client-build.ts`). `tests/brand.client.spec.tsx` applies the source half on the production slot and locale runtimes. `apps/desktop-shell/tests/desktop-composition-layer.spec.ts` composes the real layers, asserts the values the desktop profile ends up with, compares that restated catalog against the one below it, and compares the row against the shipped adapter's own key by key, so a field upstream adds fails there. See [apps/desktop-shell](../desktop-shell/README.md) for the shell and [apps/desktop-server](../desktop-server/README.md) for the payload.
