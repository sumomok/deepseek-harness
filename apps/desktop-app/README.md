# @deepseek-ai/dsh-desktop-app

English | [中文](README.zh.md)

The desktop application's own composition layer. `@deepseek-ai/dsh-base` and `@deepseek-ai/dsh-web-app` are the shipped bundles every `dsh web` deployment shares, and both deliberately leave some rows at the value that suits no deployment in particular; this package is where the desktop app makes those choices for itself. Its patch is `cordis.patch.yml`, named by the `dsh.bundle.patch` manifest field, which `loadProfile` reads without importing anything; its code is the Host half and the browser half behind the `desktop-brand` row and the logger exporter behind the `desktop-server-log` row, all described below. `apps/desktop-server` lists it as a dependency, which puts it in the payload `pnpm deploy` materializes, and `apps/desktop-shell/src/profile-seed.ts` names it last in `BUILTIN_WEB_BUNDLES`, which puts it after dsh-base, dsh-web-app, and every built-in plugin layer in the desktop profile's `dsh.profile.bundles`, on a fresh profile and on an upgraded one alike. Last there is last as of that seeding rather than for good: a plugin migrated from the `web` profile, or installed from the Plugins page, is appended after it. Three user layers apply later still — the profile's own `cordis.patch.yml`, then `$DSH_HOME/cordis.patch.yml`, then any `--patch` overlay — so a row here is a deployment default the user can replace, not one they are stuck with. Its rows are described here by the id each one patches. `session-query-sqlite` turns on full-text search over conversation content (`openAt: first-search` over a durable derived index), which the shipped bundles leave off. `llm-deepseek` raises `retryPolicy.backoff.maxDelayMs` from ten seconds to five minutes, which is the longest `Retry-After` a rate-limited request will wait out before the turn fails; the ceiling lives on the provider because `@deepseek-ai/dsh-llm-retry`, the plugin that executes the wait, takes no configuration of its own and rejects a `retryPolicy` key with a message saying so. That ceiling bounds one wait and a step retries at most five times, so a step sits for 25 minutes at worst and 2.5 to 10 minutes across the windows this is for, with every wait ending the moment the user stops the turn and counted down in the transcript while it runs; the [Agent Note](../../.agents/notes/implemented/feature/2026-09-06-desktop-composition-layer-content-search.md) carries the arithmetic. That row restates the model catalog a built-in plugin layer below sets on the same id, since a patch replaces the whole `config`. That catalog is one row, `deepseek-flash`, and `@deepseek-ai/dsh-llm-deepseek` now ships a row for that id itself, so the restatement repeats the shipped row field for field and names only the label and the line under it: a whole-table replacement drops every field it does not repeat, and `systemPromptUpdate: in-history` is the one that costs a warm prefix cache when it goes missing. `vision-switch` names the model an image sent on a model without vision moves the session to, the one sessions start on. `llm-permission-gateway` names the model the permission gateway's reviews run on, and adds `plugin_manager` to the calls the gateway always puts to a person, restating the gateway's own `browser_auth` entry because `alwaysAsk` replaces the default map. `plugin-manager` points upstream's plugin installer at the pnpm launcher the shell names in `DSH_DESKTOP_PNPM`, falling back to `pnpm` on `PATH` in a development launch. `office-to-pdf` is disabled, because the payload carries no LibreOffice engine. `ui-chat` starts work details compact. The layer inserts two rows rather than patching one. `desktop-brand` mounts this package. Its Host half (`src/index.ts`) registers the global system-prompt section `desktop:protected-directories`, as literal text at the `DEPLOYMENT_PERSONA_SUFFIX` order, where equal orders sort by name, so the text ends the system prompt of every session, whichever preset it runs and whether or not it is a delegated in-process subagent; a persona with `complete: true`, which the `minimal` preset uses, replaces the whole prompt and drops it, a known limitation the sandbox protection covers later. The line is `protectedDirsPrompt`, which must contain exactly `{directories}` and `{skillsDir}`. `{directories}` becomes one clause from `directoryClauses` per directory the launch knows, in a fixed order, joined with `directorySeparator` and, before the last, `directoryLastSeparator`; each clause must contain exactly its own placeholder. `installDir` comes from `DSH_DESKTOP_INSTALL_DIR`, which the shell sets for a packaged launch; `appDataDir`, `logDir`, and `updateCacheDir` come from `DSH_DESKTOP_USER_DATA_DIR`, `DSH_DESKTOP_LOG_DIR`, and `DSH_DESKTOP_UPDATE_CACHE_DIR`, the shell's Electron `userData`, log directory, and update download cache. The logs have their own clause because on macOS they sit under `~/Library/Logs`, outside `userData`; on Windows and Linux the logs folder is listed inside the settings folder. `{dataDir}`, always listed, is the harness home `resolveDshHome()` resolves (`$DSH_HOME`, else `~/.dsh`), the resolver the server's own plugins use, and `{skillsDir}` is its `skills` folder, the root `@deepseek-ai/dsh-skill-filesystem` reads user skills from, which the line exempts so the agent can keep writing skills there. A development launch of the shell lists no installation directory, and `dsh --profile desktop-shell` started by hand lists the data directory alone. A template with a missing or unknown placeholder refuses to mount, and a layer that patches the row by id must restate every key. Each path is inserted in backticks. The [Agent Note](../../.agents/notes/implemented/feature/2026-09-28-desktop-protected-directories-prompt.md) records why the line is worth its context cost. The system prompt reaches the session log as `system/message`, so the line and its paths are recorded with every prompt that carries it. Its browser half occupies `sidebar.brand.name` with 北冥 (Beiming in English) at 18px and no version, and `sidebar.brand.mark` with the fish logo at 1.25 times the size ui-sidebar asks for, 30px wide and 22px tall for its 24, in the expanded brand row and the collapsed rail alike. The same half registers an empty entry under the `current-version` id of `settings.general.item` at priority -1, which shadows ui-settings-general's row because the lowest priority of entries sharing a list id renders, so Settings → General shows no version; the desktop's release version is on the update settings page. `desktop-server-log` mounts `@deepseek-ai/dsh-desktop-app/server-log` (`src/server-log.ts`): an exporter on the root logger service, shared by every context in the tree, that appends each record at or below `level: 2` to the file the shell names in `DSH_DESKTOP_SERVER_LOG`, which is `dsh-server.log`. cordis orders ERROR 0 < INFO 1 < WARN 2 < DEBUG 3, so that threshold keeps errors, info, and warnings and drops debug. The shell sets the variable for the server child alone, and the packaging run's staged boot sets it as well so the row mounts there and its module has to resolve from the payload; a boot started by hand without it leaves the row off. The exporter writes the file itself, one append per record starting `[server-log]`, rather than printing, because the shell scans the server's stdout and stderr for its readiness line and copies both into the same file. On mount it first appends the records the logger's own buffer holds within the threshold; that buffer keeps records at INFO, so a warning logged during boot before the row mounted is lost. `build.ts` bundles both halves and the exporter with esbuild (`pnpm --filter @deepseek-ai/dsh-desktop-app run bundle`), the Host half to `lib/index.js` and the exporter to `lib/server-log.js`, both with `@deepseek-ai/cordis` and `@deepseek-ai/schemastery` left as imports, so they share the server's one cordis instead of carrying a second. The root build does not, because its client pass covers `packages/*/*` only, so the desktop package runs the bundle after `pnpm run build` and its title check (`apps/desktop-shell/scripts/client-build.ts`); the browser half reads no build-time value. `tests/brand.client.spec.tsx` applies the browser half on the production slot and locale runtimes, `tests/protected-directories.spec.ts` mounts the Host half on a real prompt registry and loads a skill from the folder it exempts through the skill provider, `tests/server-log.spec.ts` runs the exporter in a real cordis context, and `tests/host-build.spec.ts` builds both Host bundles with the options `build.ts` uses. `apps/desktop-shell/tests/desktop-composition-layer.spec.ts` composes the real layers, asserts the values the desktop profile ends up with, compares that restated catalog against the one below it, and compares the row against the shipped adapter's own key by key, so a field upstream adds fails there; it also renders the system prompt of a `standard`, `ptc`, `cordis`, and `minimal` session and of a delegated child from the composed rows. See [apps/desktop-shell](../desktop-shell/README.md) for the shell and [apps/desktop-server](../desktop-server/README.md) for the payload.
