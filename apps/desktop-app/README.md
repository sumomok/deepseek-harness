# @deepseek-ai/dsh-desktop-app

English | [中文](README.zh.md)

The desktop application's own composition layer. `@deepseek-ai/dsh-base` and `@deepseek-ai/dsh-web-app` are the shipped bundles every `dsh web` deployment shares, and both deliberately leave some rows at the value that suits no deployment in particular; this package is where the desktop app makes those choices for itself. It carries no code: the whole package is `cordis.patch.yml` plus the `dsh.bundle.patch` manifest field that names it, so `loadProfile` reads the layer without importing anything. `apps/desktop-server` lists it as a dependency, which puts it in the payload `pnpm deploy` materializes, and `apps/desktop/src/profile-seed.ts` names it last in `BUILTIN_WEB_BUNDLES`, which puts it last in the desktop profile's `dsh.profile.bundles` on a fresh profile and on an upgraded one alike. Applying last means it overrides dsh-base, dsh-web-app, and every built-in plugin layer, while `$DSH_HOME/profiles/desktop/cordis.patch.yml` still applies after it — a row here is a default the user can replace, not one they are stuck with. The one row it currently carries turns on full-text search over conversation content (`session-query-sqlite`'s `openAt: first-search` over a durable derived index), which the shipped bundles leave off; `apps/desktop/tests/desktop-content-search.spec.ts` composes the real layers and asserts the value the desktop profile ends up with. See [apps/desktop](../desktop/README.md) for the shell and [apps/desktop-server](../desktop-server/README.md) for the payload.
