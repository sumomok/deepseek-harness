# @deepseek-ai/dsh-desktop-app

[English](README.md) | 中文

桌面应用自己的组合层。`@deepseek-ai/dsh-base` 与 `@deepseek-ai/dsh-web-app` 是每个 `dsh web` 部署共用的出厂组合包，两者都刻意把一部分行留在不偏向任何具体部署的取值上；本包就是桌面应用替自己做出这些选择的地方。它的 patch 是由 `dsh.bundle.patch` 清单字段指向的 `cordis.patch.yml`，`loadProfile` 读取它时不导入任何模块；它的代码是下文 `desktop-brand` 一行背后的 Host 半边与浏览器半边，以及 `desktop-server-log` 一行背后的 logger exporter。`apps/desktop-server` 把它列为依赖，使它进入 `pnpm deploy` materialize 出的载荷；`apps/desktop-shell/src/profile-seed.ts` 把它排在 `BUILTIN_WEB_BUNDLES` 末位，于是无论全新 profile 还是升级而来的 profile，它在桌面 profile 的 `dsh.profile.bundles` 里都排在 dsh-base、dsh-web-app 与每一个内置插件层之后。那里的末位只是那一次播种时的末位，不是永远的末位：从 `web` profile 迁移过来、或从插件页装上的插件，都会追加在它之后。还有三个用户层在更后面生效——profile 自己的 `cordis.patch.yml`，然后是 `$DSH_HOME/cordis.patch.yml`，然后是任何 `--patch` overlay——所以这里的一行是用户可以替换的部署默认值，而不是无法摆脱的设定。下面按每一行所改的 id 说明。`session-query-sqlite` 打开了对话正文的全文搜索（`openAt: first-search`，落在一份持久的派生索引上），而出厂组合包把它关着。`llm-deepseek` 把 `retryPolicy.backoff.maxDelayMs` 从十秒抬到五分钟，也就是一个被限流的请求在整回合失败之前愿意等完的最长 `Retry-After`；这个上限落在供应商那一行，是因为真正执行等待的 `@deepseek-ai/dsh-llm-retry` 自己不接受任何配置，收到 `retryPolicy` 键时会直接报错说明这一点。这个上限约束的是单次等待，而一个 step 最多重试五次，所以单个 step 最坏坐等 25 分钟，按这里针对的那些窗口是 2.5 到 10 分钟；每一次等待都在用户停止本回合的那一刻结束，等待期间转录里一直在倒数；算式见 [Agent Note](../../.agents/notes/implemented/feature/2026-09-06-desktop-composition-layer-content-search.zh.md)。那一行不设模型目录，所以选择器列出的是 `@deepseek-ai/dsh-llm-deepseek` 自己的 `DEFAULT_MODELS`，与上游出厂一致。`vision-switch` 点名在不支持视觉的模型上发图片时会话切到的模型，也就是会话起步的那个。`llm-permission-gateway` 点名权限网关的审查跑在哪个模型上，并把 `plugin_manager` 加进网关总是交给人的调用里；因为 `alwaysAsk` 会替换默认表，这一行还重述了网关自带的 `browser_auth` 一项。`plugin-manager` 把上游插件安装器指向壳在 `DSH_DESKTOP_PNPM` 里点名的 pnpm 启动脚本，开发启动时退回 `PATH` 上的 `pnpm`；它还在 `requiredModules` 里点名 `@haoran/dsh-crash-resume`，于是服务拒绝停用或移除这个插件，插件页把它的开关置灰并提示「应用必需，不能停用或卸载」；这份清单与 `apps/desktop-shell/src/profile-seed.ts` 的 `REQUIRED_WEB_BUNDLES` 相同，壳的播种在每次启动时把这个 bundle 重新打开。`office-to-pdf` 没有行：出厂那一行保持开着，它的 LibreOffice 引擎由壳在用户要的时候下载到数据目录（见桌面壳的「Office 引擎服务」）。`ui-chat` 同样没有行，工作详情按对话设置表单自己的默认值起步；壳没有定义 `dshDesktop` 全局变量，所以这个默认值是 `detailed`。`desktop-product-telemetry` 与 `product-analytics` 是 dsh-web-app 的两行产品分析，它的表达式在 profile 名不是 `desktop` 时让它们保持关闭；本层直接设 `disabled: true`，于是无论那些表达式怎么改、profile 改成什么名字，都不会打开向 DeepSeek 的上报；Host 那一行上报所经的 `otel` 在 dsh-base 里出厂就是关的。这一层有三行是插入而非修改的。`desktop-brand` 挂载本包。它的 Host 半边（`src/index.ts`）注册全局系统提示词段落 `desktop:protected-directories`，按字面文本、位于 `DEPLOYMENT_PERSONA_SUFFIX` 顺位；同顺位按名字排序，所以无论会话用哪个预设、是否为进程内委派的子代理，这段文字都在系统提示词末尾；`complete: true` 的 persona（`minimal` 预设用的就是它）替换整个提示词，会把它去掉；这是已知限制，之后由沙箱保护覆盖。这一行是 `protectedDirsPrompt`，必须恰好包含 `{directories}` 与 `{skillsDir}`。`{directories}` 按固定顺序、为启动时已知的每个目录各取 `directoryClauses` 里的一个分句，用 `directorySeparator` 连接，最后一个之前用 `directoryLastSeparator`；每个分句必须恰好包含它自己的占位符。`installDir` 来自外壳在打包启动时设置的 `DSH_DESKTOP_INSTALL_DIR`；`appDataDir`、`logDir`、`updateCacheDir` 来自 `DSH_DESKTOP_USER_DATA_DIR`、`DSH_DESKTOP_LOG_DIR`、`DSH_DESKTOP_UPDATE_CACHE_DIR`，即外壳的 Electron `userData`、日志目录与更新下载缓存。日志单独占一个分句，因为 macOS 上它位于 `~/Library/Logs`，在 `userData` 之外；Windows 与 Linux 上日志目录会作为设置目录里的子目录被列出。始终列出的 `{dataDir}` 是 `resolveDshHome()` 解析出的 harness 主目录（`$DSH_HOME`，否则 `~/.dsh`），也就是服务器自己的插件所用的解析器；`{skillsDir}` 是其中的 `skills` 目录，即 `@deepseek-ai/dsh-skill-filesystem` 读取用户技能的根目录，这一行把它列为例外，让 agent 可以继续在那里写技能。外壳的开发启动不列安装目录，手动启动的 `dsh --profile desktop-shell` 只列数据目录。占位符缺失或多出未知占位符的模板会拒绝挂载，按 id 修改这一行的层必须重述每个键。每个路径都放在反引号里插入。这一句为什么值得它占的上下文，见 [Agent Note](../../.agents/notes/implemented/feature/2026-09-28-desktop-protected-directories-prompt.zh.md)。系统提示词以 `system/message` 进入会话日志，所以带这一句的每份提示词连同其中的路径都有记录。浏览器半边占住 `sidebar.brand.name`，以 18px 显示北冥（英文界面为 Beiming），不带版本；并占住 `sidebar.brand.mark`，按 ui-sidebar 所要尺寸的 1.25 倍画鱼形标志，所要的 24 画成 30px 宽、22px 高，展开的品牌行与收起的侧栏窄条都一样。同一个半边还在 `settings.general.item` 的 `current-version` id 下以优先级 -1 注册一个空条目；同一列表 id 的多个条目只渲染优先级最低的那个，所以它遮住 ui-settings-general 的那一行，设置 → 通用不显示版本；桌面发行版本在更新设置页显示。`desktop-server-log` 挂载 `@deepseek-ai/dsh-desktop-app/server-log`（`src/server-log.ts`）：它在根 logger 服务上注册一个 exporter——这个服务由整棵树的每个上下文共用——把级别不高于 `level: 2` 的每条记录追加到壳在 `DSH_DESKTOP_SERVER_LOG` 里点名的文件，也就是 `dsh-server.log`。cordis 的级别顺序是 ERROR 0 < INFO 1 < WARN 2 < DEBUG 3，所以这个阈值保留 error、info 与 warn，丢掉 debug。壳只给服务器子进程设这个变量，打包流程的暂存启动也设它，于是这一行在那里挂载，它的模块必须能从载荷里解析到；不带这个变量、手动起的启动不会打开这一行。exporter 自己写文件，每条记录追加一次、以 `[server-log]` 开头，而不是打印出来，因为壳在服务器的 stdout 与 stderr 里找就绪行，并把两路输出都抄进同一个文件。挂载时它先追加 logger 自己的缓冲区里阈值以内的记录；那个缓冲区按 INFO 收记录，所以这一行挂载之前、启动期间记下的 warn 会丢失。`tool-session-query` 挂载上游的 `@deepseek-ai/dsh-tool-session-query`，dsh-base 与 dsh-web-app 都没有挂它：五个只读工具 `session_search`、`session_event_search`、`session_trace`、`session_event_trace`、`session_event_read`，加一段讲历史检索的系统提示词，让模型能回到会话日志里查出被压缩概括掉或修剪掉的细节，查的范围是它自己的会话和同一工作区的其他会话；目标会话只有在 `cwd` 与调用方完全相同时才可读。它是 Host 行，与包自己的挂载参考一致。它注入的每个服务都是 dsh-web-app 保持开着的 Host 行，所以这些工具注册在工具注册表的全局层，每个 agent 作用域都继承它们：`standard`、`ptc`、`cordis`、`minimal` 会话，以及它委派出的子会话，除非委派时给出的工具允许清单没有列它们。放进预设里的一行意味着要在这里重述那个预设的整份 `config.plugins`，因为按 id 的 patch 够不到预设自己的行。`minimal` 会话的 `complete` persona 会去掉那段提示词，它的模型仍然看得到五个工具的 schema。这一行不带 `config`，所以一次搜索最多返回包默认的 100 条命中，过长的追溯或事件读取由 dsh-base 的 `spill-policy` 行限制内联长度。`apps/desktop-server` 列出了这个包，而 `@deepseek-ai/dsh` 并不依赖它，所以它的模块在载荷里。`build.ts` 用 esbuild 打出两个半边和这个 exporter（`pnpm --filter @deepseek-ai/dsh-desktop-app run bundle`），Host 半边打到 `lib/index.js`，exporter 打到 `lib/server-log.js`，两者都把 `@deepseek-ai/cordis` 与 `@deepseek-ai/schemastery` 保留为导入，于是它们与服务器共用唯一一份 cordis，而不是自带第二份。根构建不打它，因为根构建的客户端一遍只覆盖 `packages/*/*`，所以桌面打包在 `pnpm run build` 及其标题检查之后运行这次打包（`apps/desktop-shell/scripts/client-build.ts`）；浏览器半边不读取任何构建期取值。`tests/brand.client.spec.tsx` 在生产用的 slot 与 locale 运行时上应用浏览器半边，`tests/protected-directories.spec.ts` 在真实的提示词注册表上挂载 Host 半边，并经技能提供方从它列为例外的目录加载一个技能，`tests/server-log.spec.ts` 在真实的 cordis 上下文里运行这个 exporter，`tests/host-build.spec.ts` 用 `build.ts` 的同一组选项打出两个 Host 包。`apps/desktop-shell/tests/desktop-composition-layer.spec.ts` 组合真实的各层，断言桌面 profile 最终得到的取值，检查组合出的 `llm-deepseek` 行解析出的是适配器自己的目录、会话从 dsh-base 自己的默认模型起步；它还用组合出的各行渲染 `standard`、`ptc`、`cordis`、`minimal` 会话以及一个委派子会话的系统提示词，并把组合出的 `tool-session-query` 行挂在真实的工具与提示词注册表上，检查这些会话和一个委派子会话都看得到五个会话工具。[`snapshots/desktop`](../../snapshots/desktop/README.zh.md) 以本包的 `cordis.patch.yml` 作为基础补丁，经 `dsh --profile acp` 回放一轮录制好的对话，于是五个会话工具按模型请求实际携带的样子被钉住，会话日志里也记下一次 `session_event_read` 调用及其结果。外壳见 [apps/desktop-shell](../desktop-shell/README.zh.md)，载荷见 [apps/desktop-server](../desktop-server/README.zh.md)。
