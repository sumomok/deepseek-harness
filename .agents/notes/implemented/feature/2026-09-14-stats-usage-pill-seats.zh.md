# Agent Note: 会话 Token 用量药丸上的贡献位

Status: implemented

[English](2026-09-14-stats-usage-pill-seats.md) | 中文

## 问题

fork 的余额插件知道一个会话花了多少钱。读者会去找这个数字的地方，就是输入框下面已经在显示的 token 读数，而那里没有任何位置能承载它。

`conversation.composer.dock` 是会话作用域的 list，dock 把条目纵向排成一列，占位者因此只能在统计药丸**下方**自成一行，而不是落进药丸里面。画出这两枚药丸的 `stats` 条目不声明 children，所以进入药丸或其弹层的唯一办法是复用 `stats` 这个 id 整体遮蔽该条目——为了补两个数字而替换掉随产品发布的时间药丸、用量药丸与两个弹层。插件也无法从外部开位，因为槽名是由渲染该位置的包所拥有的 `SlotMap` 声明合并。

## 决定

在 `stats` 这个 dock 条目上开两个会话作用域子位，两者的 owner props 都是 `StatsUsageOwnerProps`。

`conversation.chat.stats.usageLabel` 是 single 槽，占据用量药丸文案的开头那一段，也就是随产品发布的药丸打印缩写 token 总量的位置。它之后的一切药丸原样保留：`aria-hidden` 的 `·` 与缓存命中段照旧渲染，而该位的 fallback 正是那个 token 总量，因此无人占位时药丸就是随产品发布的那一枚。

`conversation.chat.stats.usageRows` 是 list 槽，渲染在弹层 `dl[data-session-stats-usage]` 内部、output 行之后。占位条目直接向那个 `dl` 输出自己的 `dt`/`dd` 对并继承它的皮肤；框架不给槽条目套任何自己的 DOM 元素，所以这些 `dt`/`dd` 是该列表真正的子元素。无人占位时弹层就是随产品发布的那一个。

owner props 是药丸自己算出的那两个数：`totalTokens` 是整条持久日志上全部 prompt 侧计费桶加输出的精确总和——不是药丸打印的缩写文本——以及 `cacheHitPercent`，即药丸自己的文案所插值的那个裸数字，尚无计费时为 null。占位者由此读到该会话的计费，既不必引入 chat 实现，也不必从投影重新推算总量。

用量按钮去掉了 `aria-label`。它复述的是两段可见文案，一旦文案位被占住，它就会继续朗读一个已经不在屏幕上的 token 总量。现在可访问名由可见内容决定，而无人占位时可见内容就是随产品发布的读数。两段之间的分隔符不再 `aria-hidden` 且自带前后空格，因此渲染出的文案完整写作 `105 tok · Cache hit 90%`——正是原先 `aria-label` 持有的那个字符串，也正是可访问名据以计算的文本。

这两个位只承载呈现。钱的含义归插件所有：它的价表、它的币种、它自己的文案与本地化，以及某个模型没有价格时显示什么的决定。chat 包拥有的是这些数字摆在哪里，以及无人贡献时药丸读什么。

## 备选方案

**遮蔽 `stats` dock 条目并重画两枚药丸。** 否决：插件将因此拥有随产品发布的时间药丸、用量药丸与两个弹层——上游今后对任一药丸的每一次改动，都得在 fork 的插件里重新实现一遍才能被看见。

**再注册一个 `conversation.composer.dock` 条目。** 被需求否决：dock 是一列，花费读数会落在 token 读数**下方**自成一行而不是它旁边，而且输入框底部留白会为一个本属于既有行的数字而变大。

**把原始 `TokenUsageProjection` 交给这两个位。** 否决：占位者将重新推算计费总量与缓存命中占比，此后只要药丸求和桶的方式一改，同一枚药丸里的两个读数就可能互相矛盾。

**保留 `aria-label`，用占位者的文本重建它。** 否决：占位者渲染的是 React 子节点而不是字符串，外壳无法把渲染后的文本读回来拼名字；用别的东西拼出来的名字，描述的就不是屏幕上的东西。

**只开一个位，整体替换药丸文案。** 否决：缓存命中段是随产品发布的 chrome，有自己的文案与语种，只想加一个数字的占位者将不得不重新渲染那一段才能把它留住。

## 后果

插件注册两个条目即可在 token 药丸上加一个金额读数、在其弹层里加一行花费，不 fork ui-chat、不替换任何随产品发布的 chrome。随产品发布的组合里两个位都是空的，因此生成的 client catalog 把它们列为无占位者、`replaceRisk: 'none'`，无人占位的药丸与弹层就是随产品发布的那一套。

随产品发布的组合里按钮朗读的内容与此前一致：原先 `aria-label` 持有 `105 tok · Cache hit 90%`，现在可见文案本身就写作同一个字符串，分隔符在内。这是本次改动在两个位之外唯一的行为变化。testing-library 的名字计算会把每个子节点的文本候选各自 trim，因此测试断言的是去掉空格的 `105 tok·Cache hit 90%`；空格保留在浏览器据以计算名字的渲染文案里，也保留在时间药丸自己的 `aria-label` 里——分隔符这次改动不碰它。

**退役条件。** 这是 fork 对上游 client 包的 overlay。上游只要以任何形式（不限于这两个键）在统计药丸或其弹层上开出等价贡献位，本 overlay 即退役，fork 的插件改去适配上游形式。在此之前每轮滚动同步都要重新移植并重新核实，因为它落在上游会改的药丸标记与槽契约上。

证据由包内测试承担：两个位都收到精确总量、无人占位时药丸与弹层的渲染与改动前逐字相同、文案占位者替换开头那一段而缓存命中段仍在、贡献的行在弹层被 portal 到 `document.body` 的前提下仍落在其 `dl` 内部 output 行之后、以及按钮的可访问名在两种状态下都跟随其可见内容。
