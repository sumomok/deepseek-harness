# Agent Note: the rules a structural page read is written by

Status: implemented

English | [中文](2026-09-02-content-snapshot-engine.zh.md)

## Problem

The page reader in `packages/experimental/content-frame/src/client/access/` walks a real application — drawn by a component library, in a browser, in front of a user — and answers with a few thousand characters the model reads instead of a screenshot. Two things make that hard, and neither of them shows in the code. Pages state what they mean in HTML and ARIA inconsistently: the same tree node is a link, an icon, a tick box, and a row of buttons depending on which library drew it. And every rule that leaves something out of a read is a rule that can leave out the one thing the model needed, with no way for the model to tell that it happened.

This note records the reading rules and why each one is the way round it is. Each of them decides against a defensible opposite, and most were found by pointing adversarial review at real component-library markup rather than by reasoning about the specifications.

## Decision

The walk knows HTML and ARIA, and nothing else: no library's class name, component name, or DOM shape appears anywhere in `src/client/access/`. A rule written in terms of one framework's markup is a rule that fails on the next one, and the framework a deployment renders in its content column is not this package's business. Every rule below is stated in terms a specification defines.

### Model-visible means readable

The rule the rest bend to: a run of text a reader can see reaches the model. The rules that classify — this is a picture, this is decoration, this is the page's own wrapping — may move text from one row to another, may fold it into a name, and may drop what the browser never draws. None of them may drop what it does draw. It is a working rule rather than a property the code has been proved to have: each counter-example a round of review finds is treated as a defect however defensible the classification was, because the model cannot ask about a run it was never shown. The counter-examples still open are listed under the limits below.

### Only what the page wrote counts as a label

`declaredName` reads `aria-label` and `aria-labelledby` and stops there. It is deliberately not the accessible-name computation: that falls back to the element's own contents, which for a tree node means every button hanging off it. A label the page wrote is worth more than anything the element shows, because a menu item drawn as an icon says what it is nowhere else; an empty label, and one pointing at nothing, name nothing at all and leave the element to the ladder below.

A reference is resolved in the tree the element itself lives in, so an id inside an open shadow root names the element in that root rather than whatever the surrounding page gave the same id. A reference to the element itself, to what it holds, or to what holds it, is not a label: a browser degrades that to naming from content, and naming a node from its content is the reading the ladder exists to prevent. What each referenced element is *called* comes before what it *shows*, so a page pointing at an icon is answered with the icon's own label.

### The node-name ladder

A tree node or a menu item is named by its own label, and never by what hangs off it: the group under it prints rows of its own, and so do the buttons that act on it. The ladder is the page's own label, then the node's own text outside anything that prints a row, and last the first row inside it that names the node.

That last step is what makes real antd and element trees read correctly, and it turns on which rows name a node at all. A row showing no words does not, because every tree a framework draws puts something wordless in front of the label — a folder icon, a tick box, an icon button. A link or a heading the page named is the exception: an icon link is how a framework draws the label of a node that is somewhere to go, and the name written on it is the only place that label appears. A control that acts on the node names it in no case, however much text it shows, so a node drawn out of nothing but a folder icon and a delete button is named nothing — rather than named `删除`, and repeated in the suffix of every row underneath. Acting on the node is what a reader can operate over it: a button, a field, and the commands a menu or a strip of tabs offers. A link and a node drawn inside another are not among them, because those say what the node is and where it goes rather than what can be done to it.

Being named nothing is not being read as nothing. A node the ladder leaves unnamed is a room rather than a row: the walk reads into it, and the switch that is the whole of a leaf, the command an antd dropdown draws as a button, and the picture drawn beside the delete button each print a row of their own. Printing the node as a row instead would end the descent there, and every word the page drew inside it would reach the model nowhere at all.

A room says everything the row it replaces would have said: the role the page gave the node, whether it is ticked, whether the page has closed it over what it holds, and whether the page has switched it off. A room that reported none of those would have a reader click a checked item again and turn it off, and read the rows under a closed node as everything it holds. The one thing it does not say is the region it sits in, which the row it replaces prints at its end. That suffix names the kind of region rather than the role the page wrote, so `menuitemcheckbox` on a room and `(menuitem)` on the rows inside it are one node said two ways.

A room is opened wherever a node holds anything at all, and the listing prints the row it stands in for when the room turns out to show nothing. The answer belongs to the listing rather than to the walk because it turns on what this listing shows: a dialog the page has not opened is a row of the skeleton and of no other read, so a node holding one is a region to map and a row to list. It turns on what the read has already printed as well, since the one button under a node can be the button drawn beside the tree, which a read prints once. A node over a group the page drew empty shows nothing in either listing, and reads as its own row in both. The region a row names at its end is therefore a region this listing kept: an item marks the region holding it as one that shows something wherever this listing prints the item, so no row can name a room the listing replaced. Answering it in the walk instead means reading such a subtree twice, once to decide and once to print, and nested nodes nest those readings: in jsdom, the sixteen-node chain pinned in `tests/snapshot.client.spec.ts` costs 7.1 seconds read that way against 10 milliseconds read once, and a tree of a thousand such nodes 48 seconds against 0.63.

Inside an unnamed room a run the page makes clickable is a thing to click and prints a room of its own; inside a named one it is the node's name said twice and prints nothing, along with the text it is drawn over.

### A picture is one thing, and so is everything else a browser draws itself

`isOpaque` covers `svg`, `canvas`, `video`, `audio`, `object`, `progress`, and `meter`. What is written inside one of these is a part of the drawing or a fallback for an engine that cannot draw it, and no engine in use renders either. The walk does not descend into one, does not read its text, and counts no row inside it: a path is not a paragraph, the `title` a drawing carries is a tooltip the page never shows, and the words in a `progress` element are for a browser that has not existed for a decade. A `noscript` is not one of these: what it holds is not page content at all, and the walk skips it along with `script`, `style`, and `template`.

Three kinds of these still print a row: a drawing the page named, which is a picture; a drawing the page itself made clickable, because frameworks put the handler on the icon rather than around it and a drawing with no row is a thing the model cannot reach at all; and a bar the page named. Any other drawing is decoration, and decoration ends no run of text. The first two are named by what the page wrote on the drawing and by nothing else.

A bar the page named prints its name and its value. The value is the text the bar draws, and the number the page wrote only where it draws none: both bootstrap versions draw the percentage inside the element carrying the role, the row ends the descent, and those words reach the model there or nowhere at all. A screen reader reads the two the other way round and announces `25` over a bar drawn as `上传中，请稍候`; this read answers with the page. Text that puts nothing on the screen is no text: a control drawing nothing but a code point of Unicode's format category — a zero-width space, a direction mark, a soft hyphen — reports the number the page wrote, rather than a pair of quotes around a character no browser draws. A code point a font draws as blank is not one of them, because a page writing one has drawn it. An unnamed bar reads as structure, because the percentage is then drawn in the text beside it and a row carrying neither a name nor a number would stand in front of that text.

Every word a control draws is its value, in a bar and in a field alike, the words on the things it offers included: the row ends the descent, so the chips of a multi-select, the clear button of a text box, and the cancel button inside an upload bar reach the model on that row or nowhere at all. A value that repeats a button the reader can see beside it is the smaller fault — a value the reader can check against the screen, against a page whose words go missing with no sign that they did.

The regions a control holds are the one exception. The list a combobox drops down is what the control offers rather than what it holds, and the rows of a table are its data; a control that is itself a region, a `div` a page marks as a `listbox` in a table cell, reports no value for the same reason. Keeping them out drops those words rather than moving them, and the counter-examples below record it: a region drawn inside a control reaches no read at all, because the control's row ends the descent before the walk numbers the region and nothing can then name it. Options are read as rows where the page draws the list outside the control — in a cell of the table beside it, or as a sibling the page draws in a portal. Only a region the element's role opens counts, a table among them: a row of buttons the page wrote no role on reads as a toolbar elsewhere in the walk, and inside a control that row is the chips the control holds.

### Landmarks stop at the page, and roles stop at what ARIA defines

A run the page makes clickable that reaches a region the page is laid out in is not a thing to click: the pointer cursor was inherited from something above it. Only `main` and `nav` are matched by tag, because HTML gives those two their role wherever they are drawn, while `header` and `footer` are a banner and a page footer only at the top level and are the head and foot of a card everywhere else. A page that means one of those two inside a card writes the role, and writing it is what makes it a landmark here. A form and a dialog are left out altogether: a card holds an inline editor or a confirmation readily, and is still the thing the page offers to click.

A role the page wrote is a role only when ARIA defines it, and the tokens are read in order so a document written against a newer vocabulary falls back to an older one. Printing an undefined word would put text the page controls where the model reads the kind of a row. Every selector in the package matches a token, `[role~="x"]`, for the same reason: a selector that missed the fallback would let one part of the read see a table where another part saw a paragraph.

Two consequences follow from reading the attribute differently from `dom-accessibility-api`, which reads the first word alone. Where the walk resolves a role the library did not, an empty computed name says only that the library's role is not named by its contents, so the row is named by the text the element shows — for the roles ARIA names from their contents, and only those. And the presentational conflict is resolved here rather than by the library: an element the page marks as decoration and then contradicts is read as what it offers, because the page has written two things that contradict each other and ARIA settles it in favour of the control. The two conditions are ARIA's own — the element is focusable, or it carries a state or property ARIA defines on every role — and they apply to `presentation` and to its synonym `none` alike, where the library resolves the conflict for the first spelling and answers `none` unchanged for the second. The implicit role is then read from a shallow copy with the attribute removed, because the library asked about the element as it stands answers the very spelling being ignored.

### A control's state is what the page said, and no more

A box the browser keeps the state of is read from the browser, and what ARIA says over the top of a native checkbox is ignored, as a browser ignores it. Anything else the page draws as one has the state it wrote — and no state at all until it writes one, since ARIA requires the attribute on these roles. A reader told "off" clicks to turn on what is already on. A box reported as half checked has no state of the two either: that is the box at the head of a table with some of its rows picked, and a reader told it is off clicks it and picks every row of the page.

### Structure reaches the model, data does not

A table is collected as its shape — header, one sample row, a row count — and its rows arrive only when a read asks for that table by ref or finds a row by its text. The sample says which controls a column offers rather than what they hold, so each cell is cut to the room the sample line gives it: the text gives way to the controls first, and the list of controls is itself cut inside its brackets, because a row of buttons each named a sentence would otherwise spend the whole line on one column. A bar is the one control whose value goes in the sample with its name, because what a bar reports is the whole of what its column shows: a cell drawn as nothing but a bar has no text of its own, and naming the bar alone drops the percentage a reader sees there. A header cell is cut in another place. Its text is taken to the renderer's own limit for a column name — more room than a sample line gives, because a column's name is worth more of the line than a sample of what the column holds — while the controls the header holds print whole beside it, under the rule the renderer holds every listed cell to, that cutting a control would cut a ref in half. The limit is on the cell's text and not on the cell, so a header cell holding controls may run past it — by the separator between the two and by whatever the controls print. What the two cells share is one cut each on the cell's own text, the renderer's limit for a header and the collector's for a sample. How many columns fit four times the smallest listing budget a deployment may configure is worked out from those two, so moving either moves that column count. A box the page names nowhere else is named by the word written inside it — `placeholder`, then `aria-placeholder` — for the four roles that carry one: `textbox`, `searchbox`, `combobox`, `spinbutton`. It is a fallback under the accessible name and never an override, and it is not the neighbouring-text rule this reader deliberately does not have: the word is written on the control itself, in the attribute whose purpose is to show it there. A nameless control is one `content_act` cannot be pointed at at all, because the model can only copy a name the listing printed. The whole ladder — what an element declares, what its contents say, the word written inside it, the `label` drawn in front of it, an icon's own symbol — is one exported function; the pass over the page is its batch form, calling it for every row it prints, and a caller holding one element (the seat, checking that a step's target is still called what the read called it) computes the same string from the same rungs. Where the pass knows more is position, and position decides whether a row is printed rather than what it is called. The controls a cell holds are named by the same function as every other row, and where a drawing counts as one of the page's commands rather than ornament — inside a toolbar, a list, or a cell — is one predicate both the pass and the single-element caller ask. A password box reports that it is there and never what it holds — the type, or a page that shows the password in a text box and says so in `autocomplete`, which is the same credential under a show/hide toggle.

### A table drawn again for each pinned column is one table

A component library pins a column by drawing the whole table a second time over the top of itself, with the contents of every cell it does not pin hidden inside the cell: the cell keeps its column's room and what is written in it is drawn nowhere. Each copy is drawn in a header half and a body half like any other table, so the layer list of the real ini-web2 console read on 2026-09-02 is six tables and one table the user sees. Reading them as six answered the model with the pinned columns empty in every row, an extra table of twenty empty rows beside them, and the copy holding the names dropped outright as a thing drawn twice — and the model told the user the table has no column called 名称.

Tables drawn over each other with a row for each row are read as the pieces of one table. The pieces are found by stepping along the tables drawn against each other in one region, the walk that already pairs a frozen header with the body under it, and each column is taken from the piece that shows it — the first of them where more than one does. The columns line up by their position in the row, because that is the one thing every piece agrees on: a pinned copy is drawn over a different column of the table as soon as the reader scrolls sideways, and on that page the copy pinned to the right edge is drawn beside the columns that scroll rather than over the ones it repeats. A piece drawing fewer cells than the table has columns therefore lines up from the left, which is where a page leaves the odd one out — the placeholder a frozen header draws over the scrollbar is the last cell of the header and of no body row.

Geometry decides what the structure cannot. Two tables the page draws one after the other are two tables however alike they are, so only a table drawn over another can be a piece of it; sharing an edge is not sharing ground. A page that reports no rectangle for a table has said nothing about where it is drawn, and its neighbours stay tables of their own.

The rectangles of that page, measured in the frame: the body of the main piece and the body of the piece pinned left are both `[69,152,3204,818]`, and the piece pinned right is the same table shifted 1756 to the left, `[-1687,152,3204,818]`. The right-hand piece shares 45% of the ground it repeats — enough to be drawn over it, far short of the 80% that makes two rows of a table one thing drawn twice, which is why the read that dropped one copy printed the other as a table of twenty empty rows. Each body row carries twenty cells and the header carries twenty-one, the odd one being the placeholder drawn over the scrollbar; the main piece hides the tick box, the name, and the commands, the piece pinned left draws the first two, and the piece pinned right draws the last.

The strip that pages a table is drawn after every piece of it, so the pieces of one table stop that search for nothing: the console draws its `div.crud-pagination` after all six tables, and a search stopping at the first of them answered that the table is paged by nothing at all. The model then read `20 rows` as the whole list and told the user there are twenty layers, where the strip says 共 89 条 — the two broken reads before this one made it scroll for the rest, and the fixed one made it stop. Any other table does stop the search, so a strip drawn between two tables pages the one above it alone. A strip pages a table only where the two stand in the same region, which cuts both ways: a table no region encloses is paged by no strip drawn inside one, and the region an element stands in is the one around it rather than the element itself, since a page draws that strip as a `nav` as readily as it draws it as a `div`. A navigation landmark holding a strip directly — nested landmarks included — is part of the strip: a page marks the landmark (`<nav aria-label="Pagination">`) or marks the list and wraps it in one (`<nav><ul class="pagination">`), and reading the wrapper as a region would leave the second kind standing beside no table at all. Where the landmark holds the table too it is the region they share, which places them beside each other on the other reading; any element that is no landmark between the two ends the climb, and the landmark is a region like any other. A table a strip pages prints its size as `20 rows on this page × 21 cols` rather than `20 rows × 21 cols`, and prints the strip's own words on a `pagination:` line, in a whole-page read and in a read scoped to the table alike: the row count is what a model answers "how many are there" with, and a paged table answers that on its strip. Nothing is parsed out of those words — how many rows there are, and in which language the page says so, is the page's to say.

### A cell offers what the page makes clickable in it

A cell names the controls it holds rather than reading them as text, and a run the page makes clickable is one of them, named the way a row of its own would name it. A cell that read a click target as text would leave the model a column it can see and cannot use. The judgement is the walk's own, so a cell inside a run the page made clickable higher up offers nothing: the top of the run is above the table, and the row is not a thing to click.

This rule reaches a click target the page marks with a pointer cursor, and a button whose whole content is an icon was already reached by its role. Neither is what the console this note is written against draws: the commands of its rows carry no cursor of their own, which is why the rule below exists.

### An icon a page draws as a command is a thing to act on

The 操作 column of the layer list reached the model as an empty cell in every row. Its commands are `<i class="el-tooltip operation-modify el-icon-edit">` and an icon inside the wrapper a confirmation puts around it, measured on the page: no role, no `aria-label`, no `title`, no pointer cursor, and a click handler the framework holds as a listener rather than as an attribute. Nothing a specification defines says those elements are there at all, so every rule in this package written in specification terms reads that column as empty — and a reader who can see the icons has no way to ask for one.

An inline element that draws no words of its own and carries the word `icon` in one of its classes is therefore read as an icon: `icon "edit"`, with a ref of its own, inside a table cell, a toolbar, or a list — the places a page draws icons as the commands it offers rather than as decoration beside its text. What the page wrote outranks the class, as everywhere else: an `aria-label` or a `title` names the icon, and the class names it only when the page named it nothing.

This is a heuristic keyed to a page's own markup, and it is the only one in the package that names an element. Two more read a page's own word without taking a name from it: the strip that pages a table carries `pagination` and the trail saying where the user is carries `breadcrumb`, each recognised where a class holds the word or a navigation region is labelled with it, and each answering with the words the page draws rather than with anything the word itself says. It is kept as narrow as it can be and still work: only the word `icon` counts, in any class token that holds it, and no library's prefix is matched — `el-icon-edit`, `anticon anticon-delete`, `icon-trash`, and `iconfont` all reach it through that one word, while an icon font spelling its classes some other way (`fa-trash`, `mdi-pencil`) reaches it not at all. The name is what a token writes after the word: `el-icon-edit` says `edit` and `el-icon-arrow-down` says `down`, while a token ending at the word — `el-icon`, `edit-icon`, `iconfont` — marks an icon and names it nothing, which prints a row with a ref and no name. **The rule retires** when an adapter can hear the framework's own click listeners, which is what those elements really carry; until then it is the only thing standing between the model and a column of commands it can see and cannot name.

An icon set that draws its shapes in the document rather than in a font reaches the rule through the same word. antd v4 and Element Plus put an `svg` in the page, and Bootstrap Icons ships a sprite beside its font; such a set writes its name in one of three places: the classes of the wrapper around the drawing, the symbol a sprite reference points at (`<use href="#icon-edit">`, `<use href="#bi-pencil">`), or the drawing's own `title`. A symbol id names the drawing whatever it is called — a page pointing at one has named it on purpose — and only a class has to carry the word. A drawing is read whatever its own classes say, because those places are where the name is; a wrapper is read only where its classes mark it as an icon, and the drawing it holds and nothing else then prints no row, so one icon stays one ref. A wrapper whose classes name nothing is named by the drawing it holds, since the name a browser computes for a wrapper reads no title one element further in; where the classes and the drawing both say a word, the class wins, as the page's outermost word on the thing the reader clicks. A drawing naming itself in none of the three is decoration and prints nothing at all: a page draws far more decoration than commands, and a row for each would spend the budget this read exists to protect. The console this note is written against draws Element UI 2, which is a font — the rule is written now because the next console will not be.

### A field is named by the words a page draws in front of it

A form drawn by a component library ties no label to any field: the label is a `label` element with no `for`, and the box carries no name of any kind, so every field of the new-layer dialog on the ini-web2 console has an empty accessible name. The read answered with forty-nine rows of `textbox = ""` and the words beside them as runs of their own, and nothing reading that could tell one field from another.

A field the page named nothing is now named by the `label` drawn in front of it: the last one before the field, inside the smallest element holding both, searched outwards as far as the region the field stands in. The search stops where anything else the reader can act on stands between the two — two boxes in one group take the label for the first of them and nothing for the second — and a label running longer than a label does is a run of the page rather than a name for something beside it. The label prints once: the row it would have printed of its own is dropped, the way the text of a `label` a page does tie to its control already is.

Only a `label` counts. A page draws its own notices, headings, and captions in front of a field as readily as it draws the field's label, and a rule that took any of them named a field `公告` after the paragraph above it and took that paragraph's own row away — the model then reads a name that is not the field's, which is worse than reading no name at all. A `label` is the page saying these words label a field, whether or not it says which field.

### The mark a page draws rather than writes

A form says a field must be filled by drawing a star in front of its label with a stylesheet. That star is in no attribute, in no text, and in nothing a read of the document can reach: on that dialog the model looked for `*` and for `＊`, was told nothing matches, and ended up asking the user to tick 「只显示必填」 so the form would show the required fields alone. The read now asks the page what it draws around each element that labels a field — `::before` and `::after`, through an injected reader defaulting to the computed styles of the window that draws the document — and prints `(required)` for a star there, or for what the page says on the control itself with `required` or `aria-required`.

Every label the page ties to the field is read, not only the one the field takes its name from: `label for=`, the labels HTML resolves for a control, and the elements `aria-labelledby` points at. A form that ties its label properly is the likeliest of all to draw the star, and reading only the untied case would have left the most correct markup as the one shape that fails. The mark is looked for inside what the page draws rather than taken as the whole of it, because a form draws the star in front of the label and the colon after it, and both reach this as one run.

### A picker drawn in two halves is one field

A page draws a picker as a box it fills itself and an arrow that opens what it offers. The box takes no typing, which the read says with `(readonly)`: a reader told nothing types into a field that answers no key. The arrow carries no role and no name, and a row of its own would have the model choosing which half of one field to click, so it prints on the field's row as the ref that opens it — `e173 textbox "是否显示" = "" (readonly) [e174 opens]` — and only where the page draws it inside the element that holds the field.

### Never a blind cut

A whole page too large for the budget comes back as a skeleton of its regions and where to read next; a listing too large comes back with a cursor to continue from. A read never answers with half a list and no way to reach the rest, and a listing cut short backs off the trailing rows the model cannot name so a continuation covers the listing exactly once.

### Layout is injected

jsdom lays nothing out, and a frame's layout belongs to the frame, so visibility and geometry arrive as `isVisible` and `rectOf` and reach the DOM only through the caller. Every conclusion this package's tests reach about what a reader can see is therefore conditional on the implementation the page seat injects.

## Alternatives considered

**Naming every row with the accessible-name computation.** It is the specification, it is implemented for us, and it is what a screen reader would say. Rejected for the rows where "what a screen reader says" is the wrong answer: a tree node's computed name is its whole subtree, which puts the delete button's text in the node's name and then in the suffix of every row under it. The computation still names everything else, and the ladder is confined to the roles where content-naming is wrong.

**Reading a drawing's `title` and `text` as page text.** It is text, and a chart legend genuinely says something. Rejected because a `title` is a tooltip the page never draws and the words in a chart are labels of a picture: reading them broke the run of text around every icon and printed tooltips as if a reader could see them. The cost is recorded under the limits below.

**Keeping a decoration role as written, without the conflict resolution.** Simpler, and one fewer thing to keep in step with ARIA. Rejected because it deleted labelled buttons and text boxes from the read entirely — an element carrying a name is an element the page contradicted itself about, and ARIA and every browser resolve it the same way. Taking the library's answer for it was rejected in turn: it resolves one of the two spellings, and `none` is the spelling newer code writes.

**Printing `mixed` as a third state.** Honest, and it costs one more token in the row. Rejected for now because every reader of the row would have to be taught the third word, while saying nothing already means "look at it": the model asks about the box rather than acting on a state it was told wrongly.

**Cutting the sample line after assembling it.** One cut instead of two, at the place where the line is printed. Rejected because it cuts the controls off the end of a cell whose text runs long, and the column then reads as one offering nothing to do.

**Keeping out of a control's value everything that would earn a row of its own.** It reads well — a row saying an upload stands at `取消` states something about the page that is not true of it — and it was the rule for one round. Rejected on the evidence that the premise is false: what would earn a row somewhere else earns none inside a control, because the control's row ends the descent before the walk reaches it. The rule cut `文档` out of the middle of `见 文档 一节`, emptied a multi-select of its chips, and left an upload bar drawn as a table of one cell reporting nothing at all. Losing words is the worse fault, so the rule now keeps them and cuts only the regions a role opens.

**Letting any labelled click target print its own row.** The rule that a name the page wrote makes the target a thing of its own is what keeps a labelled card from being read through. Rejected in the one case where the label repeats what the single control inside says: that is one thing said twice, and two rows for it would have the model choosing which of them to click.

**Reading the star a stylesheet draws as text of the page.** It is text a reader sees, and the rule the rest bend to says such text reaches the model. Rejected as a general rule because `::before` and `::after` carry a page's punctuation, its icon font, and its decoration as often as they carry meaning, and putting all of it into the runs a read prints would change what every `find` matches. The mark is read where it means something — on the words naming a field — and reported as a word of the row rather than as text of the page.

**Printing the arrow of a picker as a row of its own.** It is a thing the reader clicks, and every other click target the page draws prints a row. Rejected because the box and the arrow are one field drawn in two halves: two rows for it would have the model choosing which half to click, and the ref on the field's row reaches the same element.

**Naming a field by any run the page draws in front of it.** It reads the page the way a person does — the words above the box are what the box is — and it named the fields of the dialog correctly. Rejected on the counter-example: `<p>公告</p>` in front of a field made the field `textbox "公告"` and took the paragraph's row away, so the model read a name that belongs to the page rather than to the field, and lost the run as well. A `label` is the one element that says these words label a field, and the rule is confined to it.

**Teaching the walk about component libraries.** Every defect in six rounds of review was found in antd, element, or bootstrap markup, and matching their class names would have fixed each one in a line. Rejected because the reader runs against whatever a deployment renders, and a rule keyed to a class name is a rule that silently stops working when the page ships a new version of its own dependency. Two kinds of rule break that. The strip that pages a table and the trail saying where the user is are found by the word a page's own markup carries, because no specification marks either and both are drawn on every console; neither is named by that word. And an icon carrying no role, no name, no title, and no cursor is a thing the reader can see and no specification describes, so either the class says what it is or nothing does. It is written against the word every icon font shares rather than against any library's prefix, and against the two places an inline icon set writes a name that is not a class at all; it is confined to the places a page draws commands; and it retires against the framework's own listeners.

## Consequences

The reader answers with the structure of a page rather than its contents, under a budget it never spends blindly, and stays correct against the markup four component libraries actually emit. What it gives up is recorded here rather than discovered in the field.

Nothing a drawing holds is read as content: a chart's slices, its legend, and the words in it are unreachable, and a page whose data lives only in an SVG reads as a heading and nothing else. What the page draws inside one and the reader can still operate stays a control — a table cell names the icon link in a chart and a listed row reaches it, because that link is often the only way into the row — but it prints no row of its own and never names the node around it. A control drawn as an icon needs `aria-label` to be named at all, which is what accessibility requires of the page anyway. An element pointed at by `aria-labelledby` that carries no name of its own and no text — a `span` wrapping an `img` — contributes nothing to the name. And `meter` carries a tag-to-role mapping of this package's own, read for the implicit role of a decorated bar as well as for a bare one, because the library maps every other bar and not that one.

Whitespace is the only thing taken out of the text a read prints, so a control character a page draws arrives in the snapshot as it stands: `= "​70%"` keeps the zero-width space the page wrote in front of the number. The format code points are read as blank only in deciding whether a control draws text at all. What answers for the rest is the seat carrying the read to a terminal, not the walk.

A node named by a picture reads as a room rather than as a row, so the map prints it as an unnamed node — `e2 treeitem  1 buttons, 1 texts` — with the label on the picture's row inside it, which a map does not print. For the same reason `find: 华北` answers with the picture's ref rather than the node's, and a model clicking that ref clicks the icon. A node the page names outright answers with its own ref.

A table drawn over another without a row for each of its rows is not a piece of it, and is dropped as one thing the page drew twice: the second table's rows reach the model nowhere. So does a pinned piece the page draws in a region of its own, which is not a piece at all — two tables in two regions are two tables. A strip drawn outside the region the table stands in pages nothing either, so a page drawing its table in one region and its pager in another reads as a table with no strip at all.

Only a `label` names a field the page tied nothing to, so a form drawing those words in a `div` leaves its fields unnamed rather than risk naming one after a notice beside it. A field taking its name from a `label` drawn inside a longer run keeps that run as a row, so those words reach the reader twice. The drawn mark is read on the labels a page ties to a field and on the one drawn in front of it, so a field the page names itself with `aria-label` and stars on a label it ties to nothing is not reported as required.

The icon rule carries three blind spots of its own. An icon font that never writes the word `icon` — `fa-trash`, `mdi-pencil` — reaches the read as nothing at all; a drawing naming itself in neither a class, a symbol, nor a title is read as decoration, which is what most drawings are; and an icon drawn outside a cell, a toolbar, or a list is read as decoration however much the page means it as a command. All three are the price of confining a markup heuristic to what it can be trusted for.

Nine counter-examples to the rule that model-visible means readable are open.

Four are the read losing text outright. A checkable control the page labelled says everything it holds in its checked state, so it reports no value, and `<div role="checkbox" aria-checked="true" aria-label="选中">华北</div>` inside a tree node reaches the model as `checkbox "选中" [x]` with `华北` on neither side — `find: 华北` answers that nothing matches. A region drawn inside a control prints nowhere, because the control's row ends the descent before the walk reaches it: the buttons of an editor's format toolbar go, a table drawn inside a text box goes with the shape a read reports it by anywhere else, and so do three chips a page wrapped in a `ul`, where two chips in the same `ul` are kept because a list needs three items to read as one. A node the ladder does name — by a label the page wrote, or by text of its own — prints one row and folds away the controls drawn beside it, so the delete button of a labelled tree row reaches the model nowhere. And the fallback content of a `progress` or a `meter` is dropped on the strength of the specification saying no engine in use renders it, which jsdom cannot confirm either way.

Three are a role the read cannot make sense of. A role the page wrote that falls back to one ARIA does not name from its contents drops the words the element shows, unless that role carries a value instead: `<span role="bogus img">趋势图</span>` prints an unnamed picture. The tag-to-role mapping is reached only by an element the page wrote no role on, so `<meter role="bogus" aria-label="磁盘">` reaches the reader as nothing at all. And a layout table the page contradicts is read as the table it says it is, which stands it between the halves of the table beside it: the header half lends its header to the layout table, and the body half is left with none.

Two are the read reporting more than the page says. A native `select` inside another control is read as the text it holds rather than as the option it has selected, so a two-option select reports both: `visibleText` has no notion of an element a browser draws its own text for, and the one place that shows is a control drawn around a native field. And the words on the things a control offers join its value, so a text box drawn around a clear button reports `= "东风 清除"` — the price of never dropping a word, paid where a reader can see both.

## Deferred

`cellText` in `render.ts` builds a control out of its role, its name, and its state beside `controlText`, which builds the same run for a control's own row. The two differ in the ref a cell prints in front of each control and in the folded-away mark, which a cell control carries nowhere: one could call the other once `CellControl` says whether the page has folded the control away. It is not worth a change on its own.

## Testing

`tests/snapshot.client.spec.ts` pins every string the model can see, word for word, over fixtures written as the four libraries draw them — a table pinned column by column and a dialog form among them, written from the real ini-web2 console page, the rectangles measured in its frame, the classes its row commands carry, and the stylesheet marks it draws; `src/client/access/**` is covered per file at 100%. Conclusions that depend on what a reader can see hold in jsdom with an injected `isVisible`, and are conditional on the browser implementation until a real page is read in one.
