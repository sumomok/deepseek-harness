# Agent Note: 桌面端自带账户余额与花费

Status: implemented

[English](2026-08-23-desktop-builtin-balance.md) | 中文

## Problem

GUI 对钱只字不提。跑在计量 API 上的 agent 每一轮都在花用户的余额,而想看看还剩多少、或者这次对话花了多少,唯一的办法是开浏览器进供应商的控制台读。对一个「不需要终端」就是全部理由的客户端来说,「去网站上看」和「去跑 `dsh plugin add`」是同一种失败;而且它对花费比对余额更糟:供应商的控制台报的是一个账户总数,不是这一台安装做了什么,更绝不是屏幕上这个对话花了多少。

harness 本来就有这些数。每条 `assistant/message` 会话事件都带着供应商路由 id、模型 id、一个时间戳和一份 `TokenUsage` 记录,所以一个回合的成本是对会话日志已经握着的数据做算术。缺的是把这道算术做了、并把答案放到用户正在看的地方的那个东西。

## Why not the community plugin

`dsh-cost-meter` 是注册表里做这件事的领头答案,动手写任何东西之前先审了它。五条发现,对一个要塞进安装包分发的包来说,任何一条都足以出局。

**不带鉴权的可变更 RPC,外加 `{{ENV}}` 模板。**它的配置接受会展开环境变量的请求模板,而写这些模板的那条 RPC 不需要任何鉴权,于是任何能够到服务端的调用方都能把模板指向自己控制的主机、让进程把自己的环境变量发过去——局域网上任何东西都能做的凭据外泄。

**它去读别的应用的凭据文件。**它的密钥发现是去遍历无关工具的已知配置路径,而不是向宿主要一份凭据,于是它手里握着用户从没给过它的密钥。

**它把 API 密钥以 `0644` 明文写进磁盘。**机器上每个账户都读得到。

**它不暴露任何 `Config`。**上面这些一条都关不掉、收不窄、也改不了指向,所以一个部署没法把它调成自己审计能接受的状态。

**五天里发了三十五次。**对某一个版本的审计对下一个版本什么都不说明,而且并不存在一个「已修复」的发布版本可以指。

## Decision

`@sumomok/dsh-balance` 0.1.0 是为这个部署写的,是第八个内置插件。

**用户看到什么。**侧栏底部 Settings 旁边的一个 chip(`sidebar.footer.action`)以账户自己的币种显示剩余额度,按两个可配阈值着色,也按供应商自己的 `isAvailable` 标志着色——因为账户可以在有钱的情况下被停用。悬停它会打开一个浮层,里面有总额、赠送额与充值额、这次读取的时间,以及今日 / 本月 / 累计花费和每一档价格各占的比例。输入框下面的一行(`conversation.composer.dock`)显示当前对话花了多少,外加价格表没能定价的 token 数。解析不出密钥、或者端点不是这个插件可以说话的那一个,就是 `unconfigured` 状态,**什么都不渲染**——从来就不想要这个功能的部署,看到的是它装之前的那个侧栏,而不是一句解释失败的占位文字。

**两种不同的数,插件从不把它们混起来。**余额是供应商自己的数字,从它的账户端点读来。花费是 harness 自己记下的 token 用量乘以这个部署自己拥有的价格表,所以价格表没定价的模型会报成未定价 token,而不是报成零。运行期什么都不抓取,任何价格页面都不去请求。

**价格 schema 不带任何厂商的词汇。**每个币种一份价目表,因为一个按两种货币计费的供应商发布的是两份价目表,而不是一份表加一个汇率;而一个 CNY 余额旁边摆一个 USD 花费总额,是两个谁都没法比的数。一个条目声明按 token 单位计的基础费率,和一列有名字的排期;每条排期在该条目自己的 IANA 时区里主张若干挂钟时间窗,并且要么重述费率、要么用倍数缩放基础值,先匹配者胜。随包默认带着 DeepSeek 公布的两份表,转录于 2026-08-23,`asOf` 显示在浮层里币种旁边;保持它们是最新的,是部署自己的活。

**账本里只有数字,没有别的。**`$DSH_HOME/dsh-balance/ledger.jsonl`,目录 `0o700`、文件 `0o600`,每次 LLM 请求一个 JSON 对象:时间、会话 id 与日志序号、模型与供应商 id、五个 token 桶、成本、定价所用币种,以及生效的那一档价格。没有提示词,没有补全,没有密钥,没有端点。超过 `ledgerDays` 的行在启动时丢弃并重写文件。

**它是第一个宿主那一半真干活的内置插件。**这个包有三张面:`.` 是宿主插件,`./client` 是浏览器那一半,`./typert` 是线上 schema 清单。第三张面由 `@deepseek-ai/dsh-typert-loader` 自行发现——某个 loader 条目挂载时,它解析该条目的 `package.json`、读 `exports['./typert']`、import 它,并把 `TYPERT` 清单注册进 `ctx.typert`,卸载时撤回——所以一个第三方 Remote 不需要白名单,也不需要本仓库改任何东西。这个 loader 由 `@deepseek-ai/dsh-base` 的 patch 层挂载,而 `desktop` profile 把它编排在每个内置插件之下。

**它的运行时依赖挺过了载荷坍缩。**`zod` 是宿主面与 Typert 面真正的依赖,不是 peer,而 `scripts/bundle-closure.ts` 会删掉每一个没有可达者 import 的第三方包。它被保留下来,是因为可达性遍历除了从 `@deepseek-ai/*` 出发,也从 profile bundle 出发:这个包声明了 `dsh.bundle`,于是被整个保留并加入 `external` 集合,遍历随后在它随包分发的文件里找到 `from "zod"`,把 `zod` 一起留下。拿遍历自己的 `specifierFor` 对着已安装的树重放一遍可以确认这一点;而它的范围就是每个 workspace 包都在用的 `^4.4.3`,所以载荷只带一份。它需要的东西也没有一样丢在拷贝过滤器上:`PRUNE_SUFFIXES` 丢掉 `.map` 与 `.ts`,而它 `exports` 的五个目标——`lib/index.js`、`lib/client.js`、`lib/typert.js`、`cordis.patch.yml`、`package.json`——都在那道过滤器的另一侧。

**播种顺序。**名字追加在两个对话插件之后、`@haoran/dsh-default-model` 之前,后者在全新 profile 上仍是最后一层 bundle。顺序其实什么都不影响:这一层插入一行、用的是它自己的 id,不 patch 任何别的层设过的条目。

## Security posture

这个插件正是被审掉的那个所不是的形状。

**一个只读服务。**Typert 网关恰好暴露两个方法,`accountBalance/get` 与 `accountBalance/spend`。没有任何变更方法:价格表、阈值与轮询窗口只能通过 `cordis.yml` 改。一个经反向代理放进 `/api` 的调用方能读数、什么都改不了,而且拿不到密钥、拿不到端点、拿不到提示词。

**密钥从不被握住。**它每次读取都经宿主凭据缝重新解析一次,请求结束即丢弃——这也正是轮换后的密钥不用重启就能在下一次轮询生效的原因。它以 `Authorization: Bearer` 头发出——从不进 URL、从不记日志、从不回传给浏览器、从不写进账本。宿主缓存的是余额,不是密钥。

**出网只有一个源。**端点由供应商自己的 `baseURL` 推导:去掉末尾一段 `/v<数字>`,再接上账户路径;不是 `http(s)` 的 base URL,或者任何会离开那个源的推导,都会被拒绝并报成 `unconfigured` 而不是发出去。没有遥测,没有更新检查。

**没有路由,也没有会话事件。**这个插件不注册任何 HTTP 路由;浏览器那一半经 harness 自己的 `/api` Typert 网关够到宿主,继承它的信任围栏。它不往任何会话日志追加东西,所以卸载它不可能让某个会话读不出来。

## What an existing installation sees

播种往 `dsh.profile.bundles` 追加一个名字、把包链接进 `$DSH_HOME/profiles/node_modules`,除此之外什么都不做;profile 自己的 patch 层、依赖,以及清单里其他每个字段都不被碰。

汇总从这台安装写下的第一行算起,浮层会说明这一点。插件安装之前就存在的会话,以及从磁盘恢复的会话——它们种入的历史不会在事件流上重播——都不出现在今日、本月或累计总额里。本会话那一行不受影响,因为它是对每个会话自己那份持久日志的投影,所以打开一个几个月前的对话,会按当前价格表把它整段历史重新定价。

## Alternatives considered

**直接把 `dsh-cost-meter` 作为内置插件。**它现成、有人维护,只要一行依赖。按上面那份审计否决:把它塞进安装包分发,等于在每一台桌面机器上放一条不带鉴权的外泄通路,而且没有任何配置能把它关上。

**只做余额,不做花费。**这是更小的插件,不需要价格表、不需要账本、也不需要保留策略——余额是供应商已经算好的一个数。被产品负责人的要求取代:用户真正问的是这次对话花了多少,而只有余额,只能靠两次瞥一眼再相减来回答。

**包住 `llm/stream`,而不是观察 `session/event`。**这个瀑布能看见每一次请求,自己也不需要什么持久身份。否决,因为那把这个插件放进了请求路径里,而在那里,一个记账插件的 bug 能让一个回合失败。`session/event` 订阅在提交之后、发出即不管,所以它做的任何事都不可能让一个回合失败;而且每条记录本来就带着模型、供应商、用量,以及一份可以写下来的持久 `(session, seq)` 身份——这正是那个瀑布给不出的。

## Consequences

每台桌面安装现在只要有窗口开着,就会每分钟向供应商的账户端点发一次请求,用的是与会话相同的凭据。答案缓存 `refreshMs`、由每个标签页共享,失败的读取抑制 `retryMs`,并发调用方共享同一个在途请求,标签页不可见时浏览器整个跳过这次轮询。

随包的价格表是一份带日期的转录,DeepSeek 改价那天它就过期了。症状很安静——花费总额是漂移而不是报错——所以 `asOf` 就摆在屏幕上币种旁边,而更新这张表意味着发一个桌面构建,和其他每个内置插件一样。表里没有的模型会报成未定价 token,那是同一种过期的可见形态。

改动一份价目表、或者换到另一个币种的表,会改变本会话投影的缓存版本,于是每个会话在下次读取时重新定价,而不是继续往按旧费率算出的总额上加。账本自己的行保留它们写入时的币种与档位,汇总也按币种分开,所以换表的部署看到的是新币种从零开始,而不是继承旧币种的一个总数。

这个插件在 `$DSH_HOME` 下拥有一个 harness 其余部分并不知道的文件。`dsh plugin remove` 会去掉依赖与层、把账本留在原地;删掉 `$DSH_HOME/dsh-balance/` 是用户自己的动作。
