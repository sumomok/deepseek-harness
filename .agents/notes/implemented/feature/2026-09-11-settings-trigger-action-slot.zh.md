# Agent Note: 设置触发行右端的同行贡献位

Status: implemented

[English](2026-09-11-settings-trigger-action-slot.md) | 中文

## 问题

fork 的桌面外壳需要把「有更新」控件放在用户本来就会去看应用级状态的地方：侧栏脚部的设置行上。那里没有任何位置能承载它。

`sidebar.footer.action` 是离设置最近的加法位，但 `.footArea` 是纵向 flex——侧栏自己的注释写着「Footer actions stack above Settings」——占位者因此落在触发按钮**上方**自成一行，而不是它旁边。`settings.trigger` 是覆盖按钮**内容**的 single 槽：占进去就是替换随产品发布的齿轮与文案，而不是与它们并列。这两个缺口都不是插件够得着的，因为槽名是由渲染该位置的包所拥有的 `SlotMap` 声明合并。

## 决策

`settings.trigger.action` 是根作用域 list 槽，声明在 ui-settings 里与其余每个设置槽类型为邻，由 ui-settings-general 外壳渲染在触发行的最后一个元素、连接指示器之后。条目按 `order` 升序渲染。

owner props 是本位专用的 `SettingsTriggerActionOwnerProps`：侧栏的 `wide` 状态（与触发内容位收到的是同一份 currency），外加 `openSection(id)`——外壳自己那个组件内的开面板入口，它选中以该 id 注册的分区并打开模态框。占位者由此直达某个设置页面，而不必去按它旁边的触发按钮；没有任何 `settings.section` 条目认领的 id 不会选中任何分区，面板照常打开、落在导航第一行。onboarding 协调器本来就收到同一个入口，所以本位拿到的是外壳早已发放的那份份额。

右对齐是结构性的而非声明出来的：触发按钮是 `flex: 1`，因此它之后的一切都贴住行的右缘。本位的包装层与渲染器自己的槽锚点都是 `display: contents`，所以无人占位时它既不贡献 flex 项、也不占掉行里的 8px 间隙——没有贡献方的那一行，版式与本次改动之前逐字节相同。

折叠后的 56px 轨道把该行收成一个 36px 的触发圆圈，旁边没有任何空间。该行在轨道下用 CSS 隐藏本位（`.triggerRow.railRow .triggerActions { display: none }`），而不是跳过 `renderSlot` 调用，因此占位者的自有状态、定时器与订阅能跨越折叠与展开存活。`wide` 仍然送达占位者，它据此得知该行已折叠。

## 备选方案

**注册进 `sidebar.footer.action`，接受上方那一行。** 因需求不予采纳：该控件必须读起来属于设置，而触发按钮上方自成一行读起来是另一个控件。

**占用 `settings.trigger`，自己画一个带角标的齿轮。** 不予采纳：那个位是 single，占位者拥有整个按钮内容，插件为添一个相邻控件就得接管随产品发布的图标、文案及其本地化。

**放宽 `SettingsTriggerOwnerProps`，让触发行两个位都带上这个入口。** 不予采纳：内容位画的是那颗按钮内部的图标与文案，而那颗按钮本来就会打开面板，所以入口放在那里，对它的占位者是一个用不上的能力。一个位的 owner 份额只装它自己的占位者用得上的东西。

**照连接指示器的做法在轨道下不渲染本位。** 不予采纳：指示器派生自外壳本来就持有的 store，折叠后重新派生是免费的；而本位的占位者拥有私有状态，重新挂载会把它丢掉。

**让轨道行放宽到容得下占位者。** 不予采纳：轨道固定 36px 的列版式是与其余每个轨道控件共享的随产品发布的版式，为一个可选贡献方放宽它，会连没有任何贡献方的组合也一起改掉折叠侧栏。

## 后果

插件注册一个条目即可在设置行上放一个控件，不必 fork ui-settings-general，也不必替换随产品发布的 chrome。随产品发布的组合里本位为空，因此生成的客户端目录把它列为无占位者、`replaceRisk: 'none'`。

**退役条件。** 这是叠在上游客户端包上的 fork overlay。若上游开出等价的同行席位——无论采用何种形式，不限于这个槽名——即退役该 overlay，并让 fork 的插件适配上游形式。若 fork 改用上游的桌面外壳、不再需要那个更新插件，同样退役。在此之前每轮滚动同步都要重新移植并重新核实，因为它落在上游会改的同一段触发行标记与同一份槽契约里。

浏览器金样零改动。随产品发布的组合不注册占位者，因此本位渲染成一个没有角色的 `display: contents` 元素，任何 ARIA 快照都看不见它；`apps/web/tests/settings-chrome.e2e.ts` 与 `lifecycle-chrome.e2e.ts` 原样重放通过。证据改由包内测试承载：声明出来的子槽规格、空位不成盒、占位者落在触发按钮之后的行末位置、折叠行仍向已挂载的占位者传 `wide: false`，版式主张所依赖的那四条 CSS 声明，以及那个入口：拿到本位 owner props 的占位者能把面板开在它点名的分区上，点名一个无人注册的 id 时则开在导航第一行。
