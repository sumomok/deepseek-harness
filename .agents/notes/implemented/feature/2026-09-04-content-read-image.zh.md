# Agent Note: 页面上的一张图，作为模型直接看的像素

Status: implemented

[English](2026-09-04-content-read-image.md) | 中文

## Problem

五件内容读取答的都是关于页面的文字，而控制台画出来的东西，没有任何关于它的文字描述得了。一个配对二维码是一个既无 alt、又无 title、也无名字的 `img`：清单为它什么都不打印，`content_read_dom` 打印 `img#pairing {class: code}`，`content_read_attrs` 打印 `src="/pairing?ts=1788…"`，`content_read_dom_content` 打印一个空答案。这些都是对「页面写成什么样」的正确读法，而没有一个说出页面显示的是什么。验证码、画进 `canvas` 的图表、以 `svg` 路径而非字符画成的图标，同理。

[sign-in Note](2026-09-04-sign-in-pages-are-read.zh.md) 记下了这条路的尽头。用户要人帮忙处理一个控制台的登录页——画着二维码和验证码的那种——他要的正是 agent 对页面所显示内容的解读。当各件读取只答得出页面的写法时，模型伸手去调 `bash screencapture` 截了整个显示器，再用 `read_image` 读回那张 PNG：那一刻屏幕上的一切都以像素抵达，经由一件对其中任何东西都没有规则的工具，分辨率是显示器碰巧多少就多少。删掉页面级拒绝，去掉的是模型离开这条通道的理由；它并没有让这条通道具备回答模型那个问题的能力。

## Decision

再加一件读取 `content_read_image`，一个必填参数：前一次对本页的读取印出的一个 `ref`。它答出那个元素自己渲染出来的像素——在浏览器座位里导出、由宿主存下、作为一个 image 块挂到工具结果上让模型直接看——旁边配一行关于「导出的是什么」的事实。

四种标签自己带像素，这一读取的就是它们的全部。`img` 与 `canvas` 导出自己存着的那份栅格；`picture` 导出它实际渲染的那个 `img`，标签仍记外层那个；`svg` 没有存着的栅格，按它的布局盒栅格化。其余标签在画任何东西之前，就按标签被拒。

按多大导出，则是把供应商自己那道视觉下限读成一个面积。`MIN_PIXELS` 是 384 × 384 总像素，供应商会先把任何小于这个面积的图放大到正好这么大再计价，于是同一比例、面积都在下限之内的两张图落在同一张网格上、token 数相同，而越过下限的图按自己的像素计价。所以导出朝这道下限的面积放大，且绝不越过它：矢量栅格化到这个面积，位图按仍能装进这个面积的最大整数倍绘制——一枚 32 × 32 的标识放十二倍，超过下限四分之一的一律一倍——并关掉平滑，于是没有一个存下来的像素被重采样。这条规则做出的每一次放大都是免费的，而且请求的像素预算之后也不可能再把它缩下去，因为下限的面积只是那份预算的一小部分。

这不是截屏。它取的是一个元素，从不是一块区域、一棵子树、一整栏或一个显示器，所以它能答出来的东西，被页面自己画进那一个盒子里的东西框住——而 `ref` 只能由本次会话自己那一栏里对页面的一次读取铸出。

读取不需要审批，而这件是读取。它能携带的，就是一个元素画出来的东西：对一个 `img` 的截图不可能装着某个密码框里的值，因为那个值不是那个 `img` 的任何一个像素。[sign-in Note](2026-09-04-sign-in-pages-are-read.zh.md) 立的那条扣留规则——密码控件的值永远不到达模型——不受影响，这里也不需要为它新增一条分支。

### The gate

五个机制，每个都填同一张表的五个空。说不出它防的失败的边界是噪音，不列；列出来的每一条都标了永久，或者标了暂缓和重新打开它的触发器。

#### 工具本身与它的两道闸

- **0 — 已定的原则替它答了什么。** 「Plugins, not loop changes」对动 `agent-loop` 说了 no：这只是本包已经拥有的那条通道上多一件工具。「一条能力缝是三个角色，从不是一个」对声明一个「拍图」服务说了 no——一个实现、一个消费者，都在一个包里。「Model-visible ⟺ logged」对「把像素塞进一份没有任何会话事件记录的请求」说了 no，这才把答案放进一个由 `tool/result` 点名的存下来的附件里，而不是直接放进请求。本包自己定下的「读取不需要审批」对新增一道审批闸说了 no，所以从没设计过。
- **1 — 碰几个新东西：6。** 工具名、必填参数 `ref`、一种 wire 请求 kind、一个 `ReadOutcome` 分支（`status: 'image'`）、一份输出 schema、一段描述。不是 `ReadKind`、不是 `Config` 字段、不是审批闸、不是事件类型：这个分支是一次读取的第三种结局，不是第四种读法。
- **2 — v0。** 拍板它的那个版本根本不是这件工具的任何版本——三张从真实控制台上取下来的图，人工递给模型（见下面的 Evidence）。真要写成工具、又还能回答同一个问题的最便宜做法，是按 `ref` 导出一个 `img`、按它自己的尺寸、挂上去：没有别的标签、没有缩放、没有模态闸。被砍掉的每一块，答的都是同样那三张图已经显示出来的条件——那个控制台把图表画进 `canvas`，把行命令画成 `svg`。
- **3 — 缝，还是写死。** 写死。这里的缝会是一个「别的包也能调的拍图服务」，而它需要点名两个真会出现的调用方；只有一个，就在这个文件里。整个改动里唯一的一条缝是绘制原语，它属于下面那个机制。
- **4 — 边界。**

| 方向 | 这条线 | 它防的失败 | 期限 |
| --- | --- | --- | --- |
| 邻居 | 工具对像素不做任何决定：一张图是什么，是座位的事；什么能留下来，是仓库的事。 | 两边各自决定「一张图片是什么」，谁一动就开始漂。 | 永久 |
| 契约 | 两道闸——先 `ref` 的写法，再本次会话的路由——都在等待窗口打开之前跑，且按这个顺序。`isConcurrencySafe` 为真。 | 为一份注定会丢掉它的请求存下一张图：仓库对交给它的东西一律长期保留。 | 永久 |
| 诱惑 | 拿这张图去替代一次读取。`ref` 只能来自已经跑过的一次读取，描述写的是那个元素必须是什么，而不是什么时候该优先用它。 | 一个只看不读的 agent，一眼 117–349 tokens。 | 永久 |
| 红线 | 路上不从这张图里读出任何东西：不解码、不配文、不 OCR、不分类。那行标题只写尺寸、格式和字节数。 | 本包编造一段模型自己就看得见的载荷——并且被当真。 | 永久 |
| 天花板 | 一个元素、一次、按页面画出来的样子。不是一块区域、不是一棵子树、不是 `video` 的一帧、不是换个尺寸重试，会话卡片里也没有图。 | 被当成一件截屏工具，而那正是这件读取要堵掉的那条路。 | 卡片这条暂缓——触发器：上游 `tool.call.images` 变成 keyed，或者接受第二份声明；其余永久 |
| 假设 | 本次会话的路由声明了图片输入，且 `ref` 点的是本次会话自己那一栏里的元素。缺失的 `inputModalities` 读作否，解析不出的路由是一句拒绝。 | 猜一个模态，然后存下请求随后就会丢掉的像素。 | 永久 |

#### 座位里的导出

- **0 — 已定的原则替它答了什么。** 「优先用维护中的依赖而不是自己写——**当它真能删掉自有代码和测试时**」两个方向都读了，答案是 no：一个 DOM 转 canvas 的库替掉的是四个浏览器调用，一个测试都删不掉。「包边界上显式优于隐式」对「让绘制自己挑尺寸、自己挑平滑」说了 no——`exportSpec` 两样都定好，再告诉原语。「在同进程的类型化边界上信任 TypeScript」对「在一个进程内再核一遍 `captureElement` 收到的东西」说了 no。
- **1 — 碰几个新东西：4。** 两个模块——[`capture.ts`](../../../../packages/experimental/content-frame/src/client/access/capture.ts)，一次导出所做的全部决定；[`export-pixels.ts`](../../../../packages/experimental/content-frame/src/client/access/export-pixels.ts)，做出一次导出的那四个浏览器调用——加上座位上那个注入的原语（`draw`）和它跑在其中的那道截止时间（`budgetMs`）。
- **2 — v0。** 一个 `img`，用 `drawImage` 加 `toBlob` 按它存着的尺寸画出来，别的什么都没有：不查可见性、没有尺寸算术、不回读媒体类型。后面加上的每一项检查，答的都是那个 fixture 页面自己产出来的一种结局——不可见、没加载完、零尺寸、被污染，以及一次再也没回来的绘制。
- **3 — 缝，还是写死。** 一条缝，而且它点得出自己的两个实现：`export-pixels.ts`，浏览器那份；以及 `content-image-capture.client.spec.ts` 里每个用例注入的那个记录用替身——因为 jsdom 没有 canvas，而本包不引入原生的。它周围的一切都是写死的：标签清单、检查顺序，以及通往下限的两条路。
- **4 — 边界。**

| 方向 | 这条线 | 它防的失败 | 期限 |
| --- | --- | --- | --- |
| 邻居 | 布局与可见性属于测量它们的那个 frame：导出复用每次读取都在用的那个 `isSkipped` 和那个注入的可见性。 | 「可见」有两套定义，于是一次读取打印出来的元素，导出却拒绝。 | 永久 |
| 契约 | 各项检查按固定顺序跑，第一个不过的就是那句拒绝；导出只读不写，不往 frame 的文档里加任何东西。 | 一次导出唤醒了读取正在等的那个变化监视，于是拍完图之后的读取再也不落定。 | 永久 |
| 诱惑 | 为了让绘制可测，引入一个 DOM 转 canvas 的库，或者一个原生 `canvas` 包。 | 往一个全部原语只是 `createElement`、`getContext`、`drawImage`、`toBlob` 的包里塞一整套构建工具链。 | 永久 |
| 红线 | 跨源像素永不导出：被污染的画布就是一句拒绝，没有任何东西去试 `crossorigin`、试代理抓取，或者在服务端把 `src` 再抓一次。 | 这个控制台把浏览器已经拒绝的像素转手递出去，绕开浏览器自己守的规则。 | 永久 |
| 天花板 | 浏览器交回来的那点东西，一次，在读取截止时间的一份份额之内。不承诺 WebGL 画布还有一帧可给，不承诺矢量指向外部的东西会跟着来，也不承诺两台机器编出同样的字节。 | 被读成一个渲染器，而不是「对浏览器已经画好的东西的一次读取」。 | 暂缓——触发器：真实页面上报出一次空白的 WebGL 导出，那时「导出成功而像素是空的」就必须变成一句拒绝 |
| 假设 | 元素在这个座位够得到的同源文档里，且引擎有 canvas。两者都不绕：拿不到上下文就是抛错，按「读取方自己失败」上报。 | 在没有 canvas 的引擎上返回一张空图，而那读起来像是页面什么都没画。 | 永久 |

#### 图片路由

- **0 — 已定的原则替它答了什么。** 「在同进程的类型化边界上信任 TypeScript——并在 wire 边界上做校验」让这个解析器成了不可选项，也让它成了整个改动里唯一一处不是类型的校验。「配置错误要响亮地失败」对「一条路由默默忽略它读不懂的载荷」说了 no。「显式优于隐式」对「从字节里推断媒体类型」说了 no：类型从 blob 上回读，再对一个封闭集合核。
- **1 — 碰几个新东西：4。** 一条路由路径（`POST /content-frame/image`）、一份 wire 文档（`ImageReportRequest`）、一个解析器（`parseImageReport`）、一道字节上限（`IMAGE_REPORT_BYTES`）。
- **2 — v0。** 有解析器、后面没有仓库的那条路由：投递、解析、落定。`content-read-wire.client.spec.ts` 至今仍单独驱动它，也正是它在存下任何一张图之前就把算术定了下来——上限是 `MAX_EXPORT_BYTES` 的 base64 加上信封，而正好落在 `MAX_IMAGE_DATA_CHARS` 上的载荷必须被接住。
- **3 — 缝，还是写死。** 写死：一道围栏、一个媒体类型集合、一道上限、一个调用方。切缝需要点名的那两个变体点不出来——投递方全是本包自己的座位——而这道上限不做成 `Config` 字段，因为它是从供应商自己的计价算出来的。
- **4 — 边界。**

| 方向 | 这条线 | 它防的失败 | 期限 |
| --- | --- | --- | --- |
| 邻居 | 路由负责解析和投递。一张图能不能留下来是仓库的答案，一个调用在不在等是那张表的答案。 | 一条路由自己编出工具编不出的拒绝，用的还是模型从没见过的词。 | 永久 |
| 契约 | `/content-frame/report` 原样不动——它的上限和解析器属于文字读取——而读图的失败也走这条路由，因此同一个 call id 永远不会被两条路由抢。 | 两条路由落定同一个调用，谁先到算谁。 | 永久 |
| 诱惑 | 让字节走回报路由，它已经存在，也已经会解析一个 outcome。 | 每一次文字读取都为一份文字读取根本不产出的载荷，付那道字节上限。 | 永久 |
| 红线 | 载荷先核过——base64 字母表、长度、上限、封闭的媒体类型集合——然后才谈解码；而且不为任何一个没人在等的调用写下任何东西。 | 一次未鉴权的 POST 往一个从不回收的仓库里写进几 MB。 | 永久 |
| 天花板 | 一次投递一张图，最多 `MAX_EXPORT_BYTES`。不分片、不续传、不换个更小的尺寸再来一次。 | 一架重试的梯子长在一条路由里。 | 暂缓——触发器：真实控制台上的真实元素被 `MAX_EXPORT_BYTES` 拒掉 |
| 假设 | 调用方是本包自己的座位，call id 是宿主铸出、且只发布进那个会话自己的投影流的。这里没有 Host 围栏，也没有鉴权。 | 把这个 id 猜不中当成本包拥有的安全属性；它是供应商的，而暴露在不可信网络上的部署要在自己的反代上设围栏。 | 永久 |

#### 宿主半边：先存，后落定

- **0 — 已定的原则替它答了什么。** 「Model-visible ⟺ logged」自己就把顺序定了：日志记下的那个引用，必须在事件被追加时指向一个已经存在的对象。「在持久边界上做校验」把图片限额和归一化留在它们本来的地方——仓库里。「空 `catch` 要写明它吞了什么」对「吞掉仓库的拒绝」说了 no——它被接住，变成一句模型读得到的话。
- **1 — 碰几个新东西：3。** 一个模块（[`image-report.ts`](../../../../packages/experimental/content-frame/src/access/image-report.ts)）、本包 inject 清单里的一个服务（`attachments`），以及调用表上的一个方法（`PendingCalls.reserveReport`）。
- **2 — v0。** 先存，再把引用交给那张表。没有队列、没有后台写、没有清理轮次——这就是这个机制的全部；小到它当初唯一缺的东西，就是在它前面加一句 `reserveReport`，取走的还是 `report` 本来就在用的那套受理条件，于是一个在等的调用只有一次投递到得了仓库。
- **3 — 缝，还是写死。** 写死。顺序不可配，仓库在这一处也不可换：`attachments` 是仓库自己的能力，本模块只是它的一个消费者。第二个仓库是那条能力后面的第二个提供方，不是这个文件里的第二条缝。
- **4 — 边界。**

| 方向 | 这条线 | 它防的失败 | 期限 |
| --- | --- | --- | --- |
| 邻居 | 图片限额、归一化和命名策略仍归附件仓库；本模块交给它字节、媒体类型和一个名字，并把它的拒绝原样传出去。 | 两个地方各自决定「一张图片可以是什么」，而模型被告知的是输的那一方。 | 永久 |
| 契约 | 像素在调用落定之前就已在磁盘上，而且只为那张表正替投递方那个 tab 守着的那个调用、只为取走了它那次落定的那一份投递而存。 | 一条 `tool/result` 点名一个并不存在的对象；以及一堆谁也不会去读、也不会去删的字节——并发投递各写一份也算在内。 | 永久 |
| 诱惑 | 先落定、再后台存，读起来更快。 | 一个指向虚无的引用，进了一份比这次请求活得更久的日志。 | 永久 |
| 红线 | 没有仓库，就没有这件工具：注册写在 `ctx.inject(['tools', 'attachments'], …)` 里，没有仓库时工具不存在、路由也不挂载。 | 一个部署提供一件把答案无处可放的读取。 | 永久 |
| 天花板 | 它保留交给它的东西。没有过期、没有配额、没有「一轮之后就删」；一个在自己那次被预定的保存正在写时耗尽截止时间的调用，那些字节照样留下——每个调用至多一份，而不是每次投递一份。 | 本包发明一套仓库并没有的保留策略。 | 暂缓——触发器：附件仓库自己长出一套回收策略 |
| 假设 | 仓库的失败是 `AttachmentError`，也只有它自己描述得了；而一个调用在不在等，只有那张调用表知道。 | 猜一个这边并没有的理由，或者为一个这边早已知道的失败去告诉模型「控制台没声音了」。 | 永久 |

#### 导出常量

- **0 — 已定的原则替它答了什么。** 「插件里不许有写死的可调项：随部署变化的选择要做成受校验的 `Config` 字段」——照字面读，它说的是不随部署变化的选择就留作常量，并且点名协议常量与外部规范正是这一类。这五个不是前者就是后者，第六个由其中之一导出，所以 `Config` 块一个字段都没多。
- **1 — 碰几个新东西：6。** [`wire.ts`](../../../../packages/experimental/content-frame/src/access/wire.ts) 里四个协议常量——`IMAGE_MEDIA_TYPE`、`IMAGE_PIXEL_BUDGET`、`RASTER_MIN_PIXELS`、`MAX_EXPORT_BYTES`——导出所跑在的那份读取截止时间份额 `EXPORT_WAIT_SHARE`，以及由这份份额导出的、压在 `readTimeoutMs` 上的加载期下限 `MIN_READ_TIMEOUT_MS`。零个 `Config` 字段。
- **2 — v0。** 一个常量——字节上限——配上元素自己的尺寸，两个方向都不缩放。是那次探针说了这不够：一个 24 像素的 `svg` 按 24 像素栅格化，不是任何东西读得出来的图；而它该按多大栅格化，早就以供应商自己的下限的形式存在了。下面那两次真机读取对一张存下来的位图说了同一句话，所以这道下限两类通用；而供应商的计价方式，则决定了它是位图放大的上界，而不是位图要被送到的目标。
- **3 — 缝，还是写死。** 六个全写死。会把其中任何一个设成别的值的那两个部署，得点得出名来，而点不出：它们是供应商的计价、附件层的投射、canvas 退回去的那个格式、本包本来就在切分的一份截止时间，以及这份份额压在那个部署真会设的字段上的下限。
- **4 — 边界。**

| 方向 | 这条线 | 它防的失败 | 期限 |
| --- | --- | --- | --- |
| 邻居 | 计价属于供应商，投射属于附件层；每个常量都在复述它们中的一个，并写明出处。 | 本包自己发明一个数，然后从拥有它的那一层漂开，而且没有任何东西会察觉。 | 暂缓——触发器：供应商的 `MIN_PIXELS` 或附件层的 `DEFAULT_REQUEST_IMAGE_PIXEL_BUDGET` 变了 |
| 契约 | 供应商那道下限是一个面积，任何导出都不放大到越过它——矢量栅格化到它，位图按装得进它的最大整数倍绘制，且关掉平滑——而越过它抵达的图，仍由附件层投射请求图片所用的同一套几何压进像素预算。 | 图在下限之下抵达而被读错；放大时把页面画出来的边重采样掉；以及放大到越过下限，而那之后供应商是按像素计价的。 | 永久 |
| 诱惑 | 把其中任何一个做成 `Config` 字段，因为它们看着像可调项。 | 一个部署付的是任何请求都不携带的像素。 | 永久 |
| 红线 | 超限的导出带着它的大小被拒，绝不压低质量重编码。 | 用一张已经解不出来的图，去回答一个关于二维码的问题。 | 永久 |
| 天花板 | 2 MiB、PNG、一份像素预算，加上读取截止时间的八分之一。任何一项超了，都不承诺那张图还到得了。 | 一架退路的梯子——更小的尺寸、更有损的格式、更长的等待——长在本该是一句拒绝的地方。 | 暂缓——触发器：真实元素被 `MAX_EXPORT_BYTES` 拒掉，与路由那条天花板同一个触发器 |
| 假设 | canvas 会编出 PNG，这是 HTML 规范对任何引擎不支持的类型所要求的退回格式；而报出去的是回读的 `blob.type`，不是当初要的那个。 | 描述一份谁也没产出过的字节。 | 永久 |

### Evidence

在写下这一切之前，三张从真实控制台上取下来的图被直接递给了 `deepseek-v4-flash-vision-exp`，一次一张，各 n = 1：

- 一个登录二维码——被点名为二维码，载荷没有被读出来：模型说出了那是什么，并且不去编造它编码了什么；
- 一排画出来的行命令——读成一支铅笔和一个垃圾桶，正是原文读取把那一列打印成空的那一列；
- 一张画进 `canvas` 的柱状图——最高的那个月被读了出来，八月。

三张图、一个模型、各 n = 1，挑的是五件文字读取对它们什么都答不出来的那种图。它没有测量任何准确率，也不替代任何一次这样的测量。它定下来的是第二个空问的那件事——一个视觉模型对「页面画了什么」的回答，好到值不值得为它开一件工具——而录下来的那个 Web 场景，把三张里的第一张端到端地跑通了，走的是真实通道。

这件读取上线之后，又有第四次读数取自真实控制台：同一枚 32 × 32 的标识，在 2026-09-04 与 2026-09-05 各读一次，n = 2。按它自己的 32 像素导出时，它被描述成了一张它不是的图；随后模型把这张已存下来的 PNG 按最近邻放大八倍，描述对了。一张图读两次同样测量不了准确率，它定下来的是更窄的一件事：供应商在计价前所做的那次放大，不是模型读到的那一张，所以一张在下限之下抵达的位图会被读错——无论计价之后是否再把它放大。这就是把下限从矢量带到位图的那件事，也是把位图通往下限的方式定成「整数倍、关平滑」的那件事。

## Alternatives considered

**给内容栏截屏。** 最顺手的形状，也正是模型拿 `screencapture` 干过的事。它需要 `getDisplayMedia`（每次会话一次用户手势加一次操作系统级授权弹窗），或者宿主上的一个无头浏览器（把一个状态活在用户浏览器里的页面再渲染一遍）。两者答出来的都是这一帧里的所有东西——包括页面画的其余一切——而问题问的是一个元素；两者也都产不出一张模型能凭 `ref` 指回去的图。

**把任意子树栅格化。** 用一个 `scope` 参数取代一个元素，于是任意区域都能导出。浏览器没有这样的原语：把标记栅格化，意味着把一棵子树连同它的计算样式序列化进一个 SVG foreignObject，或者引入一个 DOM 转 canvas 的库。两者都把页面按第二种方式再渲染一遍，都会以谁也审不了的方式与用户看到的东西不一致，也都把一张图的正确性塞进本包。一个自己就有像素的元素，是答得准的。

**引入 `canvas` npm 包，让导出跑在 Node 里。** 这能让绘制原语可测，也能让一条宿主侧路径成立。它同时把一整套原生构建工具链，塞进一个全部导出只是四个浏览器调用的包；而且它照样拿不到页面：像素在用户的浏览器里，不在宿主上。

**新增一个 `ReadKind`。** 三件原文读取是同一份快照的三个 `ReadKind`，所以第四个看上去很对称。但 `ReadKind` 命名的是「把页面渲染成文字进 `ReadSnapshot`」的一种方式，而这个答案不是文字，也没有快照。`ReadOutcome` 的第三个分支说的才是它本身：一次以图而非清单收尾的读取。它同时把 [`isActOutcome`](../../../../packages/experimental/content-frame/src/access/wire.ts) 逼回了肯定式写法——它原本写成「不是读取」，那会把任何新增的读取分支悄悄归成动手结局。

**不设模态闸，图照挂，让请求自己丢。** 更简单，也错得没法回头：路由丢掉那个块时像素已经在磁盘上，仓库会长期保留，而模型手里只剩一行描述着一张它从没见过的图的标题。一句点名模型的拒绝，花掉的是一次调用，存下的是零。

**所有位图都保持自己的尺寸，交给供应商自己的下限去放大。** 供应商在计价前本来就会把小图放大，所以 240 × 240 的图标两种做法都按 384 × 384 计价，在这里放大买不到任何 token 意义上的东西。这套计价的说法是对的，也正因如此，放大要被下限的面积卡住。另一半则不对：供应商计价前所做的那次放大，不是模型读到的那张图——这一点由上面那两次真机读取定下。

**整数倍一路送到下限，而不是被下限卡住**——对短边取 `ceil`，而不是对面积取 `floor`。它对任何输入都能到下限，而不是在「下限四分之一到下限」这一段停在原地。它同时会越过去：100 × 100 的图标放四倍是 400 × 400，越过了那个此后按像素计价的面积；而 348 × 348 的图按 696 × 696 导出要花 329 tokens，按 348 × 348 只花 117。「到下限」对模型一文不值，供应商自己马上就要到；而越过去，一次读取最多要花 349 tokens，对着供应商 384 tokens 的上限。

**按小数倍缩放，正好落在下限的面积上。** 同样免费，而且对任何输入都能到下限，不像整数倍只在能整除的那些面积上到得了。它会重采样：在小数倍下，一个存下来的像素会不均匀地落在两个导出像素之间，而一枚小图标据以被读出来的那些边，恰恰就是这样糊掉的。整数倍把它们一条不落地留下。它付出的代价是「下限四分之一到下限」这一段：没有整数倍装得下，图就按原样导出；而上面那两次读取发现被读错的图，远在这一段之下，不在这一段之内。

**在会话卡片里渲染这张图。** 上游的 `tool.call.images` 子槽是 `kind: 'single'`，且已经有一个声明者（[`read-image-row.tsx`](../../../../packages/client/ui-tool/src/client/tool/toolviews/read-image-row.tsx)）；第二份声明会在 [`ui-slots`](../../../../packages/client/ui-slots/src/index.ts) 加载时抛错。在这里注册 toolview，要么把这个槽从内置的读图那里抢走，要么直接让控制台起不来，所以本包一个都不注册，落定后的卡片退回通用卡片。

## Consequences

模型能回答页面画了什么，走的是同一条通道、用的是与其他读取同一批 `ref`；而 [sign-in Note](2026-09-04-sign-in-pages-are-read.zh.md) 记下的那条 `screencapture` 路径，现在有了一个有界的替代：一个元素而不是一整个显示器，按导出从这个元素定出来的尺寸而不是屏幕的尺寸。

卡片显示的是那行标题，不是那张图，理由见上面那个槽。读记录的用户看得到导出的是哪个元素、多大、什么格式、多少字节——想看 agent 看到的是什么，得自己打开页面。

每一张导出的图都是永久的。附件仓库对交给它的东西一律保留、从不回收，因此每一次读取都在 `$DSH_HOME/attachments/` 里留下一张 PNG，活到那个 home 的尽头，并随会话日志的任何一次导出一起走。读过一次的登录二维码，就是永久留着的登录二维码。

图作为一条合成的 `user` 消息，紧跟在产出它的那条工具结果之后进入请求，因此从第一次读图起请求后缀就变了，而它前面的前缀仍然成立。一张方图在供应商下限及以下花 117 tokens，占满整个像素预算花 349，对着供应商 384 tokens 的上限；换一个比例，这两处各是别的数。放大后的栅格仍在下限的面积之内，于是它和它自己的自然尺寸投射到同一张网格上，token 数相同。

跑在纯文字路由上的部署，拿到的是这件工具加一句点名它那个模型的拒绝——自[模型切换那篇](2026-09-05-content-image-model-switch.zh.md)起，拒掉卡片的用户得到的也是这句话，而那张卡是这道闸的另一个出口；没有附件仓库的部署，工具和路由都拿不到。两者都在用到的那一刻才显形，而不是在加载时，因为两者都是会话与组合的属性，不是那个配置块的属性。

一次再也没回来的导出，收尾于一句关于这张图的拒绝，而不是通道那句通用的超时。绘制拿到读取截止时间里属于自己的八分之一，排在加载等待的二分之一和静止等待的四分之一之后，而这份份额像静止等待那份一样在加载时受检：`readTimeoutMs` 低于 8 时导出四舍五入后拿到的预算不是零毫秒就是一毫秒，于是这一行拒绝启动，而不是让每一张图都收到一句「控制台没画完」的拒绝；浏览器里没有任何东西取消得了一次 `toBlob` 或 `image.decode()`，所以这道截止时间结束的是座位对它的等待，而那个 promise 会一直悬到这个标签页的尽头。调用在座位这边落定，而不是在宿主那边；模型收到的是 `<ref> did not finish exporting within Ns.`，而不是「控制台没声音了」。

## Testing

`tests/content-image-capture.client.spec.ts` 拿注入的绘制原语，对着真实文档驱动每一项导出决定——四种标签与对其余标签的拒绝、可见性/加载完/零像素/污染四句拒绝、一次再也没回来的绘制耗尽的那道截止时间、页面把标签写得比 wire 能带的更长时被截到的样子、媒体类型集合、字节上限，以及每条规则定出的确切尺寸与平滑——32 × 32、64 × 64、16 × 64、100 × 100 四张栅格各自取到的整数倍、没有整数倍装得下的那些尺寸、一条已经越过下限的长条、一次缩小，以及一次 SVG 放大——外加对一组尺寸钉住放大自身的几条不变量：在下限面积之内、整数倍、两轴同一个倍数。`tests/content-read-image-tool.client.spec.ts` 对着真实工具运行时逐字符钉住描述、参数表与那行标题，并驱动模态闸的两个分支、失败分支、误报分支，以及 image 块里的附件引用。`tests/content-image-report.client.spec.ts` 管宿主半边：解码后的确切字节到达仓库、存下的名字跟着页面与元素走、落定的调用带引用不带字节、拒收的仓库以它自己的理由让调用落定、没人在等的调用、被别的 tab 认领的调用，以及取走那次落定之后的每一次投递，都让仓库原封不动，以及像素在调用落定之前而非之后就已提交。`tests/content-read-wire.client.spec.ts` 覆盖新解析器与路由的字节算术，`tests/content-read-routes.client.spec.ts` 覆盖路由本身——包括一个真在等的调用，其投递的捕获经真实 HTTP 到达仓库、并以那个引用让它落定，以及 `readTimeoutMs` 那道加载期下限——`tests/self-contained-copy.client.spec.ts` 走遍第七件工具定义与十二段新文案。`src/` 保持按文件 100% 覆盖。

一个 Web 场景为它兜底：`apps/web/tests/content-read-image.e2e.ts`，对着原文场景用的同一个 `tests/fixtures/markup-app`，那个应用新增了一个没有 alt 的配对二维码、一个画着固定八柱图表的 `canvas`，以及一个内联 `svg` 星形。它有自己的一层补丁 [`content-read-image.overlay.yml`](../../../../apps/web/tests/content-read-image.overlay.yml)，写明这套组合里新建会话起手在哪条路由上；随后 spec 通过 `sessionController.selectModel`——也就是编辑器里模型选择器发的那个调用——把这条路由选到那个被 seed 的会话上。光靠这层补丁路由不了这个会话，也不可能路由得了：已经记过一次 request header 的会话，按自己的日志推导路由，组合的默认值只对一次都没记过的会话生效（[`selectionFor`](../../../../packages/api/session-controller/src/agent.ts)）。这些场景重放的那份 seed 记过。spec 在驱动提示之前就断言选中的路由及其声明的图片输入，于是路由错了的会话在那里就失败，而不是在这一轮里变成三句拒绝。

这个会话还由它自己的一份 preset 组合而成——[`tests/fixtures/presets/content-column`](../../../../apps/web/tests/fixtures/presets/content-column/agent.cordis.yml)，一件工具都不挂：给模型一个二维码再给它一个 shell，它会联网装 OpenCV，从存下来的附件里把载荷解出来，而那种记录没有任何一次回放能复现。Web profile 提供的每一件模型工具都来自 preset——profile 把自己全部 `tool-*` 行禁掉，`standard` 再把它们挂回来——所以补丁层拿不走任何一件；而一份不挂任何工具的 preset 剩下的，恰好就是内容栏那七件。spec 在驱动提示之前也把这份清单钉住。页面按 `?pictures=code` 提供，这让它只剩一张图；而这么做的理由，正是那份录制钉住的东西：回放把整份日志与录下来的那份逐字节比对，而一张图的 `attachmentId` 是导出字节的内容哈希、由回放实时重新算出来——所以录制钉住的是这一轮做过的每一次导出，而不只是断言读到的那一次。一张入仓 PNG 解码后重编码，在哪台机器上回放都产出同样的字节；那个页面里的 `canvas` 与 `svg` 由浏览器栅格化，字体与抗锯齿既不保证跨平台一致，也不保证跨引擎版本一致，读了它们的录制在这两处都会漂。它们留在页面里供本包自己的用例使用，而 spec 在驱动提示之前会断言前台那个 frame 里恰好只有一张图。带 key 录制：

```sh
DSH_SNAPSHOT=record pnpm exec vitest run --config vitest.web.config.ts apps/web/tests/content-read-image.e2e.ts
DSH_SNAPSHOT=refresh pnpm exec vitest run --config vitest.web.config.ts apps/web/tests/content-read-image.e2e.ts
```

那次 refresh 不需要 key，也不是可选的，理由与四个文字场景相同：录制带着实时供应商解析出来的东西，而一次回放跑永远不会产出它们。只要 `snapshots/web/content-read-image/` 还不存在，这个 spec 就自行跳过，于是场景与它的录制可以落在不同的改动里，而不会把一条无 key 的流水线搞红。
