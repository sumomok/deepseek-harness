# Agent Note: 结构化页面读取遵循的规则

Status: implemented

[English](2026-09-02-content-snapshot-engine.md) | 中文

## Problem

`packages/experimental/content-frame/src/client/access/` 里的页面读取器遍历一个真实应用——由某个组件库画出来，跑在浏览器里，摆在用户眼前——并用几千个字符作答，模型拿它代替一张截图。有两件事让这件事很难，而它们都不写在代码里。页面用 HTML 和 ARIA 表达自己的含义时并不一致：同一个树节点，换一个库来画就分别是一个链接、一个图标、一个勾选框和一排按钮。而每一条把某样东西排除在读取之外的规则，都可能恰好排除掉模型唯一需要的那样东西，而模型无从知道这件事发生过。

这篇 Note 记录这些读取规则，以及每一条为什么是这个方向。每一条都是在一个站得住脚的反面之间做的选择，而其中大部分是把对抗性复核指向真实组件库的标记语言找出来的，不是靠推演规范得出的。

## Decision

这次遍历只懂 HTML 和 ARIA，别的一概不懂：任何库的类名、组件名、DOM 形状都不出现在 `src/client/access/` 的任何地方。一条按某个框架的标记语言写下的规则，就是一条在下一个框架上失效的规则，而某个部署在它内容区里渲染什么框架，不是这个包该管的事。下面每一条规则都用规范定义的词说出来。

### 模型可见就等于可读

其余规则都要为它让路的那一条：读者能看见的一段文字，一定到得了模型面前。那些做分类的规则——这是一幅画、这是装饰、这是页面自己的包装层——可以把文字从一行挪到另一行，可以把它折进一个名字里，也可以丢掉浏览器根本不画的东西。它们都不可以丢掉浏览器确实画出来的东西。这是一条工作准则，不是已经被证明成立的性质：每一轮复核发现的每一个反例都按缺陷处理，无论那个分类多站得住脚，因为模型没法去问一段它从未见过的文字。仍然敞着的反例列在下面的限制一节。

### 只有页面自己写下的才算标签

`declaredName` 读 `aria-label` 和 `aria-labelledby`，读完就停。它有意不是无障碍名字的完整计算：那套计算会回落到元素自身的内容，而对一个树节点来说，那意味着挂在它上面的每一个按钮。页面写下的标签比元素展示的任何东西都值钱，因为一个画成图标的菜单项在别处不说自己是什么；空标签，以及指向页面上不存在的东西的标签，什么都没命名，元素交给下面那道阶梯。

引用在元素自己所在的那棵树里解析，因此开放影子根里的一个 id 指的是那个根里的元素，而不是外面页面里恰好同名的那一个。指向元素自己、指向它包着的东西、指向包着它的东西，都不算标签：浏览器在这种情况下退化成按内容命名，而按内容命名一个节点正是那道阶梯存在的理由。被引用的元素**叫什么**排在它**显示什么**之前，因此页面指向一个图标时，得到的是图标自己的标签。

### 节点名的阶梯

一个树节点或菜单项由它自己的标签命名，绝不由挂在它上面的东西命名：它下面那个组会印出自己的行，作用于它的那些按钮也会。阶梯是：页面写的标签，然后是节点在任何会出行的东西之外的自有文字，最后是它内部第一个能命名这个节点的行。

正是最后这一步让真实的 antd 树和 element 树读对，而它取决于哪些行才能命名一个节点。不显示任何字的行不能，因为每个框架画出来的树都在标签前面放一个没有字的东西——文件夹图标、勾选框、图标按钮。页面命名过的链接或标题是例外：图标链接正是框架给「能点进去的节点」画标签的方式，而写在它上面的那个名字是这个标签唯一出现的地方。作用于节点的控件在任何情况下都不能命名它，无论它显示多少字，因此一个只由文件夹图标和删除按钮画出来的节点没有名字——而不是被命名为 `删除`，再出现在它下面每一行的后缀里。所谓作用于节点，指的是读者能在它身上操作的东西：按钮、字段，以及菜单或标签条提供的那些命令。链接和画在另一个节点里的节点不在其列，因为它们说的是这个节点是什么、通向哪里，而不是能拿它做什么。

没有名字不等于读不出内容。阶梯没能命名的节点是一个房间而不是一行：遍历读进去，那个「整个叶子就是它」的开关、antd 下拉里画成按钮的那条命令、画在删除按钮旁边的那幅图，各自印出自己的一行。改为给这个节点印一行，就会在那里结束下降，而页面画在它里面的每一个字都将哪儿都到不了。

房间会说出它顶替掉的那一行本会说的一切：页面给这个节点的角色，它是否被勾上，页面是否把它折叠了起来，以及页面是否把它禁用了。一个这些都不汇报的房间，会让读者再点一次已经勾上的项、把它取消，也会让读者把折叠节点下面的行当成它的全部。唯一不说的是它自己所在的区域，那是它顶替掉的那一行印在末尾的东西。那个后缀说的是区域的种类而不是页面写下的角色，因此房间那一行上的 `menuitemcheckbox` 和它里面各行末尾的 `(menuitem)` 是同一个节点的两种说法。

只要节点里装着任何东西就开房间，而房间最后什么都没显示出来时，这次列表就印出它顶替的那一行。这个答案属于列表而不属于走查，因为它取决于这次列表显示什么：页面没有打开的对话框是骨架图的一行，别的读取里都没有它，因此装着这样一个对话框的节点，在骨架图里是一个区域，在清单里是一行。它同样取决于这次读取已经印过什么，因为节点下面唯一那个按钮可能就是画在树旁边的那个按钮，而一次读取只印它一遍。节点罩着一个页面画成空的 group 时，两份清单里它都什么也显示不出来，于是都读作它自己的一行。因此，一行印在末尾的那个区域，一定是这次列表留下来的区域：一个条目把装着它的区域标记成有东西可显示，凡是这次列表印出这个条目的地方都是如此，所以没有哪一行能说出一个被这次列表顶替掉的房间。改在走查里回答，就意味着把这样的子树读两遍，一遍用来判断一遍用来印出，而嵌套的节点会把这些试读层层套起来：在 jsdom 里，`tests/snapshot.client.spec.ts` 钉住的那条十六层节点链，这样读要花 7.1 秒，读一遍是 10 毫秒；一千个这样的节点组成的树是 48 秒对 0.63 秒。

在无名房间里，页面让其可点的一段是一个可点的东西，会印出自己的一个房间；在有名房间里，它是这个节点的名字说了两遍，什么都不印，它盖着的那段文字也不印。

### 一幅画是一个东西，浏览器自己画出来的其余东西也是

`isOpaque` 覆盖 `svg`、`canvas`、`video`、`audio`、`object`、`progress` 和 `meter`。写在这些东西里面的，要么是画的一部分，要么是给画不出它的引擎准备的回退内容，而在用的引擎两者都不渲染。遍历不下降进去，不读它的文字，也不把里面的任何东西算作一行：一条路径不是一个段落，一幅画带的 `title` 是页面从不展示的提示，而 `progress` 元素里的字是给十年前就不存在的浏览器看的。`noscript` 不在其列：它装的根本不是页面内容，遍历把它和 `script`、`style`、`template` 一起跳过。

其中仍会印出一行的有三类：页面命名过的画，它是一幅图片；页面自己让它可点的画，因为框架把处理函数放在图标上而不是图标外面，而一幅没有行的画是模型根本够不着的东西；以及页面命名过的进度条。其余的画都是装饰，而装饰不断开任何一段文字。前两类的名字只取页面写在这幅画上的东西，别的都不取。

页面命名过的进度条印出名字和值。值就是这个进度条画出来的文字，只有在它什么都没画时才取页面写下的那个数：bootstrap 的两个版本都把百分比画在带角色的那个元素里，而这一行结束下降，那些字要么在这里到得了模型面前，要么哪儿都到不了。屏幕阅读器把这两者反着读，会在一个画着「上传中，请稍候」的进度条上念出 `25`；这次读取以页面作答。在屏幕上什么都不落下的文字不算文字：一个只画出 Unicode 格式类码位的控件——零宽空格、方向标记、软连字符——汇报页面写下的那个数，而不是用一对引号裹住一个浏览器根本不画的字符。字体画成空白的码位不在其列，因为页面写下它就是画出了它。没名字的进度条读作结构，因为百分比这时画在旁边的文字里，而一行既无名字又无数字的行会挡在那段文字前面。

控件画出来的每一个字都是它的值，进度条与字段同理，包括它提供的那些东西上的字：这一行结束下降，因此多选框的标签块、文本框的清除按钮、上传条里的取消按钮，要么在这一行到得了模型面前，要么哪儿都到不了。一个值重复了读者在旁边就能看见的一个按钮，是较小的那种错——读者能拿它跟屏幕对照，而一个页面的字悄悄消失时没有任何迹象。

控件装着的区域是唯一的例外。下拉框弹出的那张列表是这个控件提供的东西，而不是它装着的东西，表格里的那些行则是它的数据；控件自己就是一个区域时同理——表格格子里一个被页面标成 `listbox` 的 `div` 不汇报任何值。把它们排除在外是把那些字丢掉，而不是把它们挪到别处，下面的反例清单如实记着这一点：画在控件内部的区域任何读取都够不着，因为控件的那一行在走查给这个区域编号之前就结束了下降，此后没有任何东西能点到它的名。选项能作为行被读出来的地方，是页面把列表画在控件外面的时候——画在旁边那张表的格子里，或者由页面用 portal 画成一个兄弟节点。只有元素的角色开出来的区域才算，表格也在其列：一排按钮在走查别处读作工具条，哪怕页面没写角色，而在控件内部那一排就是控件装着的标签块。

### 地标只到整页级，角色只到 ARIA 定义的那些

页面让其可点的一段，若够到了页面自身布局所用的区域，它就不是一个可点的东西：那个指针光标是从上面某处继承来的。只有 `main` 和 `nav` 按标签匹配，因为 HTML 无论它们画在哪里都给这两个标签那个角色，而 `header` 和 `footer` 只有在顶层才是 banner 和页脚，在别处是一张卡片的头和脚。页面若要在卡片里表达那两者之一，就写出角色，而写出来正是它在这里成为地标的原因。表单和对话框整个不在其列：一张卡片很容易装下一个行内编辑器或一次确认，而它仍然是页面提供给你点的那个东西。

页面写的角色，只有在 ARIA 定义它时才算角色，而且词是按顺序读的，因此按更新的词表写的文档会回落到更旧的那个。印出一个没人定义的词，等于把页面控制的文字放到模型读取「这一行是什么」的位置上。这个包里每一个选择器都按词匹配，`[role~="x"]`，理由相同：一个漏掉回落的选择器会让读取的一部分看见一张表格，而另一部分看见一个段落。

由于我们读这个属性的方式与 `dom-accessibility-api` 不同——它只读第一个词——有两个后果。当遍历解析出的角色不是库解析出的那个时，算出来的空名字只说明「库的那个角色不按内容命名」，于是这一行由元素显示的文字命名——仅限 ARIA 规定按内容命名的那些角色。而装饰性角色的冲突消解由这里自己做，不再交给库：页面标为装饰、随后又自相矛盾的元素，按它提供的东西来读，因为页面写下了两件互相矛盾的事，而 ARIA 判给控件。两个条件是 ARIA 自己的——元素可聚焦，或者它带着一个 ARIA 在所有角色上都定义的状态或属性——而且对 `presentation` 和它的同义词 `none` 一视同仁，库则只对前一种拼法消解，对后一种原样答 `none`。隐式角色随后从一份去掉该属性的浅克隆上读出，因为照元素原样去问，库答的正是这里刚刚决定忽略的那种拼法。

### 控件的状态就是页面说过的，不多说一个字

浏览器替它保管状态的框，从浏览器读，而写在原生复选框上的 ARIA 被忽略，浏览器也是这么忽略的。页面自己画成框的其他东西，状态就是它写的——在它写之前没有任何状态，因为 ARIA 在这些角色上要求这个属性。被告知「关」的读者会去点开一个本来就开着的东西。被汇报为半选的框同样不属于两态之一：那是一张表格头上、行被选中了一部分的那个框，被告知它是关的读者会去点它，然后把整页的行都选上。

### 结构到得了模型，数据到不了

一张表按它的形状收集——表头、一行样本、一个行数——它的行只有在读取按 ref 点名这张表、或按文字找到某一行时才到来。样本说的是某一列提供哪些控件，而不是它们装着什么，因此每个格子都被裁到样本行给它的那点地方：文字先让位给控件，而控件列表自身也在方括号内被裁，因为一排每个名字都是一句话的按钮，否则会把整行样本花在一列上。进度条是唯一一个把值和名字一起写进样本的控件，因为进度条汇报的东西就是这一列展示的全部：一个只画着一根进度条的格子没有自己的文字，只写出条的名字会丢掉读者在那一列看到的百分比。密码框汇报自己在那里，绝不汇报它装着什么。

### 绝不盲截

整页超出预算时，回来的是它各区域的骨架和下一步该读哪里；列表超出预算时，回来的是一个可以续读的游标。一次读取绝不用「半张列表加上没有办法够到其余部分」作答，而被截断的列表会退掉尾部模型无法指名的行，好让续读恰好覆盖列表一次。

### 布局是注入进来的

jsdom 不做任何布局，而一个 frame 的布局属于那个 frame，因此可见性与几何以 `isVisible` 和 `rectOf` 的形式到来，只经由调用方触到 DOM。因此这个包的测试关于「读者能看见什么」得到的每一个结论，都以 page 座位注入的实现为条件。

## Alternatives considered

**用无障碍名字计算去命名每一行。** 它是规范，已经有人替我们实现了，而且它就是屏幕阅读器会念出来的东西。在「屏幕阅读器念的正是错误答案」的那些行上被否决：一个树节点的计算名字是它的整棵子树，这会把删除按钮的文字放进节点名，再放进它下面每一行的后缀。其余一切仍由这套计算命名，阶梯只限于按内容命名会出错的那些角色。

**把一幅画的 `title` 和 `text` 当页面文字读。** 它们是文字，而一张图表的图例确实说了点什么。被否决，因为 `title` 是页面从不画出来的提示，而图表里的字是一幅画的标签：读它们会在每个图标处把周围那段文字断成两截，还会把提示当成读者看得见的东西印出来。代价记在下面的限制一节。

**照页面写的保留装饰性角色，不做冲突消解。** 更简单，也少一件要跟着 ARIA 走的东西。被否决，因为它把带标签的按钮和文本框整个从读取里删掉了——一个带着名字的元素正是页面自己前后矛盾的那个元素，而 ARIA 和每一个浏览器都以同样的方式判定它。转而采用库的答案同样被否决：它只消解两种拼法中的一种，而 `none` 正是较新的代码会写的那一种。

**把 `mixed` 印成第三种状态。** 诚实，代价是行里多一个词。目前被否决，因为这一行的每一个读者都得被教会那第三个词，而什么都不说本身已经意味着「去看一眼」：模型会去问这个框，而不是照一个被告知错了的状态动手。

**把样本行拼好之后再裁。** 只裁一次，就在这一行被印出来的地方裁。被否决，因为它会把文字很长的格子末尾的控件裁掉，那一列于是读起来像是什么操作都不提供。

**把控件的值里一切会自己出行的东西剪掉。** 读起来很顺——一行说一次上传进行到「取消」，是在陈述一件关于页面的、并不成立的事——而且它当了一轮的规则。依据「前提为假」被否决：在别处会出行的东西，在控件内部一行都不出，因为控件的那一行在走查够到它之前就结束了下降。这条规则把「见 文档 一节」中间的 `文档` 剪掉，把多选框里的标签块清空，还让一个画成单格表格的上传条什么都不汇报。丢字是更重的错，所以这条规则改为保住这些字，只剪掉角色开出来的区域。

**让任何带标签的可点目标都印出自己的一行。** 「页面写了名字就说明这目标是它自己的东西」这条规则，正是带标签的卡片不被读穿的原因。在唯一那种「标签重复了里面那一个控件所说的话」的情形下被否决：那是同一件事说了两遍，两行会让模型在其中挑一行去点。

**教这次遍历认识组件库。** 六轮复核里的每一个缺陷都是在 antd、element 或 bootstrap 的标记语言里发现的，匹配它们的类名本来一行就能修掉每一个。被否决，因为读取器面对的是某个部署渲染出来的任何东西，而一条挂在类名上的规则，会在页面升级自己那个依赖的版本时悄悄失效。

## Consequences

读取器用一个页面的结构而不是它的内容作答，在一份从不盲目花掉的预算之内，并且在四个组件库真实产出的标记语言上保持正确。它放弃了什么记在这里，而不是留到现场去发现。

一幅画装着的任何东西都不作为内容被读：图表的扇区、它的图例、它里面的字都够不着，而数据只活在 SVG 里的页面读起来只有一个标题。页面画在画里、读者仍然能操作的东西仍然是控件——表格单元格会指名图表里的那个图标链接，列出行也够得着它，因为那个链接常常是进入这一行的唯一入口——但它不印出自己的一行，也绝不给周围的节点命名。画成图标的控件必须有 `aria-label` 才能有名字，而这本来就是无障碍对页面的要求。被 `aria-labelledby` 指向、自身既无名字也无文字的元素——包着一个 `img` 的 `span`——对名字没有任何贡献。而 `meter` 带着一份这个包自己的标签到角色映射，被标为装饰的进度条读隐式角色时也走这份映射，因为库映射了其余每一种进度条，唯独没有它。

一次读取印出来的文字里，只有空白会被拿掉，因此页面画出来的控制字符会原样进入快照：`= "​70%"` 保留页面写在数字前面的那个零宽空格。格式类码位只在判断「一个控件到底画没画出文字」时才当空白看。其余部分由把这次读取送到终端的那个座位负责，不是这次遍历。

由一幅画命名的节点读作房间而不是一行，因此骨架把它印成一个无名节点——`e2 treeitem  1 buttons, 1 texts`——标签在它内部那幅画的行上，而骨架不印那一行。同理，`find: 华北` 答的是那幅画的 ref 而不是节点的 ref，模型照那个 ref 去点，点到的是图标。页面直接命名过的节点答的是它自己的 ref。

「模型可见就等于可读」这条准则目前还敞着九个反例。

有四个是读取把文字直接丢了。页面标了标签的可勾选控件用勾选态说完了它装着的一切，因此不汇报值，于是树节点里的 `<div role="checkbox" aria-checked="true" aria-label="选中">华北</div>` 到达模型时是 `checkbox "选中" [x]`，`华北` 两侧都读不到——`find: 华北` 答的是没有任何东西匹配。画在控件内部的区域哪儿都不印，因为控件的那一行在走查够到它之前就结束了下降：编辑器格式工具条上的按钮会丢，画在文本框里的表格连同读取在别处报出它的那份形状一起丢，页面用一个 `ul` 包起来的三个标签块也会丢，而同一个 `ul` 里两个标签块留得住，因为一张列表要三项才读作列表。阶梯确实命名了的节点——由页面写的标签命名，或由它自有的文字命名——只印出一行，把画在它旁边的那些控件折叠掉，因此一个带标签的树行上的删除按钮到不了模型面前。以及 `progress` 与 `meter` 的回退内容被丢掉，依据是规范说在用的引擎都不渲染它，而 jsdom 两个方向都证不了。

有三个是读取看不懂的角色。页面写的角色回落到一个 ARIA 不按内容命名的角色时，元素显示的字会丢掉，除非那个角色改为带一个值：`<span role="bogus img">趋势图</span>` 印出的是一幅没有名字的图片。标签到角色的映射只有页面没写角色的元素才够得到，因此 `<meter role="bogus" aria-label="磁盘">` 到达读者时什么都不剩。以及被页面自相矛盾地标为装饰的布局表会按它自称的那张表来读，于是横在旁边那张表的两半之间：表头那一半把表头借给了这张布局表，而承载数据的那一半一个表头都没有。

有两个是读取说得比页面多。另一个控件内部的原生 `select` 按它装着的文字读，而不是按它选中的那一项读，因此一个两项的 select 把两项都报出来：`visibleText` 里没有「浏览器替这个元素画它自己的文字」这个概念，而这一点唯一显形的地方就是一个画在原生字段外面的控件。以及控件提供的那些东西上的字并进它的值，因此一个画在清除按钮外面的文本框汇报 `= "东风 清除"`——这是「一个字都不丢」的代价，付在读者两样都能看见的地方。

## Deferred

`render.ts` 里的 `cellText` 用角色、名字和状态拼出一个控件，与替控件自有的那一行拼出同一段文字的 `controlText` 并列。两者的差别在于格子会在每个控件前面印一个 ref，以及那个「已折叠」标记——格子里的控件哪儿都不带它：只要 `CellControl` 说出页面是否把这个控件折叠了起来，其中一个就能调用另一个。单凭这一点还不值得动。

## Testing

`tests/snapshot.client.spec.ts` 把模型看得见的每一个字符串逐字钉住，夹具按那四个库真实的画法写；`src/client/access/**` 逐文件 100% 覆盖。凡是取决于「读者能看见什么」的结论，都在注入了 `isVisible` 的 jsdom 里成立，在真实页面被读到之前，它们以浏览器的实现为条件。
