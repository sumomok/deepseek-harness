# Agent Note: 结构化页面读取遵循的规则

Status: implemented

[English](2026-09-02-content-snapshot-engine.md) | 中文

## Problem

`packages/experimental/content-frame/src/client/access/` 里的页面读取器遍历一个真实应用——由某个组件库画出来，跑在浏览器里，摆在用户眼前——并用几千个字符作答，模型拿它代替一张截图。有两件事让这件事很难，而它们都不写在代码里。页面用 HTML 和 ARIA 表达自己的含义时并不一致：同一个树节点，换一个库来画就分别是一个链接、一个图标、一个勾选框和一排按钮。而每一条把某样东西排除在读取之外的规则，都可能恰好排除掉模型唯一需要的那样东西，而模型无从知道这件事发生过。

这篇 Note 记录这些读取规则，以及每一条为什么是这个方向。每一条都是在一个站得住脚的反面之间做的选择，而其中大部分是把对抗性复核指向真实组件库的标记语言找出来的，不是靠推演规范得出的。

## Decision

这次遍历只懂 HTML 和 ARIA，别的一概不懂：任何库的类名、组件名、DOM 形状都不出现在 `src/client/access/` 的任何地方。一条按某个框架的标记语言写下的规则，就是一条在下一个框架上失效的规则，而某个部署在它内容区里渲染什么框架，不是这个包该管的事。下面每一条规则都用规范定义的词说出来。

### 模型可见就等于可读

其余规则都要为它让路的那条不变量：读者能看见的一段文字，一定到得了模型面前。那些做分类的规则——这是一幅画、这是装饰、这是页面自己的包装层——可以把文字从一行挪到另一行，可以把它折进一个名字里，也可以丢掉浏览器根本不画的东西。它们都不可以丢掉浏览器确实画出来的东西。每一轮复核里凡是发现某条规则丢掉了可见文字的，都按缺陷处理，无论那个分类多站得住脚，因为模型没法去问一段它从未见过的文字。

### 只有页面自己写下的才算标签

`declaredName` 读 `aria-label` 和 `aria-labelledby`，读完就停。它有意不是无障碍名字的完整计算：那套计算会回落到元素自身的内容，而对一个树节点来说，那意味着挂在它上面的每一个按钮。页面写下的标签比元素展示的任何东西都值钱，因为一个画成图标的菜单项在别处不说自己是什么；空标签，以及指向页面上不存在的东西的标签，什么都没命名，元素交给下面那道阶梯。

引用在元素自己所在的那棵树里解析，因此开放影子根里的一个 id 指的是那个根里的元素，而不是外面页面里恰好同名的那一个。指向元素自己、指向它包着的东西、指向包着它的东西，都不算标签：浏览器在这种情况下退化成按内容命名，而按内容命名一个节点正是那道阶梯存在的理由。被引用的元素**叫什么**排在它**显示什么**之前，因此页面指向一个图标时，得到的是图标自己的标签。

### 节点名的阶梯

一个树节点或菜单项由它自己的标签命名，绝不由挂在它上面的东西命名：它下面那个组会印出自己的行，作用于它的那些按钮也会。阶梯是：页面写的标签，然后是节点在任何会出行的东西之外的自有文字，然后是它内部第一个显示了文字的行，最后才是除组之外的一切。

第三步会跳过完全不显示文字的行。每个框架画出来的树都在标签前面放一个没有字的东西——文件夹图标、勾选框、图标按钮——而停在第一行就会掉到最后一步，把删除按钮的 `删除` 带进节点名，再让它出现在下面每一行的后缀里。正是这一步让真实的 antd 树和 element 树读对。

### 一幅画是一个东西，浏览器自己画出来的其余东西也是

`isOpaque` 覆盖 `svg`、`canvas`、`video`、`audio`、`object`、`progress`、`meter` 和 `noscript`。写在这些东西里面的，要么是画的一部分，要么是给画不出它的引擎准备的回退内容，而在用的引擎两者都不渲染。遍历不下降进去，不读它的文字，也不把里面的任何东西算作一行：一条路径不是一个段落，一幅画带的 `title` 是页面从不展示的提示，而 `progress` 元素里的字是给十年前就不存在的浏览器看的。

页面命名过的画是一幅图片，有自己的一行；没命名的是装饰，而装饰不断开任何一段文字。页面自己让它可点的画无论如何都保留一行，因为框架把处理函数放在图标上而不是图标外面，而一幅没有行的画是模型根本够不着的东西。这一行的名字只取页面写在这幅画上的东西，别的都不取。

汇报数量的进度条是唯一仍可能印出一行的不透明元素：有名字时，它印出名字和值，因为空 `div` 上的 `aria-valuenow` 就是页面关于这次上传所说的全部。没名字时它读作结构，因为百分比画在旁边的文字里，而一行既无名字又无数字的行会挡在那段文字前面。

### 地标只到整页级，角色只到 ARIA 定义的那些

页面让其可点的一段，若够到了页面自身布局所用的区域，它就不是一个可点的东西：那个指针光标是从上面某处继承来的。只有 `main` 和 `nav` 按标签匹配，因为 HTML 无论它们画在哪里都给这两个标签那个角色，而 `header` 和 `footer` 只有在顶层才是 banner 和页脚，在别处是一张卡片的头和脚。页面若要在卡片里表达那两者之一，就写出角色，而写出来正是它在这里成为地标的原因。表单和对话框整个不在其列：一张卡片很容易装下一个行内编辑器或一次确认，而它仍然是页面提供给你点的那个东西。

页面写的角色，只有在 ARIA 定义它时才算角色，而且词是按顺序读的，因此按更新的词表写的文档会回落到更旧的那个。印出一个没人定义的词，等于把页面控制的文字放到模型读取「这一行是什么」的位置上。这个包里每一个选择器都按词匹配，`[role~="x"]`，理由相同：一个漏掉回落的选择器会让读取的一部分看见一张表格，而另一部分看见一个段落。

由于我们读这个属性的方式与 `dom-accessibility-api` 不同——它只读第一个词——有两个后果。当遍历解析出的角色不是库解析出的那个时，算出来的空名字只说明「库的那个角色不按内容命名」，于是这一行由元素显示的文字命名——仅限 ARIA 规定按内容命名的那些角色。而装饰性角色的冲突消解仍然交给库：页面标为装饰却仍然给它写了标签的元素，按它提供的东西来读，因为页面写下了两件互相矛盾的事，而 ARIA 判给控件。

### 控件的状态就是页面说过的，不多说一个字

浏览器替它保管状态的框，从浏览器读，而写在原生复选框上的 ARIA 被忽略，浏览器也是这么忽略的。页面自己画成框的其他东西，状态就是它写的——在它写之前没有任何状态，因为 ARIA 在这些角色上要求这个属性。被告知「关」的读者会去点开一个本来就开着的东西。被汇报为半选的框同样不属于两态之一：那是一张表格头上、行被选中了一部分的那个框，被告知它是关的读者会去点它，然后把整页的行都选上。

### 结构到得了模型，数据到不了

一张表按它的形状收集——表头、一行样本、一个行数——它的行只有在读取按 ref 点名这张表、或按文字找到某一行时才到来。样本说的是某一列提供哪些控件，而不是它说了什么，因此每个格子都被裁到样本行给它的那点地方：文字先让位给控件，而控件列表自身也在方括号内被裁，因为一排每个名字都是一句话的按钮，否则会把整行样本花在一列上。密码框汇报自己在那里，绝不汇报它装着什么。

### 绝不盲截

整页超出预算时，回来的是它各区域的骨架和下一步该读哪里；列表超出预算时，回来的是一个可以续读的游标。一次读取绝不用「半张列表加上没有办法够到其余部分」作答，而被截断的列表会退掉尾部模型无法指名的行，好让续读恰好覆盖列表一次。

### 布局是注入进来的

jsdom 不做任何布局，而一个 frame 的布局属于那个 frame，因此可见性与几何以 `isVisible` 和 `rectOf` 的形式到来，只经由调用方触到 DOM。因此这个包的测试关于「读者能看见什么」得到的每一个结论，都以 page 座位注入的实现为条件。

## Alternatives considered

**用无障碍名字计算去命名每一行。** 它是规范，已经有人替我们实现了，而且它就是屏幕阅读器会念出来的东西。在「屏幕阅读器念的正是错误答案」的那些行上被否决：一个树节点的计算名字是它的整棵子树，这会把删除按钮的文字放进节点名，再放进它下面每一行的后缀。其余一切仍由这套计算命名，阶梯只限于按内容命名会出错的那些角色。

**把一幅画的 `title` 和 `text` 当页面文字读。** 它们是文字，而一张图表的图例确实说了点什么。被否决，因为 `title` 是页面从不画出来的提示，而图表里的字是一幅画的标签：读它们会在每个图标处把周围那段文字断成两截，还会把提示当成读者看得见的东西印出来。代价记在下面的限制一节。

**照页面写的保留 `role="presentation"`，不做冲突消解。** 更简单，也少调一次库。被否决，因为它把带标签的按钮和文本框整个从读取里删掉了——一个带着名字的元素正是页面自己前后矛盾的那个元素，而 ARIA、每一个浏览器和这个库都以同样的方式判定它。

**把 `mixed` 印成第三种状态。** 诚实，代价是行里多一个词。目前被否决，因为这一行的每一个读者都得被教会那第三个词，而什么都不说本身已经意味着「去看一眼」：模型会去问这个框，而不是照一个被告知错了的状态动手。

**把样本行拼好之后再裁。** 只裁一次，就在这一行被印出来的地方裁。被否决，因为它会把文字很长的格子末尾的控件裁掉，那一列于是读起来像是什么操作都不提供。

**让任何带标签的可点目标都印出自己的一行。** 「页面写了名字就说明这目标是它自己的东西」这条规则，正是带标签的卡片不被读穿的原因。在唯一那种「标签重复了里面那一个控件所说的话」的情形下被否决：那是同一件事说了两遍，两行会让模型在其中挑一行去点。

**教这次遍历认识组件库。** 六轮复核里的每一个缺陷都是在 antd、element 或 bootstrap 的标记语言里发现的，匹配它们的类名本来一行就能修掉每一个。被否决，因为读取器面对的是某个部署渲染出来的任何东西，而一条挂在类名上的规则，会在页面升级自己那个依赖的版本时悄悄失效。

## Consequences

读取器用一个页面的结构而不是它的内容作答，在一份从不盲目花掉的预算之内，并且在四个组件库真实产出的标记语言上保持正确。它放弃了什么记在这里，而不是留到现场去发现。

一幅画里的任何东西都不可读：图表的扇区、它的图例、它画出来的链接都够不着，而数据只活在 SVG 里的页面读起来只有一个标题。画成图标的控件必须有 `aria-label` 才能有名字，而这本来就是无障碍对页面的要求。被 `aria-labelledby` 指向、自身既无名字也无文字的元素——包着一个 `img` 的 `span`——对名字没有任何贡献。`role="none"` 得不到它的同义词 `presentation` 得到的那次装饰性冲突消解，因为库只对一种拼法实现了它。而 `meter` 带着一份这个包自己的标签到角色映射，因为库映射了其余每一种进度条，唯独没有它。

## Testing

`tests/snapshot.client.spec.ts` 把模型看得见的每一个字符串逐字钉住，夹具按那四个库真实的画法写；`src/client/access/**` 逐文件 100% 覆盖。凡是取决于「读者能看见什么」的结论，都在注入了 `isVisible` 的 jsdom 里成立，在真实页面被读到之前，它们以浏览器的实现为条件。
