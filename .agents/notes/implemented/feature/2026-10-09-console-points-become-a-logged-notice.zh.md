# Agent Note：控制台里指的一处，以每条消息一条写进日志的说明到达模型，来源种类是它自己的

Status: implemented

[English](2026-10-09-console-points-become-a-logged-notice.md) | 中文

## Problem

控制台的用户问的是内容栏里显示的东西——数据页的一列、工具栏按钮、原系统页面上的控件、组件视图里的一块——光看问题说不清是哪一个。核心补丁 `rail-references` 让所属插件登记一条提示引用，浏览器随消息发出，宿主记在收下的消息来源上，而第一方提供方的序列化从不把来源放进请求。所以引用只是显示和所属插件的数据：所属插件不为模型写文字，模型就什么都看不到；而仓库规定每个模型输入都要能从会话日志重建，这段文字必须写进日志。

`agent/pre-step` 在一轮的每一步之前都跑，不是每条消息跑一次，所以在那里加的文字，这一轮的每一步、以后每一轮重放历史时都会再给一次。数据页的描述还带着取到它的那一行，最多二十列直接从行对象读出的记录值，而会话日志永久保存。

## Decision

**`@deepseek-ai/dsh-experimental-content-point` 把一条消息里指的地方，写成紧跟在它后面的一条写进日志的用户消息。** 它的宿主一半是一个 `agent/pre-step` 监听器。进入这一步的每条用户消息，只要它的 `user-rpc` 来源记有以 `content-point` 来源登记的引用，就在它后面插入一条用户消息；正文每个引用一段——标签、键行和显示文字——最多 `MAX_PROMPT_REFERENCES`，即 16 个。

**插入的消息有自己的来源种类 `content-point`，声明带 `@persistenceAttribution`。** 来源指名它对应的用户消息（`message`），带 `form: 'notice'` 和一行摘要，所以没有这个包的读取方保留内容，按日志里的种类显示这一行。它不是会话事件，不是 `ignorable`；它的声明走了持久化类型变更的确认（[记录](../../../../docs/persistence-changes/2026-10-09-content-point-source.zh.md)）。

**每条消息里指的地方只追加一次。** 一步里已经有指名某条用户消息的 `content-point` 消息时，监听器不再为它追加；一条用户消息只进入一步：它为那一步从收件箱取出并记下，所以之后一步的 `messages` 只有那之后才到的消息。说明在同一步里紧挨着它记下，之后每次请求都从历史里把两者一起重放。

**任何一行的值都不进入引用，也不到模型那里。** 浏览器一半在 `toPromptReference` 之前从 point-anchor 的描述里去掉 `row` 和 `rowOmitted`，宿主一半不管日志里的数据带了什么，都去掉这两项再写。格子、整行和行内操作按列和操作命名。

**组件视图里的每一块都能指。** point-anchor 描述数据页、原系统页面、图片和侧栏条目；它当作不描述的组件拒绝的块，登记为整块引用（`v: 1, kind: 'block'`），写出座位、`data-component-block` 与 `data-component-node` 的值和显示文字，键行写成 `block seat=… component=… node=…`。整块引用放在本包而不是 point-anchor，因为只有控制台的组件视图写这些属性，北冥壳从不在那里拾取。

**这一行不写 `content-component/shown`。** 它唯一的持久输出是插入的那条用户消息。

## Alternatives considered

**自己的会话事件，带 `ignorable: true`。** 模型可见的输入必须是组装请求所用的消息；事件还要一个提取器才能变成消息，而可忽略的事件会让没有这个包的读取方无法重建包含它的请求。

**改写用户自己的消息，把指的地方带进去。** 浏览器的消息按用户写的样子记下，引用在它的来源上；改写内容会让键行出现在用户的气泡里，也分不清哪些是用户打的、哪些是控制台加的。

**在 `session/prompt` 时追加，而不是 `agent/pre-step`。** 宿主在一步收下消息之前就记下这条消息；排在运行中的一轮后面的消息要晚些才收下，在提示时追加会让说明排在这一轮自己的消息前面，或者要第二套排序规则。

**把整块引用放进 point-anchor。** point-anchor 的键行由北冥拾取脚本和 FDE 导出共用，它们看不到组件视图；在那里加 `block` 锚点，会是导出的技能都对不上的键行。

**带上行值并做脱敏。** 值读自行对象，不是页面画出来的内容，页面隐藏或脱敏的列照样会读到；计划把行值推迟到 point-anchor 能只保留画出来的非脱敏列之后。

## Consequences

模型知道用户指的每一处，键行与 FDE 拾取写的一样，日志里记的正是告诉它的文字。去掉这一行的部署，会话照样能读：说明按它的种类作为内容留着。

说明每一处约 40 到 80 个 token，只出现在带有指向的消息里，对 KV Cache 只追加。模型不知道格子或行内操作属于哪一条记录。表单页、信息卡的字段只能按整块指，直到这些组件有自己的描述。point-anchor 的 `checkDeliverySet` 与 skill-pack 读取器的等价还没有测试；它随 point-anchor 0.2.0 一起来。
