# Agent Note: 两级设置导航

Status: implemented

[English](2026-09-14-settings-navigation-groups.md) | 中文

## 问题

设置导航栏是所有 `settings.section` 注册项按 `order` 排出的一条平铺列表。上游出厂四个分区，fork 的桌面组合再加七个，于是发行产品在同一列里画出十一个并列项：通用设置、模型、插件、Agent 预设、余额、自动审查、MCP 服务器、At file、截图登录、视觉、桌面更新。没有任何东西告诉读者其中哪些关于模型、哪些关于扩展、哪些关于账户——而且十一项里有八项画的是同一个齿轮，因为 `navIcon()` 只点名了 `models`、`agent-presets` 和 `plugins`。

这个规模的成熟设置界面——macOS 系统设置、Chrome、VS Code——一律给导航栏分组而不是把它拉长，这一对照定下了方向。

这一列还长不了。`.panel` 是 `min(800px, 100vh - 48px)` 且 `overflow: hidden`，`.nav` 是纵向 flex 而其 `.navList` 既没有 `min-height: 0` 也没有 overflow，于是一个拒绝收缩到内容以下的 flex 项就被面板直接裁掉。十一个 40px 单元加上标题已经占到 478px；视口再矮一点、字号再大一点，或者再多一个插件，最后几行就无声消失且无从抵达。

注册方从外部修不了这一点。一个 `settings.section` 注册项只带 `key`、`id`、`order`、`label`、`priority`，别无其他（`@deepseek-ai/dsh-client-ui-slots` 的 `register`），因此它无从声明分组或图标。

## 决定

导航栏画成两级：一张固定的分组表，每组一个图标和一个不可交互的标题，其下是账本行本身。分区 id、`order`、label 与 `openSection(id)` 入口全部未动——变的只是一行画在哪里。

七个分组，按导航栏顺序及各自认领的分区：通用（`general`、`at-file`）、模型（`models`、`vision-switch`）、智能体（`agent-presets`、`llm-permission-gateway`）、扩展（`plugins`、`mcp-servers`、`screenshot-logins`）、账户与用量（`balance`）、关于（`desktop-update`），以及收尾的「其他」承接表中未点名的一切 id。被点名的分组按表内顺序而非账本顺序排列成员，因此无论注册方选了什么 `order`，导航栏读起来都一样。成员全部缺席的分组一行都不画，卸载的插件不会留下空标题；未被识别的 id 则按账本顺序留在「其他」组内——没有哪个分区会因为不被认识而消失。

**这张表放在外壳里**，硬写在 `nav-groups.ts` 中，因为把它移出去的两条路都不存在。注册方无从声明自己的分组（见上面的 register 选项），浏览器端插件也收不到任何配置：客户端引导线每行只带 `id`、`inject`、`immediately`（`@deepseek-ai/dsh-client-modules` 的 `BootPluginRow`），`bootClient` 以 `loader.create({ name })` 创建每个条目——引导线上根本没有 config 字段。客户端一面的 `apply` 仍可以声明 `Config` 参数（`ui-conversation` 就声明了），但线上没有任何东西能填它，这样的参数只会取到 schema 默认值。双面行在 cordis.yml 里的 `config:` 只到该包的 node 半边。要让这张表可配置，就得为一个纯展示事实新开一条 Host 到 Client 的通道，那比分组本身的改动还大。

图标移到组标题上，成员行不带图标。`account` 取人形而非仪表：仪表已经是输入框药丸里会话 token 计量自己的标记，一个图标在同一产品里表示两件事，比人形用在一个同时承载用量的分组上稍显宽泛更糟。`about` 取问号圆环，这是本图标集中唯一的信息类标记，按导航栏的 16px 绘制。「其他」复用通用的齿轮，与原先平铺导航栏的兜底一致。

**可访问性：每个分组是一个 `role="group"`，由 `aria-labelledby` 指向其标题命名**，而不是把标题对辅助技术隐藏起来。两级结构正是本次改动的要点，隐藏标题只会让读屏用户仍旧面对十一个按钮的平铺列表——其中「视觉」与「模型」无从分辨。标题仍是 `div`：不可聚焦、不可点击、不带任何交互角色。

另有两处结构修复随行。`.nav` 与 `.navList` 加 `min-height: 0`、`.navList` 加 `overflow-y: auto`，导航栏因此滚动而不再被裁；面板已经重绑了高层表面的滚动条 token，会向下继承。导航投影改读 `ctx.slots.entriesOfSlot('settings.section')` 而非 `entries()`：`entries()` 是原始账本，同一分区 id 上的两个条目会画出两行而出口只渲染其一——被遮蔽的那一行点开后显示的是胜出者。投影的 version/revision 缓存保持快照引用稳定，这正是 `entriesOfSlot` 坐在 `getSnapshot` 后面所需要的。

## 备选方案

**让注册方自报分组。** 否决：分组集合是关于这一条导航栏的产品决定，而一个注册选项会让任何插件——包括第三方插件——凭空造组或把自己放错位置，且无处仲裁。

**把这张表做成 ui-settings-general 的校验过的 `Config` 字段，fork 的完整表写进组合 overlay。** 否决的理由是做不到而非不想要：客户端引导线不带 config，加载器只按名字创建客户端条目（证据见上）。一旦客户端插件能接配置，这就是首选形态。

**可折叠分组。** 否决：十一行的导航栏没有什么需要藏起来，而折叠状态是逐用户的持久状态，外壳还得承担它。

**只按分组排序平铺列表、不加标题。** 否决：那只是把同样的十一个并列项重排一遍，读者看不出任何东西。

**成员行也各自保留图标。** 否决：同一缩进上的十一个图标又读成十一个并列项，正是要解决的问题；图标属于起区分作用的那一级。

## 后果

导航栏显示六个具名分组加一个兜底组，每组一个图标，超出面板高度时滚动。把一个分区加进某个具名分组是 `nav-groups.ts` 的一行改动；不加也照样能用，因为该分区会落进「其他」并正常打开。

组标题与其下的成员可能读作同一个词，因为组标题是外壳的文案（`nav.group.*`），行标题是注册方的文案（本包的 `general.nav`、`settings.models` 命名空间的 `nav`）。两者会撞名时，**改的是成员行、组标题不动**：组标题是意图名，必须短到能领起一列；成员 label 则描述它打开的那一页。于是「通用」组下是 **General settings**（中文「通用设置」，本就不撞名），「模型」组下是 **Providers & models** / **提供方与模型**——那一页装的正是提供方卡、API 密钥与模型清单。中文取「提供方」而非「供应商」，是因为该页正文每一处都作「提供方」，导航行独用另一个词会让同一页出现两种叫法。分区 id、页面标题与组标题一概未动，只有这两行的 label 承担区分。

包内测试承载证据：每个分区按表内顺序归入其分组——夹具里有三个分组的成员顺序与升序 `order` 相反，退回账本顺序就会失败——每个分区在所有分组里只画一次、表中从未点名的 id 落进「其他」且能打开、成员全部缺席的分组不画标题、六个互不相同的组图标且成员行零图标、每个分组经由不可交互标题上的 `aria-labelledby` 获得名称、组标题跟随当前语言、让导航栏滚动并拉开两级的四条 CSS 声明，以及第二个条目遮蔽已占用 id 时每个分区单元仍只出一行。

**退役条件。** 这是落在上游客户端包上的 fork 覆盖层，与 `settings.trigger.action` 一族同文件。上游若给 `settings.section` 注册项自带分组或图标，或外壳自己长出任何分组、图标、滚动机制，对应部分即退役、由 fork 适配上游形态。在那之前每轮滚动同步都要重新移植并重新核实，因为它落在上游会改的导航标记、导航样式表与账本投影上。
