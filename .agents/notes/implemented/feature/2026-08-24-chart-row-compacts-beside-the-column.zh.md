# Agent Note: Beside a content column, the chart row keeps the verdict and gives up the picture

Status: implemented

[English](2026-08-24-chart-row-compacts-beside-the-column.md) | 中文

## Problem

[content surface](2026-08-24-content-surface-router.zh.md) 给了 `show_chart` 第二个落位，于是开着 content 栏的 session 把每张图都画了两遍：栏里一份整屏高度，调用所在处又一份整屏高度。会话记录里那一份是贵的那份——每次调用一块 340px 的舞台，一块块摞起来，落在两栏中较窄的那一栏，而且正是用户滚动的那一栏——它展示的东西，旁边那一栏已经在展示了。

但仅仅「在那里不渲染」不成立。[会话记录里那一行](2026-08-24-show-chart-tool-chat-view.zh.md)是渲染判定与截图的唯一所有者：工具体阻塞等待**这个 call id** 被画出来，而栏里的 `chart` 座位刻意什么都不回答，因为它本会回答的那次调用早就结算了，用户仅仅是再次选中某张图时回报第二次，那次回报没有对象。

## Decision

组合了 content 栏时，会话记录里那一行交出画面、留下判定。这推翻了 [`show_chart` 那次决策](2026-08-24-show-chart-tool-chat-view.zh.md)中「图表就是会话记录里那一行」的那一半；判定、截图、回报归谁，一点没动。

**那一行通过 `contentSurface` 投影感知这一栏。** 有值就意味着组合了 content 栏，而这在构造上就意味着本 session 的图表都是栏里的 entry：栏的 `chart` 抽取器和会话记录里那一行读的是同一批事件、走的是同一个 reader，因此这一行会画的每张图，在切换条里都已经有一条。没有值——已发布布局，或者任何没有这块 surface 的组合——那一行的行为与从前完全一致。

**三种状态，两种例外。** 调用等待判定期间，那一行显示 `<标题>：正在绘制…` 并把引擎挂载在布局流之外；判定一到，它显示 `<标题>：已在内容区展示。` 并卸载引擎。**被取代**的行优先保持它自己的提示，因为无论哪种布局它都不回答任何调用、也不挂载引擎。**失败**的图表把本地化的错误行留在会话里，因为没画出来的文档在那一栏里同样不存在，而这条消息正是下一次调用需要的东西。

**移出流，而不是移出布局。** 等待中的舞台是 `position: fixed`、固定尺寸、挪到一边。ECharts 按已布局元素来定 canvas 尺寸，因此 `display: none` 会给它一个零尺寸元素，判定就成了对空无一物的判定——这与已发布舞台用 `visibility` 隐身是同一个理由。fixed 定位补上了单靠 `visibility` 做不到的那件事：会话不再为它花掉任何高度。

## Alternatives considered

**把判定挪到栏里的 `chart` 座位，让会话记录里那一行彻底消失。** 否决：那个座位只画**选中**的那条 entry，于是用户从不选中的图永远得不到验证，一张画得好好的图会把工具耗到超时；而被再次选中的那张则会回报两次。判定的归属跟着调用走，而调用坐在会话记录里。

**逐条匹配——只把确实在栏里的那些图对应的行收紧。** 作为一次改变不了任何结果的查表被否决：两边都从同一批事件、经同一个 reader 派生出条目，因此当前的图必定有条目，而被取代的那些本来就已例外。它还会让那一行依赖栏的 entry 词汇，而不是依赖「究竟有没有一栏」。

**留下紧凑卡但不挂引擎，接受 `Shown; not verified`。** 否决：这会让每一个开了栏的部署都悄悄失去第二层和第三层反馈——没有任何东西确认文档画出来了，引擎拒绝文档时也没有它自己的消息，更没有截图——而这几乎就是这个工具的全部。

**用一个 `Config` 字段来选落位。** 否决：这个选择已经被表达过了，而且表达得更好——由组合表达。想把图放在会话里的部署不组合 content 栏；组合了栏的部署已经说明了内容该去哪里。多一个字段只会让两者互相打架。

**让紧凑卡在栏里选中它那张图。** 是推迟而非否决：两个组件分属不同的包，之间没有通道，而 slot 组件也不得自行订阅任何东西。它作为一条限制记在包的 README 里，而不是靠那一栏被迫发布的某个全局量来实现。

## Consequences

已发布布局分毫未动，其物证是 `apps/web/tests/show-chart.e2e.ts` 的已发布布局那一组场景一字未改，断言的还是它一直断言的那些已绘制 canvas。它的服务线场景随行为一同改了：现在断言的是紧凑卡、会话里没有 canvas、chat 栏里也不剩任何舞台。

`apps/web/tests/content-surface.e2e.ts` 承载「这次收紧之后往返仍然成立」的证据。它从浏览器侧盯住 `/show-chart/report`，断言恰好是那两张当前的图回报了判定、被取代的那一行一次都没有——这份证据紧凑卡自己给不了，因为卡片和回报是同一个判定的两个结果。

一行紧凑的行仍会构建一个 ECharts 实例，并在判定到来时销毁。这是把所有权留在调用所在处的代价；回放一份画了几百张图的会话记录时，每一行滚进视野都要付这份代价。

新增两个词典 key（`row.delegating`、`row.delegated`）和一个属性（`data-show-chart-delegated`，先 `pending` 后 `shown`）。卡片复用被取代卡的样式，因为两者对读者说的是同一件事：这次调用画的那张图，现在在别处。

## Testing

`show-chart-row.client.spec.tsx` 在两种组合下驱动那一行：紧凑卡的两种状态、流外舞台的 class 及其背后的引擎、判定到来后引擎消失而截图照样随行、留在会话里的失败行、优先生效的被取代行，以及这份契约里 `develop` 的那一半——没有 `contentSurface` 值时那一行完整保留整张图。
