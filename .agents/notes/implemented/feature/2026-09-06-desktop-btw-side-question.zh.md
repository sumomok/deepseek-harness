# Agent Note: A side question that leaves the conversation as it was

Status: implemented

[English](2026-09-06-desktop-btw-side-question.md) | 中文

## Problem

就手上这件事去问助手——某一步为什么这么走、某个词是什么意思、某个做法是否站得住——要付两次代价。助手会去回答而不是继续手上的任务;而且这个问题与它的答案会坐进此后每一次请求的上下文里,以后每一轮都要为它付钱。此前没有办法只问、不付这两样。

## Decision

`@haoran/dsh-btw` 0.1.1 加入 [`apps/desktop-shell/README.zh.md`](../../../../apps/desktop-shell/README.zh.md) 所列的桌面内置插件,以 `apps/desktop-server/vendor/haoran-dsh-btw-0.1.1.tgz` 的形式 vendor 进来(sha256 `4ce89b8925904c6a208c51e7625f9a9a71126eb62b1594d35d044876b99960ab`)。它只注册一个命令:`/btw <问题>` 把到目前为止的对话连同这个问题一起送出去,把答案显示在它自己的一行里,并让对话保持原样。

**这份隔离是结构性的。**问题与答案就是命令注册表自己的那两个事件——`command/run` 带着 `name: 'btw'` 与逐字的问题,放在 `args` 里;`command/done` 带着答案、或没有答案的原因,放在 `text` 里。两者都不是 surface 事件类型,而唯一构建模型请求消息列表的那个函数 `Session.deriveMessages()` 只在 surface 节点上折叠。这个插件写下的任何东西都到不了之后的请求,也不需要谁记着别把它带上。

**记下它们不是可选的。**问题进了一次模型请求,而 harness 的规矩是:模型请求看到的任何东西都必须能从会话日志重建出来。

**它不声明任何自己的会话事件。**更完整的记录——问题、答案、模型、token 用量放在一个结构化载荷里——需要这个插件自己声明一个事件类型,而它不能有:`SessionEventMap` 是从本仓库生成的,日志里出现该词汇表之外的事件类型时会拒绝重建,除非信封被标记 `ignorable: true`,而 `Session.append(type, data, ...opts)`([`packages/core/session/src/index.ts`](../../../../packages/core/session/src/index.ts))没有任何参数能写这个字段。仓外插件若声明了一个,就会让用过它的每个会话在重启后读不出来,而卸载了这个插件的人也一样读不出来。于是模型 id 改成搭在答案末尾的一行署名上,由那一行卡片渲染成副标题;token 用量不记录。

**走对话自己那条路由的一次请求。**没有摘要环节,也没有第二个模型:输入是整段对话加上这个问题,所以长对话里的一次岔开提问,花的就是这段对话里一轮的钱,而且每一次都按那个完整长度单独计费。出厂配置里没有 `provider` 与 `model`,这正是让路由跟着对话走的原因——换模型无需任何配置就跟过去,而在对话还没有自己的路由时(`/btw` 是你打的第一句)则跟随本部署的默认模型。配置里的系统提示词是唯一告诉模型要什么样的答案的东西:岔开的问题带着对话作为上下文抵达,却不带 agent 自己的系统提示词,也不带工具。

**答案不是流式的。**它整段出现,而不是一个词一个词地出来,因为唯一能把增量送到浏览器的通道是会话事件,而这个插件不写任何属于自己的事件。能承载它们的第二道缝是 Typert 流式 remote,那道缝没有建。

**出货客户端停不掉旁支问题,而那一行读的是一个它永远收不到的停止。**界面为进行中的智能体轮次显示的停止按钮到不了命令这一层:这个客户端不会把取消信号传给它发起的命令,所以问出去的回答一定会跑完,用 × 关掉那一行也只是把它收起来。真正会被放弃的是跑到 `timeoutMs` 的请求,用的是这个插件自己的文案。host 那一半仍然处理取消,因为确实会传信号的调用方遇到的还是这一套:注册表会中止运行中的处理器,用 `signal.reason` 作为消息把命令结算掉,盖过这个插件自己那句「已取消」——于是那句话在本产品里永远到不了任何一张卡片。存下的那段文字是英文且技术性的(`This operation was aborted`,或注册表的 `command aborted` 兜底),所以一次失败的 `/btw`,只要它的文字里带 abort 这个词,就按界面语言画成**已取消**,原文放在悬停里。这层识别放在那一行里而不是放在写下的内容里,因为存下的文字不由这个插件来写,而没有装它浏览器那一半的部署会退回通用命令卡片,那张卡片显示的是原文。

## Alternatives considered

**在对话里回答,事后靠压缩把它清掉。**不需要插件,而且复用 harness 已有的压缩。但压缩是有损的,而且由压力触发、不由意图触发:在有什么东西来压缩它之前,这段交换仍然进入每一次请求,而压缩之后留下什么也不是提问者能决定的。这个功能要消除的那笔开销,它恰好原封不动地留着。

**先把对话摘要出来,再拿这份摘要去问一个小模型。**这是更便宜的那次请求,而它回答的是一份摘要而不是对话。岔开的问题通常问的是细节——某个参数、某段报错、某一步的确切措辞——而摘要最先丢掉的正是这些。而且除了极长的对话,两次请求也比一次更贵。

**声明一个自己的事件类型,把问题、答案、模型与用量都带上。**这是这个功能配得上的记录。出于上面的原因,仓外插件拿不到它;而且它的失败形态是最糟的那种:会话一直读得好好的,直到有人卸载了这个插件、或换了一个不认识这个类型的构建去重载日志。

**开一个子会话,让这段交换有自己的日志。**它能带上用量与流式,又不碰父会话的消息列表。但为了一个「全部价值就在于什么都不留下」的问题,它要多出一大片表面——一个要创建、命名、投影、列出、清理的会话——而且凡是列出会话的地方都会冒出它的行。

## Consequences

这个插件声明了 `dsh.client`,所以打包的启动闸要求它的 `client.js` 出现在所服务的 index 所列的客户端模块里;没有这一半时,显示的是通用命令卡片里 host 自己写的文字,而不是那一行。

一次岔开提问是一次全价请求。问过一次不会让下一次更便宜,它也不搭正在进行的对话已经缓存下来的任何东西的便车,所以长对话既是这个功能最有用的地方,也是它最贵的地方。

一次 `/btw` 留下的记录是两个事件加一行署名。想按问题做 token 记账的,得去读供应商自己的用量,而不是会话日志。

host 那一半自己写的那些句子是双语的、中文在前,因为它们是持久的,而且在没有装这个插件浏览器那一半的地方由通用命令卡片逐字显示。只有那一行的外壳——标题、关闭按钮、「正在回答…」、「由 … 回答」、「已取消」——跟随界面语言;那一行还会按浏览器记住自己是否被收起。
