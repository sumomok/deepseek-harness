# Agent Note: 内容区的眼和手 v1

Status: implemented

[English](2026-09-01-content-column-eyes-and-hands-v1.md) | 中文

## Problem

内容区把一样东西摆在用户面前——今天是一个托管页面，旁边是一张图表，等第二个 kind 出现之后还可能是表格或演示稿——而在它旁边的 agent 一样也看不见。它只知道部署配好的页面目录：用户打开了什么、正在看哪个标签、frame 里的应用自己路由到了哪里，它都不知道，那个应用画出来的东西更是一无所知。

四个切片为 page kind 补上了这段缺口的大部分，各自记录了自己的机制。它们都没有记录的是这些机制合起来是什么：哪一层回答哪个问题、第二个内容 kind 要交出什么、什么进会话日志而什么故意不进、部署可以设什么、真机控制台教会了什么，以及这条线在哪里刻意停下。

## Decision

五层，按各自回答的问题划分，而不是按实现它的包划分。v1 为 page kind 交付前两层。第三层正在单独一条线上实现，第四层是词汇，第五层是一条带两个前置的路线。

### 五层，各自的家在哪

| 层 | 回答什么 | 家在哪 |
|---|---|---|
| 感知 | 内容区里有哪些条目、谁放的、哪一个在前面、里面的应用去了哪里 | [感知层那篇](2026-09-02-content-column-perception.zh.md) |
| 眼 | 在前面的那一项到底显示了什么，以编号结构给出，后续调用可以指着它 | [读取规则那篇](2026-09-02-content-snapshot-engine.zh.md)，由[读取通道](2026-09-01-content-read-page-channel.zh.md)承载 |
| 手 | 像用户那样操作那一项，一批动作一次审批 | 正在单独一条线上实现；见 [Deferred](#deferred) |
| kind 契约 | 内容区里装的不是页面时，什么保持不变 | 本篇 |
| 沉淀 | 把做过一次的事变成下次可以直接调用的能力 | 未落地；路线见 [Deferred](#deferred) |

读的这半边先于动的那半边交付，这个顺序是依赖而不是排期：动作的每一步都用读取器发出的 ref 指认目标，因此读错页面的读取器就是点错元素的 agent。

### 一个 kind 要交出什么

上面这套机制里只有一小块知道「页面」是什么。这条分界就是第二个 kind 所依据的合同，现在就定下来，因为词汇才是接口——注册表不是，它只有一个实现可供归纳，所以要等。

| 层 | 与 kind 无关 | kind 自己交 |
|---|---|---|
| 感知 | 条目流、哪一个在前面、通知、提示词上下文 | — |
| 寻址 | ref：一个条目内部的地址 | 地址长什么样 |
| 看 | 骨架、进入某个区域、游标，以及它们渲染所用的预算 | 结构怎么从这样东西里读出来 |
| 动 | 一批带 label 的步骤、一次审批、逐步结果 | 动作词汇 |
| 指 | 对话里一枚写着 kind、地址与 label 的芯片 | 渲染方怎么让用户点选 |
| 沉淀 | 对象签名、能力声明、编排、来源记忆 | 签名怎么算 |

一个 kind 要交四样：[`content-column`](../../../../packages/experimental/content-column/README.zh.md) 分发的 `content.surface.kind` slot 里的一个渲染座位、一份结构读、一种地址形式连同一套动作词汇，以及可选的点选器。带数据的 kind 还要交第五样——以值而不是文本作答的数据读——数据重的 kind 没有它就没有用。用户递过来的东西，无论走对话还是走这一栏，都得到一个座位，同一套指、看、动、沉淀对它们全都适用。

### 什么进会话日志

由两条规则决定。凡是进入模型请求的东西都必须能从日志重建。以及回放必须能说出用户当时看见了什么——内容区里有什么、哪一个在前面、frame 去了哪里。

| 事实 | 怎么记录 |
|---|---|
| 用户或 agent 把一个页面放进内容区 | `content/shown` |
| 关掉一个标签 | `content-surface/dismissed` |
| 用户选中的标签 | `content-surface/selected`，由切换器自己的命令追加 |
| frame 自己路由到了哪里 | `content/navigated`，在浏览器的去抖窗口之后追加 |
| 打开页面、关掉标签这件事在对话里的样子 | 命令注入的一条 `user/message` |
| 每次请求所带的内容区现状 | `content:column` 提示词上下文，由两个 projection 折叠而来 |
| 一次读取的调用与结果 | `tool/call` 与 `tool/result`；读取跑在 `run_code` 里时是 code-mode 的那对 dispatch 事件 |
| 审批的问与答 | `approval/asked` 与 `approval/decided` |
| 认领、被钉住的标签页、某个 frame 的 ref 表、frame 重新加载 | 什么都不记：运行态，模型从结果或失败文案得知 |

这条线新增的每个事件都是读取时必需的，因为 `Session.append` 没有把事件标成可忽略的途径，而这个 fork 不改上游内核去加一个（[机制](2026-09-02-content-column-perception.zh.md)）。不认识这些类型的构建因此拒绝整份日志，而不是跳过一个它无法定型的事件。

### 部署可以设什么

这条线里随部署而变的数字，没有一个是插件里的常量。它们全是 [`content-frame`](../../../../packages/experimental/content-frame/README.zh.md) 上经过校验的 `Config` 字段，每一个该往哪个方向调、为什么，由它自己的 JSDoc 说明；本篇拥有的是这份清单，以及每一项在加载时被拒的界。

| 设置 | 界定什么 | 加载时被拒于 |
|---|---|---|
| `cacheSize` | 保活的 frame 数，按 (会话, 页面) 计 | 小于 1 |
| `navigationPollMs` | 多久问一次在前面的 frame 现在在哪 | 小于 1 |
| `contextEntries` | 提示词上下文列出多少条目 | 小于 1 |
| `contextFieldChars` | 上下文的一行带多少个名字字符 | 小于 8 |
| `claimTimeoutMs` | 等控制台认领一次读取的时长 | 小于 1 |
| `readTimeoutMs` | 等认领方回答的时长 | 小于 1 |
| `pinMs` | 应答过的标签页保持首选多久 | 小于 1 |
| `settleQuietMs` | 多长的静止算作页面已经画完 | 小于 1，或超过它在 `readTimeoutMs` 中的份额 |
| `outlineChars` | 一份列表渲染所用的字符预算 | 小于 1000 |

读取那半边是一个块而不是每件一个开关：`pageAccess` 缺席意味着没有工具、没有路由、没有待办 projection、浏览器里也没有读取器，因为这些拼图分开毫无用处（[原因](2026-09-01-content-read-page-channel.zh.md)）。模型自己没有预算参数——给它的工具是缩小读取范围，不是调一个数字。

### 先探针后引导，以及引导怎么退役

一句告诉模型该做什么的话，会在带着它的每一次请求上永久花掉上下文。所以「模型会不会自己这么做」这类问题先测再答：对着真机控制台页面用固定提示词，十个全新的草稿会话，从会话日志上打分。P0 问的是：用户说「右边这个表」，agent 会不会去读这个页面。

| 构建 | 首个调用是读取 | 多余的 `content_show` | 答对真值 | 读取次数中位 | 用时中位（秒） |
|---|---|---|---|---|---|
| 上下文之前 | 2/10 | 8/10 | 10/10 | 6 | 12.5 |
| 带内容区上下文 | 11/11 | 0/11 | 10/11 | 6 | 13 |
| 带合并副本的读取器 | 10/10 | 2/10 | 1/10 | 3 | 6 |

P0 完全不需要引导：每一轮里模型都自发去读，只要读取器给了它正确的数字，答案就是对的。内容区上下文换来的是省下那次多余调用——看不见内容区的模型，十次里有八次去展示一个已经在前面的页面，上下文把这一项归零。第三轮暴露出来的是一处计数回归，记在 [Deferred](#deferred)。

真要写引导时，三样东西一起交：一个把它关掉的 `Config` 开关、Agent Note 里两行写明它补的是模型的哪个弱点、以及哪次探针结果让它退役，还有入库的探针脚本。这条规则不覆盖承担安全的东西——审批、步骤执行前的 label 核对、拒填登录表单——它们不是补偿，也永不退役。

### 真机控制台教会了什么

读取器先对着夹具写成，然后被指向一个真实的 Element UI 控制台。下面每一条都改变了产品，它们各自催生的规则记在各自所属的规则那里。

组件库固定一列的做法，是把整张表在自己上面再画一遍，于是用户看见的一张表在文档里是六张，而把它们分开处理的读取器答出来的是每一行的固定列都空着，并告诉用户一个他们看得见的列不存在。一行的操作控件可以完全没有可点信号——没有 role、没有 label、没有 title、没有 pointer 光标——读取器那条按 class 名判断图标的启发式规则正是为此存在。一张表单可以不给任何字段绑定 label，并用样式表画出必填标记，于是只信任文档的读取答出一张四十九个字段、没有一个带名字的表单，且无从分辨页面要求填哪些。

模型一个问题读三到十次，沿着骨架、区域、文字匹配走下来，而且它把收集到的 ref 引用给了一个根本看不到 ref 的用户——这正是禁止这么做的那条规则落在内容区上下文里、而不是工具描述里的原因（[落点](2026-09-02-content-column-perception.zh.md)）。应答的座位离开该会话之后，那句先建议 `content_show` 的失败文案把模型送进了十次调用、八十秒的循环，这正是这句话现在要按内容区里有什么分岔的原因（[两条路径](2026-09-01-content-read-page-channel.zh.md)）。

同时开着两个页面时，agent 每一次都点对了页面，包括用户关掉它刚读过的那个标签之后。ref 按 frame 独立，而两个页面的主表可能拿到同一个编号，因此指向不在前面那个页面的 scope 可能被接受却什么也匹配不到，而不是被拒。

### 这条线不做什么

| 规则 | 它防的失败 | 什么时候重议 |
|---|---|---|
| 不做页面适配器：读取器里不出现任何组件库的名字 | 部署升级自己的依赖时读取器就不工作了 | 永不 |
| 两个工具都不碰 frame 里的登录态 | 工具伪造登录，以及 [`auth-gate`](../../../../packages/experimental/auth-gate/README.zh.md) 的活渗进来 | 永不 |
| 读取只答在前面的那一项，不接受地址 | 在用户背后读，以及把 frame 导航到任意地方 | 永不 |
| 读取绝不盲截：超预算给骨架，或者给游标 | 模型拿着半份列表，够不到剩下的部分 | 永不 |
| 模型对内容区的认知只来自感知层，别无他处 | 模型「以为」自己知道内容区里有什么 | 永不 |
| 不是浏览器：不开标签页、不读别的会话、不读对话栏 | 长成第二个浏览器扩展 | 永不 |
| 页面里不跑任意脚本 | 审批预览写不成人话 | 读与动合起来够不到关键数据 |
| 不做「保留最近一份列表」的机制 | 第二个压缩机制 | 永不 |
| 没有可见的控制台就不执行，也不排队等一个 | 动作在没人看着的时候发生 | 永不 |
| 一次调用只被认领一次，认领过的调用绝不重放 | 「删除」被点两次 | 永不 |
| 密码的值永不离开页面，看不见的内容不读 | 凭据进日志，以及模型点空气 | 永不 |
| 补偿模型的引导连同它自己的退役条款一起交付 | 强模型还在为一份写给更弱模型的引导付上下文 | 永不 |
| 不做截图、不做 hover、不做两次读取之间的 diff | 多一个渲染依赖和一个 diff 引擎要维护 | 某个页面证明读不出来，或者菜单只在 hover 时出现 |
| page 是唯一落地的 kind | 为一个实例造注册表 | 第二个真 kind 落地 |

## Alternatives considered

**读的这半边和动的那半边作为一刀交付。** 一次设计、一次评审、一轮测试。不予采纳，因为动作用读取器发出的 ref 指认目标，而面对真实组件库的标记，读取器答出的是一个用户看得见而模型叫不出名字的列、一张被当成「页面画了两遍」而丢掉的表、以及一张任何东西都分不清其字段的表单。每一个都是一次作用在错误元素上的动作。读取器给错一个 ref 就是一次作用在错误元素上的动作，所以它在被允许点击任何东西之前，先对着真机控制台量过。

**用截图而不是结构化列表作答。** 用户看见的就是一张图，而且视觉模型读得懂图。不予采纳，因为图里没有地址：列表存在的全部意义是模型能在后续调用里指名一个元素，这正是读大页面并对它动手成为可能的前提。截图仍然是一条天花板而不是被否掉的想法——它的触发器是某个页面的关键信息读取器给不出来。

**先写引导，再去测量。** 设计稿里的失败文案与系统提示词，每一句都像是该告诉模型的话。第一次探针就否掉了它：模型十次里十次自发地读了页面，因此告诉它去读的引导，会是为一个并不存在的弱点永久花掉的上下文。上下文块是靠实测省掉模型本来会发的一次调用赢得位置的，不是靠多加一条指令。

**允许读取指名任意条目或任意地址。** 一个指名条目或 URL 的参数，会让工具在控制台关着时也有用，也让 agent 能在不惊动任何人的情况下巡查页面。不予采纳，因为读取的定义就是「用户正在看的东西」：读用户看不见的东西会让答案对他不可验证，而地址参数会把这一栏变成 agent 驾驶的浏览器。换读别的要花一次 `content_show`，那是用户看得见的。

**现在就造 kind 注册表。** 合同已经写好；在它之上加一个注册表是一小步，还能让第二个 kind 白得。不予采纳，因为一个实现看不出词汇里哪些部分是通用的。定下来的是词汇，那才是第二个 kind 真正需要的，而注册表等到有第二个 kind 可供归纳时再抽。

## Consequences

agent 能用用户自己的说法讲出屏幕上是什么，并回答关于它的问题。它碰不了：动的那一层不在这次交付里（见 [Deferred](#deferred)）。

常驻成本是每一次请求上的一个提示词上下文块——只要该会话有活着的内容区——由两个部署设置界定，再加每次读取一份由第三个设置界定的列表。不写 `pageAccess` 块的部署，读取这半边一分不付：没有工具、没有路由、没有读取器。

分页表格的计数是这条线在真机控制台上唯一答错的东西，而且读取器越好它越糟：一张看起来完整的表，就是模型不再往下找的表。还要为它做什么，见 [Deferred](#deferred)。

部署要改的每一样东西都是经过校验的字段，因此用户同时开一打条目的控制台、或者重绘很慢的应用，是配置出来的而不是打补丁打出来的。代价是上表里的每一个字段都要设对，每一个都会在加载时拒掉它没法工作的值。

这条线的会话词汇不是桌面构建的，而且没有一个是可忽略的，所以两者不能共用一个 harness home：这个控制台跑在自己的那一个上。

## Deferred

**对页面动手。** `content_act` 不在这次交付里；它正在单独一条线上实现，下面这份合同是它据以实现的依据，而不是一份定稿的接口——实现会把它定下来，随它一起交付的那篇 Note 拥有结果。对在前面的那一项执行一批步骤，每步是 `click`、`fill`、`select`、`press`、`wait` 之一。每一步都带 `label`、照抄列表里的名字，因为审批面板除了这次调用自己的参数什么也渲染不了，而浏览器在执行该步之前拿元素的名字与它核对。整批一次审批，没有组合审批服务时直接拒绝。首个失败即停，步骤执行期间页面自己做了什么随结果一起回来。不新增事件类型：调用、结果、审批都已经有各自的。`actTimeoutMs`、`maxSteps`、`settleMaxMs` 随这一刀进入 `pageAccess`，所以上面那张表是这次交付的字段，不是最终的全集。

**分页表格的计数。** 承载表格总数的分页条，配对给画在它最近处的那张表，而两者之间的任何另一张表都会打断这次配对——固定列的副本正是这样一张表。因此在真机控制台上，模型十次里有九次答的是本页的行数而不是总数。改法是让分页条跨越同一张表的各片来配对，而暴露出它的正是 P0 的第三轮。

**v2，每项各带启动它的触发器。** 在页面上点选一个元素、把一枚芯片递给 agent；按页面所用框架来读数据，以及在没有 DOM 可读的地方按 canvas 库自己的 API 来读；在反向代理侧捕获这个部署自己的网络流量，它同时给静止等待一个「页面还在取数据」的信号；文件上传与下载的一份留存；滚动到某一行出现、拖拽、编辑富文本字段；以及让文件能递到 agent 手里。

**v3，沉淀。** 对象签名、声明自己接受哪些签名的能力、先分析再动手的编排步骤，以及「上次这类输入用了什么」的记忆。它的前置是 v2 的网络捕获，和一个探针结果：模型会不会在没人要求的情况下提出并保存一项能力。

**kind 注册表**，等第二个真 kind 落地。

## Testing

P0 是这条线的固定回归探针，不是一次性测量：同一个真机控制台页面、同一个问题、十个全新草稿会话，按首个调用、多余的 `content_show` 次数、读取次数与答案打分。任何改动读取器或上下文的构建都重跑它，而计数回归正是它抓到的——没有任何单测能抓到。

为这条线录制无密钥 fixture 的做法是：一个会话一个脚本，调用按首次出现顺序绑定，并在收割之前用 `session/end-seed` 边界裁掉种子历史（[`apps/web/tests/scaffold.ts`](../../../../apps/web/tests/scaffold.ts) 里的 `afterSeed`），这样 fixture 回放的是这一轮，而不是这个场景被种下的历史。录制需要一把 API key，回放不需要。

单测与浏览器覆盖属于各个切片，也记在各自那里：按四个组件库的画法写成的夹具上的读取规则、通道那两条路由及其拒绝、以及感知层的事件、上下文与导航监视，各自都带一个跑在真实组合上的 Playwright 场景。
