# Agent Note: 页面读取器按结构读格子和条目里画的图标

Status: implemented

[English](2026-10-05-content-reader-structural-icons.md) | 中文

## Problem

[通用工具 note](../simplification/2026-09-03-content-reader-general-tools-only.zh.md) 退役了「从 class 词元里读出 `icon` 这个词」的图标规则，于是 `packages/experimental/content-frame/src/client/access/` 里的读取器，对一个没有 role、没有名字、没有文字、也没有指针光标的元素什么都不打。控制台的操作列正是这样画行内命令的：2026-10-05 实测，一张列表的编辑、警告、删除三个命令就是三个这样的 `<i>`，于是每一行的命令格都读成空的。模型没有 ref 去对它们动手，而一个靠复制这套遍历来称呼用户所指之物的工具，给三者得到的是同一条键行。

## Decision

在表格格子或重复条目里，画成图标样子的元素就是一个控件，role 是 `icon`。`dom.ts` 里的 `isIconShape` 就是全部判定，它看结构和渲染结果：元素没有 role，里面不装元素（`svg` 是一幅画，所以它装的东西既不算子元素也不算文字），去掉空白后不装文字，`rowMark` 不为空，并且画出了图形（见下）。清单把它打成 `e3 icon {class: el-icon-edit operation-modify}`，给它自己的 ref；`content_act` 经过与其他每一个页面没命名的行相同的标记核对、相同的审批请求去点它。

### 在哪里算

表格格子在 `cellControlRole` 里问这个判定；遍历则通过 `marksIcon` 在 `heldByItem` 找到元素外面有重复条目的地方问它：不论 role 的 `<tr>`，role 为 `listitem`、`row`、`treeitem`、`option` 的元素，以及 `feed` 里的 `article`（`isRepeatedItem`）。这个查找穿过 shadow root 和同源 frame，一直到这次读取起步的那份文档，因此限定在一个条目里面的读取仍然找得到范围外面的那个条目。别处什么都不变：工具栏里的图标不打行，除非页面把它做成可点的；步骤要核对的那一个名字 `itemName` 也不给它名字，所以经原文读取找到它的步骤传空的 label。`itemName` 为同一个查找接收这次读取起步的那份文档，只算一个元素的调用方必须把它传进来。

这个判定在问光标之前跑，所以指针光标下的图标是 `icon` 而不是 `clickable`，同一列不会为同一种命令打出两种行。三个例外让它不挡在页面已经说过的东西前面：为某个控件命名的 `label` 里装的东西、已命名树节点的标签区里装的东西，都是那个名字的一部分；格子里装着控件的画交出那个控件；装着字段的元素里的无名图标印在字段那一行上作为 `[eN opens]`。

整页读取不为这样的 `label` 或标签区里的图标打行，也不为它打成一行、不往里读的元素里的图标打行——有名字的单行树节点、选项、格子里的按钮。以这些元素里面的某个元素、或以图标自身为范围的读取从那里起步，会打出这个图标。`itemName` 给重复条目里的图标起的名字，就是页面写在它上面的名字，即 `namedAs(el, ICON_ROLE)`；图标自己的那一行和表格格子里的控件都用这同一套算法起名，所以每个为这个图标打行的读取打出的都是这个名字。以图标自身为范围的读取，不论图标在条目里的什么位置，都为它打一行，所以这样的图标没有一个缺少为它打行的读取；经原文读取找到这个图标的步骤，带的也是这个名字。

### 画出了图形

叶子元素是 `svg` 或 `img`，或者它的 `::before`、`::after` 生成了字形或图片，或者它自己的 `background-image`、`mask-image`、`-webkit-mask-image` 有一个不是 `none`，就算画出了图形。生成内容只在算出来的 `content` 含私用区字符（U+E000–U+F8FF、U+F0000–U+FFFFD、U+100000–U+10FFFD），或者在字符串之外含 `url()`、`image-set()`（包括 `-webkit-image-set()`）、线性/径向/锥形渐变（含 `repeating-` 形式）时才算。Chromium 把私用区字符答成字符本身；值先按 CSS 转义规则解码再查找，所以样式表里写的转义（`"\e78c"`）同样算，而转义的反斜杠后面跟着的十六进制数字是文字。这覆盖了组件库画图标的三种办法：字体图标映射到私用区、写进伪元素的字形，画成背景或经遮罩画出的图片，以及一幅画。生成进伪元素的文字什么都没画：页面写进空值 `::before` 的 `--`、用普通字符写的 `✓` 或 `✗`，以及 `attr()`、计数器、引号解析出来的东西。组件库画成 `<div class="cell"></div>` 的空值、树形表格放在一行文字前面的缩进和占位 span、只涂了颜色的叶子元素，这几样一样都没画。先读元素自己的属性，再读它的两个伪元素；引擎算不出某个属性时答空串，空串算什么都没画。

算出来的样式经读取的 `computedStyle` 注入拿到，和 `isClickable` 并排设默认值，默认用元素所在窗口的 `getComputedStyle`，于是算不出伪元素样式的测试环境把它注入进来，这套遍历的副本也注入同一个读取函数。遍历先找元素外面的重复条目，再问元素的样式，所以格子和条目以外的叶子元素从不被问。判定仍把「没有 role」放在最前：HTML 给每个 `img` 一个 role——`img`，`alt` 为空时是 `presentation`——它按那个 role 读，所以 `img` 只在页面写了一个 ARIA 没有定义的 role 时才走到这个判定，那时它因为是 `img` 而算画出了图形。

### 精灵图的标记

`rowMark` 就是 `elementMark`，只有一处不同：第一个 `use` 指向某个符号的 `svg`，用它的 class 词元、后面跟上这个符号 id 作标记，中间隔一个空格——id 是这个 `use` 的 `href` 里 `#` 之后的部分，没有 `href` 时取 `xlink:href`，前面写着什么路径或域名都不管。class 里已经有同一个完整词元时不再重复加，所以不带 class 的 `svg` 只用这个 id 作标记。精灵图标集用同一个 class 画每一个命令，只在引用里写它是哪个命令：`<svg class="svg-icon"><use href="#icon-edit">` 的标记是 `svg-icon icon-edit`，它旁边指向 `#icon-delete` 的那个是 `svg-icon icon-delete`。清单打印 `rowMark`；原文读取仍打印 `elementMark`，因为一行原文说的是 `class` 属性里写着什么。步骤的 `mark` 等于两者之一，座位就认，所以从树形行抄来的步骤和从清单抄来的一样点得到这幅画，别的标记一律当成「页面变了」拒绝。

### 为什么这不是把退役的规则请回来

退役的规则从词元里读出 `icon` 这个词，再用它后面的部分给这一行命名，那是读取器在解读厂商的拼法。这一条不为任何词元说了什么去读它：有没有 class 是一个条件，和光标是不是指针一样；叶子元素画没画出图形从它算出来的样式里读，和它看不看得见一样；词元整串、原样地作为标记打出来。通用工具 note 划的那条红线仍然成立；它永久拒绝的那一类规则——由页面原文而不是规范挣来的规则——也不是这一条：这些条件在每一个页面上都一样。

## Alternatives considered

**让格子保持为空，把模型打发去原文读取。** 每个这样画命令的页面都要多读一次；而遍历是指点工具称呼元素的依据：遍历不为它打行的元素，不论模型怎么找到它，都分不清它和它的邻居。

**匹配一张图标 class 前缀表**（`el-icon-`、`anticon`、`bi-`）。通用工具 note 以「这是本包维护不了的组件库目录」否决了它，这一点没有任何变化。

**让光标决定**：指针下打 `clickable`，没有指针打 `icon`。指针随状态变——被禁用的命令、被选中的页签——于是同一个命令在两条记录上会打出两种行，从一条记录抄下来的键行对不上另一条。

**只接受行内元素**（`i`、`span`、`svg`），这样能把组件库为空值画的空 `<div class="cell">` 排除在外。没有采用：一张标签表和一张 class 表是同一类猜测，而树形表格的缩进同样是一个 `span`。看叶子元素画没画出图形，两者都排除在外。

**只看结构**，不要「画出了图形」这个条件。空值格和树形表格的缩进、占位都是图标的结构，于是一个格子打图标还是什么都不打取决于那条记录，指点工具从这套遍历抄下来的键行也跟着变。产品侧 2026-10-05 第一轮复核锚点时发现了这一点；看渲染结果，才能不靠 class 表就分清字形和空的包装元素。

**不从精灵图引用里取标记。** 精灵图标集只在 `use href` 里写自己的身份，于是不带 class 的精灵图标就没有标记，也就不是图标。符号 id 是页面自己的词，原样打出、不加解读，与 class 一样。

**带 class 的精灵图只用它的 class 作标记。** 精灵图集画的每一个命令都带同一个 class，于是同一格里的编辑和删除图标会打出同一个标记，步骤分不清它们。

**生成内容只要不是 `none`、`normal`、`""` 就算。** 页面用 `.cell:empty::before { content: "--" }` 给空值画占位时，那个空值格会打成图标，于是一列打图标还是什么都不打取决于那条记录。规则的第三轮复核在 2026-10-06 发现了这一点。字体图标把字形映射到私用区，占位是普通文字，所以私用区能把两者分开；代价是页面用普通符号画的图标读不到。

**在所有地方读图标，而不只在格子和条目里。** 页头上每一个画来装饰的字形都会打出一行，花掉这次读取本来要守住的预算；格子和条目才是页面画「对一条记录动手的命令」的地方。

## Consequences

操作列读出来就是它的命令：三个图标打出三行、带三个标记，样本行写 `[icon icon icon]`，骨架把它们算在按钮里，一个步骤可以凭 ref 和标记点名其中每一个。

这条规则看渲染结果，所以只涂了颜色的叶子元素不是图标：组件库画成 `<div class="cell">` 的空值在每条记录上都读成什么都不是，`tests/snapshot.client.spec.ts` 里的 ini-web2 夹具在勾选框列上就是这样；树形表格的缩进 span、占位 span，以及画成色块、既没有字形也没有图片的命令，也一样。有三种图标读不到：页面把字形写进叶子元素外面那个元素的伪元素里的，那个元素装着元素，而叶子元素什么都没画；读取运行时样式表还没生效的；以及用 `✓`、`✗` 这类普通 Unicode 字符画在伪元素里的，它和空值的 `--` 占位一样是文字。页面按记录换 class 的状态图标，每一行带的标记都不同。`title` 不命名图标，正如它不命名可点目标；标了 `aria-hidden="true"` 的精灵 `svg` 与其他被藏起来的子树一样被藏起来。

以重复条目里某个图标自身为范围的读取，不论图标在条目里的什么位置，都打出它那一行和页面写在它上面的名字，而这正是 `itemName` 给的名字，所以从这次读取、或从任何一个打出这个图标的读取里抄来这个名字的步骤都会被接受。页面给这个图标起了名字时，带着 `label: ""` 和它的 class 词元的步骤（从原文树里抄来的步骤就是这样）会被拒，拒绝里写着这个图标在这里的名字。

这套遍历的每一份副本都得跟着改，算出来的样式的注入也在内，因为副本要像读取器一样称呼元素。
