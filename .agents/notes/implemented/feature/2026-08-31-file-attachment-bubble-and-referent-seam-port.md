# Agent Note: porting the file-part bubble card and the referent/open seam onto the 0.1.2 reorganization

Status: implemented

English | [中文](2026-08-31-file-attachment-bubble-and-referent-seam-port.zh.md)

## Problem

The original patch (`fabc93555c`, "file-part bubble card and the referent/open seam") added a ROOT-scope cordis waterfall event, `referent/open`, that every "open this reference" user gesture in the browser conversation UI runs through before falling back to its own default action; wired the existing `openFile` chokepoint through it; and rendered a message's `{kind: 'file'}` content part as an inline, lazily-expanding `FileCard` in both the user bubble and the Assistant markdown stream, backed by a new `ISession.readFile`/`loadFile` pair mirroring the image gallery's `readAttachment`/`loadImage`. It predates the same three upstream changes the composer-intake port (`98020a23cd`, ported as `a21f837b51`) predates: the package reorganization that split `ui-conversation`'s `chat/` subtree into a new `ui-chat` package, the `dsh.client` cross-package runtime-import gate, and the optimistic submission-echo system. It also depends on `98020a23cd`'s own `ComposerFileAttachment`/`attachment-labels.ts` surface, so it could not be ported before that patch landed.

## Decision

**`referent.ts` moves to `packages/api/session-controller/src/client/`, not `packages/client/runtime/src/client/`.** The original patch's target package, `client/runtime`, does not exist in the reorganized tree; the reorganization folded its Client-facing Session/Sessions contract and adapter into `packages/api/session-controller`. `dispatchReferentOpen`, `ReferentRef`, and `ReferentKindMap` land there unchanged in substance (only import paths and the module doc's package name change), re-exported from that package's `client` barrel the same way the original re-exported from `runtime`'s. `ISession.readFile()` and its implementation join the existing `readAttachment()` pair in `contract/session.ts`/`sessions/session.ts` in the same package, for the same reason.

**`FileCard.tsx`, its render call sites, and the `openReferent`/`loadFile` slot wiring move to `ui-chat`, not `ui-conversation`.** `MessageItem.tsx`, `AssistantMarkdown.tsx`, `AssistantNodeView.tsx`, `ChatNodeSeat.tsx`, and `ChatView.tsx` — every file the original patch touched for rendering — already relocated to `ui-chat` before this port began, carrying their own `chat` locale namespace (`ui-chat/src/client/locale.ts`) distinct from `ui-conversation`'s `conversation` namespace. `OpenReferent`, `loadFile`, and the file-open locale keys (`file.open`/`file.loading`/`file.loadFailed`) join `ChatNodeOwnerProps`/`ChatViewInjected` and `ui-chat`'s own locale file, not `ui-conversation`'s — a key lives in the namespace its only consumer reads. `attachment-labels.ts`'s `SUBAGENT_FILE_UNSUPPORTED` case and its `file.subagentUnsupported` key stay in `ui-conversation`, since `attachmentErrorText` (the function that reads it) still lives there, unmoved by the reorganization.

**Importing a session-controller runtime value into `ui-chat` and `ui-conversation` is unrestricted by `verify-client-packages`.** Both are dynamic (`dsh.client`-bearing) client packages; `packages/api/session-controller` is not under `packages/client/*`, so `scripts/verify-client-packages.ts`'s `CLIENT_MANIFEST_GLOB` (`packages/client/*/package.json`) never enumerates it as a row subject to the dynamic-package `external` restriction. `dispatchReferentOpen`/`ReferentRef`/`readFile` cross that boundary as ordinary runtime imports, verified empirically by running `pnpm run verify-client-packages` clean after wiring them in.

**A durable file block renders as an interactive `FileCard`; a submission echo's in-flight file renders as a non-interactive chip.** The original patch predates `PendingSubmission`/`PendingSubmissionRetirement` entirely — it had no submission-echo bubble to extend, only the durable-event-backed message bubble it targeted. The current tree's `PendingSubmissionBubble` (added by the composer-intake port's own echo-system work) needed a symmetric extension: a `PendingSubmissionFile` in flight carries only `{name, bytes}`, no durable `attachmentId`, so it cannot resolve through `loadFile` or dispatch `referent/open` the way a `FileCard` does. `UserStyleBubble` gained a `previewFiles` prop, rendered as a plain `name`+`attachmentSizeText(bytes)` row (`MessageItem.module.css`'s `.filePreview*` classes), reserving `FileCard` for content blocks that already carry a real `attachmentId`.

**The client-side subagent pre-transport rejection check is not ported.** The original patch added a `SUBAGENT_FILE_UNSUPPORTED` check inside `Session.prompt()` itself, paired with the pre-existing `SUBAGENT_IMAGE_UNSUPPORTED` check at the same call site. Family A's own work on this sync (`121338b26f`, prompt-RPC file content admission) already added a server-side, symmetric equivalent: `admitPromptContent()` in `packages/subagent/subagent/src/control.ts` rejects both `SUBAGENT_IMAGE_UNSUPPORTED` and `SUBAGENT_FILE_UNSUPPORTED` for a subagent that cannot continue, with existing coverage in `packages/subagent/subagent/tests/control.spec.ts`. A `packages/client/runtime/tests/session.client.spec.ts` test from the original patch's own base tree carries a comment confirming this is deliberate design, not an oversight this port should correct: "The image reaches the wire unfiltered: refusing it is the Host's call." Re-adding a client-side duplicate would reject on the client before the Host's own admission logic ever runs, diverging from the already-shipped, already-tested design. This is a deviation from the original patch, not a mechanical placement decision — it is recorded here and in the ledger rather than silently ported or silently dropped.

## Alternatives considered

**Port the client-side `SUBAGENT_FILE_UNSUPPORTED` check anyway, on the reasoning that duplicated validation is defense in depth.** Rejected: `packages/subagent/subagent/tests/control.spec.ts`'s existing coverage and the session-controller test's own comment establish that letting an unfiltered image or file reach the wire and rejecting it at the Host is the intended design for this sync's architecture, not an accidental gap. Adding a second, client-side rejection point would create two sources of truth for the same policy and risk them drifting out of sync silently, which the "misconfiguration fails loud" and "explicit > implicit" conventions argue against.

**Keep `file.open`/`file.loading`/`file.loadFailed` in `ui-conversation`'s locale file and have `ui-chat` import them.** Rejected for the same reason `98020a23cd`'s note gives for `attachmentSizeText`: `ui-chat` is itself a dynamic client package, and importing another dynamic package's locale values as runtime constants across that boundary is the same class of import `verify-client-packages` exists to police for code, even though these specific keys happen not to trip the gate today (locale objects are plain data, not gated the same way). Keeping the keys with their sole consumer avoids depending on that gate's current scope remaining unchanged, and matches the general principle that a key lives in the namespace of the package that reads it.

## Consequences

`packages/client/ui-chat/tests/file-card.client.spec.tsx` is a new file, ported near-verbatim from the original `ui-conversation/tests/file-card.client.spec.tsx`, following `FileCard.tsx`'s own relocation. `packages/client/ui-chat/tests/image-labels.client.spec.tsx`, `chat-branch-tails.client.spec.tsx`, `gate-branch-tails.client.spec.tsx`, `coverage-tails.client.spec.tsx`, and `reasoning-row.client.spec.tsx` needed `loadFile`/`openReferent` stubs threaded into every `<AssistantMarkdown>` call, mechanically following the widened props. `packages/client/ui-workflow-run/tests/workflow-run.client.spec.tsx` and `packages/test-support/client-runtime/tests/runtime.client.spec.tsx` needed the same mechanical addition for `ISession.readFile`'s new fail-loud stub. `packages/extensions/cordis-client-runner/src/client/api-catalog.ts` and `slot-catalog.ts` (generated) picked up `referent/open` and the widened `ChatNodeOwnerProps`/`ChatViewInjected` shapes via `pnpm run gen-cordis-inspect-catalog` and `pnpm run gen-client-catalog`. `scripts/gen-cordis-catalog.ts` gained a `referent/open` entry in `EVENT_WALK_EXEMPTIONS`, since the event's contract is documented at `packages/api/session-controller/README.md` rather than at a per-event JSDoc site the generator can walk to directly. `packages/client/ui-trajectory/src/client/layout.ts` and `TrajectoryView.tsx` gained the same mechanical `case 'file':` arm the original patch's target files needed for the trajectory projection of a file content block, tracking the pre-existing `case 'image':` arm each already had.

`packages/api/session-controller/README.md`/`README.zh.md` gained a new paragraph documenting `dispatchReferentOpen`/`ReferentRef`, mirroring the original patch's addition to `packages/client/runtime/README.md`/`README.zh.md` at that package's later location. `packages/client/ui-conversation/README.md`/`ui-chat/README.md` do not carry the original patch's "chat view keeps Tool placement..." paragraph update or its new `FileCard` paragraph: neither README currently discusses `openFile`/tool-call dispatch or `FileCard` implementation detail at all in the reorganized tree — that content was already trimmed during the upstream reorganization, the same pattern `98020a23cd`'s port found for `ui-attachment/README.md`'s equivalent section.

**Retirement.** Unchanged from the original: `referent/open` is a fork-only interception seam for a capability upstream's own conversation UI does not yet expose. If upstream's own session UI natively renders file content blocks and exposes an equivalent open/reference interception point, this patch (and this port) retires and the fork adapts to upstream's form.
