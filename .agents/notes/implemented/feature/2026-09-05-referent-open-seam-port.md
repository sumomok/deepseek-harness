# Agent Note: the referent/open interception seam for reference clicks

Status: implemented

English | [中文](2026-09-05-referent-open-seam-port.zh.md)

## Problem

Every "open this reference" affordance in the browser conversation UI runs its own open action: the `openFile` closure that `packages/client/ui-chat/src/client/apply.ts` hands the chat view (tool rows, produced-file chips, mentions) resolves a workspace path through `ctx.remote.session.openWorkspacePath`, and the chat-prose `referents.open(span)` path a few lines above resolves a model-authored prose span the same way, plus `window.open` for a URL. A feature that wants to take one of those clicks over — a plugin that opens a path in its own viewer rather than the Host desktop — has to reach into each dispatch site individually and grow a bespoke intercept point there, and every affordance added later silently misses it.

Upstream has no interception point for reference clicks: `referent/open`, `dispatchReferentOpen`, `ReferentRef`, and `ReferentKindMap` each have zero occurrences at `upstream/master`. The seam is fork-only, and so is every listener: no package in this repository registers `referent/open` outside its own tests, so the listeners it exists for are out-of-repo plugins compiled against the published `session-controller` client face.

## Decision

**One ROOT-scope cordis waterfall event, `referent/open`, is the single interception point every reference click runs through.** It is declared in `packages/api/session-controller/src/client/referent.ts` and exported from that package's `client` barrel. A dispatch site runs the waterfall before falling back to its own pre-existing open action, so a listener anywhere in the tree intercepts a click without the affordance knowing a listener exists, and a new affordance becomes interceptable by dispatching rather than by growing a seam of its own. Both current dispatch sites are in `ui-chat`'s `apply.ts` — the `openFile` chokepoint (`source: 'chat-view.openFile'`, `provenance: 'structured'`) and the [chat-prose referents seam](2026-09-01-chat-prose-referents-seam-port.md)'s span opener (`source: 'chat-prose'`, `provenance: 'model-text'`) — and `ui-chat` declares `'referent'` in its `apply.ts` `inject` list.

**`ReferentKindMap` is merge-extensible through declaration merging, seeded with `file`, `dir`, and `url`.** A package that opens a new kind of target declaration-merges a key into the map rather than widening `referent.ts`, mirroring `ContentBlockMap`'s vocabulary growth. A listener therefore switches on `kind` with a documented `default` arm and never `assertNever`: the union grows across package boundaries, so a listener compiled against a narrower `ReferentKindMap` than the running build's receives a kind it cannot name, and delegating that click through `next()` is the correct answer.

**`ReferentRef` carries identity only, never content.** Its fields are `kind`, the resolved `target` (an absolute path for `file`/`dir`, a URL string for `url`), the `raw` text as it appeared at the reference's source, an optional `sessionId`, a free-form `source` naming the dispatch site, and `provenance` (`'structured' | 'model-text' | 'tool-output' | 'user-text'`). A listener that needs the referenced bytes reads them itself from the target, the same way the default open action does. Most listeners decline most clicks, so a payload that carried content would pay a read per click for a value nearly always discarded.

**A listener claims a click by returning without calling `next()`; every failure path still resolves to some open action.** Calling `next()` delegates to the next-registered listener and finally to the dispatch site's own default, the waterfall's terminus. A listener that throws, or whose returned promise rejects, is caught, logged to `console.error`, and treated as a fall-through, because the click came from a user and must resolve predictably regardless of a third-party listener's state. `dispatchReferentOpen` memoizes the default action's promise, so a listener that throws *after* delegating neither re-runs the default nor masks its real failure: once the default has run, its own outcome — success or the genuine error the pre-existing open action raises — is the call's outcome, and the caller sees exactly what it saw before the seam wrapped that action. Only a listener that fails before ever delegating reaches the recovery path that runs the default for the first time.

**Dispatch happens only from a direct user-gesture handler, never from a programmatic or background path.** This is the seam's security invariant, not a style rule: a claiming listener is trusted to perform a user-authorized action, so an automatic delivery path that dispatched a `ReferentRef` would let a script trigger that action silently, with no click behind it.

**`ctx.referent` is how a `packages/client/*` feature package reaches the dispatch; the free function stays the entry point everywhere else.** `ClientReferent extends Service` mounts `open(ref, onDefault)` as a one-line forward to `dispatchReferentOpen(this.ctx, ref, onDefault)`, and `packages/api/session-controller/src/client/index.ts` constructs it in `apply`. Cordis rebinds a `Service` subclass's `this.ctx` to whichever context a caller reaches the service through — the mechanism `ctx.conversation` and `ctx.workspaces` already rely on — so `ctx.referent.open(...)` dispatches on the calling plugin's own context, matching a direct call to the free function exactly. `dispatchReferentOpen` itself is unchanged and still exported: a consumer outside `packages/client/*`, an out-of-repo plugin with no `dsh.client` manifest row included, calls it directly.

**Client bundle purity, not `verify-client-packages`, is the gate that decides this, and the fork's earlier `core-patches-v6` record of the seam concluded otherwise.** That record held that a client-side value import of `session-controller`'s runtime export is unrestricted, on the reasoning that `scripts/verify-client-packages.ts` enumerates only `packages/client/*/package.json` and so never treats `packages/api/session-controller` as a subject. The reasoning describes that script correctly and the conclusion is still wrong, because a second gate enforces the same design intent independently: `packages/client/tsdown.client.ts`'s `dsh-client-bundle-purity` plugin throws from `resolveId` for any `@deepseek-ai/` value import that is neither a platform module, nor a specifier in the importing package's own `dsh.client.external`, nor an inline-safe wire or generated `/remote` layer. `PRELOADED_CLIENT_EXTERNALS` is empty and `ui-chat` requests no externals, so a bare `dispatchReferentOpen` import in `ui-chat` is a build error — a genuine cross-plugin runtime call, not an erased type — while `verify-client-packages.ts` passes it clean and only a real tsdown build of `ui-chat/client` reports it.

## Alternatives considered

**Grow a bespoke intercept point at each affordance instead of one shared event.** Rejected: it multiplies claim, delegation, and failure-recovery rules by the number of dispatch sites, forces a listener that cares about every reference click to register once per site, and makes each affordance added later a silent gap until someone remembers to wire it.

**Declare `@deepseek-ai/dsh-api-session-controller/client` in `ui-chat`'s `dsh.client.external` and keep the bare function import.** Rejected: `verify-client-packages.ts` rejects any manifest under `packages/client/` that requests a runtime external supplied by another dynamic row, and its message names the two permitted routes ("import shared types only or call an injected Cordis service"). `packages/api/session-controller/package.json` and `packages/api/workspace-controller/package.json` do declare `external`, but neither manifest path starts with `packages/client/`, so neither reaches that check; no `packages/client/*` row declares an external at another row at all.

**Close `ReferentKind` and end every listener switch with `assertNever`.** Rejected: the vocabulary grows by declaration merging across package boundaries, including from out-of-repo plugins, so an exhaustive switch converts every added kind into a throw inside a click handler on builds that predate it. A documented `default` that delegates keeps an unknown kind a no-op for that listener and lets the click reach the default action.

**Let `ReferentRef` carry the referenced content alongside its identity.** Rejected: it would make every dispatch pay a read whose result the great majority of listeners discard, and it would put a durable read path inside a seam whose only job is routing a click.

**Let `ctx.waterfall`'s error propagate instead of memoizing the default action's promise.** Rejected: a listener that throws during its own cleanup after a successful `next()` would then either re-run the default — a second opener invocation for one click — or replace the default's genuine failure with the listener's error, hiding the failure the caller needs to classify.

## Consequences

`packages/api/session-controller/tests/referent.client.spec.ts` pins the seam: the no-listener default, a claiming listener suppressing it, delegation through `next()`, outermost-first registration order and `prepend`, removal of a listener through its `ctx.effect` disposer, the synchronous-throw and rejection fall-backs with their log, the no-re-run guarantee for a listener that throws after delegating, and an unrecognized `kind` delegating instead of throwing. Its `ClientReferent` block covers registration as `ctx.referent`, parity with the free function for both the default and the claim path, dispatch on the caller's context rather than the construction context, and unregistration when the owning fiber unloads. `packages/client/ui-chat/tests/apply-inject.client.spec.tsx` pins the dispatch sites: the exact `ReferentRef` each produces, the workspace root arriving as `kind: 'dir'` while every other path is `kind: 'file'`, and the unclaimed fall-throughs to `openWorkspacePath`, to `window.open`, and to the composer's not-found notice.

`packages/test-support/client-runtime`'s `SlotTestRuntime` mounts the production `ClientReferent`, not a double: it is a stateless dispatch wrapper, so every bench gets authentic `referent/open` waterfall behavior without a stub to keep in step.

`packages/api/session-controller/README.md` and its Chinese counterpart own the API prose. `scripts/gen-cordis-catalog.ts` names both `referent` (in `SERVICE_WALK_EXEMPTIONS`) and `referent/open` (in `EVENT_WALK_EXEMPTIONS`) with that README as the documentation owner, so neither renders into the generated catalogs: the service is client-face and the host-face projection never sees the browser Context, and the event's contract lives in the README rather than at a per-event site the rendering projection can walk to.

The seam carries no file-attachment surface, and its absence is a decision rather than an omission: upstream's generic file upload (PR #2984) owns file attachments on this base, so the fork's own file family — `FileCard.tsx` and `FileCard.module.css`, the `{kind: 'file'}` inline message-part rendering in the user bubble and the Assistant markdown stream, `loadFile`, `ISession.readFile`, the session event projection's file branch, `attachment-labels.ts` and its file copy, and the `OpenReferent` slot prop whose only consumer was the file card — is not part of this line. A maintainer looking for a file bubble card or a client-side file read to hang a listener on will not find one.

`ReferentRef` has no `attachment` field. The file bubble card was that field's only producer, so it carries nothing on this base; a listener that wants a durable attachment reference resolves it from `target` and `sessionId`.

`referent/open` retires when upstream lands its own interception point for reference clicks, at which point the fork adapts its dispatch sites to upstream's form and deletes this seam rather than running two. The check is a `git grep` for `referent/open`, `dispatchReferentOpen`, `ReferentRef`, and `ReferentKindMap` at `upstream/master`; all four are currently zero.
