# Agent Note: porting the secret-container confirmation onto the 0.1.2 reorganization

Status: implemented

English | [中文](2026-09-01-secret-container-confirmation-port.zh.md)

## Problem

Two original patches land this capability in sequence: `ebd4e9c1f4` ("confirm before sending a file that lives in a known secret container") adds a pure name/path heuristic (`matchSecretContainerFiles`), an immediate chip warning state, and a two-button send-time confirmation gate wrapping both composer submit entry points; `7e37c74cdf` (a same-series fix) realigns the chip visually with the image rail, upgrades `attachmentSizeText` from megabytes-only to a B/KB/MB scale, and strengthens the easy-to-miss dot+outline warning with a readable inline label plus a below-row notice. Both predate the upstream 0.1.2 package reorganization and depend on `98020a23cd`'s composer draft-file surface (ported as `a21f837b51`) and `fabc93555c`'s referent/open seam (ported as `0b32bd30ad`), which this port already has in place. A third patch, `16daeaa345`, then moves the confirmation from send time to add time — a product decision that overrides the first patch's timing — and is the shipped (rc.25) form of the capability. This port squashes the first two into one commit and lands the third as its own follow-up: `7e37c74cdf` never shipped independently upstream of `ebd4e9c1f4` in a state worth reproducing separately, and both the squash and the follow-up are recorded in the ledger.

## Decision

**The host-side config field and projection move from the retired `packages/host/apiproxy` onto `SessionController.Config`.** `packages/host/apiproxy` does not exist in the reorganized tree; the reorganization already moved its `imageLimits`/`fileLimits` boot-constant session projections to `packages/api/session-controller/src/list.ts`, registered inside `ApiSessionList`'s constructor. `secretContainerExtraPatterns` follows the same path: a new `Config.secretContainerExtraPatterns?: readonly string[]` field (validated `z.array(z.string()).default([])`) flows from `SessionController`'s constructor into a new `ApiSessionList` constructor parameter, which registers the `secretContainerExtraPatterns` projection directly — unlike `imageLimits`/`fileLimits`, it names no other seam's capability (it is the deployment's own Config value, not an attachment-service query), so it needs no companion `ctx.inject(['attachments'], ...)` wrapper and is always present once a projection registry is composed at all, exactly like the original's own comment on this point.

**`Config`'s zod schema needs an `as z<Config>` cast, not a bare `z<Config>` annotation.** `secretContainerExtraPatterns` is `readonly string[]` on the TypeScript interface (matching every other array-typed field in this codebase's `Config` interfaces) but zod's inferred array type is mutable; under this repository's `exactOptionalPropertyTypes: true`, a direct `static Config: z<Config> = z.object({...})` annotation fails compilation with a variance error. `packages/preset/agent-presets/src/index.ts`'s own `AgentPresets.Config` carries the identical readonly-array-vs-schema mismatch and resolves it with `}) as z<Config>` instead of an assigned-type annotation; this port uses the same established cast rather than inventing a new pattern.

**The client-side heuristic module (`secret-container.ts`) ports unchanged into `ui-conversation`, not `ui-primitives`.** Unlike `attachmentSizeText`/`partitionDroppedFiles` (moved to `ui-primitives` during the `98020a23cd` port because `ui-attachment`, a separate dynamic client package, needed to import them as runtime values), `matchSecretContainerFiles`/`secretContainerCandidate` are consumed only inside `ui-conversation`'s own `InputBar.tsx` — no other package imports them as runtime values. `ui-attachment`'s `FileChip`/`ComposerAttachments` never see the heuristic itself, only the already-computed `secretContainerHitIds: ReadonlySet<DraftAttachmentId>` passed down through `ComposerAttachmentsOwnerProps`, so no `dsh.client.external`/cross-dynamic-package concern applies and the original patch's package placement carries over exactly.

**`attachmentSizeText`'s B/KB/MB fix lands in `packages/client/ui-primitives/src/byte-size.ts`, not `ui-conversation/attachment-labels.ts`.** The original `7e37c74cdf` patch edited `attachment-labels.ts` because that file was `attachmentSizeText`'s home in the patch's own base tree; the `98020a23cd` port already relocated the function to `ui-primitives` for the cross-package-import reason above, so this fix's target follows the function to its current location. Every consumer of the function (the composer chip, the message-bubble `FileCard`, and the image/file rejection banners) shares the one implementation, so the fix reaches all of them without a second edit site.

**The confirmation fires from `intakeFiles`; neither submit entry point carries a gate.** Per `16daeaa345`, the whole add batch — matched and non-matched files alike — attaches first, and the dialog then offers to undo the matched subset: "仍要添加" is a plain close, "不添加" calls `removeImage` per matched id. The matched ids are not known synchronously, because this tree's `addFiles` (`apply.ts`) discards `createDraftFiles`' return value and reports only a rejection string, so `intakeFiles` stashes the raw `File` references and a `useEffect` watching `fileAttachments` resolves them to `DraftAttachmentId`s on the next render. The Lexical keymap this reorganized tree registers in a `useEffect` keyed only on `[editor, keyboard]` therefore carries nothing of this: `gate.current` keeps its pre-existing `intakeDrop` and the `submit:` case calls `keyboard.submit(...)` directly, as does the primary Send button's `onPrimary`.

**`Modal`'s `closeLabel` is a required prop on this tree's version, unlike the original patch's `<Modal open ... />` call with no `closeLabel`.** The current `packages/client/ui-primitives/src/Modal.tsx` discriminates on `headless`: non-headless (the default, and what this confirmation dialog needs — a titled dialog with a description and a footer) requires `closeLabel: string`. Every other non-headless `Modal` call site in this codebase's client packages supplies `closeLabel={t('close')}`, resolving through the common locale namespace (`@deepseek-ai/dsh-client-locale`) merged into every package's translator rather than a package-local key — `ui-conversation`'s own `PermissionSelect.tsx` already does exactly this with no local `close` key declared. This port's `Modal` call follows the same convention instead of adding a redundant `secretConfirm.close` key.

## Alternatives considered

**Keep `ebd4e9c1f4` and `7e37c74cdf` as two separate commits, honoring "one original patch, one commit" literally.** Rejected for this pair specifically: `7e37c74cdf`'s own diff is inseparable from `ebd4e9c1f4`'s in the target tree — it edits the exact chip markup and CSS `ebd4e9c1f4` introduces, and its own commit message frames it as the same feature's field-test refinement, not an independent capability. Porting them as two commits would require an intermediate commit shipping the original patch's genuinely-unreadable warning state (confirmed unreadable by the original's own commit message, citing rc.25 field testing) as a deliberate, briefly-shipped regression. The squash is recorded in the ledger with both original SHAs named.

**Register `secretContainerExtraPatterns`'s projection inside the existing `ctx.inject(['attachments'], ...)` block alongside `imageLimits`/`fileLimits`, for proximity.** Rejected: doing so would make the projection's presence conditional on an attachment service being composed, when the field is actually always available (it is the deployment's own `SessionController.Config`, present whenever `ApiSessionList` itself is constructed) — the original patch's own host-side design explicitly calls out needing no companion dependency, and nesting it inside the attachment-gated block would silently narrow that availability.

## Consequences

`packages/api/session-controller/tests/test-remote.ts`'s `TestSessionRemoteDefaults` gained `secretContainerExtraPatterns?: readonly string[]`, threaded into the `SessionController` constructor call the same way `coldBlankProbeMaxBytes`/`nativeOpen` already are. `packages/api/session-controller/tests/session-projections.host.spec.ts` gained the original's two host-side projection tests (constant-unit publication with no attachment service required, and the empty default), adapted to call `createSessionTestRemote` directly with `secretContainerExtraPatterns` in its defaults rather than the original's `createApiProxy`. `packages/client/ui-conversation/tests/input-bar.client.spec.tsx` gained a `secretContainerExtraPatterns` `BenchOptions` field and `useProjection` mock arm, plus the originals' `describe('secret-container add-time confirmation', ...)` and `describe('secret-container: no send-time re-prompt', ...)` blocks. The add-time block drives real intake through `onAddFiles` against a fake machine that actually attaches; its draft ids come from a per-block counter rather than the original's `crypto.randomUUID`, which this tree's `no-restricted-properties` lint rule bans outside `@deepseek-ai/dsh-util-crypto`. On the branch that also carries the `apps/web` suite, `apps/web/tests/secret-container-confirmation.e2e.ts` needed two idioms this reorganized tree established after the scenario was written: the page opens `scaffold.authenticatedUrl` (a plain `baseUrl` now serves the sign-on gate's "authentication required" page), and the composer is located as `[data-composer-input][contenteditable="true"]` — the Lexical surface carries its placeholder copy on `data-placeholder`, so no `textarea[placeholder]` query reaches it. Its golden replays unchanged: it was recorded against the add-time flow. `packages/client/ui-attachment/tests/composer-attachments.client.spec.tsx` and `packages/client/ui-conversation/tests/attachment-labels.client.spec.tsx` needed their pre-existing megabyte-format assertions (`5MB`, `1MB`, etc.) updated to the new `5 MB`/`1 MB` spacing, and `packages/client/ui-primitives/tests/byte-size.client.spec.ts` gained the full B/KB/MB matrix. `docs/config-catalog.md`/`.zh.md` and `packages/api/session-controller/README.md`/`.zh.md` gained the new Config field's entry (regenerated via `pnpm run gen-config-catalog` for the English catalog; the Chinese catalog's code-fence content stays English verbatim per this doc's own established convention, with only the surrounding prose in Chinese — there is none needed here since the fenced block is the whole addition). `packages/extensions/cordis-client-runner/src/client/slot-catalog.ts` picked up the widened `ComposerAttachmentsOwnerProps` shape and shifted several unrelated `source:` line-number references via `pnpm run gen-client-catalog` (mechanical, from the new field's position in `slots.ts`).

**Retirement.** Unchanged from the original: this is a fork-only product safeguard for a capability upstream does not have. If upstream's own composer gains an equivalent add-time content-sensitivity confirmation, this patch (and this port) retires and the fork adapts to upstream's form.
