# Agent Note: 有界历史补丁身份登记保留既有提交历史

Status: implemented

[English](2026-11-13-bounded-historical-patch-identities.md) | 中文

## 问题

第一父链上的三个既有提交缺少[补丁身份规则](2026-09-17-core-patch-identity-trailers.zh.md)要求的 `Patch:` trailer。它们分别实现账号资料重试、生成配置目录收敛和账号平台共享资料读取。补丁归属已明确，但追加后续提交不能修改它们的消息；重写则会替换后代提交身份，与[仅合并的补丁线](2026-09-24-merge-based-core-patch-line.zh.md)冲突。

## 决定

[历史身份清单](../../../../.claude/core-patches-history.json)为这些精确提交补充缺失的 slug。版本 1 格式允许一至三项及一个固定的集成前截止点。每项包含完整小写提交 SHA、精确标题、已登记的补丁 slug 和非空理由。未知字段、重复键或提交条目、缩写标识和错误值均导致解析失败。清单由显式维护产生，检查器不自动追加条目或推进截止点。

在声明的补丁线上，截止点必须是真实提交且位于 HEAD 的第一父链上。每项必须指向截止点第一父链上严格早于截止点的非合并提交；实际标题必须匹配，slug 必须已登记且可处于任意状态，Git 必须报告完全没有 `Patch:` trailer。已有的空值、错误、重复或冲突 trailer 都不能由清单覆盖。补丁代码退役不抹去其历史身份。

只有通过校验的条目才能为当前第一父链比较中缺少 trailer 的提交提供身份。其他历史提交和未来提交仍需普通 trailer。之后的基准可能把某项排除在当前比较范围之外，只要截止点及其历史关系仍成立，该项仍有效。路径认领与精确合并父检查保持独立且不变。

没有历史补登记的检出可以不含清单；缺少普通 trailer 时照常失败。其他读取错误或清单格式错误在按分支跳过之前就导致失败。仓库引用检查使用同一个解析器，只对清单中 `cutoff` 与 `entries[].commit` 的 JSON 字符串 token 按语法位置放行。理由、标题、其他文件或无效清单中的哈希仍受检查。

本决定局部补充 trailer 要求。既有身份和合并线记录继续有效，仍拥有 slug 身份、普通 trailer、合并准入与路径认领规则。

## 备选方案

**重写三个提交及其后代。** 这可以在原提交消息中插入 trailer，但会替换既有历史并需要协调下游分支。清单保留提交身份，并显式记录缺失的归属。

**忽略某个日期或祖先之前的全部提交。** 范围例外会隐藏其他缺失或错误的身份。截止点只限制资格，只有逐项列出的完整提交 ID 才获得补登记。

**让整个清单文件跳过引用检查。** 这也会允许解释字段中出现任意历史哈希。按解析后的 token 位置放行，可以让所有不参与 Git 校验的字段继续遵守引用规则。

## 后果

补丁检查器可以接受三处已有明确归属的遗漏，同时继续拒绝其他缺少 trailer 的提交。这是一份有界维护记录，不是普通提交 trailer 的替代方式。扩大清单或移动截止点属于需要显式审查的政策变更，正常开发不使用它登记新工作。

测试通过真实临时 Git 历史覆盖有效补登记及错误截止点、祖先关系、父数、标题、slug 和 trailer；解析器与引用测试覆盖重复键、错误格式及操作字段之外的相同哈希文本。清单不改变后续未发布上游合并的显式基准规则。
