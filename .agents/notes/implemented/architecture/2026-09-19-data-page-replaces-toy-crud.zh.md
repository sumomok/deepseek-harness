# Agent Note: 数据页取代只读块，而它的排布由视图文件定下

Status: implemented

[English](2026-09-19-data-page-replaces-toy-crud.md) | 中文

## Problem

控制台为一张表画的那个块是 `toy.crud`，它在构造上就是只读的，而且是两重只读：摆放包会把一份冻结的、专门压掉写入的属性记录盖在调用写下的任何东西之上，被 vendor 进来的那份构建又把六个写入对话框编译成了空桩。这答复了第一版提的那个问题——能不能让这套部署自己的页面出现在一个人面前，而宿主全程不在请求路径上——却对一个人真正在里面干活的那张页面什么也没答。这个页面来自的那个控制台，画这张表时工具栏上有 新增，每一行有一个修改按钮，有一张把表格挤窄的侧边卡片，还有整页的新增与修改面板。这些在这里一个也画不出来，也没有任何属性能要来：因为宿主对每一个写入属性的答复就是把它覆盖掉。

还有两件事错在形状上，而不是错在设置上。

八个声明属性是一组。「哪张表、怎么筛、怎么排」和「画哪些区域、留哪些按钮」由同一条规则判定，并作为同一份清单交给模型——于是一个摆页面的模型被塞了一个它根本没法判断好的排布选择；而为「一个人在里面干活的那张页面」加的第一个属性，本来也会变成调用又能多要的一样东西。

而这个块在内容列里是按自己的高度坐着的。这个页面是一块查询面板压着一张表格压着一个翻页器，尺寸写的是 `height: 100%`；一个不分担列高的格子，会让那个 `100%` 去对着「里面恰好装了什么就多高」的盒子求值，列的其余部分空在下面。

## Decision

**`toy.crud` 退役，而 `toy.data-page` 不是它的一个版本。** 组件 id、渲染器、摆放包里那个模块、它的两个 `Config` 字段、三个词典键、快照道次与 web 场景在同一次改动里全部改名，并且没有留下任何还应答旧名字的东西：没有别名，没有兼容路径，目录里也没有第二个条目。被 vendor 的 tarball 从 `@sumomok/toy-crud-kit` 0.2.3 走到 0.4.1，它的 `DataPage` 导出是 `Crud.vue` 自己的子组件按 `Crud.vue` 自己的摆法拼起来的，而不是对它们的重写。一份点名 `toy.crud` 的规格留在会话日志里时，会走内容列本来就有的那条路降级——那是任何一个别的构建写下的规格都会走的同一条路——这也正是这次退役不需要格式版本、不需要迁移的原因。

**按钮存不存在是排布数据；按下去成不成是后端的答复。** 摆放包不持有「这个用户可以有哪些按钮」的名单，不做「这位访客能干什么」的检查，也没有任何一句会因此分叉的文案。视图文件说页面有哪些区域、留哪些按钮；`readOnly: false` 说这个页面到底能不能被写；从那儿往后，每一次新增、每一次编辑、每一次操作，都是这个页面用访客自己的凭据发出的请求，由这套部署自己的后端答复。宿主不做关于权限的第二种意见，因为第二种意见就是可以跟那个算数的意见不一致的意见。

**一条声明决定了模型／视图这条分界的两边。** `PropsField` 多了 `viewOnly`——一句话，而不是一个开关。带着它的属性会被从模型读到的描述里滤掉，而同一句话就是一个写了这个属性的调用被拒时拿到的理由——于是模型既不会被提供这个属性，也不会在硬写了之后被用另一套说法告知。这条拒绝点名路径（`spec.nodes[0].props.regions`），讲清楚它由谁定、页面因此会是什么样，不点名任何别的工具、也不给绕路的办法。视图走同一道判定，只是 `written` 为真，因为视图文件里的排布就是写下那个文件的人的排布。

**那两份清单属于被 vendor 的页面，宿主这边的副本被钉在它们身上。** 页面导出 `DATA_PAGE_MODEL_SETTABLE_PROPS` 与 `DATA_PAGE_LAYOUT_PROPS`，各七个名字。摆放包 import 不了浏览器包，于是它自己声明 `DATA_PAGE_MODEL_PROP_NAMES` 与 `DATA_PAGE_VIEW_PROP_NAMES`——同样那七个，加上 `metaLabel`（用户在审批卡上读到的名字，停在这个包里），再加上 `readOnly`（它和排布在同一个文件里定下）——而两边都 import 得到的 `component-kit` 断言这份相等。页面长出来、宿主没跟上的属性，会是一条失败的测试，而不是一张默默无视视图写下内容的页面。

**九个手势离开这张页面，每一个都是计数与名字。** 只读块报的那三个在种类上没变，其中两个变宽了：`load` 现在点名这张表、头二十个画出来的列，以及这套部署为这位访客答复的 rights；`query` 与 `cell-click` 带的还是它们本来带的。新增六个：`select` 报勾了多少行，并按 `toy.table` 点名选择的那种方式点名它们；`card-open` 与 `card-close` 报侧边卡片是在哪一行上打开的、以及它关了；`added` 与 `modified` 报一条记录存下了、以及存下那一行画出来的各格——最多八个，读法跟点到的那一行用的是同一批列，永远不是用户填的那张表单；`operation` 报按下的是哪个加进来的行操作、按在哪一行。九个全部按 `context` 分级，走目录本来就声明着的内容组件动作路径，所以没有新的会话事件类型，`SESSION_FORMAT_VERSION` 停在原地。`load` 的 rights 表封顶十六个键、每个二十四字符，因为整份文档要和二十个最宽的列一起去量动作载荷上限——这一点是被一条测试量出来的，不是估出来的。

**页面填满列，是因为三个格子给了它确定的高度。** 席位的滚动视口是一个 flex 列，最外层那一叠取 `flex: 1 0 auto`，渲染器自己那一节是一个 flex 列、它的盒子取 `flex: 1` 并带 `32rem` 下限。视图再在装着这个块的格子上写 `flex: 1`，页面的 `height: 100%` 就对着整列求值。这里没有任何东西在测量：高度从头到尾都是 CSS，这正是它能在一列被调宽调窄、被拆分、被滚动之后依然成立的原因。

**示例是排布数据。** `examples/space-data-page` 把这套部署自己的控制台为它那张图层表画的页面复刻了出来——查询面板收成一行、新增 挨着查询按钮、每行一个修改按钮、侧边卡片、新增与修改整页面板——全部写在 `views/space-layer.yml` 里，带 `readOnly: false`，表名与它的名字用 `{"$param": …}`，而 `SKILL.md` 的正文仍然是占位符，因为正文是技能包作者要写的。示例里没有代码，摆放包里也没有任何东西知道这张表存在。

## The decision gate

| Gate | Answer |
|---|---|
| 0. 哪条既定原则已经决定了它？ | **预发布姿态：地基优先于影响面** 直接决定了这次退役——块被改名、被重新封装，所有引用一并更新，而磁盘上的旧规格由那条本来就在拒绝「这个目录没写过的规格」的路拒掉，而不是靠一层垫片续命。**包边界上显式优于隐式** 决定了模型／视图这条分界是一句声明出来的 `viewOnly`，由描述与拒绝共同读取，而不是一个 `??`、或者一份写两遍的过滤。**在做出决定的那次操作里执行它** 决定了这条分界在判定调用的那道 pass 里执行，而不是在描述它的提示词里。**插件里不写死可调项** 让报告上限留作两边一起编译的协议常量，而基础路径与加载期限仍然是 `Config` 字段。**模型可见 ⟺ 已记录** 决定了六个新手势复用命令注册表本来就逐字记录的那条动作路径，于是 agent 能看到的关于这张页面的一切都是可重建的。**客户端 UI 文案归 locale 所有** 决定了这个块能画的三行都是词典键。 |
| 1. 新增了多少条永久表面？（先数，再列） | **加 17，撤 4。** 加：一个目录组件 id（`toy.data-page`）；九个此前不存在的声明属性（模型侧的 `customOperations`；视图侧的 `regions`、`toolbarButtons`、`rowOperations`、`queryExpanded`、`pageSize`、`pageSizes`、`infoCardTabs` 与 `readOnly`）；既有内容组件动作路径上的六个动作 id（`select`、`card-open`、`card-close`、`added`、`modified`、`operation`）；一个目录声明字段（`PropsField.viewOnly`）。撤：`toy.crud` 这个 id 及其渲染器、`isExpandQuery` 属性（并进视图侧的 `queryExpanded`）、宿主对被 vendor 页面那份冻结只读记录的覆盖，以及 0.2.3 那份 tarball。属于改名而不是新增的：两个 `Config` 字段（`crud` → `dataPage`、`crudLoadTimeoutMs` → `dataPageLoadTimeoutMs`）、三个词典键、一条快照道次、一个 web 场景。**零**新增会话事件类型、路由、服务、工具、npm 依赖与审批闸——摆放时那张卡片就是本来那张，只是换了准确的名字。 |
| 2. 能证明它对的最小版本 | 一个带 `readOnly: false` 与那八个排布属性的视图文件，点一下打开，在真实浏览器里：页面填满整列，查询面板是一行，工具栏上有 新增，每一行带一个修改按钮，点一行会打开侧边卡片而表格让出位置，新增 打开整页面板，element-ui 的浮层开在这个块自己的盒子里——而摆放包不持有任何按钮名单，也不做任何权限检查。其余一切都是这个主张在「页面可写」之后要付的代价：`viewOnly` 声明，因为不能把那套排布交给模型；六个新手势，因为一个人真正在里面干活的页面会做一些必须告诉 agent 的事；三个 flex 格子，因为填不满列的页面不是那张页面。 |
| 3. 缝，还是写死？ | **写死，而且是故意的。** 那两份属性清单是被 vendor 页面自己的导出，宿主的副本被断言与它们相等，所以只有一个来源，也没有第三方需要为之抽象。九个手势 id、它们的上限、卡片与通知的中文措辞，以及「调用可以点名一张表但不可以排布它」这条规则，都在目录条目与它旁边那道判定里写了一次。这样的页面只有一张，要它的部署只有一套；第二套规则需要第二套部署才配得上。**复查触发器是内容列里出现第二个客户的页面**，那一天模型／视图这条分界就得用一个组件声明之外的东西来表达。**不加新配置字段：** 这个页面到底能不能摆，仍然是工具本来就在读的那一个字段。 |
| 4. 边界 | 见下。 |

### 边界

| 方向 | 这条线 | 它挡住的那次失败 | 期限 |
|---|---|---|---|
| 邻居 | `component-kit` 画这张页面并读它；`component-surface` 判定调用并提出那个问题。两边都不点名任何一张表，两边都不知道「权限」是什么。 | 摆放包长出这张页面权限模型的一份副本，然后跟真正答复的那个后端不一致。 | 永久 |
| 契约 | 排布属性由同一道 pass 在调用上拒、在视图上收，读的是同一条 `viewOnly` 声明，而这条声明同时把它们挡在模型的描述之外。 | schema 里提供、调用时又拒掉；或者用提供时从未用过的说法去拒。 | 永久 |
| 诱惑 | 不做按钮白名单，不做「这位访客能不能按 新增」的检查，没有任何文案因 `readOnly` 分叉，也没有任何做决定的东西去读 `load` 报上来的 rights 表。 | 宿主用第二种声音，去回答一个唯一正解只在「用户自己的凭据发出的那次请求」上的问题。 | 永久 |
| 红线 | 模型自己通往这张页面的路保留它的审批卡，一次调用不能摆两张页面，不能与 `dataSource` 并排摆，也不能排布它打开的那张页面——所以调用摆出来的页面以只读打开，用的是页面自己的排布。 | 模型打开一张可写的页面，按它自己挑的排布，卡片上写的却是一次读。 | 永久 |
| 天花板 | 离开这张页面的是九份有界读数，而其中每一份带行的，带的都只是这一行画出来的那些列：人碰到的那一行、操作按在的那一行，以及他们存下的那一行至多八个画出来的格。用户填的那张表单不会离开浏览器，一页行、方案藏起来的属性、这一行的主键，也都不会。 | 把「agent 知道有一条记录被存下了」读成「agent 手里有那条记录」——以及它更窄的那一种：保存接口答复的东西，因为恰好就是那条记录，就被原样报了上去。 | 永久 |
| 假设 | 这套部署的后端在每一次请求上、按访客逐个地决定每一次写入，所以 `readOnly: false` 是一种排布，而不是一次授权。 | 一套部署把视图文件当成授权写入的那样东西，发出一张「按钮就是全部检查」的页面。 | 暂缓 — 复查触发器：某套部署的后端答复写入时不看是谁在问，或者这个页面对着一个控制台并不同源的后端打开。 |

## Testing

单元用例把整道判定与整份读数都钉住了。摆放侧：模型／视图分界的两个方向——写了那八个排布属性中任意一个的调用被按路径拒掉、用的是目录自己那句话，写全八个的视图被接受，而视图用例走的那张 `WRITTEN_PROPS` 表被断言等于 `DATA_PAGE_VIEW_PROP_NAMES`，于是只加一边的属性会失败而不是悄悄没被测到；模型读到的那份描述，里面有模型属性、没有任何排布属性；页面仍然会挣到的那些拒绝（未交出、第二张页面、两个排序方向、与 `dataSource` 并排）；审批卡的措辞、条件只数不展示、标识符独占一行；以及 `PendingLoads` 的单发结算、按会话、按条目 id。画图侧：九个手势每一个，包括没有东西可报的那几种；让重画不至于把同一句话说两遍的一次性记忆；哪些属性到得了页面、哪些到不了；等基础路径就位才挂载；以及 Vue 正在销毁页面时盒子仍然是盒子。`component-kit` 断言宿主那两份清单等于被 vendor 页面的两份导出。

一次真实 Loader 组合把这一行连同视图注册表与内容面路由器一起启起来，用一次点击打开视图，并断言内容列收到的规格带着文件写下的那份排布。快照道次 `snapshots/console/show-data-page-turn` 承载模型看到的整个回合——工具 schema 里的提供、卡片、允许、记录与结果行——而 `apps/web/tests/component-surface-data-page.e2e.ts` 拿构建产物对着一个桩后端跑。

每一个改动过的 `src` 文件逐文件覆盖率 100%：`component-kit`、`component-surface`、`skill-pack` 与 `skill-pack-components` 上 57 个文件、1062 条测试。

## Alternatives considered

**留着 `toy.crud`，把可写页面摆在它旁边。** 否决。一张被 vendor 的页面挂两个目录 id，意味着两个渲染器、模型每一份描述里两个条目、快照树里两条道次，外加一条「视图该用哪一个」的规则——换来的只是某一个预发布构建的日志还能继续画出来。预发布姿态已经把这件事定了：旧规格走那条本来就为「这个目录没写过的规格」准备好的路降级。

**把 `toy.crud` 别名到 `toy.data-page`。** 按这个别名必须意味着什么来否决。一份 `toy.crud` 规格带着 `isExpandQuery`、不带任何排布，所以这个别名不是改名，而是一次有自己规则、要测试要维护的翻译，服务的只是预发布日志里才有的文档。

**让宿主决定一位访客可以有哪些按钮。** 否决，而且这正是整次改动立足的那条边界。宿主要这么干，就得从页面恰好报上来的一份 `rights` 表里去学这套部署的权限模型；它于是成了对一个后端每次请求都在回答的问题的第二个答案；两者第一次不一致的那天，用户看到的要么是宿主画出来、后端拒绝的按钮，要么是本该能按却不见了的按钮。按钮存不存在是排布；按下去成不成是后端的事。

**把那八个排布属性做成 `Config` 白名单，让部署挑调用可以写哪几个。** 否决。这是一个没有任何部署在要的可调项，而且它给出的选择谁也做不好：一个在这套部署上能写 `regions`、在那套上不能的模型，必须被告知是哪一套，而描述对两者是同一段文字。

**把 load 的 rights 表当成「你能按的按钮」报给模型。** 按实测否决。对被 vendor 的 bundle 做的一次 jsdom 探针显示，一张只读页面照样答复 `search`、`exp` 与 `searchSetting`，于是这句话恰恰会在它重要的那种情形下是假的。这份读数带的是这套部署自己的答复，用这套部署自己的词：它为这位访客答复的 rights。

**把保存接口答复的那条记录原样报上去。** 否决，而且这是唯一一份先那样造了、又被改回来的读数。端点答复的是那条记录，也就是这一行的主键，加上方案持有的每一个属性——包括它对表格藏起来的那些——于是把答复报上去，等于把屏幕上谁也看不见的东西摆到 agent 面前。其余每一份带行的读数本来就走页面自己 `load` 记下的那些画出来的列；保存这一份也走它们，按它自己八个的上限。答复里一个画出来的格都没有的保存仍然会被报出来，record 为空，因为「有一条记录被存下了」正是 agent 需要的那件事。

**用列上的 resize observer 给这个块一个量出来的高度。** 否决。三条 flex 声明在 CSS 里就做成了，能扛过调宽调窄、拆分与滚动，路径上不需要任何 JavaScript，也不可能晚一帧才对。`32rem` 下限挡住的是一列短到不值得画进去时，页面塌在自己身上。

**把示例的排布写进组件的默认值。** 否决：默认值是被 vendor 页面的默认值，而调用摆出来的页面必须以它们打开。需要另一套默认值的示例，正是视图文件存在的理由——这也正是这个示例要立的那个主张。

## Consequences

**买到的。** 控制台能按这套部署自己的控制台的画法，把它自己的页面画出来：可写，由一个人写下的文件排布，而摆放包既不持有关于这张表的任何东西，也不持有关于权限的任何东西。视图把那份排布当数据发出去，于是下一张表是又一个 `.yml`，而不是又一个渲染器。模型那条路在「能做什么」上没变，在「能要什么」上更窄了：它点名一张表和怎么筛它，而它打开的页面是只读的、带着页面自己的排布。

**付出的。** 九个手势 id 与它们的上限，此前是三个——每一个都是目录要声明、席位要构造、并由一条测试对着动作载荷上限去量的东西。一份从 0.2.3 长到 0.4.1 的被 vendor tarball，对客户源码的补丁从五条变成十条，其中三条是拼起来的页面机械上就需要的修复。一条住在单一声明里的模型／视图分界，等到第二个组件需要它的那天就得重新表达。还有视图文件里那个读起来像权限、其实不是权限的 `readOnly: false`——它作为一条假设记在这里和包 README 里，复查触发器是一个不做检查的后端。

当初把这张页面挂上来的那个决定——凭据从不离开浏览器、宿主从不在请求路径上、摆放时那张卡片、容纳，以及第一次请求之前就定好的基础路径——没有改变，并由 [`@deepseek-ai/dsh-experimental-component-kit`](../../../../packages/experimental/component-kit/README.zh.md) 与 [`@deepseek-ai/dsh-experimental-component-surface`](../../../../packages/experimental/component-surface/README.zh.md) 以现在时陈述。它当初的理据，以及它击败的那些备选，在已归档的[这套部署自己的数据页，用访客的凭据在面板里打开](../../archived/feature/2026-09-10-toy-crud-kind.md)。
