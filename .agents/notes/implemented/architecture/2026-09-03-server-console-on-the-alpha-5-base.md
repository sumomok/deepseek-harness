# Agent Note: The product-console line on the 0.1.2-alpha.5 base — composition over accommodation

Status: implemented

English | [中文](2026-09-03-server-console-on-the-alpha-5-base.zh.md)

## Problem

The `product/server-console` line is nine `packages/experimental/*` packages that replace the shipped shell, sidebar, and content column with a customer-facing console, plus eight browser scenarios that pin it. It was pinned to a 0.1.1-era base. Moving it to 0.1.2-alpha.4 crossed a package retirement (`dsh-client-runtime` split into five owners), a service relocation that put Workspace navigation behind a plugin the line deliberately removed, several Session API renames, and a browser-harness change. On that base the line did not compile; once compiling, it did not boot; once booting, none of its eight scenarios passed. The step from alpha.4 to alpha.5 was a different size — four merge conflicts and two repairs — but it failed in the same place: what a stored session log is allowed to contain got stricter, and this line's own seeded fixtures were written against the older rule. The question each repair had to answer, at either size, was whether to accommodate the base in our packages, patch the base, or change what the composition loads.

## Decision

Every repair lands in the composition or in this line's own packages. Two upstream files carry a change, both registered in `.claude/core-patches.md` with a retirement condition, and one of them fixes an upstream defect rather than accommodating one.

**Where the client vocabulary went.** `@deepseek-ai/dsh-client-runtime` retired into five owners; eight symbols moved across 29 import sites. `ClientContext` is now `Context` from `@deepseek-ai/cordis`; `SessionId` comes from `dsh-session/types`; `defineStore` and `EngineStoreHandle` from `dsh-client-store`; `SessionProjectionMap` from `dsh-session-projection/types`; `SlotRegistry` from `dsh-client-ui-renderer/client`; `SessionListState` from `dsh-api-session-controller/client`; `ToolCallBlock` from `dsh-client-ui-chat/client`. Each package's `dsh.client.inject` names the service owners that package actually reaches instead of the retired aggregate. `settingsNamespace()` is gone and the namespace key is unchanged, so `'server-sidebar' as SettingsNamespace` is a pure string substitution and no stored settings migrate. `Session.events` is now `snapshotEvents()`, `SessionEvent.seq` is branded, and the chat surface moved from a Session snapshot field to `dsh-client-ui-chat`'s own session-standard hook.

**`gen-tsconfig-paths` cannot generate an alias for a package whose npm name differs from its directory**, which is every package on this line (`dsh-experimental-<dir>` under `<dir>/`). Following what upstream already does for its own inspector and Agent Teams packages, the aliases are hand-written above the generated block. The per-package change the migration needed was each package's `references` list, re-derived from what its `src` actually imports — not a Host/Client config split. `docs/development.md` reserves that split for `api/remotes` alone and states that having both a Node loader entry and a browser entry is not a reason to take it.

**A strict session-scope slot must be wrapped in the standard-kit `SessionProvider`.** `ShellFrame`'s details column renders one, and without it the renderer raises `SlotAssemblyError` and no column mounts at all — the whole shell renders nothing, not just that column.

## `ui-workspace` is composed, and one CSS rule carries the vocabulary

alpha.4 moved `dsh-client-ui-conversation`'s client inject from the `workspaces` Controller to `ui-workspace`'s `uiWorkspace` service. Three overlays on this line disabled `ui-workspace` outright to keep Workspace vocabulary off a customer page; under alpha.4 that leaves the conversation column and five sibling rows unactivated. All three overlays now compose it.

The vocabulary it was disabled for is already covered without the disable. Its `sidebar.workspaces` registration goes through `ctx.slots.inject`, which is declaration-gated, and this shell declares no such slot, so that half stays inert. Its `conversation.hero.workspace` registration does land, in a row `terminology-guard.ts` hides. That rule stops being belt-and-suspenders and becomes the only thing keeping a real Workspace title and a working picker menu off the page, so its scenario asserts the element is present **and** invisible: every rule in that stylesheet is a class-substring match against a CSS-module local name, so the way one fails is the element ceasing to match it, and an invisibility assertion alone passes just as happily on an element that is not there.

The composer's access chip named a Workspace through a different route: the shipped `permission` preset table, displayed by the chip, the `/permission` popup, and the Settings default row. No dictionary reaches it — the label belongs to `dsh-client-ui-conversation`'s own locale namespace, and the locale registry throws on a second registration for a namespace/locale pair it already holds, so no plugin can shadow another's key. Both client surfaces render a host-supplied preset name verbatim whenever it differs from the built-in default, so the overlays restate the preset table with customer-facing names and the word leaves every surface at once. `PresetSpec.name` is one string rather than a locale map, so this gives every locale the same name.

One leak has no seam: with no Workspace connected, `ConversationRoot` renders its inert composer under `placeholder.workspace`. It is not chrome to hide — the composer is genuinely unusable in that state and the placeholder is the only thing saying so — and the deployment answer is that a console with no Workspace is already a no-op, so a service-line deployment always has one. A scenario pins the leak to that single placeholder so a second one cannot appear unnoticed.

## What is restated from upstream, and what must not be

`recentWorkspace` — which Workspace a new session lands in — is a module-private function in `ui-workspace/src/client/navigation.ts` with no seat on the `UiWorkspace` interface, and `startSession`, the only public verb that uses it, is fire-and-forget and returns no session id. `session-resolution.ts` restates it, and that restatement is a maintenance coupling with no compiler or clone-detector behind it: a divergence silently changes which Workspace a click lands in. Its unit tests pin every branch.

Connecting that Workspace is delegated, not restated. `UiWorkspaceService.connectWorkspace` holds a per-Workspace in-flight promise map; a restatement of its blank-session-reuse logic loses it, and losing it is not cosmetic — the mount-time auto-open and a workbench click then mint two sessions milliseconds apart, because the second caller re-reads a Workspace snapshot that does not yet list the first caller's new session. The rule this line follows: restate a decision upstream does not expose, never a coordination mechanism.

## What the alpha.5 step cost

Two repairs, both in this line's own files. alpha.5's session reader validates every replayed `tool/result`: `data.message` must carry an `id`, `role: "user"`, a `source.kind`, and a `content` array. The line's two chart scenarios still spliced the older flat payload, with `callId`, `content`, and `isError` directly under `data`, so each seeded log was refused as corrupt at open time. The failure surfaced two layers away — the transcript rendered nothing, and the shared `expandTurnProcesses` helper timed out waiting for a disclosure control that never existed — which is why the seeded log's own rejection message is the thing to read first, not the helper it broke. A seeded fixture is a hand-written session log, so every tightening of the reader is a migration for it. The other repair is a version bump: `check-workspace-constraints` requires each workspace package.json version to equal the root's, and the nine packages this line owns were the only ones left on `0.1.2-alpha.4`.

The merge itself conflicted in four files, down from twenty-two: two package-table READMEs hand-merged to the union of both sides' rows, their pairing record re-recorded, and one generated client catalog regenerated rather than edited. The `.gitattributes` pairing merge driver declined to recompute a hash while its owner files were still conflicted, which is the fail-closed behavior its own comment states.

## Upstream gaps this migration found

Three, each re-checked on alpha.5. `packages/attachment/attachment-spill` carried version `0.1.2-alpha.2` against a root of `0.1.2-alpha.4` (`pnpm run constraints`) and shipped an empty invariant companion the repository's own rule rejects (`pnpm run verify-package-invariants`); both are fixed upstream on alpha.5 — the package now matches the root version, and its `src/invariant.ts` is gone. `packages/experimental/client-ui-agent-team/src/css-modules.d.ts` is still not named in `tsconfig.client.json`'s include, so the Client aggregate never loads it; upstream's own `scripts/client-tsconfig.spec.ts` checks two package groups and cannot see it, and widening that spec to the experimental group is what exposed it. That third one is fixed here because the widened gate is this line's own, and leaving it red would have meant exempting the upstream package from the check.

## Alternatives considered

- **Keep `ui-workspace` disabled and stub `uiWorkspace`** — a stub must track a seven-method upstream interface whose semantics the conversation column depends on, and every upstream addition to it becomes a silent gap rather than a compile error.
- **Hide the composer's access chip with the de-terminology stylesheet** — the chip is a permission control, so hiding it takes away a choice (which files the agent may write) rather than renaming one. Renaming the preset table changes the words while leaving the control.
- **A locale language pack for the vendor's labels** — the registry does accept a new locale id for an existing namespace, so a derived locale with a fallback would shadow individual keys. It also adds a second Chinese entry to the Language settings row and requires overriding the user's own language preference to take effect.
- **A compiler face of the Vue probes' own**, so Vue 2.7's global `JSX` augmentation never reaches the Client aggregate — the durable fix for the one upstream test this line had to touch, but `docs/development.md` registers each package in exactly one of two aggregates, so a third face is an architecture decision rather than a migration repair.
- **Per-package Host/Client config splits for the dual-face packages** — `docs/development.md` reserves that shape for `api/remotes`; re-deriving each package's `references` is what the migration actually needed.

## Consequences

The line compiles, boots, and passes its eight browser scenarios on the alpha.5 base, with per-file 100% coverage across its nine packages and no coverage violation repo-wide. Two upstream files carry a registered change, and both were re-checked here: restoring the JSX spread in the trajectory-cell test still raises TS2375, and upstream's include still omits the Agent Teams declaration file, so each stays in effect. The Vue one retires when the probes get their own compiler face, the aggregate one when upstream names its own declaration file. `terminology-guard.ts` now carries a load-bearing rule rather than a redundant one, which is why its scenario pins element presence rather than only invisibility. The restated `recentWorkspace` retires if upstream exports it or seats it on `UiWorkspace`.

Two session events on this line (`content/shown`, `content-surface/dismissed`) remain required-on-read, so a `DSH_HOME` written by this composition and reopened by a stock profile refuses its logs — a pre-existing property, unchanged here, and worth one live check before a deployment migrates. alpha.5 does not soften it. The envelope keeps `ignorable?: true` and the read path still honors it, but `Session.append` offers no way to set it: its only option argument is `SurfaceIntent`, carrying `surfaceOp` and `sourceEventSeqs` and nothing else, and no first-party code writes the marker at all. Inside this repository both events are in the generated `KNOWN_SESSION_EVENT_TYPES`, so this tree reads them; moving these packages to an out-of-repo plugin would put them outside that set with no writer face for the marker that would excuse them. That is the condition to settle before the extraction, not after.
