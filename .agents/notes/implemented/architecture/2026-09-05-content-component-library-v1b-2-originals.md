# Agent Note: three more of the customer's own components — the table, the filter, the metric

Status: implemented

English | [中文](2026-09-05-content-component-library-v1b-2-originals.zh.md)

## Problem

[The vendoring slice](2026-09-05-content-component-library-v1b-1-seam.md) proved the seam on the smallest component the tarball exports: `TcFormDetail`, plain data in, nothing emitted, nothing fetched. What it deliberately left out is everything that makes those libraries worth vendoring. The three remaining exports each break one of the assumptions that slice was allowed to make.

- **`TableDetail` emits seven events and hands its rows back differently in each.** Its selection event carries deep clones, so the row objects the caller handed over are gone by the time the gesture is reported; its cell click carries them by reference; and a click on a row's name reaches el-table's own cell handler on the way up, so one gesture emits two events.
- **`TuQueryCondAdv` emits nothing at all.** What the user built is readable only by calling `getData()` on the mounted instance, and the bridge this repository owns passes data one way. It also reads its attribute list once, in `data()`, and never watches it.
- **`TcProcessBall` is a chain of timers** whose only stop is the `beforeDestroy` a build patch adds.

And the properties themselves are past what the schema union could express. A table's rows are keyed by whatever its columns read, so their field names are the model's to choose rather than a list the catalog can declare; a column carries a yes-or-no; a cell renderer is chosen by name from a fixed set; a cell's configuration carries a color.

The gesture channel had a second problem, and it was not visible until two components declared more than one action each. The [return channel](2026-09-04-content-component-library-v0.5-return-channel.md) folds one cell per `(entryId, nodeId)` and a renderer refuses a further gesture in every state but `idle` and `refused`. With one action per component that is exactly right. With four, a tick claims the cell and the row button underneath it is refused for the rest of the entry; with two, the filter bar disables its own submit the first time the user commits an edit. Each package's own tests pass either way, because neither package holds both halves.

## Decision

**Three catalog entries and three renderers, in one change.** `toy.table` (`TableDetail`), `el.filter-bar` (`TuQueryCondAdv`) and `el.metric` (`TcProcessBall`) enter `COMPONENT_CATALOG` and `COMPONENT_RENDERERS` together, because `CatalogId` is derived from the catalog and the seat's `satisfies Record<CatalogId, ComponentRenderer>` fails to compile the day one names a component the row cannot draw. The tarball is unchanged at `0.3.1`; every one of its four exports now has an entry.

**A gesture is the block's answer only when it is a `wake`.** `answersBlock(componentId, actionId)` reads the grade off the catalog, and both halves of the channel consult it: the fold writes no cell for a `context` or a `silent` gesture, and the seat files no row in the page's waiting table for one. The state a block draws is therefore the state of the answer it was placed for, and every other gesture is reported and leaves the block as it found it — a table keeps taking ticks and sorts while an `operation` is travelling, and a filter bar keeps its submit button alive while the user types. This is not a new rule so much as the one the grades already carry: `wake` is defined as the gesture that means "this is the answer you stopped for", and the block's own state is the only place that definition was not being read.

Two limitations the return-channel slice recorded are answered by it rather than by work of their own. A `silent` action's block no longer says the conversation has it, because it has no cell to say anything from. And the per-block cell is now correct rather than merely tolerable: a component declares at most one `wake`, so the second one on a single component is what pays for growing the key by `actionId`.

**The pass gains three readings, and two of them are what the table needs.** `PropsFieldSchema` grows `boolean` and `record`, and `ArrayFieldSchema.item` widens from an object to any field schema so a `select` can carry a bare list of numbers. A `record` is an object whose keys are the caller's own: an alphabet and a length for the keys, a count of them, and scalars only for the values. It is what a table row is, and what a cell renderer's configuration is.

**A `record` declares its own tightened readings, and does not inherit its component's.** A component-level `sanitize` rule matches by property name across the whole tree, which is right for a component's own declared properties and wrong for a record's keys, because those keys are data: `color` is a cell renderer's configuration key and also a perfectly ordinary column of somebody's records. The rule that reads `relatedComponentObj.color` as a color therefore sits on that record rather than on `toy.table`.

**`describeCatalog` became fully recursive.** It previously wrote one level, so `tableConfig{gridItems}` would have told the model a table has columns without naming a single field of one — a refusal per property to discover. The trigger was written into that function's own code as a comment before this slice existed. `MAX_SPEC_DEPTH` is measured off the catalog rather than written down, so the table's extra two levels widened it by exactly what they need.

**The match-strategy table is the editor's, all sixteen of it.** The condition editor draws sixteen; the component library's own `matchUtil` evaluates fifteen. Declaring the fifteen looks like the careful choice and is the wrong one: the sixteenth is one the user can still pick, and the host then refuses the whole submitted filter — a person builds a filter out of a strategy the console itself offered them and is told it was not recorded. Nothing in this package evaluates a condition; the notice is an account of what the user asked for, and a backend asked to run `NOT_BETWEEN` answers for itself.

**Every reported row is an index, never a row.** `TableDetail` freezes the list it is given and hands the same objects back, so a reported gesture carries a position in `displayValueList` and the host reads the row out of the call the model itself wrote. Where the component hands back clones — the selection event — the renderer reads the identities off the mounted instance with `doGetSelection()` instead. Nothing about the data travels back out of a block.

**The bridge gains one handle, and it goes one way.** `VueBridgeOptions.instanceRef` publishes `root.$children[0]` — the component, not the bridge's own root — for as long as the block is mounted. It exists for the two components that answer through methods, and its documentation says renderers use it to read: calling something on it that writes is reaching around the prop record the two frameworks agree on. `ElDatePicker` joins the popper table in the same change, because a filter bar over a date attribute draws one and the table is closed precisely so that a fourth popper is added deliberately. The sweep that reads the table still has no caller: it runs for `visible: false`, and this column unmounts a hidden block instead, which is what closes the popper today.

**What a renderer writes dead is what decides what the block *is*.** A table's own modify and delete buttons are removed (they emit an event no action here carries), its translated-value links are off (nothing supplies the values they resolve through, and leaving them on makes the name column a link whatever the call asked), and it offers no selection column until the call asks. A filter bar always receives `metaConfig` (without it the component fetches its own attribute list and the vendored build answers that fetch by throwing), a complete `confStyle` (the component reads all three fields without a guard), and `ifChange: '0'` beside every declared `dataType` (the component consults `dataType` only for that kind). None of these is a property the model chooses, because none of them is a thing about the data.

**The filter bar's send button is React's, and the block remounts when its attributes change.** The component's own buttons add and remove condition rows; none of them means "I am done". And `metaConfig` is copied into the component's data at creation and never watched, so a call carrying different attributes remounts the Vue root rather than leaving the previous ones on screen — which is what a user would expect of a new call anyway.

## Alternatives considered

**Declaring the fifteen match strategies the library evaluates.** Rejected once the failure was written out: the editor draws sixteen whatever the catalog says, so the sixteenth becomes a strategy the user picks and the host silently refuses the whole gesture for. Narrowing the *editor* instead was the other way to make the two agree, and it needs the fifteen ids in `component-kit`, which cannot import the catalog — `component-surface` depends on it, not the other way about, and the host half must never reach a module that touches element-ui. A second copy of the table is the duplication the repository's own gate exists to catch.

**Keying the gesture fold by `(entryId, nodeId, actionId)`.** Rejected for this slice, and it is the fix the day it is needed. It requires `ComponentRendererProps.state` to become a per-action lookup, which is a change to every renderer in the row, to the confirmation bar's tests, to the projection's stored cell and its wire schema. What it buys today is nothing: a component declares at most one `wake`, and no other gesture reaches a cell. The trigger is the second `wake` on one component.

**Gating nothing on `state` in the table.** The other way to stop a tick disabling the row buttons, and it was rejected because it throws away what the state is for: a per-row operation is a `wake`, the model put that button there to be pressed, and a press with no answer and no visible progress is the case the whole return channel was built around.

**Letting the renderer supply the fifteen strategies as its own constant.** Rejected as the same table twice. See above.

**A `default` on the schema, materialized by the tightening pass.** Considered as the general answer to "the component's own default disagrees with the catalog" — `attrEqEnums` is the instance. Rejected as a mechanism introduced to solve one case, when making the two tables agree solves it with no mechanism at all. The review trigger is a second property whose component default the host cannot accept.

**An ACP snapshot scenario driving a gesture.** Impossible rather than rejected, for the reason [the return-channel slice](2026-09-04-content-component-library-v0.5-return-channel.md) recorded: `/component-action` reaches the host through `remote.commands`, and the ACP protocol has no command method. The lane gains `show-table-turn` and `show-filter-turn` for the placement and the description; the gestures are the browser lane's.

**Naming a reported row by its first column's value rather than its index.** Rejected on the same ground the whole channel rests on: what the browser sends is text, and a notice assembled from it is a page putting words in the user's mouth. The index is resolved against the spec the model wrote, and the name in the notice comes from there.

**What the three components cost.** The row's client bundle goes from 2.9 MB raw and 557 KB gzipped to 2.97 MB and 566 KB — nine kilobytes gzipped for three vendored components, because element-ui and its stylesheet were already the whole of it. The price of this row is the seam rather than the components on it.

**What the integration found that neither half could.** Both packages were written and tested apart, and both passed. Composed, the filter bar was inoperable: its `change` gesture is reported at every committed edit, it claimed the block's one cell, and the submit button is disabled in every state but `idle` and `refused`. The table had the same defect one step milder — a tick disabled the row buttons for the rest of the entry. Neither package's tests could see it, because the rule that decides it (which gestures reach a cell) lives in one package and the rule that reads it (which states are pressable) lives in the other.

**What the review of this slice changed.**

- **A notice named a row by a column the table never drew.** `tableColumns` answered with every declared column, so a call that hid its first one had its rows named — to the agent and to the user — by a value nobody on screen could read. The reading is the drawn columns alone, which also leaves a sort on a hidden column stating nothing; a table that hides every column names its rows by position, through the fallback that was already there.
- **The AND/OR control was on by default and its answer went nowhere.** `showMatchMode` defaulted to `true`, so a call writing no `confStyle` — the ordinary one — drew a control whose value the submitted action did not carry. It is off unless a block asks for it, and a bar that does draw it submits `matchMode` beside the conditions, which the notice states in both languages.
- **An empty press was answered as a failure.** The bar starts holding one empty condition row, so the first press a user can make submitted no conditions at all, was refused by the action's own `minItems`, and earned the block the sentence saying the gesture was not recorded. A press with nothing complete in it reports nothing.
- **A full table's select-all was unreportable.** The table drew up to five hundred rows and its header checkbox ticks every one of them, while a selection carried at most four hundred indexes — a number derived from the byte ceiling on one action document. Ticking every row of a table past four hundred therefore reached nobody, and, because a selection is `context` and claims no cell, with nothing on screen saying so. The two are one number now: the selection ceiling *is* the row ceiling, and the byte ceiling was widened to 4096 to carry the document that gesture writes.
- **A gesture too big was reported as a gesture that went nowhere.** Every unresolvable action answered with the same sentence, so a user who had ticked or typed too much was told the click was not recorded — the one wording that names nothing they can do. A payload past a declared ceiling on how much a value carries is now told apart from a payload that is the wrong thing, and answered with the sentence saying there is too much.
- **A filter past ten conditions answered every later edit with a refusal.** The condition editor adds rows without limit, and `change` — the silent report it makes at every committed edit — declared the same ceiling as a submitted filter. An eleventh row therefore earned the user a refusal per edit, for a report they never asked to send. The edit's count is bounded by what an editor can hold rather than by what a submit carries; the submit keeps its ten and says so when it is passed.
- **The user's line quoted JSON escapes back at them.** A condition's value is the user's own text. The agent's account keeps the escaping — nothing in a value may end the quotation it sits in — and the user's line reads the text back as they wrote it, with anything that would not stay on one line replaced by a space.
- **One quoted value in a sentence was scrubbed and its neighbours were not.** The escaping and the one-line reading were applied to a condition's value alone, while the entry's title, a column's header, a button's label and the cell a row is named by went into the same two sentences untouched — so a line break or a bidirectional override in any of them rearranged the line the user reads. Every value a notice quotes goes through one helper now, and the sentence has no value its neighbours are treated differently from.
- **The three colors had no stated notation.** They are strings the tightening pass reads as colors, and a value outside the notation is dropped rather than refused, so a model writing `red` lost the property and was told nothing — under a description promising that a refusal names what was sent. A property declaring a reading now states its notation, and so does a record key that declares one.
- **The account of the `change` gesture was wrong.** It said an edit is reported on every keystroke. The editor's value control reports on `change` rather than on `input`, so what reaches the agent is one report per committed edit — picking an attribute, picking a strategy, leaving the value box. The decision that account justified is unchanged; the test that pins it now drives the value box with the browser's own input and change events rather than through `setData`.
- **The browser lane's rows carried an identifier for a reason that does not hold.** Every fixture row had an `int_id`, documented as what el-table keys rows by and as what a selection of more than one needs. A selection reports positions read off the mounted instance, and the lane passes without the field; it and its explanation are gone.
- **`visible` and the popper sweep still have no caller**, and this note read as though the date picker's entry gave them one. The bridge's own documentation says what is true: the sweep runs for a placement package that hides a mounted block, none here does, and element-ui's `beforeDestroy` is what removes the popper when this column unmounts one.
- **Every tick answered the user with a receipt in the conversation.** The handler answered any delivery that reached the inbox with 已记下，你下次发消息时对话会看到。, so the two `context` gestures — ticking a row, opening one — put a line in the chat per gesture, under the agent's replies. The delivery is now four rather than three: a `wake` that missed its turn keeps the sentence, because its author is waiting on an answer; a `context` notice reports `context` and settles textless, which is the settlement the chat row draws nothing for.
- **Any cell click was reported as an opened row.** `table-cell-click` is el-table's own, bound to every cell, so a table the call left with nothing to open reported an opened row whenever a user touched it. The report is gated on `isNameClick` — the property that decides whether a row opens at all — and a table that asked for openable rows still reports a click anywhere in the row, because the component offers no event narrower than that one.
- **Unclaimed `context` notices accumulated without limit.** Each tick injected a notice and nothing removed the one before it, so a user working a table queued a notice per tick, every one of them corrected by the next, in an inbox with no ceiling of its own. A second occurrence of one gesture — the same entry, block and action — now replaces the first through `Inbox.replace` while the first is still pending, which the agent log accounts for as work still pending; a claimed notice is never rewritten, and a `wake` is never replaced.
- **A record's tightened key read as required.** `describeRecord` wrote `color: #RGB|…` while every optional property elsewhere in the same line carries a `?`, so the one notation a model reads for a record it chooses the keys of said the key had to be there.

**Known Limitations, carried in the READMEs.**

- The condition editor draws a strategy nothing in the component library evaluates. It is reported as what the user asked for; what a backend does with it is that backend's answer.
- A filter bar draws the AND/OR choice only where the call asks for it. A bar that draws it submits the mode with the conditions; nothing in this package evaluates the filter either way.
- A table of five hundred rows rarely fits under the spec byte ceiling, and the refusal says so by byte count. Ticking every row of one that does fit is always reportable.
- The condition editor has no ceiling of its own, so an eleventh condition is built with nothing on screen saying it cannot be submitted; the press that submits it is answered with the sentence saying there is too much. Capping the editor needs the ceiling on `component-kit`'s side of the seam, and a component row must not import a placement package.
- The vendored components' own Chinese — a table's `操作` heading, the editor's `属性名`, `匹配策略`, `属性值`, `增加` — does not follow the interface language.
- A table is drawn at a fixed height with no paging, `isNameClick` reaches only a `display_default` column named `zh_label`, and a filter bar's values are all typed as text because the vendored build replaced the seven fetching controls with a disabled stand-in.
- `TableDetail`'s function-shaped properties — per-row button visibility, row styling, permission checks — are not offered, and cannot be: no member of the schema union can express one.
- A metric's gradient degrades to a flat ball when its background is spelled as a color keyword, which the tightening pass does not admit anyway.
- The gesture fold is still per block rather than per action; today that is exact, because a component declares at most one `wake`.
- A press with nothing complete in it looks like a button that does nothing: the first press of a filter bar submits its one empty row, reports nothing, and draws nothing. Greying the button out needs it drawn off the count the `change` gesture carries, which is a timing both packages have to agree on.
- A block says 这个动作没能记下来，可以再试 for every refusal while the chat row beside it may say 内容太多了，少选几项或写短一些再试。 Telling them apart on the block needs a further `ComponentActionState` member, which is a contract across the two packages.
- The table of unclaimed `context` notices is per live agent and forgotten on restart, exactly like the wake budget: the first tick after one queues a second notice beside the one the log holds.
