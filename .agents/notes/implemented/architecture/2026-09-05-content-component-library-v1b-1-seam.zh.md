# Agent Note: 在内容栏里画客户自己的 Vue 组件 —— 引入外部组件的那条缝

Status: implemented

[English](2026-09-05-content-component-library-v1b-1-seam.md) | 中文

## Problem

[组件库的第一片](2026-09-04-content-component-library-v0.zh.md)把整条路都建起来了——工具、目录、被判定的 spec、座位、渲染器表——但摆在上面的只有一条在这里用普通 React 写的确认条。它要长成的那个库不是在这里写的。客户维护的三个源库里有 354 个 Vue 2 单文件组件，其中 191 个直接写 element-ui 的组件，153 条 CSS 规则伸进它们的标记。那才是原料，这一片要回答的问题是：把其中一个画进控制台，要付什么。

这批原料的每一点，对它要落上去的那个界面都是敌意的。

- **它是 Vue 2，外壳是 React 18。** Vue 2 没有独立的 `render(vnode, container)`，它把组件收到的东西改写成响应式的，而它的响应式不跨运行时副本——对着第二份副本构建的组件会停止更新，没有报错也没有告警。
- **它要 element-ui，而那是进程级状态。** `Vue.use(ElementUI)` 往一个运行时的原型上注册约八十个组件，盖上 `$ELEMENT`，并把一个单调递增的 z-index 计数器从 2000 开始——压在 harness 自己 1100 的界面上，也压在 1000 的审批弹窗上。
- **它没有这个仓库能消费的 git 历史。** 源码待在一个称不上有版本控制的构建仓库里，组件也从没进过 npm：没有可以安装它们的注册表。

而控制台自己的规矩早已挡在路上。仓库给每个包一份编译面、`rootDir: src`，源码面与产物面从不混用；`publint` 拒绝 `file:` 依赖；第三方声明生成器拒绝许可证字段为 `UNLICENSED` 的包。

## Decision

**原件走一条缝进来，不重写。** `@sumomok/toy-surface-kit` 是那批组件的构建产物，在拥有它们源码的那个仓库里编译，以 `packages/experimental/component-kit/vendor/sumomok-toy-surface-kit-0.3.1.tgz` 的形式落在这里。这一片把它导出的四个里的一个——`TcFormDetail`，一份只读记录——包成目录条目 `toy.record`，因为它是那棵树里最小的东西，也因此是自身行为最不挡路、最能证明整条路走通的那个：只进数据，不发事件，不取数。

**tgz 是一份快照，而那个坑是无声的。** pnpm 按文件路径加一个完整性哈希来记这次安装，规格没变时它不会重读那个哈希，于是就地覆盖 tgz 只会让构建停在旧字节上，还不给任何诊断。每次重新构建都抬版本号、落到新文件名下、改掉规格，然后才 `pnpm install`。

**四个补丁和六道门禁在构建仓库里，不在这里。** 补丁——去掉一个 `cronstrue` 依赖、去掉一个下载列、修一处 `toUpperCase` 调用、拿掉一处从 `localStorage` 读 token 的代码——随 tgz 放在 `patches/` 下，理由写在它的 `SOURCES.md` 里。门禁拒绝发布这样的产物：里面还留着 `from 'vue'`、`'element-ui'`、`'toy-core'` 或 `'toy-comp'`；字节里带着 `fontawesome-webfont`；或者过不了 jsdom 挂载冒烟。四道文本门禁抓的是某个 barrel 导入把模块求值期的副作用一起拖进来，第五道抓一份 1.1 MB 的图标字体，冒烟抓的是文本门禁看不见的那种——被裁过的依赖在自己模块求值时就抛。它们在那边而不在这边，因为它们是**构建**产物的条件，而一道要等字节提交完才能失败的门禁，失败得太晚。

**整页只有一个 Vue，是请求来的不是打包进来的。** `dsh.client.external` 写的是 `@deepseek-ai/dsh-experimental-vue2-echarts-poc/client`，也就是拥有全页唯一那份 Vue 2.7 的那一行；`src/client/vue-shim.ts` 把那一行供给的东西重新导出；`tsdown.config.ts` 只对浏览器产物、把裸规格 `vue` 别名到这个文件上。别名是这条规矩对不是这个仓库写的代码也成立的原因：被内联进来的库里，只有 element-ui 内部 `require('vue')`，没有别名它会把一份自己的运行时拉进产物。tgz 两个包名都不写——它编译出来的组件跑在渲染它的那份运行时上，`el-*` 标签靠 `installElementUI()` 做的全局注册解析，这正是那个函数承重的地方。两个后果是承重的，也都有门禁：**`src/` 下任何文件都不许 import `vue`，写成什么形式都不行**——那里的 import 会被别名绕回 shim 形成环，而子路径的 import 会绕过别名去拿第二份副本，因为别名只映射裸规格（`tests/source-vue-imports.client.spec.ts`）——被内联的库要什么源码门禁看不见，那一半量在产物上：`tests/client-bundle-vue.client.spec.ts` 去数构建出的 `lib/client.js` 里的 `_isVue`、`__patch__`、`defineReactive`，多出第二份运行时就红。（第四个备选标记 `initGlobalAPI` 实测后弃用：打包器会把普通函数改名，有没有第二份它都是 0。）

**别名指向的是源码文件，这是对「源码面与产物面不混用」的一次刻意例外。** 它指向 `src/client/vue-shim.ts` 的绝对路径，而不是 `lib/types/client/vue-shim.js`。rolldown 在任何插件的 `resolveId` 之前就解析 `resolve.alias`，目标缺席时硬失败；而打包的那一刻，Client 面的 `tsc` 还没产出那个文件。路径是绝对的，因为工作区构建时 tsdown 的 `process.cwd()` 是仓根。这是这一行里唯一一处构建配置写 `src` 路径的地方，除了这里，也写进了 `tsdown.config.ts` 自己的模块文档。

**element-ui 只装一次，只从一个地方装，两个选项都写死。** `installElementUI()` 持有全包唯一的 `Vue.use(ElementUI, { size: 'small', zIndex: 300 })`，由一个模块级布尔守住；这一行的客户端插件启动时调它。它不是 `ctx.effect`，因为 `Vue.use` 没有反操作——把这一行拆掉，组件仍然注册在别的行也持有的那个运行时上，所以让重载安全的是幂等而不是可逆。`300` 是因为 element-ui 的计数器只增不减：从它自己的 2000 起步，会让一个展开的下拉盖住那扇请用户批准的窗；从 300 起步则把每个弹层都压在界面和弹窗之下。两个选项都不是 `Config` 字段：插件的浏览器半边收不到 cordis 配置，而这一行没有宿主半边，所以要让某一个可配，办法是落位包读设置再传给这个函数——改的是调用点，不是这里。

**`vue` 与 `element-ui` 是这一行的 `dependencies`。** 它们是它自己的构建输入，而不是组合方提供的东西：element-ui 被内联进客户端产物，`vue` 在这里是为了让这一行的测试和类型解析有个运行时可解析。真正保证运行时只有一个 Vue 的是产物别名和 external 请求，不是包管理器——不过两者本来也一致，因为 pnpm 把这一行的 `vue` 和 `vue2-echarts-poc` 的解析到同一个 store 条目。`element-ui` 钉死版本而不是写范围，因为它的样式表是手工拷进这个仓库的，范围会让拷贝和代码各走各的。

**样式表是物理拷贝，只改了一处。** `src/client/element-ui.css` 是 `theme-chalk/index.css`，图标 `@font-face` 的 woff 内联成 `data:` URI、truetype 备选删掉：客户端产物把这张表当 `<style>` 标签注入，相对字体地址会解析到页面上而不是包上。

**三条红线，每一条守的都是发生时看不见的那种失败。** 永远不许有 `window.Vue`——element-ui 的 UMD 构建会把自己装到它在那里找到的任何东西上，把组件注册到这一行并不拥有的运行时上。块里不许用 `el-dialog`、`el-message`、`el-notification`——它们的元素在宿主之外，这里没有任何东西关得掉；**允许**的那三个带弹层的组件是桥里的一张闭表，落位包说这块不在屏上时被逐个收起。以及，没有任何数据以未冻结的状态到达 Vue 组件。监听器映射是实测出来的例外，不是漏网：Vue 的 `updateListeners` 会把 invoker 写回它拿到的那个对象，冻住那张表会直接抛异常，而冻住的记录只是被跳过——桥交给 Vue 的是一份拷贝，调用方自己的那张表保持写下来的样子。

**冻结发生在收紧那一遍里面，不在它旁边。** `sanitizeNodeProps` 本来就把一块内容的整棵属性树重建一遍——它走的是 schema 而不是那条记录——所以它交出来的每个记录和列表都是这次走查新建的，在交出去的那一步逐个冻上既不多走一趟，也不从调用方手里拿走任何东西。因为校验是这一遍唯一的调用点，每个读到通过判定的节点的人都拿到同一份保证：工具、日志上的折叠、浏览器座位。它换来的正是 Vue 本来会悄悄做掉的那件事——观测一条 React 还持有的记录、换掉某个嵌套数组的原型、然后让两个框架对「什么变了」各执一词。

**`toy.record` 在同一次改动里同时进目录和渲染器表，因为两者之间那根销钉要求如此。** `CatalogId` 是从 `COMPONENT_CATALOG` 推出来的，座位的 `satisfies Record<CatalogId, ComponentRenderer>` 会在目录点名一个这一行画不了的组件那天编译不过。这一行新内容带来的一个后果：`renderer-coverage.client.spec.ts`——它的全部主题就是那条编译期断言——现在声明 `@vitest-environment jsdom`，因为它 import 的那个 barrel 会碰到 element-ui，而后者自己的模块求值时读 `document`。

**模型送来的是一个像素数，CSS 长度是渲染器的事。** `labelWidth` 声明成 `{ kind: 'number', min: 40, max: 240 }`，`TcFormDetailRenderer` 把它变成 `96px`。schema 联合刻意没有任何一个成员能表达 CSS 值，这个做法维持了这一点：布局能承的长度是一个量，单位由知道哪个组件要什么的那段代码加上。`columnNum` 做成 `1, 2, 3` 的枚举而不是区间，理由是同一类的——区间会连 `1.7` 一起放行。

**从现在起，画块内容的组合也要一并组合 Vue 运行时那一行。** `component-kit` 通过加载器的模块表请求 `@deepseek-ai/dsh-experimental-vue2-echarts-poc/client`，而没人提供的请求不会退化成一块空白——它会把整页的客户端产物一起带走。两份组合这一行的 overlay 都在它前面插入 `vue2-echarts-poc`，只为那份运行时；web 场景也把它链成一个解析得到的行。

**两道仓库门禁各拿到一条窄的、写明理由的豁免。** `publint` 把 `file:` 依赖报成 error，因为从注册表安装的用户解析不了它；`packages/experimental/` 下的东西一律不发布，所以这道检查已经没有要保护的对象了，`scripts/publint-all.ts` 只对这一个区域丢掉这一条消息。第三方声明生成器把 `@sumomok/toy-surface-kit` 列为第一方：它在兄弟仓库里用同一个所有者提供的源码构建，`UNLICENSED` 字段是「没有公开许可证」而不是「有限制性许可证」——把它写在那里是关于归属的陈述，不是对它编译的那些源码的许可证主张，那些条款在那个仓库的 `SOURCES.md` 里。`element-ui` 另外拿到一条仓库地址覆盖，因为它的 manifest 声明的是 scp 式 ssh 远端（`git@github.com:…`），那不是 URL，生成器的归一化会把它变成一条死链。

**工作区里有两个 Vue 大版本，文档站必须说清楚它要哪一个。** `vitepress-plugin-mermaid@2.0.17` 在它自己的 `Mermaid.vue` 里 import `vue`，却没有声明对它的依赖，于是解析落到 pnpm 的 hoist 兜底槽——现在这个工作区把那个槽填成了 element-ui 那边的 Vue 2——VitePress 的 SSR 入口就在 `vue/server-renderer` 上失败。`pnpm-workspace.yaml` 用 `packageExtensions` 把这条缺失的 peer 补上，让插件按解析而不是按 hoist 顺序钉在 Vue 3 上。

### 闸表 6 —— 收紧那一遍，以及还没有人声明的那三种读法

| 格 | 内容 |
|---|---|
| **0 —— 哪条已定原则先说了不** | 「在同进程的类型边界上信任 TypeScript」把这一遍放在值的类型只是一个说法而不是保证的地方——wire 上，以及从 checkpoint 里读回来的记录——别的地方一处不放。「包边界上显式优于隐式」否掉了让每个渲染器在画的时候自己收紧字符串：声明在 schema 旁边的读法只执行一遍，一个通道，三个读者共用。「配错就大声失败」被权衡后有意不适用：这一遍丢掉那一个值而不是拒掉整块，因为它的两个调用点都已经没有人可以被告知了。 |
| **1 —— 新增触达面：0** | 数据源 **0**；界面 **0**；工具或参数 **0**；路由或 RPC **0**；`Config` 字段 **0**；事件类型 **0**；审批闸 **0**；依赖 **0**。这一遍是一个模块，落在本来就在判定同一批文档的那个包里。 |
| **2 —— 能证明它的最小版本** | 走 schema 的那趟重建，加上交出去时的冻结——两个目录条目经 `validateComponentSpec` 都跑过。三种收紧读法（`path`、`color`、`related-component`）**没有**到这条线：今天没有任何目录条目声明其中之一，它们只在 `tests/sanitize.client.spec.ts` 的探针组件上被证明。它们在这里，是因为设计把收紧这一层排成独立一期，排在第一个声明读法的组件 `toy.table` 之前。这一格是把这个例外记下来，而不是留给别人发现。 |
| **3 —— 做缝还是写死** | **写死。** `SanitizeClass` 是三个成员的闭合联合，渲染器白名单是一张写下来的表，组件按属性名声明读法。三种全部保留：下一片就是 `toy.table`，它声明 `relatedComponent` 和一个单元格颜色，三种里的两种在那里遇到第一个声明者。还在等的是 `path`；那一片若不要它，它连同测试跟着那一片一起撤掉，而不是等第三个组件来替它说话。 |
| **4 —— 每个方向一句** | *邻居*：这一遍只读目录，别的什么都不读，所以浏览器半边跑的是同一遍。防的是同一块内容有两种读法。*契约*：它交出来的是属性，绝不是一次拒绝。防的是一条存下来的记录因为规则在它写下之后收紧而画不出来。*诱惑*：在某个组件旁边发明第四种读法，而不是加进那个闭合联合。防的是每个组件各拼一个自己的消毒器。*红线*：schema 联合里没有任何成员能表达标记或函数体，所以下游没有任何东西需要去认出一个来。*天花板*：今天这一遍不改变任何被画出来的东西——两个条目的每个属性都是纯文本——README 把这一条记在 Known Limitations 里。 |

## Alternatives considered

**用 React 重写这些组件。** 按数目否掉的，不是凭偏好：354 个单文件组件里有 191 个直接写 element-ui 的组件，153 条 CSS 规则伸进它们的标记，重写等于把客户已经付过账的 bug 历史重来一遍——而且三个源库各要来一次。这条缝换来的代价则是页面里多一个框架，以及上面两张闸表说的全部；这笔交换正是这份记录的主题。

**把 element-ui 放进 `vue2-echarts-poc`，和它拥有的那个 Vue 运行时放在一起。** 否掉：那是一行图表，而 element-ui 是约八十个组件加一张 200 KB 的样式表，图表一个都不需要。这会让每个画图表的组合替一个自己不用的组件库买单，也会把关于 `zIndex` 和 `size` 的决定放进一个没有组件可配的包里。运行时之所以共享，是因为 Vue 的身份是进程级的；element-ui 不共享，因为它只是某一行恰好用到的库。

**用 `link:` 而不是 `file:` 链这份组件 tgz。** 按桌面端自己那条引入规矩同样的理由否掉：link 解析到的是一棵可能在构建过程中变化的工作树，于是这里提交的东西不再决定发出去的东西。`file:` 把字节按完整性哈希拷进 store，这才让 tgz 成为一份快照。代价是那个无声覆盖的坑，由抬版本号来答。

**把组件发到注册表，然后按版本依赖。** 作为超出范围而不是作为错误否掉：它需要一个注册表、一个所有者，以及一套面向客户私有组件的发布流程，三样都不存在。`file:` 规格就是这三样缺席的样子；这也正是 `publint` 的反对可以回答的原因——带着它的那个包同样不发布。

**把 `vue` 别名到 shim 的构建产物而不是源码。** 先这么试过，被 rolldown 否掉：`resolve.alias` 跑在任何插件的 `resolveId` 之前，目标缺席时硬失败，而打包那一刻 Client 面的 `tsc` 还没产出 `lib/types/client/vue-shim.js`。别名被查询时唯一存在的目标就是源码路径。

**在浏览器座位里冻结，从组件行 import `freezeDeep`。** 一看清耦合就否掉了：座位今天从那一行拿的运行时导入只有 `COMPONENT_RENDERERS`，再加一个具名导入就扩大了「旧版本的行必须导出什么」——而 `component-surface-mismatch.client.spec.tsx` 存在的意义正是让那种不匹配还能活着：缺一个渲染器代价是一块内容，缺一个导出代价是整页。另一个选项是在落位包里再抄一份同样的函数，作为「同一个函数写两遍」否掉。冻结放进收紧那一遍，两者都不需要。

**给渲染器加一个由座位设置的 `visible` prop。** 作为死管道否掉：只有当这个座位正在显示时，栏才会给它一条条目，所以这个值会恒为 `true`、它的 false 分支不可达——而不可达的代码正是逐文件覆盖率门禁要拦的东西。桥上的 `visible: false` 这条路留着，因为它是给「藏起块而不是丢掉块」的落位包用的；这一栏是丢掉，而丢掉时 element-ui 自己的 `beforeDestroy` 会把弹层移掉。

**给 `publint` 开全仓豁免，或者通用地修生成器的仓库地址归一化。** 两个都作为「比事实更宽」否掉。`file:` 豁免限定在 `packages/experimental/`，也就是唯一永不发布的那一层，而且丢的是一个消息码而不是把一个包整体噤声。scp 式远端由生成器自己那张写明的覆盖表来答，而不是教归一化器认第二套只有一个实例的 URL 语法。

**直接复用 `vue2-echarts-poc` 那座桥，或者把两座并成一座。** 这一片否掉，并且把差别写下来而不是留给人去发现：图表那一行的桥是浅冻（`Object.freeze({ ...props })`），对图表拿到的那条扁平配置记录够用，对一块内容里嵌套的行不够用；它没有监听器映射，也没有弹层收拢。要并起来，就得让图表那一行的桥同时长出这两样、并把冻结改深——那是在动这一片本来不碰的一行，它自己的测试要在同一个 PR 里跟着改。两边的挂载序列近到重复是真的，又小到 jscpd 不会报。复核触发点是第三个调用方，或者第一次得改两遍的改动。图表那一行的浅冻是那一行的已知缺口，不是一个决定——echarts 配置里嵌套的那些值今天在那边是被观测掉的——它按那一行的缺口登记在案，并有自己的复核触发点：第三个 Vue 2 包加入这个页面，或者图表那一行第一次出现能追到「配置被观测」的缺陷，也就是调用方还握着的值上多了一个 `__ob__`。两者都还没发生，而把那份冻结改深是在动这一片本来不碰的一行。

**这个仓库付了什么。** 这一行的客户端产物原始 2.9 MB、gzip 后 557 KB，几乎全是 element-ui 和它的样式表；这一片之前它是几 KB 的 React。这就是这条缝的价钱，由每个画块内容的组合来付——这也是这一行处在实验层、不进任何发布包的原因。`component-kit` 还多了一条对 `vue2-echarts-poc` 的 Project Reference，正是它让 Client 编译面去解析共享运行时的类型，而不是把它的源码拉进这个包自己的程序里。

**这一片的复核改了什么。**

- **桥在每次 React commit 都重建监听器映射**，那会重新赋值一个响应式的根属性，把整棵 Vue 树为一次什么都没变的 commit 重渲染一遍。拷贝仍然要做——Vue 会改写交给它的那个对象——但只在调用方的映射换成了另一个对象时才做，上一次是哪一个记在根旁边的一个 ref 里。属性记录不需要这一手：它是就地冻结而不是拷贝，所以 Vue 自己的 setter 会丢掉对同一个对象的重新赋值。让这一条对记录成立的是 `TcFormDetailRenderer` 对块属性的那层 memo；桥的 spec 现在用数渲染次数来钉它，而不是去看 DOM——为一次什么都没变的 commit 重渲染的根，画出来的和之前一模一样。
- **值为空的那一行现在保留。** `readDisplay` 当时把空串当作缺失值丢掉，连带丢掉了名称，让用户根本看不出这条记录有这个属性。空串是一个值：这一行保留，由组件自己的 `v-if` 画出名称、旁边什么也不画。只有谁也没命名的行，或者值根本不是文本的行，才被丢掉。
- **描述现在写出每个组件的属性**，在它的身份行下面派生出一行。此前它告诉模型一块内容只带「上面那个组件声明过的属性」，而目录行一个属性也没声明，于是模型第一次用某个组件的那次调用，是花在打听上的一次拒绝。这一行来自 `propsSchema`，所以组件的 schema 长出一个属性，同一次改动就把它提供出去；拒绝语句本来就会说的那些边界略去不写，因为描述是每次请求都要付的。
- **`publint` 的豁免有了它的反例。** 它那个条件的两半——消息码，以及 `packages/experimental/` 前缀——现在各有一个必须仍然失败的用例钉着。
- **「构建产物里只有一份 Vue」这条断言，按「在 CI 上不执行」登记在案**：写在 spec 自己的模块文档里，也写在 `component-kit` 的 Known Limitations 里。它跳过，是因为跑本包 `vitest` 的 CI 作业都没有先构建：pull request 上的覆盖率作业不构建，master 的 `linux-primary` 泳道把 build 排在覆盖率门禁之后。没有为它加门禁：仓库里没有任何门禁去读已构建客户端产物的正文，而同类的另外两个 spec——都属于发行行——在 CI 上因同一原因跳过。给一个实验行单配一个门禁脚本、而让那两个发行行空着，那才是不对称，不是修好。把这三条一起挪上门禁的触发器，是第一个去读已构建客户端产物的门禁出现。
- **`visible` 在这里没有接上**，而且就这样。桥的弹层收拢只在落位包传 `visible: false` 时才跑；这个内容栏是把块卸载掉，于是座位什么都不传，这条路径在这套组合里用不到。它留着，是因为对「隐藏而不丢弃」的落位来说它才是正确行为；它是对着探针组件测的，不是对着这个座位。

**Known Limitations，写在两份 README 里。**

- tgz 是一棵自身没有版本历史的源码树的快照，「哪些源码产出了这些字节」只能从构建仓库的 `SOURCES.md` 里回答。
- element-ui 为它自己拥有的文案自带中文串（日期选择器的月份名、表格的空态行），它们不跟随界面语言。
- `PopupManager.nextZIndex()` 只增不减。一次会话打开约七百个弹层后，会重新越过审批弹窗。
- tgz 导出的四个组件里有三个没有目录条目、也没有渲染器。
- 用户在块里输入的东西挨不过内容栏画另一条目：座位会卸载这些块，Vue 根跟着一起走。
- 记录里值为空的那一行显示名称、旁边什么也不显示，这是组件自己对「有这个属性但没填」的读法。
- 构建产物那条「只有一份 Vue」的断言在 CI 上不执行，理由见上。
