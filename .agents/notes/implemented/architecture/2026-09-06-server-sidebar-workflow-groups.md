# Agent Note: server-sidebar — workflow groups and the temporary section

Status: implemented

English | [中文](2026-09-06-server-sidebar-workflow-groups.zh.md)

## Problem

The [v2b slice](2026-09-06-content-component-library-v2b-vendor-views.md) landed `groups` in the durable server-menu document and drew none of it: the console still showed one flat 我的工作流 list, `groupId` changed nothing, and the POST route accepted `workflows` and `workbenchSessionId` only. That note named the interface as the next slice's work.

A second gap sat next to it. The console's own entry points — the 工作台, a 导航 row, a saved workflow — each resolve or create a conversation internally, and the workbench click deliberately displaces a draft it can no longer reuse ([clean-draft rule](2026-09-04-server-sidebar-clean-workbench-draft.md)). A displaced draft had nowhere to be found again: no session browser is composed here, and only a saved workflow gets a row. Work a visitor had actually done receded with no way back to it.

The shipped `dsh-client-ui-workspace` browser solves a superficially similar problem, but not this one: it groups sessions by the Workspace directory they belong to, which is exactly the vocabulary this console removes, and it exports only its plugin entries — its tree algorithms are private.

## Decision

**Groups are drawn as lanes derived on every render, never stored as a list.** Pinned groups first, then the rest by `order`, then every ungrouped workflow at the console's own top level. `client/workflow-actions.ts` states each lane as a pure transform over the two arrays (`pinnedGroups`, `otherGroups`, `workflowsInGroup`, `ungroupedWorkflows`), so the composition is asserted against arrays rather than through a rendered tree, and every workflow appears in exactly one lane. A lane is the one level of hierarchy this section has, and indentation is all that states it on screen, so each one carries `role="group"` named by its own header (`aria-labelledby`) and its fold caret names the list it folds (`aria-controls`); the top level, which has no header, is the section itself and its heading already names it.

**Pinning is a group-level fact and nothing else.** A pinned group sorts ahead of every unpinned one without touching its `order`, so unpinning restores its place. Pinning a single workflow is deliberately absent: rows inside a lane already carry a manual drag order, and a per-row pin would contradict it.

**One patch per user action, because a group deletion is not decomposable.** Deleting a group ships the shortened group list and its members' cleared `groupId` in the same POST: the document refuses a `groupId` naming a group nothing defines, so either half alone is a document the route rejects. The sidebar's injected seat is therefore `onSaveMenu(patch)` — one call taking any subset of `{workflows, groups, workbenchSessionId}` — rather than a callback per array. The route's `readPatch` accepts the same three-key subset and the settings write stays a merge, so a groups-only patch never resends the workflow list.

**Cross-group movement has two paths, and both need a pointer or a touch.** A row can be dragged onto another lane's rows, onto its header, or onto the placeholder an empty lane draws — the top level, which has no header, draws one only while a drag is in flight, since an empty top level is the ordinary state of a console whose workflows are all filed. The row's 移动到… menu lists every lane but its own; a console with no group at all has one lane and nowhere to send a row, so the control is left out rather than drawn over a list that opens empty. HTML5 drag-and-drop has no touch equivalent, so the menu is not a convenience — it is the only path touch has, which makes the reveal rule load-bearing: `:focus-within` sits on the row and on the lane header, never on the hidden container itself, because a `display: none` subtree holds nothing focusable and would never match; and a device with no hover, which matches neither condition, gets the controls drawn from the start under `@media (hover: none)`. Each row and header starts with a control that is always drawn (the name button, the fold caret), so focusing it reveals the rest and Tab walks in. `apps/web/tests/server-sidebar.e2e.ts` presses that Tab. The keyboard's reach ends there: `Menu` portals its list to the end of `document.body` and neither takes the focus nor answers arrow keys, so the destinations sit behind every other focusable element on the page. Closing that gap needs a focus-managed dropdown of this package's own or a change to the shared primitive, and this slice does neither — it only makes the focus leaving the row close the list, so a portaled list cannot outlive the trigger the reveal rule then hides. Both commit through one transform, `reorderWithinGroup(workflows, groupId, ids)`, which states "this lane is now exactly these rows in this order" and files each named row under the lane as it rewrites its `order`; a same-lane reorder and a cross-lane move are the same call.

**临时工作流 is derived from the live session directory, with nothing durable behind it.** Five predicates decide membership (`temporarySessions`): not a subagent child, not archived, not the workbench's conversation, not any workflow's `homeSessionId`, and not a blank draft unless it is the one on screen. The last predicate is what keeps a nameless empty row from accumulating on every workbench visit; the fourth is why a saved workflow leaves the section by itself, with no second bookkeeping mechanism. Rows sort by `updatedAt`, most recent first, and the section shows five before 显示更多. None of the five asks whose conversation a row is: the filter runs over the whole conversation directory this process serves, and what makes it read as "this person's own" is the deployment shape — one visitor per process, per `$DSH_HOME`. Nothing in this package enforces that, and both READMEs record it as a limitation.

**A temporary row shows the conversation's own durable title or fixed copy — never `displayTitle`.** That field's lower rungs are a directory basename and then a bare session id: the first is the vocabulary this console exists to remove, and the second is not something the banned-word assertion can catch, because a bare id matches no word. `ServerSidebarRoot`'s `temporaryRow` reduces a session to `{title | undefined}` before the component sees it, so the fallback chain is unreachable from the render tree rather than merely unused by it.

**移出列表 archives and asks twice, and the second click cannot be an accident.** It calls `ctx.workspaces.archiveSession`: the log and the accounting slot survive on the host, and nothing here deletes a conversation. But this shell composes no unarchive control and the shipped browser's own is not composed either, so the action is one-way for the person using the console — the control turns into a second, explicit 确定移出 button before it commits. Position carries that weight rather than a timer: 确定移出 opens to the LEFT, and the row's right edge — the 移出列表 icon's own footprint, and where a double click's second press lands — becomes 取消. A double click therefore disarms. Escape disarms too, listened for on the document because a click arms the row without leaving the focus anywhere the component owns, and so does folding the section shut.

**Taking the conversation on screen off the list lands the shell back on the workbench.** Archiving clears the selection along with it (the workspace projection's own sweep), and the sidebar's load-time landing is a one-shot ref that never fires again, so the console would otherwise come to rest on a shell with a read-only composer and nothing to say. A successful dismissal therefore runs the workbench landing path itself (`landOnWorkbench` — the same code the load-time auto-open uses, writing `workbenchSessionId` back when it had to create a conversation), and the seat takes the workbench's two facts for it: the recorded id and whether it is still live, the same pair the workbench click takes. Whether the archived row was the one on screen is read *before* the archive; afterwards there is nothing left to compare against. A refused archive is a flag rather than a message, and the section says so in fixed copy ("移出失败，请稍后重试"): the refusal's own text is the host runtime's (`session archive failed: …`) and carries the vocabulary this console removes, so it goes to the browser console instead.

**Fold state and 显示更多 live in the browser, not in the deployment's document.** `localStorage` under `dsh.server-sidebar.view.v1`, written by hand from the two view actions rather than through `defineStore`'s `persist`: that mechanism stores and rehydrates the whole state, which would let a stale workflow list overwrite the server-read document the store is seeded from on every page load. Reads and writes are each contained — the `typeof localStorage` guard included, inside the `try` rather than in front of it, because a browser configured to block site data throws on the global's own getter and the guard is itself the statement that fails. A browser with no `localStorage`, one that refuses it outright, a full quota, or unreadable text all fall back to everything expanded, with the click that asked still landing. The map is pruned against the authoritative group list on both documents this store sees — the one it loads with and each one a save answers — because a browser that only ever reads would otherwise keep a deleted group's fold entry forever, and a fold entry is the one thing here that accumulates for the life of a browser profile.

**The invariant companion re-runs `validateServerMenu` on the committed document.** v2b exempted the group constraints from the companion on the grounds that no interface could produce a document breaking them. This slice writes groups, so the exemption is withdrawn: the companion calls the same function the route's `validate` hook does, rather than restating its rules.

### Two build facts this change forces

**`TEMPORARY_GROUP_ID` and `MAX_GROUP_NAME_LENGTH` move to `src/menu-constants.ts`, a module that imports nothing.** The browser half reads both as values — the reserved id keys the temporary section in its own fold map, and the length caps the naming field so a rejected write never travels to the route. The fold map is the reserved id's only live use: nothing durable carries it, and `validateServerMenu` refuses both a stored group claiming it and a workflow filed under it. `src/workflows.ts` imports `@deepseek-ai/dsh-settings` and `@deepseek-ai/schemastery` for the durable schema, and a value import of that module from the client tree pulls both into the browser bundle, which the client-bundle purity gate refuses. `src/route.ts` already held this package's HTTP paths for the same reason.

**The package's two Node entries are built as independent bundles.** With the companion re-running `validateServerMenu`, `lib/types/index.js` and `lib/types/invariant.js` both reach `src/workflows.ts`, and the single two-entry build hoisted it into a hash-named shared chunk that the package's exact `files` list cannot publish — publint and `verify-built-package-invariants` both refuse that artifact. `tsdown.config.ts` now passes the invariant entry as a companion config, which is what `packages/core/agent` already does for the same reason; `clientLibraryConfig` is exported from `packages/client/tsdown.client.ts` so the split restates no dependency rules.

## Alternatives considered

**Reusing `dsh-client-ui-workspace`'s tree.** Rejected, and its shape borrowed instead. That package exports three plugin entries and keeps `tree.ts` private, so there is no import to make; composing the package itself is what this console removed in the first place ([the replacement decision](2026-08-29-server-sidebar-replaces-ui-sidebar.md)), and its grouping key is the Workspace directory — the vocabulary the console bans. What carried over is the shape of four solved problems: a three-predicate visibility filter, a recency comparator with a stable tie-break, a zero-or-five collapse rather than paging, and a browser-local view account with a versioned key that is pruned against the live keys. All four are re-stated here over this console's own facts.

**Pinning individual workflows.** Rejected. The shipped client has no such affordance to match — an earlier activity-pinning design was dropped outright — and a per-row pin fights the manual drag order that already exists inside a lane. Group-level pinning is new here, and both READMEs say so rather than implying inherited behaviour.

**Deleting a temporary conversation.** Rejected. `ctx.workspaces` offers archive, not delete, and this console has no authority to destroy a log a deployment may be accounting for. Archiving with an in-place confirmation gives the visible outcome ("it is off my list") without the destructive one, at the cost of being one-way from inside this shell — recorded as a limitation rather than hidden.

**Two callbacks, `onSaveWorkflows` and `onSaveGroups`.** Rejected. Each individual write would be legal, but a group deletion split across two round trips leaves a document the route rejects in the middle, and an interruption between them leaves an empty group or an orphaned `groupId` behind. One patch makes the atomicity a property of the seat rather than of the caller's discipline.

**Storing the fold state in the server-menu document.** Rejected. Which lanes a person folded is a per-browser display preference, not a fact about the deployment; putting it in the document would make one browser's view state a write every other browser has to read, and would bump a durable format for something a cleared cache is allowed to forget.

**Keeping the group constraints out of the invariant companion.** Rejected with the premise it rested on. v2b's reasoning was that no interface could produce a document breaking them; this slice is that interface.

## Consequences

The console draws four sections instead of three, and a displaced draft has a row again. `groups` becomes patchable, so the v2b limitation it named is closed. The temporary section derives over the whole session directory on every relevant change (`session.list` has no paging in v1), so the five-row cut shortens what is drawn rather than what is computed; a very long history is filtered in the browser.

Two costs are carried openly. Group order itself has no interface at all — a group takes its `order` at creation and only pinning moves it afterwards; the durable field is there, and the transform that would rewrite it is not, because nothing calls it. And 移出列表 cannot be undone from this console.

`ServerSidebarInjected` changed shape: `onSaveWorkflows` became `onSaveMenu`, and `onOpenTemporary`/`onDismissTemporary` joined it, the latter also carrying the workbench's two facts. A failed archive is reported inline the way a failed save is, because the component never awaits either — but through its own store flag (`temporaryFailed`) and its own fixed copy, so it lands in the section the click was in rather than under 我的工作流 saying a save failed.

## Testing

Package unit coverage is per-file 100% across `src`: the lane transforms and the five membership predicates against arrays, the two components against a rendered tree, the route's three-key patch (including a groups-only patch that would orphan a `groupId` being refused whole), and the companion against five broken committed documents. `apps/web/tests/server-sidebar.e2e.ts` carries the browser evidence over a real composition — create a group, move a workflow into it, pin it, fold it and reload, then find an unsaved conversation in 临时工作流 and take it off the list — and its banned-word assertion runs over every string this package's dictionaries added. Three of its steps guard a promise code alone cannot show: a Tab from a row's own name button lands on 移动到… — where the keyboard's reach ends, as the README's Known Limitations records — a real double click on 移出列表 leaves the row where it was, and taking the row that is open on screen off the list lands the page on the workbench with no banned word anywhere in its text.
