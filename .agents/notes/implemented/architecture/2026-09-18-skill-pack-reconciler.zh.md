# Agent Note: 技能包在它的组件部件注册之前一律扣下

Status: implemented

[English](2026-09-18-skill-pack-reconciler.md) | 中文

## Problem

一套部署想把一个技能，和这个技能所讲的那套界面，当成一件可安装的东西一起发出去：正文，加上摆放某个组件插件部件的那些视图。技能本来就是按目录安装的，文件系统技能提供方又原样透传技能 frontmatter 里的 `metadata`，所以一个目录本来就能同时承载这两样。缺的是那道判定。一个视图要摆 `toy.crud` 的技能，在一套没有任何组件插件注册 `toy.crud` 的组合里是没用的——比不存在还糟：模型被告知这个技能在，照着做，用户拿到的是一个带窟窿的页面，或者什么都没有。

发放侧同样需要一条整体替换部署手里那份东西的路。技能包会在上游退役，技能包会在机器上被手工改，而一次合并形状的安装留下的是一个谁也说不清里面是什么的根目录。

## Decision

**技能包就是一个普通的技能目录，只是它的 frontmatter `metadata` 里带着一份清单。** `pack.version` 与可选的 `pack.platform` 区间描述这个技能包；`requires.components` 把组件插件的包名映射到一个语义化版本区间，`requires.parts` 写明必须存在于组件目录里的部件 id；`views` 列出这个技能包自己的视图文件。这个对象是严格读的——不认识的键就拒掉这个技能包——因为写错的 `requires` 等于没人提过这条要求，而这个技能包接下来就会在它当初依赖的那些部件都不在的情况下被交出去。`@deepseek-ai/dsh-experimental-skill-pack` 拥有清单 schema、判定器、提供方、状态路由和技能包根目录的安装器。

**激活是整包的。** 每条要求都满足的技能包整包交出去；只要有一条没满足，这个技能包就谁也拿不到——模型拿不到，面向用户的命令拿不到，它的视图一个也不交。判定是一个纯函数，输入是解析好的清单、已注册的部件和平台版本，输出是一个封闭的 `PackMissing` 联合，每一项都点名那个被拒的值。

**这个包就是技能包根目录的技能提供方。** `ctx.skills` 把各提供方报上来的东西合并起来，对别的提供方的目录既没有过滤、也没有否决、也没有瀑布钩子，所以能把一个技能包扣下来的地方，只有本来会报出它的那个提供方。把被扣下的技能包报上去、但两个调用标志都设成 false，确实能对每个面都藏住它，可它仍然在合并目录里占住那个名字，会把另一个提供方同名的技能盖掉，因此被扣下的技能包干脆一个也不报。部署把通用文件系统提供方指向它其它的技能根目录。扣下这件事在加载时同样生效：一次加载会重新读根目录，除非这个技能包仍然激活，否则答 `undefined`，因为注册表会缓存一份完成的目录，而一次选择可能活得比它当初所处的状态更久。

**部件来自这个包自己声明的一个可选服务 `ctx.skillPackParts`。** 它的 `PartsSource` 接口是 `list(): readonly ProvidedPart[]` 加 `onChange(listener): () => void`，其中 `ProvidedPart` 是 `{ id, plugin, version }`。在有人挂上这个键的提供方之前，部件表是空的，于是每个点名了部件的技能包都未激活——这正是 fail-closed 的正确答案。接到组件目录自己那套注册表上的适配器是单独一行；这里没有任何代码伸进那个包里。

**状态不用重启就翻转。** `onChange` 和被监视的技能包根目录都会通过提供方那个绑定到本次注册的 `invalidate()` 让技能目录失效，下一次读取重算。每一次读——`statuses()`、`activeViews()`、以及每次提供方调用——都是在调用那一刻从技能包根目录和部件来源算出来的，所以没有属于我们自己的、会过期的缓存。

**`GET /skill-pack/status` 是被扣下的技能包唯一可见的地方。** 它答 `{ packs: PackStatus[] }`，带名字、版本和被拒原因，不带文件内容、不带技能包内部路径，不做缓存。没有它，一套装了技能包却找不到它的部署将无处可读。

**`syncPackRoot(targetRoot, delivery)` 让根目录等于发放集。** 它先落到一个同级目录里暂存，在那里核对，再用 rename 换进来；它先对一遍，根目录已经一致时什么都不写。技能包带 `.md`、`.yml`、`.yaml` 和位图图片；其它每一种扩展名、每一个符号链接、每一条走出自己技能包目录的路径，都以一个带类型的 `PackInstallError` 拒掉。`.svg` 和其它一起被拒，因为 SVG 文档里可以带脚本。没有命令行入口：这个仓库禁止包自带 bin，发放侧调用这个库函数。

### 边界

| 方向 | 那条线 | 它防的具名失败 | 期限 |
|---|---|---|---|
| 邻居 | 这个包判技能包；`packages/skill` 拥有合并与加载，组件目录拥有一份 spec 里能放什么。技能包的 `spec` 与 `params` 原样带过去，在这里一律不读。 | 对一份 spec 的第二个意见，和真正判一次 `show_component` 调用的那个答案对不上，于是部署配好的一个视图在这里被接受、在那里被拒。 | 永久 |
| 契约 | 一个技能包要么激活要么不激活。没有部分激活，也没有「除了一个视图之外都激活」。 | 一个带窟窿的页面：模型照着技能走进一个画不出来的视图。 | 永久 |
| 诱惑 | 被问到那个缺的插件时，这个包只报告然后停下。它绝不去取、去装、去挂一个插件。 | 技能包变成一条装代码的后门：一条从技能包数据跑起来的安装路，正是那条「不装代码」的规矩要堵死的路。 | 暂缓 —— 触发器：发放侧能把插件和技能包打成一个包一起发，那时安装这个决定属于解这个包的人，不属于这里。 |
| 红线 | 技能包绝不带代码。`.md`、`.yml`、`.yaml` 和位图图片能装；`.js`、`.mjs`、`.cjs`、`.ts`、`.vue`、`.node`、`.sh`、`.svg` 以及其余一切都被点名拒绝，符号链接和走出技能包目录的路径同样。 | 技能包根目录——一个远端发放方往里写的目录——变成往机器上放可执行文件的一条路。 | 永久 |
| 天花板 | 每次读都重扫根目录、重解析每份清单。没有缓存，没有增量监视差分，对状态路由在轮询下的表现不做任何承诺。 | 一份缓存答出技能目录早已越过的那个状态，而这正是整包规则要避免的那个 bug。 | 暂缓 —— 触发器：技能包根目录大到一次实测扫描在请求里显形，那时这份缓存需要的是一个失效的归属者，而不是一个 TTL。 |
| 假设 | 一套部署一个技能包根目录，里面一份发放集。`root` 是单个目录，`syncPackRoot` 把它整个替换。 | 发明一个这个包并不拥有的按用户身份，以及一个内容取决于是谁在问的根目录。 | 暂缓 —— 触发器：多用户那个决定。 |

## Testing

单元用例钉住清单 schema 与它的拒绝所点名的字段、判定器的封闭联合与固定顺序、视图文件解析、技能包根目录扫描，以及安装器的首次安装、增改退役、幂等、漂移修复、代码文件拒绝、路径逃逸拒绝、符号链接拒绝，和「失败不动根目录」这条保证。一次跑在真实技能包根目录上的真实 Loader 组合启动技能注册表、Web 服务器和这一行，断言合并目录、模型与用户调用过滤、加载到的正文、状态文档、405、视图、部件来源到场/变化/被销毁时两个方向的翻转、一个技能包出现在被监视的根目录里、拒绝加载根目录已不再交出的技能包，以及 fiber 销毁时提供方的撤走。`src` 的逐文件覆盖率是 100%。

## 适配器

`ctx.skillPackParts` 的提供方是 `@deepseek-ai/dsh-experimental-skill-pack-components`，它是单独一行：注入组件目录，把每个**交出去的**组件发布成一个部件——它的 id、注册它的那个包的 npm 名、以及那个包自己的版本——并把组件目录自己的订阅连同它的销毁器一起转发出去。是交出去的而不是注册了的：部署没有打开的组件画不出来，所以要求它的技能包保持未激活。

同一行也把激活技能包的视图往另一个方向带，送进侧栏据以构建的那个索引；而 `PartsSource` 长出了它要问的第二个问题——一个视图文件画不画得出来——以及回答它的 `PackMissing` 成员 `view-refused`。[技能包视图那篇](2026-09-18-skill-pack-views-and-consent.zh.md)拥有这两样，也拥有打开数据页的视图要过的那句问话。

## Alternatives considered

**把被扣下的技能包以 `modelInvocable: false, userInvocable: false` 报上去。** 否决。它对两个面都藏住了这个技能包，但这个候选仍然在合并目录里占住那个名字、悄悄盖掉另一个提供方的同名技能；而且它把一个用不了的技能包留在 `ctx.skills.list()` 里，将来任何读那份「不分调用面」的目录的消费者都会看到它。

**给 `packages/skill` 加一个过滤或否决钩子。** 否决。注册表的贡献契约就是 `registerProvider`，而一个过滤钩子会让任何插件都能扣下任何别的提供方的技能——这是比这个包所需要的宽得多的权力，而且是为了一个 experimental 消费者加进核心包里的。

**把通用文件系统提供方挂在技能包根目录上，再对它的目录做后置过滤。** 出于同样的理由否决：没有可供过滤的通道。它还意味着两个提供方在报同一个目录，谁先答谁决定模型看到什么。

**部分激活一个技能包，交出技能本身和其中能解析的那些视图。** 否决。正文描述的是整个技能包；模型照着它走进一个被悄悄丢掉的视图，产出的正是这个技能包本来要防的那种画到一半的页面。

**在这里校验组件 spec。** 否决。一份 spec 里能放什么由组件目录说了算，这道判定的第二份实现会和第一份分叉。这个包解析视图文件，把 spec 原样带过去。

**把一次发放合并进技能包根目录，而不是替换它。** 否决。合并会把退役的技能包和被手工改过的技能包留在原地，于是没人能说清这套部署手里到底是什么。替换让根目录等于这次发放，而先对一遍那一步让重复发放不花代价。

**给安装器配一个 CLI。** 否决：这个仓库禁止包自带 bin，而且只有 `dsh` profile 才启动受支持的 Node 应用。`syncPackRoot` 是发放侧自己调用的一个库函数。

## Consequences

一套部署可以在它需要的插件之前先装技能包，拿到的是一个确定的状态而不是一个坏掉的页面：这个技能包待在未激活，路由说出它在等哪个插件、哪个部件，那个插件一出现它就激活。代价是：一个没挂部件提供方的技能包根目录，带视图的技能包一个也交不出去——这是正确答案，但很容易被当成 bug，状态路由正是为此而存在。

严格读清单意味着带了不认识的 `metadata` 键的技能包会被拒、而不是被部分采纳，于是将来新增一个清单字段，对提前采用它的技能包就是一次破坏性变更。这是有意的：对未知键像 `SESSION_FORMAT_VERSION` 那样保持沉默，正是会让一条写错的要求发出去的做法。

每次读都判一遍让答案始终跟得上现状，代价是每次调用一次目录扫描，在有实测说话之前这个包接受这个代价。
