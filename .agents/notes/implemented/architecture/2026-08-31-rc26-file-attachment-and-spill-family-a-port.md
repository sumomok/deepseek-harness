# Agent Note: Re-landing the file-attachment/spill patch series on the session-controller architecture

Status: implemented

English | [中文](2026-08-31-rc26-file-attachment-and-spill-family-a-port.zh.md)

## Problem

Six `core-patches` entries (`d56a5f7348`, `bb369aa8b0`-equivalent `a5c4d3a29d`, `c82af756b1`-equivalent readback series, `35ca000207`-equivalent `88129b7b44`+`ac91819ac4`+`a285c53cf3`, and the spill series `5cd83e5a14`/`12bc2c55da`) were recorded as SKIPPED during the rc.26 sync's first pass: the upstream base replaced `packages/host/apiproxy`'s flat `RpcErrorDetailsMap`/`rpcErrorSchema` and shared `openTarget` with `packages/api/session-controller`'s namespaced `RemoteError<'domain/code'>` convention and split, per-caller `openWorkspacePath`. Relocating file-block admission, readback, the ENOENT precheck, `probeTargets`, and file-lowering-with-spill onto the new architecture required re-deciding placement and error-namespace choices the original patches never had to make, plus one dependency-graph package (`dsh-attachment-spill`) had never been created in this tree at all.

## Decision

**Relocation, not redesign — every substantive decision from the original patches carries over unchanged.** The `attachment/materialized` idempotency cache, its `ctx.agents.currentInitiator()`-derived ownership, the per-adapter file-lowering placement (never centralized in `agent-loop`, for the same request-reconstruction-invariant reason the original notes for `d56a5f7348` and `5cd83e5a14` already argued), and `AttachmentSpill.Config`'s two fields are byte-for-byte the same design as the original `5cd83e5a14`; only the following are genuinely new judgment calls this port had to make.

**Errors adopt the destination's convention, not the origin's.** Every SKIPPED entry's flat `RpcErrorCode` member becomes a namespaced `RemoteErrorDetailsMap` entry at the consuming package (`'session/path-not-found'`, `'subagent/attachment-unsupported'`), matching the sibling entries already in each file rather than inventing a new scheme.

**`fileBlockIn`/`imageBlockIn` stay separately duplicated in `commands.ts`, not generalized.** The prompt-admission helpers this port added mirror the pre-existing image helpers structurally rather than factoring out a shared generic — refactoring working, unrelated image-admission code was out of scope for a relocation.

**`llm-pi-ai`'s `toPiContext`/`PiiAiAdapter` had already been refactored, independent of this feature, from the original patch's positional-parameter signature (`attachments, onReplayDegrade, maxRequestImageBytes, requestImagePolicy`) to an object-parameter `PiImageRequestContext` interface.** The file-lowering wiring (`d56a5f7348`'s `contentHasFile`/`lowerFileBlocksFromStore` call and `5cd83e5a14`'s `spill` parameter) adapts to that shape as an added `spill?: FileSpillOptions` field on `PiImageRequestContext`, spread conditionally (`...spill === undefined ? {} : { spill }`) rather than positionally, because `exactOptionalPropertyTypes: true` rejects an explicit `spill: undefined` property.

**A new Context-merged service needs a `tsconfig.host.json` project reference before `gen-cordis-catalog`'s static analyzer can discover it**, independent of `tsconfig.base.json`'s path-alias registration (needed for `vitest`/`vite-tsconfig-paths` source-plane resolution) and independent of the package existing in `pnpm-workspace.yaml`'s glob. `scripts/cordis-walk.ts`'s raw-AST scan (`declaredKeys`) finds a `declare module '@deepseek-ai/cordis'` merge by globbing `packages/*/*/src/**` directly, but `@deepseek-ai/dsh-typert-generator`'s `WorkspaceAnalyzer` (`renderedKeys`) resolves types through the TypeScript program rooted at `tsconfig.host.json`'s project-reference graph — a package absent from that graph is declared-but-invisible, which `gen-cordis-catalog.ts`'s partition check reports as "declared in a Context merge but invisible to the rendering projection" rather than a missing-file error. `scripts/gen-tsconfig-paths.ts` does not maintain this file; it stays hand-maintained.

**The package-README doc-standard (frontmatter `kind`/`description`, mandatory `## Summary`/`## Table of Contents`/`### Dev Note` H2/H3 headings) postdates the original `5cd83e5a14`'s README content.** `dsh-attachment-spill/README.md`/`.zh.md` are restructured onto the current template (`Use this package`/`Understand the implementation`/`Further Exploration`/`Model Experience`/`Known Limitations and Deferred Work`/`Dev Note`, following `dsh-spill-local/README.md` as the reference instance) around the original's unchanged Config table, Behavior steps, and already-conformant Model Experience/Known Limitations prose. The Chinese doc-standard gate (`scripts/doc-standard.spec.ts`) requires exactly three heading translations — `## 概述`, `## 目录`, `### 开发备注` — leaving `Use this package`/`Understand the implementation`/`Further Exploration`/`Model Experience`/`Known Limitations and Deferred Work` free to stay English; this port translates all of them anyway to match `dsh-spill-local`'s fully bilingual convention.

**`attachment/materialized` registers into `KNOWN_SESSION_EVENT_TYPES` through `gen-persistence-catalog`'s AST scan, not the `ignorable` marker.** `packages/core/session/src/known-event-types.ts`'s own header states the table is an exhaustive enumeration of every first-party `SessionEventMap` declaration under `packages/*/*/src/**`; `ignorable: true` is reserved for genuinely out-of-repo plugin events. Declaring the event in `dsh-attachment-spill/src/types.ts` and rerunning the generator was sufficient — no manual list edit, no `ignorable` marker.

**`CallId` renamed to `ToolCallId`** everywhere the original patch content referenced it (`dsh-attachment-spill/src/index.ts`'s `ToolCallId(String(attachment.attachmentId))`, both adapters' test fixtures), tracking the rename that landed upstream between when the original patches were authored and this sync's base.

## Alternatives considered

**Generalize `fileBlockIn`/`imageBlockIn` into one shared parameterized helper while relocating them.** Rejected: the existing image-admission code in `commands.ts` was working and unrelated to this port; a relocation task's job is moving and adapting the named patch content, not refactoring code the patch never touched. Deliberate duplication over an unrequested extraction.

**Give `dsh-attachment-spill`'s `resolveSpill` a threaded session-id parameter instead of reading `ctx.agents.currentInitiator()`.** Rejected, matching the original `5cd83e5a14` decision unchanged: a request always lowers file blocks from within the initiating agent's own asynchronous chain, so reading the live `Agent.session` rather than accepting a caller-supplied id structurally rules out the two ever disagreeing.

**Skip translating `dsh-attachment-spill/README.zh.md`'s `Use this package`/`Understand the implementation`/`Further Exploration`/`Model Experience`/`Known Limitations and Deferred Work` headings, since `scripts/doc-standard.spec.ts` does not require it.** Rejected in favor of full translation: `dsh-spill-local/README.zh.md`, the reference template this port followed, translates every heading; matching the gate's minimum rather than the sibling package's actual convention would leave a visibly inconsistent bilingual pair for a cosmetic time savings.

## Consequences

Six commits land the series (one per SKIPPED ledger entry, the file-lowering/spill group as one squashed commit naming both `d56a5f7348` and `5cd83e5a14`); `.claude/core-patches.md` records each entry's new landing point. `tsconfig.base.json`, `tsconfig.host.json`, `scripts/gen-cordis-catalog.ts` (`SERVICE_PAGE`), and `scripts/gen-doc-graphs.ts` (`SERVICE_ROLES`) gained the `attachmentSpill` entries their respective generators require; `packages/bundle/base/{cordis.patch.yml,package.json}` and `python/sdk-runtime/package.json` gained the `@deepseek-ai/dsh-attachment-spill` dependency `pnpm run hygiene` requires for a loaded plugin. Every touched package holds 100% per-file coverage on its changed source; `pnpm exec tsc -b tsconfig.host.json --force`/`tsconfig.client.json --force` and `pnpm run doc-sync` (32/32 gates) are clean.

**Retirement.** Each entry retires independently, on the condition already recorded in its own `.claude/core-patches.md` row (unchanged by this port): when upstream's own architecture gains the equivalent capability at the same seam.
