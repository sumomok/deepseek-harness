# Agent Note: A pack's views are versioned, checked at install, and never share an id

Status: implemented

English | [中文](2026-09-19-skill-pack-view-checks.zh.md)

## Problem

Three things about a pack's views were decided by something other than the pack.

**The view file had no version.** [The pack-views note](2026-09-18-skill-pack-views.md) added `params` and the `{"$param": …}` reference to a file format that states nothing about itself. A pack written against a later format and installed on an earlier build would be read under rules written for something else: the reader takes the keys it knows, ignores what it does not, and the pack activates with a page nobody checked.

**Nothing checked a view when it was installed.** `syncPackRoot` verified the staged tree's file names, extensions, links and paths and then swapped it in. A delivery whose manifest did not parse, whose declared view file was not there, or whose view the deployment could not draw installed cleanly and said so only on `GET /skill-pack/status`, hours after the operator who copied the file had gone. [The archive-install note](2026-09-19-skill-pack-archive-install.md) verified that an archive *is what it says it is*; nothing verified that what it says is a pack root this deployment can offer.

**Two packs claiming one view id were separated by `localeCompare`.** Reconciliation sorted packs with `left.skill.localeCompare(right.skill)` and let the first of them keep a contested id. `localeCompare` answers from the host's ICU data and default locale, so two boxes holding the same packs could offer different ones — and the pack that lost had done nothing wrong except sort second on that machine. The same call decided the scan order of a pack root and the entry order an archive is written in, where it decided the archive's bytes against a note that promises they are reproducible.

## Decision

**`metadata.pack.viewFormat` is the view-file format version, stated once per pack.** An integer, required of a pack that declares views and meaningless on a pack that declares none. `PACK_VIEW_FORMATS` is what this build reads — `[1]` — and a pack stating anything else, or declaring views and stating nothing, is withheld with the new closed-union member `view-format`, which carries what the pack stated and what this build reads. Per pack rather than per file, because a pack's view files ship together and a pack is offered whole; a per-file version would let one pack be half-readable, which is the state the whole-pack rule exists to prevent. The check suppresses the per-view reasons: what each file parsed into was read under the wrong rules, so reporting it would be reporting a reading nobody should trust.

**A delivery is verified as a pack root before it becomes one.** `verifyStaged` re-reads the staged tree with the pack root's own reader and holds every pack in it to four rules: the manifest parses, a pack declaring views states a format this build reads, every declared view file is there and is a view, and — where the caller composes a surface — that surface will draw it. Any failure refuses the **whole** delivery with a typed `PackInstallRefusal` (`pack-manifest`, `pack-view-format`, `pack-view`, `pack-view-refused`) naming the pack, the file and the reason; the staging sibling is removed and the old root stays byte-identical. Whole rather than per pack, because a delivered set is one statement of what a deployment holds, and installing the readable half of it would leave a root that matches neither the old delivery nor the new one.

**A requirement this deployment does not meet yet is not a refusal.** A pack naming a plugin, a part or a platform version that is not here installs, reconciles inactive, says on the status route what it is waiting for, and activates by itself when that row is composed — the behavior [the archive-install note](2026-09-19-skill-pack-archive-install.md) shipped and its specs pin. So the catalog judgement is asked only for a pack whose other requirements are already met: `DEFERRED_REQUIREMENTS` names the four kinds that mean "waiting", and a status carrying any of them contributes no refusal. The line is what can still change. A plugin can arrive; a malformed view file cannot become well-formed by itself.

**The catalog judgement is a parameter, because it is the only honest landing point.** `skill-pack` must not import `component-surface` — [the reconciler note](2026-09-18-skill-pack-reconciler.md) draws that boundary in both directions — and a delivery-side caller of `syncPackRoot` has no catalog at all. So `syncPackRoot(root, delivery, verify)` takes `VerifyStagedPacks`, which receives every staged pack already read and answers the first refusal. `SkillPackRegistry` supplies one built from `ctx.skillPackParts`, the seam that already answers exactly this question for reconciliation; a caller composing no surface passes nothing, the four structural checks still run, and the catalog's judgement is deferred to reconciliation exactly as it is for a pack somebody wrote into the root by hand. `$param` resolution travels with that judgement rather than beside it, because `applyViewParams` is the component surface's own and a second implementation here is the drifting second opinion the reconciler note refused.

**Two packs claiming one view id are both withheld.** The rule is judged over the whole root after every pack has been judged on its own: among the packs this root would otherwise offer, an id claimed more than once withholds every claimant with a `view-id-conflict` member naming the id and each other pack. A pack inactive for another reason claims nothing, so a pack nobody is offered cannot withhold one that would be. `PartsSource.judgeView` therefore loses its `claimed` argument: the deployment's own `configuredIds` are still refused there, because the deployment's views own their ids, and pack-versus-pack is a question only the pack root can see both sides of.

**Order is by code unit.** `compareCodeUnits` replaces every `localeCompare` in this package — the skill-name order of `statuses()`, the directory-name order of a pack root scan, and the path order `buildPackArchive` writes entries in. Two hosts holding the same packs now answer the same list and write the same bytes, whatever ICU data and default locale they have.

**`buildPackArchive` holds a set to the rules about its files and reads none of them.** Its promise is narrowed to say so: names, paths and extensions are checked where the archive is written, and the manifest, the view format and each view file are judged by the deployment that installs them, which is the side that has the surface those views are drawn on.

**The pack-root watcher re-reads the root when it arms, the way the delivery watcher already does.** A pack that lands between the watcher's own first listing and its native stream starting is in neither — the listing is ignored (`ignoreInitial`) and the stream had not begun — so before this it was offered only after the next unrelated change to the root. A measured probe of this workspace's `chokidar` on macOS loses that first event for about one arrival in forty; the reading at arm time is what makes the arrival itself, rather than a later one, the thing that offers the pack.

## Testing

Unit suites pin the format (a pack reading, a pack stating a version this build does not read, a pack stating none, a pack declaring no views under any version, and the sentence each earns), the install checks over both the packs route and the archive route (an unparseable manifest, an unknown and an absent format, a declared file the delivery does not carry, a file that is not a view, and each of them leaving the root byte-identical with no staging sibling left behind), the pack whose part is absent installing anyway, the staged set every caller's surface is handed, the surface's refusal naming pack, file and reason, the unchanged-root fast path asking that surface nothing, and a delivered directory carrying no `SKILL.md` installing as the non-pack it is. The id rule is pinned from four directions: both packs withheld and each naming the other, the same answer whichever order the packs arrive in and whatever their names sort like, every claimant of every contested id named, and a pack withheld for another reason holding no id away from one that would be offered. Ordering is pinned with mixed-case and CJK names at both the reconciler and the pack-root scan.

The watched-root case makes its pack arrive again on every poll, directory and all, rather than once. A watcher still arming loses the event for a directory created in that moment and then reports nothing about a directory it never registered, so a single arrival is a single chance at an event the operating system owns; the case asserts that the pack reaches the catalog without a restart, and the registry's catalog is invalidated by nothing else here, so a composition whose watcher never fires still fails.

Real Loader compositions cover both sides of the seam. `skill-pack`'s own composition delivers an archive into a watched directory with a parts source mounted: a view that source refuses is refused by name and the root keeps what it had, and a pack waiting for a plugin installs with `plugin-absent`, `part-absent` and `view-refused` all on the route. `skill-pack-components` boots the component catalog, the pack root and the adapter together and delivers through the same directory: a view naming a component this deployment does not offer and a view naming an undeclared `$param` are each refused with the catalog's own sentence while the sidebar keeps the views it had, and a delivery this deployment can draw reaches the sidebar. Per-file coverage of `src` across `skill-pack`, `skill-pack-components` and `component-surface` is 100%.

## Alternatives considered

**Put the version in each view file.** Rejected. A pack's view files ship together and a pack is offered whole, so a per-file version buys the ability to describe a state — half a pack readable — that the whole-pack rule already refuses to have. It also puts the compatibility statement in the place a pack author is most likely to copy-paste, and multiplies the number of places a format bump has to touch by the number of views.

**Default an absent `viewFormat` to 1.** Rejected. The point of the field is that a build meeting a file can say whether it knows the rules the file was written under; a default answers "1" for every pack that never heard of the field, including the ones a later format will produce. The pre-release stance settles the cost: a pack adopting the field now is an edit to one line of frontmatter, which is cheaper than a silence that cannot be taken back.

**Refuse the install for a pack whose required part is absent.** Rejected, and it is the rule this note is most careful about. The archive-install note shipped the delivery-before-its-plugin case deliberately: a set that installs and waits is how an operator stages packs ahead of the rows they need, and refusing it would make the order of two unrelated operations load-bearing. The discriminator is whether anything that arrives later changes the answer.

**Refuse only the offending pack and install the rest.** Rejected. A delivered set is one statement of what a deployment holds; installing part of it leaves a root that is neither the old set nor the new one, and the `retired` list in the result would name packs that were retired for a reason nobody recorded. Refusing whole keeps "what does this deployment hold" answerable by one file.

**Import the component catalog into `skill-pack` and judge views there directly.** Rejected. It is the dependency edge the reconciler note refused in both directions, and it would make a package that must compose without any component surface carry one. The parameter costs three exported types and gives a delivery-side caller a way to supply its own.

**Implement a `$param` check inside `skill-pack` so the structural pass covers it without a catalog.** Rejected. The notation's rules — a whole value or nothing, a scalar only, never a list item — are `component-surface`'s, and a partial copy here would accept what the real pass refuses and name different paths when it refused. The judgement travels with the catalog instead, which is where the rest of the same pass already is.

**Keep the first pack's claim on a contested view id and withhold only the later one.** Rejected. "Later" had to mean something, and every candidate is a property of the machine rather than of the packs: the filesystem's listing order, the locale's collation, or the order a delivery happened to be written in. Withholding both is the only answer that is the same everywhere, and it puts the correction where it belongs — one of the two packs has to change its id, and the status route names both so whoever owns them can see which.

**Sort by `localeCompare` with a fixed locale, such as `en-US`.** Rejected. It still depends on the ICU data the host's Node was built with, still answers differently for the same strings across versions, and buys a reading order nobody reads: `statuses()` is consumed by a route and by a reconciler, not by a person scanning an alphabetized list.

**Verify while staging, per file, instead of re-reading the staged tree.** Rejected for the reason the archive-install note already gave about digests: a check made as each file is written makes a half-staged tree the normal state of a failed install. Re-reading the finished tree also checks the thing that will actually become the root, including whatever the write itself did to it.

**Verify inside `buildPackArchive` so a delivery console learns early.** Rejected for this change. The writer holds packs in memory and the reader reads a directory, so the checks would need a second implementation over a file map, and the one check that matters most — will this deployment draw the view — is answerable only where the catalog is. The README records what the writer does and does not promise.

## Consequences

**Bought.** A delivery that cannot become a working pack root is refused at the moment somebody copies it in, with the pack, the file and the reason in the process log, instead of becoming a root whose packs are quietly absent from every catalog. A pack's view files now say which rules they were written under, so a later format is a refusal naming two numbers rather than a silent half-read. And what a pack root offers is the same on every host that holds it: two packs contesting an id are both withheld, by the id rather than by the locale, and the three orderings this package produces no longer depend on ICU.

**Paid.** A pack is now a stricter thing to deliver than it was: a directory with a `SKILL.md` and no `metadata` block installed into a pack root before and is refused now, which is correct — it was always reported `manifest-invalid` and offered to nobody — and it is a change every fixture and every delivery console has to make. Every pack declaring views carries one more line of frontmatter. Two packs that used to resolve an id collision silently in favor of the first now both go dark, which is louder and, on the day it happens, more disruptive: it is the price of the answer not depending on the machine. And a delivery console cannot pre-check any of it, because the surface that decides is the deployment's; the README records that as the limitation it is.
