# Agent Note：客户自己的另外三个组件——表格、筛选条、指标球

Status: implemented

[English](2026-09-05-content-component-library-v1b-2-originals.md) | 中文

## 问题

[纳入原件那一片](2026-09-05-content-component-library-v1b-1-seam.zh.md)是拿 tgz 里最小的那个组件把整条缝走通的：`TcFormDetail`，纯数据进，什么都不发，什么都不取。它有意没碰的，恰恰是这批库之所以值得纳入的全部内容。剩下三个导出，每一个都推翻了那一片被允许做的一个假设。

- **`TableDetail` 发七个事件，而且每个事件把行还回来的方式都不一样。** 选中事件带的是深拷贝，等到手势上报时调用方交出去的那些行对象已经不在了；单元格点击按引用带回；而点击行名那一下会在冒泡途中撞上 el-table 自己的单元格处理器，所以一次手势发两个事件。
- **`TuQueryCondAdv` 一个事件都不发。** 用户编出来的东西只能靠在挂载后的实例上调 `getData()` 读，而本仓自己那座桥只往一个方向传数据。它还只在 `data()` 里读一次属性表，之后不 watch。
- **`TcProcessBall` 是一条定时器链**，唯一的停止点是构建补丁加上的 `beforeDestroy`。

而属性本身也已经超出了那套 schema 联合能表达的范围。表格的行按它的列去读什么来定键，所以字段名是模型自己挑的，不是目录能事先列出来的一张表；列上带着一个是非位；单元格渲染器按名字从固定集合里选；单元格的配置里带着颜色。

手势通道还有第二个问题，而且在两个组件各自声明多个动作之前根本看不见。[回程通道](2026-09-04-content-component-library-v0.5-return-channel.zh.md)按 `(entryId, nodeId)` 折一格，而渲染器在 `idle` 与 `refused` 之外的每一个状态里都拒绝下一次手势。一个组件一个动作时，这完全正确。四个动作时，一次勾选就占了这一格，它下面那颗行按钮在这条条目剩下的时间里全被拒；两个动作时，筛选条在用户第一次改完一处时就把自己的提交按钮禁掉了。两个包各自的测试怎么跑都是绿的，因为哪个包都不同时握着这两半。

## 决定

**三个目录条目和三个渲染器，一次改动一起进。** `toy.table`（`TableDetail`）、`el.filter-bar`（`TuQueryCondAdv`）、`el.metric`（`TcProcessBall`）同时进 `COMPONENT_CATALOG` 与 `COMPONENT_RENDERERS`，因为 `CatalogId` 是从目录派生的，而座位那句 `satisfies Record<CatalogId, ComponentRenderer>` 在目录点名一个这一行画不出的组件的当天就编译不过。tgz 停在 `0.3.1` 没动；它四个导出现在全都有了条目。

**只有 `wake` 才是这一块的答案。** `answersBlock(componentId, actionId)` 从目录上读那一档，通道的两半都问它：折叠不为 `context` 或 `silent` 的手势写格子，座位也不在页面那张等待表里给它记一行。于是一块界面画出来的状态，就是它被摆出来要等的那个答案的状态，而别的手势照样上报、把这一块留在原样——表格能在一次 `operation` 还在路上时继续接受勾选和排序，筛选条能在用户敲字时保住自己的提交按钮。与其说这是一条新规矩，不如说它本来就写在档里：`wake` 的定义就是「这是你停下来等的那个答案」，而块自身的状态是唯一没有去读这条定义的地方。

回程那一片记下的两条限制因此被顺手答掉，而不是另起一份工作。`silent` 档的动作不再让那一块说对话已经收到，因为它根本没有格子可以说话。而按块一格现在是准确而不只是勉强可用：一个组件至多声明一个 `wake`，所以把键按 `actionId` 长一位这笔账，由某个组件的第二个 `wake` 来付。

**收紧那一趟多了三种读法，其中两种正是表格要的。** `PropsFieldSchema` 长出 `boolean` 与 `record`，而 `ArrayFieldSchema.item` 从「只能是对象」放宽到任意字段 schema，这样一次 `select` 才能带一串裸数字。`record` 是一个键由调用方自己决定的对象：键有字母表和长度，键有数量上限，值只能是标量。表格的一行就是它，单元格渲染器的配置也是它。

**`record` 自己声明自己的收紧读法，不继承所在组件的。** 组件级的 `sanitize` 规则按属性名在整棵树上匹配，这对组件自己声明的属性是对的，对 record 的键是错的，因为那些键是数据：`color` 既是单元格渲染器的一个配置键，也完全可能是别人记录里一个再普通不过的列。所以「把 `relatedComponentObj.color` 读成颜色」这条规则坐在那个 record 上，而不是坐在 `toy.table` 上。

**`describeCatalog` 改成了全递归。** 它此前只写一层，于是 `tableConfig{gridItems}` 会告诉模型表格有列、却一个列字段都不点名——每个属性一次拒绝去试出来。触发器在这一片存在之前就已经写在那个函数自己的注释里。`MAX_SPEC_DEPTH` 是从目录量出来的而不是写死的，所以表格多出来的那两层把它正好撑宽了它们需要的那么多。

**匹配策略表用编辑器那一张，十六种一个不少。** 条件编辑器画十六种；组件库自己的 `matchUtil` 算得了十五种。只声明十五种看着像是谨慎的选择，其实是错的：第十六种用户照样挑得到，然后宿主把整次提交的筛选整条拒掉——人用控制台自己提供给他的策略编出一个筛选，被告知没能记下来。本包不评估任何条件；那条通知是「用户要的是什么」的陈述，而被要求去跑 `NOT_BETWEEN` 的后端自己回答自己。

**上报的每一行都是下标，永远不是行本身。** `TableDetail` 把拿到的列表冻住并把同一批对象还回来，所以一次手势带的是它在 `displayValueList` 里的位置，宿主再回到模型自己写下的那次调用里去读那一行。组件把行还成拷贝的那一处——选中事件——渲染器改从挂载后的实例上用 `doGetSelection()` 读身份。数据本身一点都不从块里往回走。

**桥多了一个把手，而且只朝一个方向用。** `VueBridgeOptions.instanceRef` 在块挂载期间发布 `root.$children[0]`——组件本身，不是桥自己的根。它是为那两个靠方法作答的组件而存在的，它的文档写明渲染器用它来读：在它上面调任何会写的东西，就是绕开两个框架约好的那份 prop 记录。`ElDatePicker` 在同一次改动里进了弹层表，因为日期属性上的筛选条会画一个，而那张表之所以是封闭的，正是为了让第四种弹层必须被有意加进来。读这张表的那趟清扫仍然没有调用方：它只在 `visible: false` 时跑，而这条内容栏是把离场的块卸载掉，今天关掉弹层的是卸载。

**渲染器写死的那些，决定的是这一块「是什么」，而不是它显示什么。** 表格自带的修改与删除按钮被摘掉（它们发的那个事件这里没有任何动作承载），翻译值链接被关掉（没有任何东西提供它们要解析的那份值，而留着它会让名称列无论调用怎么写都是个链接），而选择列在调用没要之前根本不出现。筛选条永远收到 `metaConfig`（没有它，组件会自己去取属性表，而纳入的这个构建对那次取数的回答是抛异常）、一份完整的 `confStyle`（组件读它三个字段时一个都不设防），以及每条声明了 `dataType` 的属性旁边写死的 `ifChange: '0'`（组件只对这一类属性去看 `dataType`）。这些没有一条是模型该挑的属性，因为它们没有一条是关于数据的事。

**筛选条的发送按钮是 React 这边的，而属性一变这一块就重挂。** 组件自带的按钮是加一行和删一行条件，没有一个的意思是「我编完了」。而 `metaConfig` 在组件创建时被拷进它自己的 data 且之后不 watch，所以一次带着不同属性的调用会把 Vue 根重挂，而不是把上一批属性留在屏幕上——反正对一次新调用，用户期待的也正是这个。

## 考虑过的其他方案

**只声明这个库算得了的十五种匹配策略。** 把失败的样子写出来之后就否掉了：无论目录怎么写，编辑器都画十六种，于是第十六种就成了「用户挑得到、而宿主为此把整次手势静默拒掉」的那一种。让**编辑器**收窄是另一条让两边一致的路，它需要把那十五个 id 放进 `component-kit`，而这个包不能 import 目录——依赖方向是 `component-surface` 依赖它而不是反过来，而且宿主那半边绝不能碰到任何摸 element-ui 的模块。把那张表抄第二份，正是本仓那道克隆门禁存在的意义。

**把手势折叠的键改成 `(entryId, nodeId, actionId)`。** 这一片先不做，而它就是需要它那天的解法。它要求 `ComponentRendererProps.state` 变成按动作查的一个函数，那是对这一行每个渲染器、对确认条的测试、对投影存下来的格子和它的 wire schema 的一次改动。今天它买不到任何东西：一个组件至多声明一个 `wake`，别的手势根本不进格子。触发器是某个组件的第二个 `wake`。

**表格里什么都不按 `state` 上闸。** 这是另一条阻止「一次勾选就禁掉行按钮」的路，否掉是因为它把状态的用途整个扔了：行内操作是 `wake`，模型把那颗按钮摆在那里就是要人按的，而一次按下既没有答复也没有可见的进度，正是整条回程通道当初为之而建的那种情形。

**让渲染器把那十五种策略作为自己的常量传进去。** 同一张表抄两份，否掉。见上。

**在 schema 上加 `default`，由收紧那一趟把它落实。** 曾作为「组件自带的默认值与目录不一致」的通用解法考虑过——`attrEqEnums` 就是那个实例。否掉，理由是为解决一个个案而引入一套机制，而让两张表本身一致根本不需要任何机制。复核触发器是第二个「组件默认值宿主接不了」的属性。

**用 ACP 快照场景驱动一次手势。** 这不是被否掉而是做不到，理由[回程那一片](2026-09-04-content-component-library-v0.5-return-channel.zh.md)已经记下：`/component-action` 只经 `remote.commands` 抵达宿主，而 ACP 协议没有命令方法。那条泳道新增 `show-table-turn` 与 `show-filter-turn` 来钉摆放和描述；手势归浏览器泳道。

**上报的行按它第一列的值来称呼，而不是按下标。** 按整条通道立身的那条理由否掉：浏览器发上来的一切都是文本，用它拼出来的通知就是一块界面替用户说话。下标是拿去与模型写下的那份 spec 对解的，通知里那个名字从那里来。

**集成才发现、任一半都发现不了的那件事。** 两个包各自写、各自测，各自都绿。合到一起，筛选条根本不能用：它的 `change` 手势在用户每改完一处时上报一次，占掉了这一块唯一那格，而提交按钮在 `idle` 与 `refused` 之外的每个状态里都是禁用的。表格是同一个缺陷轻一档的样子——一次勾选就让行按钮在这条条目剩下的时间里按不动。哪个包的测试都看不见它，因为决定它的那条规矩（哪些手势进格子）在一个包里，而读它的那条规矩（哪些状态可按）在另一个包里。

**这一片复审改掉的东西。**

- **通知按一列表格根本没画出来的列去称呼一行。** `tableColumns` 把声明过的列全部交出去，于是把第一列藏起来的调用，它的行在智能体那边和用户那边都是按屏幕上谁也看不到的那个值称呼的。现在读的只是画出来的列，对着藏起来的列排序也因此什么都不说；把所有列都藏掉的表按位置称呼它的行，走的是本来就有的那条回退。
- **AND／OR 控件默认开着，而它的答案哪里都不去。** `showMatchMode` 默认 `true`，于是不写 `confStyle` 的调用——也就是通常那种——画出一个提交动作根本不带的控件。现在块不点名就不画；画了它的那张条会把 `matchMode` 连同条件一起提交，通知在两种语言里都说出用户选的是哪一种。
- **一次空提交被答成了故障。** 条上一开始就摆着一行空条件，所以用户能做的第一次按下提交的是零条条件，被动作自己的 `minItems` 拒掉，块因此挂上「这个动作没能记下来」。现在手里没有一条完整条件的按下什么都不报。
- **一张满行的表全选出去，谁也收不到。** 表格能画到五百行，而它的表头复选框一次勾中全部；一次勾选却最多只带四百个下标——那是从单份动作文档的字节上限推出来的数。于是把超过四百行的表整个勾上，谁也收不到；又因为勾选是 `context`、不占格子，屏幕上也没有一个字说这件事。现在这两个数是同一个：勾选上限**就是**行数上限，字节上限抬到 4096 去装下这次手势写出来的文档。
- **东西太多被报成了「哪儿也没去」。** 所有解不开的动作答的都是同一句话，于是勾多了、写多了的用户被告知这次点击没能记下来——恰恰是那句什么也没告诉他能做什么的话。现在「超过某个声明上限」的 payload 与「本来就不是这个东西」的 payload 分开了，前者答的是那句说内容太多的话。
- **筛选条超过十条之后，之后每一处编辑都被拒。** 条件编辑器加行没有上限，而 `change`——它在用户每改完一处时做的那次静默上报——声明的上限和一次提交一样。于是第十一行让用户每改一处就吃一次拒绝，而那份上报他从来没有主动要发。现在编辑的条数由「一个编辑器能拿住多少」限住，不由「一次提交带多少」限住；提交仍然是十条，超了就说出来。
- **给用户看的那行把 JSON 转义原样端了回去。** 条件的值是用户自己写的字。给智能体的那句仍然转义——值里的任何东西都不许关掉包着它的引号；给用户的那行把他写的原样读回来，凡是会让它跑出一行的字符换成空格。
- **一句话里有一个引用值被清洗了，它的邻居没有。** 转义和「读回一行」只用在了条件的值上，而条目标题、某一列的表头、按钮上的字、用来称呼一行的那个单元格，进的是同两句话却一个字没动——于是它们里面的换行或双向覆写字符照样把用户读的那一行重排。现在通知引到的每一个值都走同一个 helper，这句话里再没有哪个值的待遇和它邻居不一样。
- **三种颜色没有任何写法说明。** 它们是收紧那一遍读作颜色的字符串，写错的值是被丢掉而不是被拒绝，所以写 `red` 的模型丢了这个属性、还什么都没被告知——而描述那一段承诺过「拒绝会点名你发了什么」。现在声明了读法的属性会说出它的写法，记录里声明了读法的键同样如此。
- **关于 `change` 手势的那段陈述是错的。** 它写的是每敲一个字上报一次。编辑器的值控件绑的是 `change` 而不是 `input`，所以抵达智能体的是用户每改完一处上报一次——选完属性、选完策略、离开值输入框。这段陈述支撑的那个决策没有变；钉住它的那条测试现在用浏览器自己的 input 与 change 事件驱动值输入框，而不是走 `setData`。
- **浏览器那条线上的行带着一个理由并不成立的标识。** 每一行 fixture 都有 `int_id`，注释说 el-table 按它给行做 key、多选一行以上少不了它。选择上报的是从挂载实例上读回来的位置，去掉这个字段那条线照样全绿；字段和那段解释一起删掉了。
- **`visible` 与弹层清扫仍然没有调用方**，而这份 Note 读起来像是日期选择器的那一条给了它们一个。桥自己的文档现在写的是实情：这趟清扫是给「把块藏起来但仍挂着」的落位包用的，这里没有这样的落位包，而这条栏卸载一块时，把弹层摘掉的是 element-ui 自己的 `beforeDestroy`。
- **每勾一行都在对话里回一句。** handler 把所有进了收件箱的投递都答成 已记下，你下次发消息时对话会看到。，于是两种 `context` 手势——勾一行、点开一行——每发生一次就在聊天里多一行，夹在智能体的回复中间。投递现在是四种而不是三种：没赶上轮次的 `wake` 保留那句话，因为按下它的人在等一个回答；`context` 的通知报 `context`、结算时不带文案，而不带文案的结算正是聊天行什么都不画的那一种。
- **点任何一格都被当成点开了一行。** `table-cell-click` 是 el-table 自己的事件，绑在每一格上，于是调用没让它可点开的表格，用户碰一下就报出「点开了一行」。这次上报现在以 `isNameClick` 为门——决定一行到底能不能点开的正是这个属性——而要求了行可点开的表格，点行里任何一格照样算，因为组件没有比它更细的事件。
- **没被认领的 `context` 通知会无上限地堆。** 每勾一次注入一条，之前那条没有任何东西去掉它，于是用户在表格上干活就是每勾一次排一条，每一条都被下一条改写，而收件箱自己没有上限。同一个手势——同一条条目、同一块、同一个动作——再发生一次，现在会在上一条还没被认领时用 `Inbox.replace` 把它替换掉，智能体日志的记账把它算作仍在等待的工作；已被认领的通知永远不改写，`wake` 永远不被替换。
- **记录里那个收紧过的键读起来像必填。** `describeRecord` 写的是 `color: #RGB|…`，而同一行里别处每个可选属性都带着 `?`；模型为一份自己决定键名的记录读到的唯一写法说明，因此说这个键非有不可。

**Known Limitations，写在两个 README 里。**

- 条件编辑器画得出一种组件库里没人算得了的策略。它作为「用户要的是什么」上报；后端拿它怎么办，是那个后端自己的回答。
- 筛选条只有在调用点名要的时候才画 AND／OR。画了它的那张条会把模式连同条件一起提交；不管画不画，这个包都不去算这份筛选。
- 五百行的表很少能塞进 spec 的字节上限，拒绝语句会按字节数说出来。塞得进的那些，整个勾上永远送得出去。
- 条件编辑器自己没有上限，于是第十一条条件建得起来、屏幕上没有一个字说它提交不了；提交它的那一次按下答的是那句说内容太多的话。要拦住编辑器，上限得在 `component-kit` 那一侧，而一个组件行不能反过来 import 一个落位包。
- 纳入组件自带的中文——表格的 `操作` 表头，编辑器的 `属性名`、`匹配策略`、`属性值`、`增加`——不跟随界面语言。
- 表格按固定高度画、没有分页；`isNameClick` 只对名为 `zh_label` 且以 `display_default` 画的那一列生效；筛选条的值一律按文本输入，因为纳入的构建把七个会自取选项的控件换成了禁用替身。
- `TableDetail` 里函数形态的属性——按行控制按钮可见性、行样式、权限检查——不提供，也提供不了：那套 schema 联合没有任何成员能表达一个函数。
- 指标球的背景写成颜色关键字时渐变会退化成一个纯色球，而收紧那一趟本来也不放行这种写法。
- 手势折叠仍然按块而不按动作；今天这是准确的，因为一个组件至多声明一个 `wake`。
- 一次什么都没填的按下看上去就是按钮没反应：筛选条的第一次按下提交的是那一行空条件，什么都不上报，也什么都不画。要把按钮置灰，就得让它跟着 `change` 手势带的那个计数走，而那个时序两个包必须谈好。
- 一块界面对所有拒绝都说 这个动作没能记下来，可以再试，而旁边的聊天行可能说的是 内容太多了，少选几项或写短一些再试。要在块上把它们分开，得给 `ComponentActionState` 加一个成员，那是跨两个包的契约。
- 那张记着还没被认领的 `context` 通知的表按活着的智能体记、重启即忘，和唤醒预算一样：重启之后的第一次勾选会在日志里那条通知旁边再排一条。
