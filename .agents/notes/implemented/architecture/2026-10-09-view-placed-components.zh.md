# Agent Note: 只能由写下来的视图摆放的组件，以及把它们接到数据页上的两个输出

Status: implemented

[English](2026-10-09-view-placed-components.md) | 中文

## Problem

人真正在里面干活的那个数据页，在表单里编辑记录、在卡片里显示一条记录，而两者都画在页面里面：新增和修改表单会盖住它们要编辑的表格，所以视图没法给它们排位置。表单页是一个独立组件，好让视图把表格、表单和卡片并排摆开。

表单是一条写入路径。它用访客自己的凭据保存，而数据页已有的那条规则是：模型的调用摆出来的页面以只读打开（[数据页那条 Note](2026-09-19-data-page-replaces-toy-crud.zh.md)）。执行这条规则的方式是判定调用里的数据页节点，所以调用里的表单页就是一块没有数据页节点可判的可写块：单独摆，或者搭在一次读 `dataSource` 的调用里——那条路在用户同意一次读取之后，把整份 spec 追加成 `content-component/resolved`，抽取器照画。用户回答的那张审批卡，描述的会是一次读取。

表单和卡片还需要知道是哪一条记录。只有页面知道，而且是在它自己的绘制里：用户按的是哪个按钮、点的是哪个名称。目录里本来就有让一块读另一块所报内容的办法——输出加 `$from` 绑定——但数据页没有声明任何输出，它的每个属性也都拒绝绑定。

## Decision

**摆放是组件自己的属性，只经一个判断读取。** `ComponentCatalogEntry` 加上 `placement?: 'view'`，只由 `placedOnlyByViews` 读，`viewPlacedNodes` 挑出一份 spec 里的这类块。它在做出每个决定的那次操作里执行。工具在问用户任何事、自己写下任何记录之前拒掉带着这种块的调用，两条路都拒——自己写行的调用和读 `dataSource` 的调用——经由 `refuseViewPlaced`，无论部署提供不提供这个组件，都是同一句。它读的是调用写下的 spec，在校验判这块的属性之前，所以拒绝从不列出这个组件收什么。抽取器的 `recordsEntry` 只从 `content-component/shown`（视图被点击时写下的事件）里画出带这种块的 spec；带着它的 `tool/call`、`tool/ptc-dispatch-start` 与 `content-component/resolved` 都不记条目，所以被拒的调用留下的记录永远画不出这块。`describeCatalog` 与 `offeredEntries` 把这种组件挡在描述之外，也挡在「值得注册工具」的判断之外，视图判定则放行它。`ComponentCatalogRegistry.offered` 留着它，因为 `skill-pack-components` 按这里能画什么来回答技能包的 `requires.parts`，而视图画得出它。`dataPage: false` 把表单页和信息卡同数据页一起扣下（`DATA_PAGE_GATED_IDS`），`componentNotOffered` 列出这个设置不管的那些组件。

**页面声明两个输出，两者都是状态。** `editing` 是 `{mode (add|modify), type, id?, name?}`，页面的新增按钮或某一行的修改按钮正在编辑的东西；`opened` 是 `{id, name?, type}`，名称或关联链接打开的那条记录，由关联链接打开时 `type` 是关联的那张表。两者都不带计数：再按一次同一个按钮发出的是同一个值，座位交给读它的块的也就没有任何新东西。声明把撤回定为发出 `undefined`，座位的输出合同写明了这一点：`opened` 在页面关卡、清空、翻页时撤回，查询不撤回；两者在它们点名的那条记录被删除时都撤回。两个输出都带 `readers: 'view'`，因为收得下它们的每个属性都在只能由视图摆的组件上，所以描述把它们和那些组件一起略去；一条目录测试把这个声明和收得下每个输出的属性对上。一次调用能摆的块绑数据页时，两个输出都找不到：引用只在那块读得了的输出里查，而那一个都没有，所以拒绝说页面什么都不报，也不写出任何一个输出的字段。

**两块只收绑定，只在判视图的地方判。** `toy.form-page` 收 `relatedMeta`，写成字面值，因为保存按它上报、并拿它和页面的表比较，以及读 `editing` 的 `request`。`toy.info-card` 收读 `opened` 的 `record`，以及 `infoCardTabs`。`PropsField.bindsFrom` 为 `request` 与 `record` 点名唯一的组件、唯一的输出，以及拒绝时说的理由。两个属性在 schema 里都是可选的，所以绑定还没有东西可代入的块，拿到的是不含它的属性，而不是被画成座位的等待提示；`judgeDataPageParts` 要求视图写它们，并且写成那条绑定。这条规则不放在共用那遍判定里，因为浏览器座位是先把解析出的值放到绑定的位置、再跑那一遍的，放在那里的「只收绑定」会把每一块解析过的都拒掉。调用碰不到这个属性，因为摆放规则先把它拒了；一条目录测试保证每个带 `bindsFrom` 的属性都属于只能由视图摆的组件。

**视图规则拒的是自相矛盾的文件，对访客什么都不决定。** `judgeDataPageParts` 在共用那遍和页面自己的判定之后跑：每个带 `bindsFrom` 的属性都是绑到同一视图里某个 `toy.data-page` 块的那条绑定、整个读；表单页至多一块，存进页面的表，旁边的页面 `readOnly` 为 `false`，且页面自己的新增和修改表单都关掉；旁边没有表单页的页面，不能关掉某个表单却留着打开它的按钮；信息卡至多一块，旁边的页面关掉自己的侧边卡片。每一条挡的都是一次按下打开两个表单、一次点击打开两张卡片、表单存进视图没点名的表、或者按钮什么也打不开。访客能不能新增或修改，仍然是后端按每次请求答复的；页面画出哪些入口，仍然是宿主对访客权限的判定；这里没有任何规则读这两样。

**值只朝一个方向流，按输出来论证。** [摆法与绑定那条 Note](2026-09-05-content-component-library-v2a-layout-and-bindings.zh.md) 把单向流动建立在发输出的组件之上。数据表和数据页发输出，声明的每个属性都拒绝绑定；表单页和信息卡上报动作、收绑定，什么输出都不发。那条把每个输出绑进每个发输出组件的每个属性的测试，覆盖了数据页。

**先声明，后画出。** 两个条目放在 `COMPONENT_KIT_VIEW_ENTRIES` 里，与那六项 `COMPONENT_KIT_ENTRIES` 分开，因为 `component-kit` 注册一个条目时会连同画它的渲染器一起注册，而它两块都不画；在它画之前，点名其中任一块的视图都会以「点名的组件不在本部署里」被拒。数据页还声明了 `deleted` 与 `batch-modified`，用的是它别的动作已经在用的上限：写成功和没写成的条数、至多五条的名称，批量修改再加改了哪些属性名，从不带值。

**没有会话事件，没有格式变化。** 这两个输出永远到不了日志和模型请求：绑定的值在页面里为一次渲染解析，和所有输出一样。新动作走命令注册表本来就会记下的内容组件动作路径。`ComponentSpec` 与 `ComponentNode` 不变，抽取器的数据版本也不动：没有这两个条目的构建会拒掉点名它们的 spec，所以旧构建存下的记录里不会有它们。

## The decision gate

| Gate | Answer |
|---|---|
| 0. 哪条既定原则已经决定了它？ | **在做出决定的那次操作里执行它** 决定了摆放在工具的两条路上、在抽取器挑记录时检查，而不是靠把组件挡在描述之外。**模型可见 ⟺ 记入日志** 决定了这两个输出就是输出、任何请求都不带它们，而新动作走被记录的动作路径。**配错要大声失败** 决定了自相矛盾的视图在加载时被拒，而不是画出来带一个死按钮。数据页那条 Note 定下的「宿主不持有按钮名单、不做权限检查」决定了视图规则能看什么：只看文件，从不看访客。 |
| 1. 新增了多少条永久表面？（先数，再列） | **加 17。** 三个目录声明字段（`ComponentCatalogEntry.placement`、`ComponentOutput.readers`、`PropsField.bindsFrom`）；两个组件 id（`toy.form-page`、`toy.info-card`）；数据页上的两个输出（`editing`、`opened`）；数据页的两个动作 id（`deleted`、`batch-modified`）；四个属性（`relatedMeta`、`request`、`record`、`infoCardTabs`）；两块新组件上的四个动作声明，用的是数据页已经在用的 id（`added`、`modified`、`card-open`、`card-close`）。座位的输出合同多了一句：发出 `undefined` 即撤回。会话事件类型、路由、服务、工具、配置字段、依赖、审批闸，**全是零**。 |
| 2. 能证明它对的最小版本 | 目录和每一道判定，在任何渲染器存在之前，用装着这两块的目录测：摆表单页的调用在两条路上都于问用户任何事、工具自己写下任何记录之前被拒；抽取器只从视图的点击里画出它；三块的视图被接受，每一种接错都在它的路径上被拒；模型读到的描述，有没有这两块都一样。把它们画出来是下一块工作，它给本包带来的不止是这两个条目并进那六个已注册的条目：还有页面的 `infoCardLinks` 与 `deleteGisResource`、放宽的工具栏与行内操作名单、把信息卡与 `infoCardLinks` 连起来的规则，以及页面 `card-close` 的新文案。 |
| 3. 缝，还是写死？ | **写死。** `placement` 和 `readers` 各只有一个取值，数据页也只有一个：它的按钮驱动一个表单，它的名称驱动一张卡片。复查触发器是出现第二个「只能由视图摆、但理由不是写入」的组件，或者出现第二个应当让可由调用摆的组件来读的输出。 |
| 4. 边界 | 见下。 |

### 边界

| 方向 | 这条线 | 它挡住的那次失败 | 期限 |
|---|---|---|---|
| 邻居 | `component-surface` 声明这些块、判定它们能站在哪里；画它们、发输出归 `component-kit`；打包进来的页面决定一次按下做什么。这里没有任何东西读发出来的值。 | 宿主长出一份对「正在编辑哪条记录」的读法，然后得让它和真正编辑它的页面保持一致。 | 永久 |
| 合同 | 只能由视图摆的块，只经 `content-component/shown` 到达内容栏；点名它的调用在问用户任何事、工具自己写下任何记录之前被拒。 | 屏幕上出现一个由模型写的记录画出来的可写表单。 | 永久 |
| 诱惑 | 没有「访客什么时候能新增或修改」的规则，不读权限，没有按两者分支的文案；视图规则只看文件。 | 视图判定变成后端每次请求都在回答的那个问题的第二个答案。 | 永久 |
| 红线 | 模型的调用永远摆不了表单页，工具的两条路上都一样，无论部署提供什么。 | 模型在一张描述读取的卡片上打开一个可写块。 | 永久 |
| 天花板 | 输出只带 id、名称、表和模式，两个新动作只带条数、至多五个名称和属性名。字段值不会经由任何一样离开页面。 | 把「智能体知道删了记录」读成「智能体拿到了那些记录」。 | 永久 |
| 假设 | 发布方守着声明：`editing` 只来自页面自己的新增和修改按钮，`opened` 在关卡、清空、翻页时撤回，两者在其记录被删除时撤回。 | 表单停在一条已删的行上，或卡片停在页面已经不显示的记录上。 | 暂缓 — 复查触发器：发出这两个输出的那个 `component-kit` 渲染器。 |

## Alternatives considered

**用页面的勾选行把三块连起来。** 否决。勾选缺省是多选，服务于批量和导出入口；一次勾选说的是哪几行，不是哪个按钮，而且根本说不出「新记录」。

**让表单页自带新增按钮，修改由绑定的行驱动。** 否决：它把 新增 挪出了页面的工具栏，而部署自己的控制台把它放在那里，视图的 `toolbarButtons` 也在那里排它。

**`editing` 带一个计数，让每次按下都成为消息。** 否决：那样输出就成了事件，成了「输出」定义里唯一要写明的例外，而且每次按下都会交给表单一个新值，哪怕什么都没变。不带计数，同一行再按一次修改，表单拿不到任何新东西。

**保存后经一条从表单页出发的绑定刷新页面。** 否决：那会让数据页变得可绑定，推翻它的属性拒绝绑定所依据的回读理由，连带推翻单向论证，还会在两块之间闭成一条链。

**表单留在数据页里，只把卡片拆出来。** 否决：那样视图写下的摆法没法把表单放在表格旁边。

**在共用那遍里判「只收绑定」，由座位传入它代入过的属性集合。** 否决：它为了只在会话日志被伪造时才有的收益改动座位的判定，而能伪造日志的人已经能改宿主。摆放规则让每个调用都碰不到这些属性，一条目录测试让可由调用摆的组件不能声明这种属性。

**把两个输出留在描述里。** 否决：模型会被提供一些它能绑进的地方一个都摆不了的值——目录先给出、再拒掉的那种绑定。

## Consequences

**换来的。** 视图可以把一张可写的表、它的表单和它的卡片并排摆开，用两条声明过的绑定接起来；模型调用把表单推上屏幕的每一条路，都在本来会这样做的那次操作里被关掉。模型读到的描述不变，所以请求前缀不动。各部分彼此不一致的视图在加载时失败，失败在需要改的那个路径上。

**付出的。** 三个目录每个读者都得遵守的声明字段，其中一个（`bindsFrom`）和属性的其余部分在不同的判定里判。两个在任何东西能画它们之前就已经在目录里的条目，所以组件行把它们连同渲染器一起注册之前，部署用不上它们。还有一份发布方的义务——每个输出什么时候撤回——本包声明了它却检查不了，上面把它记成要在写渲染器的地方核实的那条假设。

## Testing

`npx vitest run packages/experimental/component-surface --maxWorkers=2` 跑 31 个文件、920 个用例。覆盖：判断本身，以及在提供和不提供数据页时工具两条路上的摆放拒绝；抽取器只从 `content-component/shown` 画出视图摆放的 spec；在每种提供下，有没有这两块描述都不变；输出声明与收得下它们的属性对上，交叉绑定的输出被拒，调用能摆的块无论写对还是拼错都找不到这两个输出；三块视图里每条视图规则的放行，以及在各自路径上的拒绝；座位里的撤回与同值重发；四个新块动作和两个新数据页动作的通知及其上限。`tests/self-contained-copy.client.spec.ts` 让本包写下的每一句话——包括两块新组件的用途和理由——除 `show_component` 外不点名任何工具。`npx vitest run packages/experimental/component-kit --maxWorkers=2`（247 通过、2 跳过）与 `npx vitest run packages/experimental/skill-pack-components --maxWorkers=2`（16 通过）照常通过。
