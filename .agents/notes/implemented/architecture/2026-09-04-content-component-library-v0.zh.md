# Agent Note: 把一块界面摆进内容栏 —— 组件库的第一片

Status: implemented

[English](2026-09-04-content-component-library-v0.md) | 中文

## Problem

业务线控制台的内容栏目前能显示两样东西：iframe 里的一个页面，和一张图表。两样各自来自一个包，每个包都独占从「模型调的工具」到「画出来的 React」这一整条路。控制台真正需要的第三样东西，不该是第三个一次性实现——它需要的是一条通道：让 agent 把**一块界面**摆到用户面前，今天是一条确认条，往后是筛选行、指标、记录视图，而不必每次都新增一把工具、一种内容种类、一类会话事件和一个座位。

有三条约束让这件事比「再加一个包」难。

- **一块界面是模型的输出，却要在外壳自己的同源里变成真实标记。** 只要设计允许模型写出「值是标记、是函数体、是 URL」的属性，就必须在某处消毒，而每一个消毒器都只是一张「某人想到过什么」的清单。
- **浏览器半边收不到任何 Cordis 配置。** 无论 host 拿什么去判定一次调用，座位都必须能拿同一套规则判定同一份文档——而那份文档可能是经另一套组合写下的持久化检查点送到它手上的。
- **本仓库此前每一个 experimental 行都没有装配态快照覆盖。** 七个包挂的是同一句 Known Limitation，而快照泳道回放的是发行组合，发行组合不含任何 experimental 行。新增一段模型可见的工具描述却不配 keyless snapshot，违反仓库自己的铁律，所以泳道必须先于工具存在。

## Decision

**三层、两个包，切分线在「一块界面长什么样」和「它落在哪里」之间。** `@deepseek-ai/dsh-experimental-component-kit` 是组件行：React 渲染器、它们的文案，以及给它们命名的那张表。它不声明任何插槽、不认识任何栏、不读配置，node 半边是一个空插件——因此整个包可以搬到任何想画一块界面的界面上。`@deepseek-ai/dsh-experimental-component-surface` 是落位包：`show_component` 工具、每次调用都要对着判的目录、`component` 抽取器，以及认领内容栏 `component` 种类的座位。座位通过加载器的模块表（`dsh.client.external`）取到渲染器表，这也是页面里只存在一份组件的原因。

**一把工具管所有组件，而不是一个组件一把工具。** 一套部署提供哪些块是它的目录，`describeCatalog()` 把目录拼进工具描述。越来越长的工具清单模型每次请求都要读一遍；写在一份描述里的目录只读一次。`show_component` 收三个参数——`id`（这次调用拥有的那条条目）、`title`（用户在切换条上读到的短语）、`spec`（`{ nodes: [{ id, component, props }] }`）。

**属性 schema 就是那道安全边界，而且它是一个类型，不是一个消毒器。** `PropsFieldSchema` 是一个封闭联合：有界字符串、枚举、记录、带标识的列表。里面没有任何一个成员能表达富文本、函数体或 URL——因此模型根本写不出这样的属性值，后面也没有哪一道处理需要认出它。它替换掉的那个替代方案，正是它防住的那个具体失败：这份目录最终要覆盖的那个源库，自己就带着一个会对 `formatter` 字符串求值的表格渲染器。

**没有任何东西写会话事件。** 已经在记录工具调用的两种日志形态都算数：顶层 `tool/call`，它的 `arguments` 是原始 JSON；以及 Code Mode 的 `tool/code-dispatch-start`，它的 `arguments` 已经解码。只认一种，会让一次经 `run_code` 走到工具的会话里一条条目都读不出来。双认的后果是：拿掉这一行，过去每一份会话日志照样可读，`SESSION_FORMAT_VERSION` 也不必动。

**判定住在两个「除了彼此谁都不 import」的模块里，两半各跑一遍。** `component-call.ts`（零 import）放目录、工具名、种类和上限；`validate.ts` 只 import 它。host 在答复模型前判一次；抽取器对**已记录**的每次调用再判一次，好让一次被拒的调用永远不会变成座位画不出来的条目；座位在 wire 边界再判一次，因为一条条目可能来自某个目录不同于本次构建的检查点。`validateField` 的穷尽检查用的是本地 `never` 赋值而不是 `dsh-llm` 的 `assertNever`，因为这个模块要编进浏览器产物，不能把 LLM 包拖进页面。

**上限是协议常量，不是 `Config`。** 两半都要执行它，而只有一半能被配置，所以「按部署可变的上限」就是「两半会对不上的上限」——表现出来是内容栏里悄悄少一块，而不是模型能据以纠正的一次拒绝。等座位能读到部署设置那天，上限和提供设置的那条路由一起到来。嵌套上限则连数字都没有写：`maxSpecDepthOf` 从目录量出它，所以某个组件声明了嵌套属性，上限就正好为它加宽，而不是让这个组件自己的合法文档被当成畸形拒掉。

**座位是 keyed 且增量的。** `content.surface.kind` 是一个开放的 keyed 插槽，认领 `component` 不动其他任何种类的座位。key 在注册处写成字面量 `'component'`，因为客户端插槽目录生成器扫的是字面量 key。`entry === undefined` 时 `return null`，与图表座位一致；内容栏用 `visibility` 留在页面上的是它为这个种类准备的外壳，不是那些块，所以一旦不被选中，块的 DOM 连同里面填过的东西一起没了。

**渲染器契约是四个 prop，没有 context。** `nodeId`、已经校验过的 `props`、`onAction(actionId, nodeId)`、以及这一行自己的 `t`。渲染器不持有 ctx、不订阅任何东西、不做导航、不发请求、不写任何东西。`COMPONENT_RENDERERS` 是一个键为字面量的普通对象，`COMPONENT_CATALOG` 是 `as const`，因此 `CatalogId` 由目录派生，座位那句 `satisfies Record<CatalogId, ComponentRenderer>` 把「目录里有条目却没有渲染器」变成编译错误，而不是一块空白。派生这一步才是承重的：在目录旁边手写一份联合类型，钉住的是一个没人会随目录一起加宽的字面量，检查照样通过，座位照样画出一块空白。`renderer-coverage.client.spec.ts` 用一个比这一行多一个条目的目录加 `@ts-expect-error` 把这套机制钉住。

**`onAction` 存在，而且哪儿都到不了。** 回传通道是下一片；座位传进去的是一个具名的丢弃口，工具描述明明白白告诉模型「用户对这块内容做了什么不会回到你这里」，两份 README 也如实登记。现在就声明这个 prop 而不是以后再加，意味着通道到来时渲染器不用改形状，改的只是座位那个丢弃口。

**只有一个词典命名空间，归组件行所有。** 座位通过 `componentKit` 取文案，自己不带词典，在自己的注册处点名它。有哪些组件是这一行的事实，因此「没有能画这块的组件」这句话该跟组件走；何况 `locale:` 一次也只接受一个命名空间。

**不变式伴生拿派生数据对着日志审。** `contentSurface` 折叠里每一条 `kind: 'component'` 记录，都必须对得上本会话日志里一次被接受的 `show_component` 调用，且用的是抽取器那同一个读取器。这层关系两个方向都真实存在：内容栏用把抽取器表哈希成 31 位的办法决定一份持久化检查点还能不能用（碰撞被它自己的 README 记为残余风险），而它的注册表不拒绝两个抽取器认领同一种类，因此第二个 `component` 生产者是可组合的。审计在启动时遍历已加载会话，之后对每一条经 `internal/dispatch` 到达的提交事件再审一遍——不走 `sessionProjections.onChanged`，因为 `Session.append` 会把抛错的监听器变成一条 `logger.warn`，那样失败永远到不了调用方。

**快照缺口是被补上了，不是被登记了。** `snapshots/console` 是控制台自己的快照泳道：控制台后端主干在 ACP 自动化传输下的样子，只组合会话记录能观察到的那些行——适配器、ACP 应用、投影注册表、`content-surface`、`host-webserver`，以及会往内容栏里摆条目的那两把工具。四个纯浏览器行按设计缺席，主干自带的技能、目标、后台作业工具也全部关掉，好让上游改动**它们**的描述时冲刷不到本泳道的表头基线。两个场景同属一个表头类，由 `show-chart-turn` 钉住，因此 `tool-schemas.expected.json` 现在完整携带两把工具——每段描述、拼进描述里的上限与目录、每个参数的描述。

### 落地后的闸表

| 格 | 内容 |
|---|---|
| **0 —— 已定的哪条原则替我说了 no** | 「Model-visible ⟺ logged」否决了「一块界面自己拉数据再交给模型」。「上游零改动」否决了动 `agent-loop`。「Explicit > implicit」否决了 `?? defaultComponent`：组件 id 必填，未知即拒，且拒绝文本里带上整份目录。「一事件一种类、第一个认出的赢、不做探测」否决了「五个组件五种种类」。 |
| **1 —— 碰了几个新东西：5** = 1 + 1 + 1 + 0 + 0 + 0 + 0 + 1 | 数据源 **1**（工具的 `spec` 入参）；UI 面 **1**（`component` 座位）；工具或参数 **1**（`show_component`，三个参数）；路由或 RPC **0**；`Config` 字段 **0**（两半必须判同一套上限，而只有一半能被配置，理由见上）；事件类型 **0**（读两种既有形态）；审批闸 **0**；依赖 **1**（组件行的 `/client` 模块请求）。 |
| **2 —— 能证明它的最小版本** | 一条仓内 `.tsx` 的确认条，经 `show_component` 摆进内容栏，并以模型写的标题出现在切换条上。零 Vue、零 element-ui、零外来 tarball。 |
| **3 —— 切缝还是写死** | **切缝：`COMPONENT_CATALOG`**，因为两个近期变化是真的而不是设想的——第一批会从一个条目长到若干个，而这份目录要覆盖的源库没有任何版本历史，那边一改就意味着这里增删一个条目。**写死**：种类名 `'component'`、spec 字段名 `nodes`，以及「目录是静态常量表而非注册式服务」这件事。「外部包贡献组件」是设想不是实例，复查触发器写进了这张表自己的 JSDoc。 |
| **4 —— 每个方向一句话** | *邻居*：工具只认目录，别的都不认——不认识内容栏、不认识侧栏、不认识任何后端。防的是工具变成第二个三十七个属性的万能入口。*契约*：`resolve()` 同步且纯；`read()` 认两种已记录的调用形态。防的是 Code Mode 会话里一条条目都读不出来。*诱惑*：`propsSchema` 在类型层就表达不出标记、函数体、跨源 URL。防的是模型写出的 formatter 字符串在外壳同源里被求值。*红线*：`component-call.ts` 零 import，host 半边绝不 import 组件本体或 element-ui——那个库在模块求值期就读 `document`，host 侧一 import 就是 `ReferenceError`。*天花板*：同一种类的两条条目不并排显示；内容栏一次只显示一条，改这一点是内容栏自己的决定，等产品提出分屏需求再说。 |

## Alternatives considered

**把目录单独做成一个包，两半都依赖它。** 否决：目录、上限、校验器是同一个决定，把它们切到包边界之外买来的是第三份 `package.json`、第三条构建、第三个要跟着走的版本号；而它本想防的那件事（两半按不同规则判）已经由「这两个模块什么都不 import」防住了——正因如此，它们从同一份源码编进任何一半都是安全的。

**把目录与校验器作为子路径导出发布。** 先是这么做的，随后删掉：唯一的读者是**同一个包里**的座位，而它是相对 import 的。留着这两个子路径就得把整棵 `lib/types/**/*.js` tsc 产物树发布出去，其中生成的 `ComponentSurface.js` 会 import 一个并未发布的 CSS 模块——这是一次真实的 `publint` 失败，起因是一个没有消费者的导出。等某个不归本包维护的包需要判定一份 spec 时再把它们放回来。

**新增一类本包自有的会话事件。** 否决：这类事件的读者数为零，`tool/call` 已经逐字记下了参数，而新增一个 `SessionEventMap` 成员是对每一个读日志的构建的兼容义务。这类事件也没法做成「读不懂可以跳过」：`ignorable` 并不属于 `Session.append` 为非 surface 事件构造的信封。

**一个组件一种内容种类。** 否决：内容栏的种类注册表一个 key 只收一个座位，五个组件就意味着五个座位、五个抽取器、五条条目争同一栏。「一种种类，payload 里点名组件」表达力相同，座位只要一个。

**把确认条做成走既有桥的 Vue 组件。** 本片否决：那会把「工具 → 事件 → 抽取器 → 投影 → 座位」这条路的第一次端到端证明，压在 Vue shim、element-ui 内联和外来 tarball 后面，每一样都是一条独立的翻车路径。`.tsx` 的确认条不需要其中任何一样就能证明这条路，而 Vue 那一半是后面的片，它的两个阻塞级实验都还没跑。

**用注册式服务代替静态渲染器表。** 否决：所有条目归一个包所有，而键为字面量的静态表正是让消费方那句 `satisfies` 变成编译期检查的东西。换成服务只会把同一个失败挪到运行时，让用户看到一块空白。

**把装配态快照的缺口继续登记下去。** 否决：设计自己就把补上这个缺口列为本片的第一件事，正是为了不让「没有泳道」悄悄变成一段模型可见的工具描述不带基线就发布的理由。

## Consequences

**本片实际产出的证据。**

| 主张 | 证据 |
|---|---|
| 模型被逐字提供了这把工具、它的目录与上限 | `snapshots/console/show-chart-turn/tool-schemas.expected.json` —— 两把工具的完整 schema，替两个场景钉住 |
| 一次调用真跑通，且模型读回了自己摆的东西 | `snapshots/show-component-turn/session.jsonl` —— 记录下来的 `tool/call` 参数，以及点名条目 id 与组件名称的 `tool/result` 文本 |
| 装配出来的系统提示词就是控制台组装的那份 | `snapshots/show-chart-turn/system-prompt.expected.md` —— persona 加 `content-surface` 的「已展示内容」段落 |
| 一次拒绝会点名出问题的参数路径 | `packages/experimental/component-surface/tests/validate.client.spec.ts` —— 每条上限各拒一次，未知组件 id 的拒绝文本带整份目录，未声明属性按路径被点名 |
| 这条路在真实浏览器里端到端跑通 | `apps/web/tests/component-surface.e2e.ts` —— 针对真实控制台组合、跑在真实 chromium 上的四条断言；截图落在 `.artifacts/` |
| 两个 id 下的三次调用折成两条条目，后一次拥有它的 id | 同一场景的第二条断言：切换条上两个 tab，被取代的初稿标题在页面上一处都不出现 |
| 切换条目时同一个座位重画 | 同一场景的第三条断言 |
| 逐文件覆盖率 | 两个包每个文件的语句、分支、函数、行均为 100% |

**新增一个 experimental 包如今有一张固定的登记清单。** `tsconfig.base.json` 的 paths（三条，必须显式写——`@deepseek-ai/dsh-*` 通配匹配不到 `experimental` 这个目录名）、`tsconfig.client.json` 的 references 与 CSS 模块声明、包内 extends 客户端基座的 `tsconfig.json`、`tsdown.config.ts`、一份真实的 `src/invariant.ts`、两份 README 加配对记录、双语的 `packages/experimental/README.md`，以及一次 `pnpm install`。新增一个 `apps/web` e2e 还要再加两行：`tsconfig.host.json` 的 `include` 与 `apps/web/tsconfig.json` 的 `exclude` 各一行。

**两个包从「未被装配态快照覆盖」那一栏里挪了出来。** `content-surface` 的提示词段落与 `vue2-echarts-tool-poc` 模型可见的全部内容，现在由 `snapshots/console` 钉住。它们的 Known Limitations 被改写为「还有什么没被覆盖」——浏览器画出来的样子——而不是继续重复一句已经不成立的话。另外五个 experimental 包保留原句，那是对的。

**`component-surface` 会发布一个哈希命名的共享 chunk。** 工具入口与不变式伴生用同一份目录和校验器判定一次调用，因此 tsdown 为两者产出 `lib/validate-*.js`。清单的 `files` 与工作区约束的白名单都点名了它，遵循 `dsh-sandbox-windows-acl` 的先例。共享模块集合一旦变化，chunk 就会改名，built-package-invariant 门禁随之变红——这个失败是对的，前提是下一个读到它的人认得出来。

**两个包 README 里带着的 Known Limitations。**

- 按下的按钮到不了任何地方。座位那个动作口把它丢掉了。
- 目录里只有一个条目。把一个真实组件库映射成目录条目、并把那些组件打进浏览器产物，是后面的工作。
- 块一旦不被选中就不会留下。内容栏留在页面上的是它为这个种类准备的外壳，不是那些块，所以切到同一种类的另一条条目、切到别的种类，都会让块的 DOM 连同里面填过的东西一起消失。
- 本次构建不能完整接受的条目会整条画成一句提示，而不是逐块降级：座位重判的是整份 spec，因此只要有一个节点写的组件本目录已经不带了，本来能画的那些块也一起没了。逐块降级需要在 `validate.ts` 里开一个只判结构的入口。
- 上限是协议常量，不是部署的选择。
- 一条条目带着自己整份 spec，因此它随线上值与持久化检查点一起走；限住它的是字节上限。
- 不变式只经调度路径上报，理由见上。
- 切换条上每条标题旁边仍有一个英文种类角标（`COMPONENT`）。删掉它是 `content-column` 里的一行删除，不在本片范围内。

**设计留下的六个待拍板项，本片一个都没有替你拍。** 第一批真正的组件里到底有没有源库组件、还是继续用仓内 `.tsx`；走 host 侧查询工具是不是取同一份数据的更优路线；内容栏里的业务块要不要固定亮色与中文；一整套组件的体积能不能接受；两处用户可见的术语违规（种类角标，以及聊天里那条折叠的上下文注入行的表头）；以及高级查询条件组件该不该进第一批。每一条都是产品决定，而它们都不挡本片已经证明的这条路。
