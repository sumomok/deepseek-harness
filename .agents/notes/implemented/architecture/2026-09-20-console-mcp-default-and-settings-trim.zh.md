# Agent Note：控制台默认挂载 MCP，其设置页不再出现插件与配置文件

Status: implemented

[English](2026-09-20-console-mcp-default-and-settings-trim.md) | 中文

## Problem

控制台部署这件事上有两处毛病，彼此无关，却都能从同一个页面看到。

**MCP 只能透过仓外材料抵达控制台。** 已上线的控制台是从一个 vendored 的 `@haoran/dsh-mcp-servers` tarball 拿到它的：该包列在部署的 `Dockerfile` 里，用 `dsh plugin --profile web add` 装进 profile。那个包是一个不错的桌面答案，却是一个错误的控制台答案：它的全部表面就是一个**设置页面**，有人在那里填进一个服务器、勾选它可以提供的工具、并在服务器改动工具时重新确认。控制台的终端用户是业务人员，根本不该能添加服务器。于是控制台为了拿到一个否则就没有的能力，携带了一个它必须藏起来的设置界面——而"这个部署有没有 MCP"，答案取决于镜像当时是用哪个 tarball 构建的。

仓内的桥接 `dsh-mcp-client` 形状正好相反，也更接近正确：每个服务器一行组合，没有界面。但它每行恰好一个服务器且要求 `serverName`，因此一个不接任何服务器的组合写不出任何一行——于是"能力缺席"与"能力在场但未配置任何东西"变成了同一份文件。如果这个承诺会在还没人选定服务器时消失，控制台就无法承诺 MCP 已挂载。它的凭据故事是另一半：`headers` 是字符串表，于是组合要靠 `!!js process.env.X` 取到秘密，而这个表达式的失效方式是某个请求头悄无声息地什么也没带。

**设置页面把两个写给维护者的表面摆给了客户。** 一个**插件**分区，里面的卡片以宿主平面子系统命名，还有一个只读的 Cordis Loader 清单按包名列出各行；以及一个**打开配置文件**按钮，会在原生编辑器里打开宿主的设置文档。第二个更尖锐，因为它看起来只影响开发者自己的机器，实际并非如此：它由 `ctx.remote.$host.isLoopback` 把关，而控制台是故意让远程访客也为真的——`server-base` 的 `ownsHost` 声明由本部署自己的登录门来决定谁能抵达该页面，于是它放进来的每一个访客都拿到了运维表面。在已上线的控制台上，那个按钮就摆在客户面前。

## Decision

**控制台组合携带 MCP 能力，部署只携带清单。** 新增一行 `@deepseek-ai/dsh-experimental-console-mcp`，由 [`customer.patch.yml`](../../../../packages/experimental/server-sidebar/overlay/customer.patch.yml) 以 `servers: []` 挂载。它接受一份清单，并为每一项挂载一个 `dsh-mcp-client` 桥接。空清单就是交付状态，并且在强意义上空闲：该行照常加载，不建立连接，不注册任何工具，不向任何模型请求添加内容。在 overlay 里写出 `servers: []` 而不是交给模式默认值，是刻意的——这样部署方自己的清单就是对一个它已经看得见的值的编辑。

**服务器被点名，而不被携带。** 每一项是一个端点加上一个凭据的**名字**，透过 `ctx.credentials` 解析。值绝不进入组合文件；若引用的名字下没有存过值，该行会在加载时失败，并只点出引用名、不点出值。这正是 `!!js process.env.X` 那种写法做不到的：缺失的环境变量会产生一个什么也没带的请求头，而第一个症状是一次被服务器拒绝的工具调用。

**仓外那个插件并不需要，也不 vendor。** 控制台想要的一切，就是仓内桥接加一份清单。`@haoran/dsh-mcp-servers` 在此之外增加的东西——一份服务器的设置文档、一个编辑它们的设置分区、一份持久化的逐工具勾选、以及服务器改动供给时的重新确认——统统是"在运行时把决定摆到人面前"的机械，而这恰恰是控制台绝不能做的事。它的逐工具闸门是这一行没有复刻的真实价值；这一点作为限制记录下来而非照搬，因为复刻它就意味着复刻那个回答它的页面。

**只支持 Streamable HTTP。** stdio 服务器是宿主启动的本地程序，位于本产品施加的一切沙箱之外，以运行宿主的那个账户身份运行。这是一个实打实的部署决定，而它不该由"在服务器清单里加一行"来做出。确有需要的部署直接组合 `dsh-mcp-client`，并显式地为那个选择负责。

**两个插件设置行被停用；设置外壳不停用。** `ui-settings-plugins` 拥有那一个插件导航项、`configurable` 页签及其四张卡片；`ui-settings-plugin-inventory` 向同一个分区贡献清单页签。两者都不在该分区之外注册任何东西，因此两条 `disabled: true` 会移除这个分区、且仅此而已。清单那一行也一并停用，而不是任由它等待一个永不会被声明的插槽，因为一个携带了"其唯一贡献永不可能落地"的插件的组合，是在谎报它运行了什么。

**打开配置文件这个动作用 CSS 隐藏，因为别的办法都够不着它。** 它由 `ui-settings-general` 注册——那正是设置外壳本身，同时还画出面板、导航与通用分区，所以它那一行不能停用。没有任何 `Config` 字段把关这个动作，而列表插槽也不接受别的插件撤回：`ctx.slots.register()` 把 disposer 交给注册者自己。于是控制台既有的去术语化样式表增加第四条规则，与之前三条同一套机制、同一套钉法。唯一干净的组合级替代方案——不组合基于文件的设置提供方，让宿主报出 `hasDocument: false`、该动作渲染为空——被否决，因为那会把持久化的用户设置一并带走。

## What the console's approval settings do and do not cover

事实陈述，且本片不改动它。

桥接过来的 MCP 工具**不声明任何审批闸**。`mcp-client/src/tools.ts` 里的 `createDefinition` 构造的 `ToolDefinition` 只有 `name`、`description`、`parameters`、`output`、`execute` 与 `finalizeContent`，此外再无别的；注册表只有在某个 `tools/pre-execute` 监听器返回 kind 为 `ask` 的 `PreToolDecision` 时才会去问审批缝。对这些工具没有任何东西返回这样的值，因此一次 MCP 工具调用在控制台提供的每一档访问权限下都无需发问即可执行——包括「只读」，其 `sandbox: read-only` 管的是文件系统与 shell 两道缝，而不是发往已配置 MCP 服务器的网络出口。

所以控制台那条规则——只跟随原系统自己的确认——在这里不适用。那条规则讲的是用户正看着的页面，那里由部署方自己的前端在写入前发问。而 MCP 工具调用是本进程向另一台机器发出的请求，前面没有页面，并且以该行 `auth` 所点名的身份发出：**本部署的服务凭据，对所有使用控制台的人都是同一个**，而不是登录的那个人。经由它写下的记录归属于这个部署、不归属于提出要求的那个人，而部署方自己的后端无从分辨两者。

已经存在的组合级缓解手段是 `auth-gate` 的 `mcpUpstreams` 转发：MCP 那一行指向一个本地路由，网关把 `Authorization` 换成浏览器投递的令牌，于是请求落在访客名下。两份 README 都把它写成"两条路中的另一条"，且它属于部署方的选择、而非这一行的默认值。超出本片范围、只报告不改动：控制台的 MCP 工具究竟该不该声明审批闸，以及仓外的权限网关（`@haoran/dsh-llm-permission-gateway`，ECS 镜像携带它）拿一个不声明闸门的工具怎么办。

## The decision gate

| 闸 | 回答 |
|---|---|
| 0. 哪条既有原则已经决定了它？ | **包边界上显式优于隐式**决定了请求/规格的切分：`resolveServers` 是一个针对整份清单的、具名的 `resolve(request): Spec` 步骤，而不是挂载里的 `?? 默认值`。**插件里不写死可调项**决定了服务器清单、请求头、scheme、调用超时与启动策略都是受校验的 `Config` 字段，而"只支持 Streamable HTTP"是安全决定、保持固定。**配置错误要响亮地失败**决定了所有自足检查在加载时抛出、且整份清单被拒绝而非跳过出问题的那一项，以及唯一需要服务参与的检查——所点名的引用是否存有值——在最早可解析的时点、也就是同一次加载中执行。**跨边界的不透明 id 要有品牌**是凭据之所以是一个经缝解析的引用、而不是组合文件持有的字符串的原因。**上游零改动**决定了 `mcp-client` 与 `ui-settings-general` 都不碰：前者被包裹，后者在控制台自己的包里被隐藏。**第三方插件只能以经审计的 tarball 抵达产品、绝不 `link:`** 决定了仓外插件被评估后婉拒，而不是被 vendor。 |
| 1. 新增多少永久表面？（先计数，再列举） | **新增 13，移除 0。** 新增：一个包名（`@deepseek-ai/dsh-experimental-console-mcp`）；一个组合行 id（`console-mcp`）；八个 `Config` 字段（`servers`，以及每项的 `id`、`url`、`auth.header`、`auth.credential`、`auth.scheme`、`toolCallTimeoutMs`、`failOnStartupError`）；`terminology-guard.ts` 里一条 CSS 选择器耦合；两条组合停用行（`ui-settings-plugins`、`ui-settings-plugin-inventory`）。**零**新增会话事件类型、路由、服务、工具、面向模型的提示文本、locale 键、审批闸、客户端包与 npm 依赖——`dsh-mcp-client`、`dsh-credentials` 与 `schemastery` 都已在本工作区内，而 `SESSION_FORMAT_VERSION` 不动，因为空闲的行什么都不写，配置了的行也只写桥接本来就会写的东西。 |
| 2. 能证明它对的最小版本 | 一个以 `servers: []` 启动、且提供给模型的工具与之前完全相同的控制台——证明方式是把该行加进 `snapshots/console/cordis.yml`，而每一份录制 fixture 保持逐字节相同，无需重录、无需 API key。然后是一个服务器，经由凭据**引用**抵达，解析出的值落在所配置的请求头上、别处皆无；以及同一个引用在无存值时按名字令启动失败。设置侧：控制台上不再有插件导航项，而普通 `web` profile 仍然画出它；打开配置文件那一行在 DOM 中存在且渲染为空。其余的一切——id 文法、重复 id 的拒绝、URL 检查——是"整份清单被拒绝而非跳过一项"这一主张在有了清单之后必然要付的代价。 |
| 3. 做缝还是写死？ | **清单做缝，传输方式与样式表写死。** 服务器清单是 `Config` 缝，因为它是唯一逐部署变化的东西，也是这一行的全部意义。只支持 Streamable HTTP 是刻意写死：一个只有一个合法值的 `transport` 字段是噪声，而第二个值是一个配得上自己一次变更的安全决定，而不是清单里的一行。**复查触发器：某个控制台部署确实需要 stdio 服务器**——那一天这个决定被显式做出，而不是被默认进来。CSS 规则是对 `ui-settings-general` 渲染结构的写死，**复查触发器：上游出现能移除该动作的 `Config` 字段或插槽撤回 API**，届时该规则退役。**不新增服务、不新增工具：** 这一行不提供任何东西，也不注册任何属于自己的东西。 |

### Boundaries

| 方向 | 界线 | 所防的失败 | 期限 |
|---|---|---|---|
| 邻居 | 这一行拥有清单、凭据读取与挂载。`dsh-mcp-client` 拥有连接、命名、调用、重连与结果约定；`ctx.credentials` 拥有秘密存放在哪里。这一行三者皆不重新实现。 | 控制台这条线里长出第二个 MCP 客户端，带着自己的命名与自己的重连策略，与产品其余部分所用的那一个逐渐漂移。 | 永久 |
| 约定 | 组合文件点名一个凭据；它从不持有凭据。值经由缝读取，放到恰好一个所配置的请求头上，且不出现在任何诊断里——被拒的 URL 只在解析器读得懂之后才被引用回来，解析器读不懂的 URL 则根本不被引用。 | 秘密进入一份会被 diff、会在部署之间复制、会被启动输出引用的文件。 | 永久 |

| 红线 | stdio 服务器在任何配置下都无法透过这一行被点名。 | 一个控制台部署因为清单里加了一行，就在本产品施加的一切沙箱之外启动了一个本地程序。 | 永久 |

## Testing

`packages/experimental/console-mcp` 带 23 个测试，其两个 `src` 文件逐文件覆盖率 100%。`tests/servers.spec.ts` 钉住每一条自足拒绝——id 文法、两项声明同一个 id、url 不是绝对 `http(s)`、url 携带用户信息、url 携带 fragment、header 名不合法、凭据引用不符合引用文法——外加一条对拒绝措辞最要紧的用例：解析器读不懂的 url **不会**被引用回来，以否定断言的形式钉住。`tests/apply.spec.ts` 在真实 `ToolRuntime` 之上挂载该行，MCP SDK 打桩、凭据用替身，钉住四条生命周期主张：空清单不打开任何传输、不注册任何工具；两个服务器各自在自己的命名空间下注册；被点名的凭据落在所配置的请求头上、位于其 scheme 之后；缺失的凭据按引用名拒绝且什么也没注册。清单级的拒绝以其后果钉住——第二项重复了 id 的清单挂载的传输数为**零**，而不是一个。

`packages/experimental/server-sidebar/tests/customer-overlay.client.spec.ts` 增加了组合断言：两条停用行的 id 与包名；同样这两行在 `packages/bundle/web-app/cordis.patch.yml` 里仍被组合且未被停用（因此控制台的停用是控制台自己的，且上游退役某一行会在这里失败，而不是悄悄变成死配置）；设置外壳刻意**不**停用；以及 `config` 等于 `{ servers: [] }` 的 MCP 行。三份控制台 e2e overlay 副本被断言逐字携带全部这些内容，方式与该文件既有地对待 permission 行一致。

`terminology-guard.client.spec.ts` 把新规则钉两遍：一遍作为字面选择器，一遍作为结构——把该选择器跑在 `SettingsRoot.tsx` 渲染出的元素树上，必须恰好匹配到表头的动作行，而一个同样把某个类命名为 `actions` 的分区元素必须不匹配。后一半正是防止该规则扩大到它无权隐藏的控件上的东西。

`snapshots/console/cordis.yml` 以 `servers: []` 组合了该行，十九个录制场景全部原样通过——该 lane 透过真实 Loader、在出厂 `acp` profile 之上启动该行，因此它同时是空闲证明与组合证明，且不需要 key。

没有自动化 lane 覆盖、改为在浏览器里人工核验的部分：设置页面改动前后的渲染。截图在本片的 scratch 目录中；插件导航项改动前在、改动后不在，打开配置文件按钮改动前在、改动后渲染为空。

## Alternatives considered

**把 `@haoran/dsh-mcp-servers` vendor 进控制台。** 因其本质被否决，而非因其交付方式。它的价值是一个运行时页面，用来挑服务器、勾工具；而控制台的要求是不存在这样的页面。Vendor 它意味着为了藏起来而交付一个设置分区，而藏起来就等于停掉它唯一做的事。

**把服务器清单放进用户设置而非组合。** 否决。设置是用户编辑的东西，而控制台的用户不该添加服务器；况且设置 Remote 接受任何命名空间，凡已被放进 `/api` 的调用方都能写它。组合才是那个作者是部署方的层，而这正是谁的决定。

**给 `dsh-mcp-client` 扩展凭据引用与空服务器模式。** 依本 fork 的上游零改动规则否决。那个包属于上游；控制台的需求是组合层面的关切，而包一层能让桥接自由演进。

**用一个子清单为空的 `cordis:group` 冒充"能力在场"。** 作为文字游戏否决。它会加载且什么都不做，而部署方仍然得自己知道要去加 `dsh-mcp-client` 行——这正是本次变更要终结的状态。

**停用 `ui-settings-general` 以移除打开配置文件动作。** 否决：它是设置外壳，停用它会把面板、导航与通用分区一并移除。

**不组合基于文件的设置提供方，使 `hasDocument` 为假、该动作渲染为空。** 尽管它是唯一真正可用的组合级移除方案，仍被否决：它会把持久化的用户设置——主题、语言、转录模式——一并带走。

**用一个核心补丁给 `ui-settings-general` 加一个 `Config` 开关。** 本片未采用，并作为"能把这件事做对的最小上游变更"记录在此：一个把 `settings.action` 注册把关起来的布尔值，或 `ctx.slots` 上的一个插槽撤回 API。两者任一都能让那条 CSS 规则退役。它需要在 `.claude/core-patches.md` 中登记并由你拍板，因此只报告、不动手。

## Consequences

**买到了什么。** 控制台部署现在在同一份文件里陈述它接着什么——与它组合的其余一切并列——而且以点名而非携带的方式陈述：一个端点加一个凭据的名字，值留在凭据缝替它保管的地方。"这个部署有没有 MCP"不再取决于镜像是用哪个 tarball 构建的。凭据缺失的服务器现在会按引用名令启动失败，而不是照常起来然后拒绝每一次调用。设置页面也不再把两个写给维护者的东西摆给客户——一个插件管理分区，以及一个在 `ownsHost` 让它对每一个被放进来的访客都为真的部署上、会打开宿主配置文件的按钮。

**付出了什么。** `packages/experimental` 里多了一个包，而它的存在是为了持有一份清单。控制台这条线现在带着第四条与上游包渲染结构耦合的 CSS 规则——这是此处用到的最弱机制，之所以采用，是因为 `ui-settings-general` 就是设置外壳，既不提供 `Config` 字段、也不提供插槽撤回；它被一个结构性测试钉住而非被信任，并将在上游长出两者之一的那天退役。仓外桌面插件确实具备的逐工具勾选没有被复刻：已配置服务器公告的每个工具都会提供给模型，需要更少的部署只能去点名一个公告得更少的服务器。凭据仍然是每进程读取一次，因为那是 `dsh-mcp-client` 的字符串请求头表唯一能表达的形态，所以轮换秘密需要重新加载。

**没有改变、但值得说明的部分。** 桥接过来的 MCP 工具仍然不声明任何审批闸，因此它无需发问即可执行，在每一档访问权限下都是——包括「只读」。本片没有改动这一点，而上面那一节精确记录了它对控制台意味着什么：请求以本部署的服务凭据离开，前面没有页面，除非该部署把这一行指向 auth-gate 转发。
