# Agent Note: 页面读取器只提供通用工具，不认识任何一个应用

Status: implemented

[English](2026-09-03-content-reader-general-tools-only.md) | 中文

## Problem

`packages/experimental/content-frame/src/client/access/` 里的读取器，为真实控制台画出来的每一种形状各长出了一条规则；每一条都修好了那台控制台上真实发生过的失败：按列固定的表读成六张、名称那一列被整个丢掉；一整列命令读成空的；四十九个框的表单读成四十九行 `textbox = ""`；分了页的表把八十九条读成二十条。这些规则连同那些失败一起记在[阅读规则 Note](../feature/2026-09-02-content-snapshot-engine.zh.md) 里。

它们挂的都不是规范定义的东西，而是某个组件库写页面的习惯：class token 里的 `icon` 这个词、class 或标签里的 `pagination` 这个词、样式表画在标签前面的那颗星、彼此画在一起且行行对应的表、孩子全是按钮的 `div`、三项起步的 `ul`。每一条在它所依据的那台控制台上都成立，换一个地方就是一次猜测——而猜错了不会有人吭声：模型分不清「页面本来就是空的那一列」和「被读取器丢掉的那一列」。

有三条既定判断回答这件事，而且答案一致。dsh 只提供通用工具：一次读、一次动手，以及 HTML 与 ARIA 定义的语义；业务知识由用户在使用中产生的技能来承担。代码与 SKILL 的边界，把机制放进代码，把知识——这个应用是怎么搭的、它的图标是什么意思、它画的哪几张表在用户眼里是一张——放进技能。而仓库禁止硬编码可调参数：`LIST_MIN = 3` 与 `TOOLBAR_MIN = 2` 是两个回答不了「为什么是三」的数字。

## Decision

凡是挂在页面自有拼法上的规则一律退役。读取器陈述的就是 HTML 与 ARIA 陈述的；应用不暴露语义时清单就变薄，而它保持薄：文档说什么就打什么，绝不拿猜测去补。

### 决策闸

- **边界。** 机制归本包：遍历文档与 frame、给元素编号、预算、认领通道、审批、沉降等待。知识归技能：页面的各个区域是干什么的、哪些图形是它的命令、它画的哪几张表是用户眼里的那一张。
- **契约。** 清单为一个元素打出的名字，就是座位拿来核对步骤 `label` 的那个名字，由同一个函数（[`itemName`](../../../../packages/experimental/content-frame/src/client/access/collect.ts)）算出；一个 ref 在页面还留着那个元素期间指向同一个元素。这两条不动。
- **诱惑。** 「给 X 页加一条规则」永久拒绝。需要由页面标记语言、而不是由规范来担保的规则，正是这篇 Note 要退役的那一类。
- **红线。** 代码永不解释厂商的 class 名。它可以原样打出来——见下面的提示——但一个字都不解读，永远。
- **保留。** 有三条读法不由任何规范定义，这次留下，各自写明什么条件下退役，也各自只有一处定义，好让退役是改一处。指针光标标记可点目标（[`looksClickable`](../../../../packages/experimental/content-frame/src/client/access/dom.ts)，座位每次读取都注入它，`collect` 的兜底默认也是它）：CSS 就是页面告诉用户「这是个可以按的东西」的方式；等到座位能听见框架自己的点击监听器，它退役。页面画在「没绑定任何标签的字段」前面的那个 `label` 给该字段命名（`drawnBefore`）：HTML 说了 `label` 是给字段的标签，只是没说给哪一个；哪天实测到它把不是标签的一段话安到字段头上，它就退役——取错名字比没有名字更糟。一个可见的密码框旁边有一个可见的文本框、邮箱框或无 type 的输入框——同一个 form 之内，没有 form 就同一个区域之内，两者都没有的文档则整篇都算旁边——就判定此页是登录页、整页拒读（[`asksToSignIn`](../../../../packages/experimental/content-frame/src/client/access/snapshot.ts)）：没有哪条规范让页面声明「我在要凭据」，而这条读法什么都不凑——它只是拒绝并停下——它曾作为 fail-closed 的凭据保护留着，等的是座位能读到页面确实有的那两处声明：伙伴框上的 `autocomplete="username"` 与密码框上的 `current-password`。这条读法已经退役，而且不是按那个条件退的：[登录页照读那篇记录](../feature/2026-09-04-sign-in-pages-are-read.zh.md)取代了它，整条删掉页面判定，只留一条凭据规矩——密码框装着的值不到模型手里。
- **天花板。** 组件库画的页面会更费字符，最多约两倍。下面量了，接受。
- **假设。** 页面用 HTML 与 ARIA 说明自己的含义。它不说的时候，清单更薄、且只说文档说了的话——fail-closed，绝不凑。

### 退役了什么

1. **固定列整套子系统。** 每一个 `<table>`、`grid`、`treegrid` 都按页面写下的样子打出来。既不合并成文档里不存在的那张表，也不把任何一张当作另一张的副本丢掉，更不因为「画在另一个东西上面」而丢掉任何元素：`splitPartner`、`neighbourTable`、`repeatsTable`、`tablePieces`、`mergeCells`、`pickCells`、`duplicate`、`rectsMeet`、`rectsOverlap` 与注入的几何（`rectOf`）全部删除。
2. **图标命名，以及「图形所在的位置使它成为命令」这个概念。** `ICON_TOKEN`、`classIconWord`、`iconPart`、`<use href>` 的 symbol id、`isIcon`、`namesIcon` 与 `icon` 这个角色全部删除。图形和别的东西一样按可访问名读：页面写下的 role、`aria-label`、`svg` 自己的 `title`；页面标成可点却没给名字的元素，是一行 `clickable`。
3. **分页条与面包屑。** `PAGINATION_MARKER`、`BREADCRUMB_MARKER`、分隔符正则、`pagination:` 行、`rows on this page` 的措辞，以及读取头部的 `breadcrumb` 字段，全部删除。这两样部件按页面把它们画成的那段文字打出来。`role="navigation"` 与别的容器无异。
4. **画出来的必填星。** `(required)` 只跟随 `required` 与 `aria-required`，别的一概不跟；`REQUIRED_MARKS` 与注入的 `drawnAround`（读 `::before`/`::after`）删除。
5. **消息观察器。** 盯着「文字变得能读到」的 `MutationObserver`，连同 `message` 这一事件种类一起删除。一次动手上报的是浏览器替页面做的事——对话框、跳转、想开的窗口——这些是任何读取都找不回来的；页面画出来的东西在收尾那次读取里。
6. **推断出来的容器。** `TOOLBAR_MIN` 与 `LIST_MIN` 删除：工具栏就是 `role="toolbar"`；`ul`、`ol`，以及任何被标成 `list` 或 `feed` 的东西就是列表，装几项都算。

7. **「超过多长就不再算标签」的那个长度。** `LABEL_LIMIT = 40` 删除。`label` 是页面在给那个字段取名字，它有多长都算；这个数字是读取器在替页面决定「名字可以说什么」，而被它丢掉标签的那个字段，印出来一个名字都没有。

### 只加了一样

页面提供出来供人操作、却没给名字的行，在名字的位置上打这个元素的 class token：`e17 clickable {class: el-tooltip operation-modify el-icon-edit}`——元素携带的全部 token，按它自己携带的顺序；元素没有 class 就什么都不打；只对 `OFFERED_ROLES` 里的角色打：可点目标、按钮、链接、可填的框。这些 token 一个字都不解读，这一行的名字仍然是空的。`el-icon-edit` 是什么意思，由技能去说。

这串 token 同时也是步骤点名这一行的方式，即这一行的**标记**：`label: ""` 加上 `mark`——那次读取为它印出的那串 token；两边由同一个函数（[`elementMark`](../../../../packages/experimental/content-frame/src/client/access/dom.ts)）算出，清单照它打，座位重算一遍并逐字比对——这就是「一个名字」的不变量落在「没有名字的行」上的形状。点名无名行却不带标记的步骤会被拒，有名字却又带标记的同样被拒：一行只有一个身份，让座位在两个字段里挑一个来核对，就是两个。一个字都不裁，理由和名字不裁一样：裁短了的标记什么都对不上。两边各一个花括号，因为两个花括号是这些控制台所用框架写插值的方式，打成 `{{class: ...}}` 会被读成一段没人渲染的模板。

## Alternatives considered

**留着图标规则，等到有适配器能听见框架自己的点击监听器。** 那是上一篇 Note 写下的退役条件，而它自己不会到来：没有任何适配器排期，规则同时还在教模型一套只在一台控制台上存在的词汇（`icon "edit"`）。现在退役，代价是那台控制台的 操作 列，换来的是一个「每一句话都是文档自己说的」的读取器。

**把 class token 当作元素的名字打。** 那样模型就能把提示抄进步骤的 `label`、座位也核得动——但名字会变成标记语言而不是名字，`find` 会去匹配它，而「一个名字」的不变量会逼着座位也去算 class token。提示只是打出来，永远不是名字。

**保留一张窄窄的厂商前缀表**（`el-`、`ant-`、`bi-`），让读取器至少能给部署实际用的那些库命名图标。那是同一个猜测配上更长的表，而且会让本包成为一份它维护不了的组件库目录的主人。

**把那两个数字做成可配置**，而不是退役 `LIST_MIN` 与 `TOOLBAR_MIN`。加个 `Config` 字段确实能满足「不许硬编码可调参数」，但那把「几项算一个列表」这个问题丢给了部署方——这不是部署方的问题：HTML 早就答了。

## Consequences

**组件库画的页面，字符数大约翻倍。** 2026-09-03 在真机 ini-web2 控制台上实测，跑的是「退役那批规则之后、标记还没打全也还没改成单花括号」的那个中间版本：整页读取图层列表是 2507 字符，这份列表到模型那儿是六张表——`e28` 到 `e33`，主片一个表头半张、一个表体半张，每个固定列副本各一份。在 `tests/snapshot.client.spec.ts` 里记录着那张页面标记语言的 jsdom 夹具上，同一次改动把整页读取从 524 字符 6 行变成 1020 字符 16 行。行和列都没变，涨的是「原来打一张表，现在打六张」。

**那台控制台的命令列读出来是空的。** 同一次读取里实测：`e33` 是固定在右边的那张表体，也就是画着 操作 列的那一片，它的二十行每一格都是空的。这些行内命令没有 role、没有名字、没有 title、也没有指针光标，于是一行都不打：看得见它们的读者拿不到任何 ref。页面确实标出来的东西照样到得了模型：同一次读取为一个画成按钮的命令打出 `e3 button {class: el-button el-tooltip head-btn el-button--text …}`，这就是步骤点得到的那种行。那次读取把 token 裁到四个、并且用两重花括号拼写标记，与这个版本打出来的差别仅此而已。

**用户眼里的一张表，到模型那儿是页面用来搭出它的那几张表**——冻结表头、表体，以及每个固定列一份副本，各自带着这一片画出的那些列，其余为空。哪几片拼成那一张表，属于「关于这个应用要懂的事」。

**分页条的字按文字打。** `20 rows` 是页面已经画出来的行数，不是一共有多少行；`共 89 条` 在页面画它的地方打出来，把总数从这些字里读出来是模型的活，不是读取器的活。

**用画出来的星标必填的表单，读出来是一张全是选填字段的表单**；把 chip 画成 `ul` 的控件，装的是一个区域而不是一个值——行结束了下降，那些字就哪儿都不打了。

**来了又走的 toast 哪儿都不留。** 只在一条会消失的消息里报成功的应用，等于没跟谁报；收尾那次读取给出的是屏幕上还留着的东西。

**读取没给名字的行按标记核对，而标记不是身份。** 座位要求这样的行仍然带着读取印出的那串 class token，这抓得住「页面把那个位置重绘成了别的东西」；但复用 DOM 节点的框架会让同一列的两行带着一模一样的 token，一次把它们换了顺序的重绘照样过关——正如两个都叫「编辑」的按钮过得了名字那道核对。在「对这种行动手 = 用户按标记批准过的那条命令」的前提下接受：等到出现第一个会毁掉东西的逐行动作，就该把行的上下文也纳入核对。

## Testing

`tests/snapshot.client.spec.ts` 逐字钉住模型能看见的每一个字符串，包括那张控制台表格读成六张表、以及标记的原文；`tests/content-act-executor.client.spec.tsx` 让一个打在无名行上的步骤穿过座位，拒掉一个「页面在底下把标记改掉了」的步骤，并在一张「读取器给东西取名的每一种方式」都齐备的页面上守住「一个名字」的不变量。`src/client/access/**` 按文件 100% 覆盖。

`apps/web/tests/content-read.e2e.ts` 对着已入仓的录制回放通过，这次改动没有让它失效。`apps/web/tests/content-act.e2e.ts` 此前没有录制，本 PR 补录：它的夹具应用把一条命令画成一个光秃秃的 class，测试又在用户拿主意期间把这条命令重绘一次，于是这份录制带上整条路径——步骤按标记点名一行、页面改了标记后那一步被拒、以及审批句子按标记称呼无名行而不是说成 点「」。录制命令：`DSH_SNAPSHOT=record pnpm exec vitest run --config vitest.web.config.ts apps/web/tests/content-act.e2e.ts`。
