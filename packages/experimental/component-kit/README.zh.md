# @deepseek-ai/dsh-experimental-component-kit

[English](README.md) | 中文

## 概述

内容面板 `component` 类目背后的组件行。它提供 React 渲染器和给它们命名的表：不声明插槽，也不认识任何布局。一块内容画在哪里由落位包决定，画成什么样由这一行决定。

node 半边提供一条路由。它送的是浏览器半边自己算不出来的那一个值——`bizBasePath`，即 `toy.crud` 数据页请求自己那张表所走的路径前缀；这一行的 `cordis.yml` 条目同时也是浏览器产物靠 `dsh.client` 被发现的原因。

这里住着两类组件。一类是仓内用普通 React 写的，不依赖别的任何东西；另一类是仓外编译好的 Vue 2 组件，经一层桥挂到另一行拥有的那份 Vue 运行时上。下面的**原件怎么进来**记着为此付出的全部代价。其中一件原件还会自己发请求取数据，**数据页**一节记着*那件事*的全部代价。

## 渲染器表

`COMPONENT_RENDERERS` 把目录 id 映射到画它的组件。键是字面量 id，因此落位包只要让自己那份目录**派生出** id 的联合类型，再写一句 `satisfies Record<CatalogId, ComponentRenderer>`，就把两张表钉在了一起：目录里有条目而这一行没有对应渲染器，会在那里变成编译错误，而不是运行时的一块空白。钉住的前提是那个联合类型确实从目录派生；在目录旁边手写一份同名联合，什么都钉不住。写好的那一句在 `component-surface` 的 `ComponentSurface.tsx` 里，对着它的 `COMPONENT_CATALOG` 派生出的 `CatalogId`。

取到这张表是一次跨包的值导入，因此消费方声明 `dsh.client.external: ['@deepseek-ai/dsh-experimental-component-kit/client']`，由加载器从这一行自己的产物里答复该 require。

<a id="what-a-renderer-receives"></a>
## 渲染器收到什么

这一行里的每个组件都收同样六个 prop（`ComponentRendererProps`）：`nodeId`，该块在一次落位中的身份；`props`，落位包的 schema 已经接受的块属性；`onAction(actionId, payload)`，用户动作的去处，带上动作 id 与该动作声明的那些属性；`onOutput(outputId, value)`，这一块对自己此刻状态的读数的去处，供旁边的块拿去当属性用；`state`，这一块上次上报的手势走到了哪一步（`idle` / `sending` / `sent` / `queued` / `refused`）；以及 `t`，这一行自己的翻译函数。

`onAction` 与 `onOutput` 是两回事，组件把它们分得很清。手势是消息：落位包会把它记下来，模型可能会读到。产出不是——什么都不记，什么都到不了模型，发过产出的块仍然算一次手势都没上报。组件每次变化都重发一遍产出，包括变回「什么都没有」的那一次，好让被它喂的块能退回等待状态；每个值都必须能过 `JSON.stringify`，也必须当成只读的，因为落位包会把它原样交给另一块当属性。一个组件有哪些产出，和动作一样，由落位包的目录声明。

契约到此为止。渲染器不持有 ctx，不订阅任何东西，不记自己的手势，不做跳转、不发请求、不写数据——它画拿到的东西，说出用户按了什么，再被告知那件事的下场。这件事有没有后续、`state` 从哪里折出来，都由落位包决定。

`state` 是整块界面共用的一个值，所以一个组件的哪个手势会推动它，是落位包的决定而不是这一行的。控制台那个落位包只为「这一块被摆出来要等的那个手势」推动它，别的手势一概不动：这正是表格能在一次 `operation` 还在路上时继续接受勾选和排序、筛选条能在用户敲字时保住自己查询按钮的原因。把自己每一个控件都按 `state` 上闸的渲染器，闸的是那个落位包的决定。

属性的类型是 `Record<string, unknown>`，因为一张表的类型要服务所有组件，所以每个渲染器自己收窄它声明过的属性。这个收窄不是对调用方的防御：这块内容早已按接纳它的目录 schema 校验过了。

<a id="copy"></a>
## 文案

这一行拥有一个词典命名空间 `componentKit`，落位包的座位在自己的注册处声明它，而不是再开第二个命名空间——有哪些组件、各自发什么产出是这一行的事实，所以按钮行的无障碍名称、「这一行没有这个组件」时显示的那句话，以及一块内容在等上游那块时画的那行字，都归这里。块上显示的其余文字全是调用方的。

数据页另有三句自己的话，在 `crud.*` 下：一块内容在「它将要请求的地址还在读」时说的那句、那次读失败时说的那句，以及这块内容压根没说要打开哪张表时说的那句。它们归这一行，是因为那次读归这一行——别的组件都不等它就画。三种原因各有各的一句，因为跟一个「没说打开哪张表」的人讲地址没配好，等于给他一个不是他的原因。

一块内容关于它上次上报的手势要说的那四句话，是这一行自己的 `action.*`，由一句共用的行画在每个可交互组件下面：渲染器的状态是被告知的、不是自己记的，所以它们对同一个状态说的是同一句话。`el.confirm-bar` 在 `confirmBar.*` 下另留了一份，因为一条确认条只回答一个问题一次，那句话要用它自己的说法。

<a id="components"></a>
## 组件清单

- **`el.confirm-bar`** —— 一段简短提示加一行按钮，用来把一个决定摆到用户面前。属性：`title`、`message`、`buttons`（每项 `{ id, label, tone? }`，tone 取 `primary` / `default` / `danger` 之一）。按下按钮会报出 `press` 动作，其 payload 是被按下按钮的 `buttonId`。

条画的是它被交给的那个 `state`，除 `idle` 与 `refused` 外每种状态都不再接受按下，并写明它处在哪一种：手势正在路上、智能体已经拿到、正等着用户下次开口、或者谁也没收到。落位包拿一次按下做什么要隔一整轮才看得见，甚至可能什么都换不来，所以一条按完仍旧原封不动的条，会让「记下了」和「丢了」长得一模一样——而一条自己记着点击的条，落位第一次把它卸载就照样干干净净地回来。`refused` 仍然可按，因为再上报一次是唯一还能做的事。

- **`toy.record`**（`TcFormDetailRenderer`）—— 一份只读记录：成对的名称与值，分列排布。属性：`dataList`（每项 `{ label, display }`）、`labelWidth`（一个像素数，在这里换成组件要的 CSS 长度）、`columnNum`。它不上报也不发产出，因此动作出口、产出出口与动作状态都不读。组件本体是随 tgz 进来的 `TcFormDetail`，这块内容因此成了走通整条 Vue 链路的那一块。

`display` 是空串的那一行仍在原位：组件画出名称，旁边什么也不画——这正是记录有这个属性、但没填值的样子。`0` 与 `false` 同样是值，按各自的文本画出来。只有当一行谁也没命名（没有 `label`，或者 `label` 是空的），或者它的 `display` 根本不是文本时，这一行才被丢掉；后者是校验过的调用产生不了、而另一个构建写下的记录能产生的情况。

- **`toy.table`**（`TableDetailRenderer`）—— 分列的多行数据，用户选了什么、打开了哪一行、按哪一列排序、按了哪个按钮，都报回去。属性：`tableConfig.gridItems`（每项 `{ relatedMetaAttr, alias?, isShow?, isSortable?, relatedComponent?, relatedComponentObj? }`）、`displayValueList`、`rawValueList`、`selectMode`（`checkbox` / `radio`）、`isNameClick`、`tableSortable`、`customOperations`（每项 `{ key, label }`）、`operationColumnWidth`。回来的动作有四个：`select` 带 `rowIndexes`、`row-click` 带 `rowIndex`、`sort` 带 `prop` 与 `order`（`asc` / `desc` / `none`）、`operation` 带 `opId` 与 `rowIndex`。选择每变一次会发一个产出：`selectionDetail`，即第一行被勾中的行改写成记录块要的那份行表——每个画出来的列一条，用用户正在看的那个表头，行里没有值的列略过。调用当初写下的那些勾中行本身不随它一起发，因为落位包声明的属性里没有一个收得下行。

每一行都按它在 `displayValueList` 里的位置来称呼，数据本身一点都不往回走，所以一次手势指的是哪一行，由落位包回到模型自己写下的那次调用里去读。组件把选中行深拷贝之后才 `$emit`，所以这些位置是从挂载后的实例上读回来的，不是从事件参数里取的。它的三个属性写死而不交给模型：组件自带的修改与删除按钮被摘掉，因为它们走的那个事件这里没有任何动作承载；翻译值链接被关掉，因为没有任何东西提供它们要解析的那份值，这同时也让 `isNameClick` 成为唯一能让一行可点开的开关；而选择列在调用没要之前根本不出现。名称链接和行内按钮都坐在表格自己监听点击的那个单元格里，所以跟在它们后面的那次单元格点击被丢掉，不会当成第二次手势报出去。单独的一次单元格点击，只有在 `isNameClick` 打开时才当作「点开了一行」上报，因为一行到底能不能点开由它决定：调用没让它可点开的表格，点格子什么都不报；要求了行可点开的表格，点行里任何一格都算，因为组件没有比它自己那个单元格点击更细的事件可用。`state` 只管行内按钮，而落位包只为按下的行内按钮推动它：勾选、点开、排序都是用户在干活而不是在作答，一张表要是因为被用过一次就不再接受这些动作，那就是一张一用就停的表。

- **`el.filter-bar`**（`TuQueryCondAdvRenderer`）—— 一排查询条件，用户改完再发回来，用的是这套系统其余部分讲的同一套词。属性：`relatedMeta`、`metaConfig.attributes`（每项 `{ attributeEnName, alias, dataType? }`）、`attrEqEnums`（每项 `{ value, label }`）、`confStyle`（`{ gutter?, showMatchMode? }`，AND／OR 选择在块不要求时不画）。按下旁边那个按钮会报出 `submit`，payload 是 `conditions`，每项 `{ key, op, value }`；块要求画 AND／OR 时，再带上用户选的 `matchMode`。一次成立条件为零的按下什么都不报。用户每改完一处会报出 `change`，带上此刻成立的条件数 `count`：编辑器在用户选完属性、选完策略、或者离开值输入框时算改完一处，不是每敲一个字算一次。筛选条什么产出都不发，它的产出出口无人读：落位包声明的属性里没有一个收得下条件表，一次改完能到达的只有智能体。

组件一个事件都不 `$emit`，所以用户建好的东西是从挂载后的实例上用 `getData()` 读出来的，而发出去的那个按钮是这个渲染器自己画的——组件自带的按钮是加一行、删一行，没有一个的意思是「我填完了」。`metaConfig` 即使块里没写也照传：不传它，组件会自己去取属性表，而 tgz 构建对这次取数的回答是抛错。那份表在组件创建时被读进它自己的数据里、之后不再被 watch，所以带着另一份表的新调用会让它重新挂载，而不是把上一次的属性留在屏幕上。属性的 `alias` 在这里换成组件要读的 `attributeCnName`；它的 `dataType` 决定这个值是敲进文本框、日期选择器还是数字输入框，连同组件在肯读它之前必须先看到的那个标志一起传下去。四列的宽度归这个渲染器、不归块：那四列装的是两个下拉、一个值控件和组件自带的增删按钮，而组件读这份布局的每个字段时一个都不设防，所以块没写的部分在这里补齐，而不是留成 undefined。条件的值是用户自己写的字，按数据原样报出去；不是文本的值会连着它那条条件一起被丢掉。

- **`el.metric`**（`TcProcessBallRenderer`）—— 一个数字加一行说明，画成一颗按这个数字灌满的球。属性：`process`（那个数字，同时按百分比决定水位）、`text`、`size`（直径，像素）、`background`、`borderColor`、`pointColor`、`isPointShow`。它不上报也不发产出，因此动作出口、产出出口与动作状态都不读。

- **`toy.crud`**（`CrudRenderer`）—— 这套部署自己那张表的完整数据页：一块查询面板加一张结果表，由用户自己查询、翻页、排序。属性：`relatedMeta`（哪张表）、`conditions`（每条 `{ key, op, value }`，生效但不显示）、`matchMode`、`querySort`（`{ asc }` 或 `{ desc }`）、`selectMode`、`isExpandQuery`、`isInitQuery`。回来三个动作：`load` 带上这张表和它查询方案画出来的那些列，`query` 带上一次查询答复的三个计数，`cell-click` 带上被点的那一列和那一行画出来的各格。它不发产出，因此产出出口不读；动作状态也不读，因为这三个都不是这块内容被摆上去要收的答案。

到得了页面的就是那七个属性。工具包的 `CRUD_READ_ONLY_PROPS` 跟在它们后面铺开，任何调用都带不了它们：所有写入、导入、导出的开关全部隐藏，菜单与卡片子树关掉，`isReadOnly` 打开，`type` 写死，`urlConfig` 为 null。它们背后的构建把这个页面的六个写入对话框编译成了空桩，所以没有任何属性能打开一个，画出来的动作按钮只有查询和清空两个——它们旁边页面还画着分页器的两个箭头，那两个只有图标、没有文字。调用同样会写的 `metaLabel` 是审批卡片上的名字，止步于落位包。下一节是这一个组件其余的代价。

<a id="the-data-page"></a>
## 数据页

`toy.crud` 是这里唯一会走网络的组件。它的方案、它那张表的字典、每次查询的行，都是直接从浏览器发出去的，带着访客自己的凭据，宿主一样都不读。

**它的地址，以及这块内容为什么要等。** `toy-core`——和页面一起编译进 tgz 的那层请求层——在它自己的模块求值时读一次 `window.$toy_env.VUE_APP_BASE_URL`，而那个模块正是随这一行的浏览器产物一起求值的。宿主没有任何时刻能赶在它前面把值写进去。这个值在两边用它之前先判一遍——先是根绝对路径，再拿浏览器自己那套 URL 解析器解一次，origin 与路径没有原样回来就拒收，因为反斜杠和百分号编码的点段都骗得过手写的判断，却照样把每一个带凭据的请求发去别处。于是 node 半边把配好的 `bizBasePath` 放在 `/component-kit/settings` 上；浏览器半边启动时读一次，交给工具包的 `setBizBasePath`，由它同时改写那个已被捕获的默认值和活着的那个请求实例；而 `CrudRenderer` 在这次读落定之前什么都不挂载。于是没有任何请求是按工具包内置默认值发出去的。读失败时，这块内容画的是那句「地址没配好」，面板上别的块画得跟以前一模一样。

这个值是一条路径，仅此而已——根绝对、没有源、没有查询串或片段、没有 `.` 或 `..` 段——node 半边在加载时判一次，浏览器半边在它过了进程边界之后再判一次。既然是路径，它指的就是外壳自己的源，所以把请求带到部署后端去的是控制台身后那层反向代理，请求也就跟任何同源请求一样花的是访客自己的令牌。

**收进盒子里。** `toy-core` 会往 `document.body` 上追加一层全屏遮罩和一条 `nprogress` 进度条，页面弹 element-ui 的提示也走同一条路；放着不管，这三样都会落在控制台外壳上而不是这块内容里。`containCrud(box)` 标记这块内容自己的容器，把它变成定位祖先，把 `nprogress` 指向它，并把 body 上的提示搬进来。tgz 自带 `toy-core` 那两个 loading 与 message 辅助模块的副本，它们渲染进登记过的那个盒子；页面的 `$notify` 按实例覆盖，于是方案取失败时那条通知画在块内。调 `containCrud` 的那个 effect 声明在桥的挂载 effect 之前，这一点正是让盒子赶在页面第一个请求之前就位的原因；注销则是声明在它之后的第二个 effect，因为 React 按声明顺序跑清理，而页面最后那几条提示是在 Vue 销毁它的过程中弹出来的。tgz 送出来的每一条 CSS 规则都在构建时按盒子自己的属性选择器加了前缀，所以它的 `.el-*` 规则一条都改不动控制台的样式；`theme-chalk` 不会再送一份，因为这一行已经装了 element-ui，而装载这个 tgz 不会动共享运行时的 `size` 与 `zIndex` 默认值。

**这个页面会写什么。** 只读说的是表：没有任何属性能打开写入对话框，构建把六个对话框全编译成了空桩。页面仍然会写的一样东西是审计记录。每一次答完的查询都会调 toy-core 的 `crudEventLog`，它带着访客自己的令牌 POST `<bizBasePath>/nrms-resourcehistory/api/log/frontevent/`，带上控制台自己的路径作为 `app_enname`、事件「查询」、表名，以及这次查询的参数——包括模型写下的隐藏 `conditions`——作为事件数据。这是部署自己的前端审计流水，以访客的身份写下；审批卡片没有提它，而 tgz 里针对这个接口的补丁只是吞掉了它的拒绝。不愿意让控制台里的查询进那条流水的部署，得在页面挂载前顶掉 `core/log` 的那个出口。页面还会在浏览器自己的存储里留下三个键，每一个都是同一层请求层写的，不是这里的代码写的。`localStorage.userInfo` 是 `toy-core` 取回来、再用它自己的 `setUserInfo` 存回去的访客档案，记录的 `token` 字段里逐字带着那枚令牌。另外两个是它对某一张表的 localforage 缓存：`localforage//console/_schemaall_<meta>` 放这张表的查询、新增、修改三套方案，`localforage//console/_meta_<meta>` 放它的属性字典——这两个键是 jsdom 探针对着内嵌产物记下来的，前缀是控制台自己的路径；真浏览器里 localforage 把同样这两条放进 IndexedDB。退出登录会清掉 `userInfo`，它在 `server-sidebar` 的退出键表里；那两条缓存原地不动，于是在共用的机器上，一张表的方案和字典活得比这次会话长。退出时清空 localforage 那个数据库是那个包的退出流程该做的事，这里没做。

**小助手学到什么，什么留在面板里。** 查回来的行，一个格子都不在这三份读数里。`load` 说出这张表和它查询方案画出来的那些列。`query` 带的是命中的总数、这一页显示了多少行、当前是第几页。`cell-click` 带的是被点的那一列，和那一行画出来的各格——用户手指点到的那一行，跟 `toy.table` 上报选中行是对称的。同一次调用里，与这块内容上次上报过的完全相同的 load 或 query 不会再报一遍，所以切换标签页把这块内容拆掉重画，不会把同一件事告诉小助手两次。这个页面没有自己的选中事件，这里也不去轮询它的实例找一个。

<a id="how-the-originals-get-here"></a>
## 原件怎么进来

这里有些组件不是在这儿写的。`@sumomok/toy-surface-kit` 是从客户维护的三个源库里搬出来的一批 Vue 2 组件的编译产物，在它自己的仓库里构建，以 `vendor/sumomok-toy-surface-kit-0.3.1.tgz` 的形式进来，依赖写成 `"@sumomok/toy-surface-kit": "file:./vendor/sumomok-toy-surface-kit-0.3.1.tgz"`。用 React 重写这条路评估过，否掉了：那些库的 354 个单文件组件里有 191 个直接写 element-ui 的组件，还有 153 条规则伸进它们的标记，重写等于把客户已经付过账的 bug 历史重来一遍。

**同三个库，两份 tgz。** `@sumomok/toy-crud-kit` 是第二份构建，带的是 `Crud.vue` 和它运行所依赖的那层请求层，以 `vendor/sumomok-toy-crud-kit-0.2.3.tgz` 的形式进来，本节对第一份说的每一条都同样适用于它。有三处不同。它内嵌的是真正的 `toy-core` 桶文件而不是垫片，因为那层请求层就是要送的东西。它的 `toy-comp` 垫片加宽到了 `Crud` 闭包所触及的七个深路径导入，正是这一点切掉了那三个 `main.js`——它们在模块求值时的 `Vue.use(Element, { size: 'small', zIndex: 2000 })` 会把共享运行时的默认值从别的每一块内容脚下挪走——以及跟着它们的那份重复的 `theme-chalk` 导入。还有，它关于身份的那条规矩是有范围的而不是绝对的：组件不读任何存储、不读 cookie，凭据的使用则被收在 `toy-core` 自己那层请求层里：它只读访客存着的 token、别的凭据一概不取，也会把用这枚 token 取回来的档案写回同一处存储——上面讲这个数据页的那一节记着这件事——这正是送它的全部意义，它自己的 README 也这么写着。它带的是七个补丁而不是五个：前一份的四个，加上一个去掉打印已登录用户的 `console.log`，一个给一处「发出去就不管」的事件日志补上 `.catch`——那个 promise 的拒绝没有任何人接——以及一个切掉从页面地址栏取 token 的那两处分支。它还是这里唯一一份把第三方 npm 库编进自己产物的载荷——四十个，axios、nprogress、localforage 都在里面——所以它随包带一份生成的 `BUNDLED.json` 逐个写明版本与条款，另带一份 `THIRD-PARTY-LICENSES.txt` 承载正文；`THIRD_PARTY_NOTICES.md` 就是从前者生成的，因为这个仓库的 manifest 与 lockfile 里都没有那些代码的名字。它没有编进去、留给宿主装的那两个——`lodash` 与 `dayjs`——由 tgz 自己的 manifest 声明，同一份文件的运行时那一档就是照着那份 manifest 读出来的。

**每一个控制台都要下载这个页面，不管有没有开。** 内嵌产物 878 KB（gzip 后 222 KB），它 import 而没有编进去的 `lodash` 与 `dayjs` 再加 553 KB（gzip 后 100 KB），而且都是静态 import，所以它是这一行那个唯一浏览器包的一部分，每次启动都到每一个访客手里——包括把 `crud` 留在默认的 `false` 上的部署。这里没有推迟它的办法：一个插件的浏览器包就是加载器按名字取的那一个闭包工厂文件（`tsdown.client.ts` 把整份产物包进 `window.__ModuleLoader__.load`），动态 `import()` 没有第二个分块可落，就算落了也没有人去取。要把这个页面挪出启动路径，得先让每个插件能有第二个可取的产物，那是加载器的改动而不是这里的改动。**复查触发器：有部署以 `crud: false` 跑控制台并量到启动代价时。**

**是一份快照，不是一个检出。** 就地覆盖 tgz 是无声无效的：pnpm 按文件路径加一个完整性哈希来记这次安装，而规格没变时它不会重读那个哈希，于是构建拿到的还是旧字节。每次重新构建都要抬版本号、落到新文件名下、改掉 `package.json` 里的规格，然后才 `pnpm install`。

**五个补丁。** 构建不是照搬：源码上打了五个补丁，随 tgz 放在 `patches/` 下，每一个的理由写在它的 `SOURCES.md` 里。它们分别去掉一个 `cronstrue` 依赖、去掉一个下载列、修一处 `toUpperCase` 调用、拿掉一处从 `localStorage` 读 token 的代码，以及在实例销毁时停下指标球的动画链——没有最后这条，一块内容离场之后那串 `setTimeout` 会继续往一个已销毁的组件上写，直到把剩下的步数跑完。

**一个往回递的把手。** 桥往 Vue 里递的只有纯数据和回调，往回不递任何东西，只有一个例外：渲染器可以传一个 `instanceRef`，桥会在这块内容挂着的整段时间里把挂载后的组件本身放进去——是 `root.$children[0]`，不是桥自己那个根。它存在是因为有两个原件是靠实例方法作答的：`TuQueryCondAdv` 一个事件都不发，`getData()` 是读到用户建好的东西的唯一途径；`TableDetail` 在自己的选中事件里把行深拷贝了，所以一次手势要用的身份得靠 `doGetSelection()` 读回来。渲染器只拿它来读。

**六道门禁，跑在 tgz 出现之前。** 构建仓库拒绝发布这样的产物：里面还留着 `from 'vue'`、`'element-ui'`、`'toy-core'`、`'toy-comp'`；字节里含 `fontawesome-webfont`；或者过不了 jsdom 挂载冒烟。前四条拦的是「桶入口把模块加载期副作用一起拖进来」，第五条拦 1.1 MB 的图标字体，最后一条拦文本门禁根本看不见的那类失败——裁剪或内联不完整，模块求值时当场抛错。

**一份 Vue，靠请求而不是打包。** Vue 2 的响应式不跨运行时副本，所以这一行从拥有那唯一一份的行里取 `Vue`：`dsh.client.external` 写上 `@deepseek-ai/dsh-experimental-vue2-echarts-poc/client`，`src/client/vue-shim.ts` 把它供给的那份再导出，`tsdown.config.ts` 把裸规格 `vue` 别名到这个文件——只对浏览器产物生效，也只对裸规格生效。正因如此，`src/` 下任何文件都不得自己 import `vue`，写成什么形式都不行——`vue/dist/…` 这样的子路径别名管不到，会去拿一份自己的副本——一旦有人开始这么做，`tests/source-vue-imports.client.spec.ts` 就会红。被内联进来的库要什么，源码里根本看不见，所以 `tests/client-bundle-vue.client.spec.ts` 去数构建产物 `lib/client.js` 里的 Vue 运行时标记，多出第二份就红。

**element-ui 只装一次，层级 300。** 全仓唯一的那句 `Vue.use(ElementUI)` 在 `installElementUI()` 里，这一行的客户端插件启动时调它。`Vue.use` 没有反操作，所以它是一个模块作用域的开关而不是 effect：把这一行拆掉，组件仍然注册在那份 Vue 上。两个选项都写死——`size: 'small'`；`zIndex: 300` 是因为 element-ui 自己的默认值 2000 会让下拉盖住 1100 的外壳和 1000 的审批弹窗，也就是让一个展开的下拉挡住正在请用户同意的那扇窗。浏览器半边收不到 cordis config，而这一行没有 host 半边，所以要把哪个选项做成配置，做法是让落位包读到它再传进来。

`src/client/element-ui.css` 是 element-ui 的 `theme-chalk/index.css` 的物理拷贝，只改了一处：图标的 `@font-face` 把 woff 内联成 `data:` URI，并且不再提供 truetype 备选——客户端产物是把这张表当 `<style>` 标签注入的，相对字体路径会去页面根下解析。升级版本后按同样的方式重新生成。

**三条红线。** 页面上永远不许出现 `window.Vue`——element-ui 的 UMD 产物会对着它找到的那份 Vue 自行安装，把组件注册到这一行并不拥有的运行时上，症状是无错误、无警告的响应式失效。块里不许用 `el-dialog`、`el-message`、`el-notification`：它们的元素落在宿主元素之外，这里没有任何东西关得掉。允许用的那几种弹层——下拉、气泡提示、popover、日期选择面板——在桥里是一张闭表，落位包说这块内容离屏时由它统一收起；组件要画第五种弹层，就得在同一次改动里加进这张表。交给 Vue 组件的记录必须先过 `freezeDeep`：Vue 会把拿到的东西一层层观测下去，被观测的数组连原型都被换掉，那会反过来动到 React 自己的数据。唯独监听器映射冻不得：Vue 会就地改写它拿到的那个对象，给每个处理函数套上自己的 invoker，所以桥交给 Vue 的是一份拷贝，调用方自己的那张表保持写下来的样子。

## Known Limitations and Deferred Work

- **状态由落位包去折，折错了这一行看不出来** —— 这一行只画 `state`，对它不作任何判断，所以某个落位若从不把一块推过 `sending`，或者把另一块的状态交给了这一块，画出来的条看着完全正常，说的却是错的。这一行没有任何东西能发现。
- **状态表是闭的，状态的含义不是** —— 条按交给它的每个状态各画一句，这张表少一句就编译不过。编译器管不了的是落位包新加的投递档并进了已有状态：某个落位悄悄吞掉、谁也没告诉的动作，折成 `sent` 之后，这里画的就是「已发送到对话」。加这种档的人，要连这句话一起定。
- **落位包自己那些句子不经这一行翻译** —— 这一行只本地化条自己关于手势画的那几句；同一次手势落位包在屏幕别处说的话，用的是那个包自己写下的语言。控制台那套落位是由宿主来答一次按下的，宿主拿不到浏览器的语言，于是 `这个动作没能记下来。`、`内容太多了，少选几项或写短一些再试。` 与 `已记下，你下次发消息时对话会看到。` 会出现在聊天里，紧挨着一条写着 `Sent to the conversation` 的条。这一行够不着它们；解法归想要统一界面语言的那套落位，触发器是控制台开始提供中文以外的界面。
- **payload 里能放什么，这一行不做检查** —— 渲染器被信任只把落位包目录为该动作声明过的东西放进 `onAction` 的 payload；这一行不检查，落位包也不做裁剪，而是整条手势一起拒掉。渲染器多放一个该动作没声明的字段，这个控件的每一次按下就都到不了任何地方。
- **一份目录，两个家** —— 这张表里的 id 和校验块属性的目录是两个包里的两份声明，只靠消费方的 `satisfies` 检查系在一起。那句检查只管 id，别的都不管：渲染器读的属性一旦与接纳它的 schema 漂移，编译照样通过，画出来的却是错的。
- **组件只发自己对自己的读数，不知道谁在读** —— 组件从不指名另一块、从不读另一块，也无从知道有没有人绑到它发出的东西上。有哪些产出、某个产出能不能站到某个属性的位置上、值最后落到哪里，都是落位包的事；这一行不管有没有人在听，每次变化都照发。
- **产出里能放什么，这一行不做检查，和 payload 一样** —— 渲染器被信任只发落位包目录为该产出声明过的东西、并且照它声明的形状发。这一行不检查；落位包的做法是让被喂的那块继续等，而不是画出一个不合形状的东西，于是用户看到的是一块永远不来的内容。
- **发出去的值之后不能再改** —— 落位包会把它当属性交给另一块，而发出方继续往里写，就等于在没人重渲染的组件底下换掉了属性。没有任何东西拦这件事：这里唯一发产出的那个组件，交出去的是它临时铺出来的一份行表，自己并不留着。
- **tgz 是一份对无历史源库的快照** —— 三个源库没有 git、没有版本号、没有变更记录。客户改了什么既 diff 不出来也察觉不到，所以这里的组件会和客户手上跑的那份分叉，而唯一的同步手段是重新人工拷贝源码再跑一遍 tgz 的门禁。这是一笔长期维护债，不是可以关掉的告警。
- **原件自带的中文串不跟随界面语言** —— 空表格的「暂无数据」编在 element-ui 里，「属性名」「匹配策略」「属性值」「条件关系」「并且」「或者」「增加」和表格的「操作」表头编在原件自己里。它们都够不着我们任何一份词典，所以在英文界面里仍是中文。要改就得重编 element-ui、并从改过的源码重出 tgz，各自都是另一件事。
- **表格的行按位置称呼，而收窄会让位置移动** —— 一次手势报的是它在这个渲染器建好的 `displayValueList` 里的下标，而它会丢掉根本不是记录的那一项，于是另一个构建写下的旧调用可能让被丢那行之后的每个下标整体前移。校验过的调用产生不了这种项。
- **表格按固定高度画，给多少行就画多少行** —— 没有分页、没有滚动加载，一次调用带的行超过可视高度时，其余的落在表格自身滚动区的折线之下。真正约束它的是目录里的行数上限，而不是这里的任何东西。
- **`isNameClick` 只对 `display_default` 的列生效** —— 组件画那个可点开的名称链接，用的是 `relatedMetaAttr` 等于 `zh_label` 的那一列，并且只在这一列按纯文本画时才画。调用要是指了别的列、或者给这一列指了单元格组件，那这张表上一条链接都没有，但行照样点哪一格都能打开，因为本行读的是调用打开的那个属性。
- **一次什么都没填的按下什么都不画** —— 条件编辑器一开始就带着一个空行，所以筛选条按钮的第一次按下提交的是零个条件，落位包什么都不上报；`state` 不动，本行也不画任何一行，因为没有手势可画。用户拿到的是一个按下去屏幕毫无变化的按钮。要把它置灰，就得让按钮的状态跟着编辑器里完整条件的条数走，而本行只能从落位包评级的那同一个 `change` 里知道这个数——两边必须对「按钮什么时候可以动」达成一致。触发条件是第一次有人反馈「点了没反应」。
- **被拒的手势只有一句话，不管是被什么拒的** —— `action.refused` 对所有拒绝都是 这个动作没能记下来，可以再试，因为 `ComponentActionState` 里被拒只有一个成员，落位包自己的理由也到不了本行。因为超量而拒绝的落位包会在屏幕上别处说出来——控制台在聊天里说的是 内容太多了，少选几项或写短一些再试。——而旁边那一块说的是另一句。要在这里把它们分开，得在那个联合里再加一个状态、和折叠它的那个落位包谈好，并在本词典里给它写一行。
- **条件编辑器加行没有上限** —— 原件自带的增加按钮，按一次加一行条件，按多久加多久，这里没有任何东西拦它。于是落位包的动作若声明了「一次提交最多几条」，被拒的就是那次提交，用户是从落位包的回话里、而不是从编辑器上知道这个上限的。要在这里拦，那个数得在缝的这一侧，而这一行是给任何摆放它的人画块的：它不能 import 一个落位包去读那个数。
- **筛选条的值只能按文本输入** —— tgz 构建把七个会自己取数的值控件换成了禁用替身，所以这个渲染器不提供挑选控件的入口，每个属性都给一个纯文本框。日期或枚举值，就是用户敲进去的那串字。
- **指标球的渐变遇到颜色关键字会退化** —— 组件把 `background` 提亮之后当渐变上端，用的是 tgz 里对某个 `toy-core` 工具的等价实现，而那份实现只转 `#rgb`、`#rrggbb`、`#rrggbbaa`、`rgb()`、`rgba()`，其余写法原样返回。所以写成颜色关键字的颜色画出来是一颗没有渐变的球，而不是报错；落位包自己的收紧也只放行那几种能转的写法。
- **`TableDetail` 里函数形态的属性一律不接** —— 组件为行内按钮的可见性、逐行样式、云端权限判断各留了一个回调位。它们没有一个能用「文本、数字、布尔和它们的列表」这套 schema 表达出来，这里也一个都不接：一块内容提供什么，由它自己带的数据决定。
- **`PopupManager.nextZIndex()` 只会往上加** —— element-ui 从 300 起给每个新弹层发下一个 z-index，而且永不复位，于是一个开了约七百次弹层的会话会爬过 1000 的审批弹窗并盖住它。隐藏一块内容会收起它开的弹层，但没有任何东西把计数器降回去。真正的解法是外壳把自己的层级整体抬到远高于 element-ui 的区间。
- **数据页在手里没有令牌、或者被答 401 时会把整个窗口导航走** —— `toy-core` 的请求拦截器会把浏览器送去部署的登录地址，控制台跟着一起走：这个页面是画在外壳里的，不在自己的框架里。记录在案，不修。在这个组件面向的同源部署里它是可以接受的——那里 [`auth-gate`](../auth-gate/README.zh.md) 会在每个请求前面把令牌保持新鲜；不带那道闸就组合 `toy.crud` 的部署，拿到的是一个能把用户从正说到一半的对话里导航走的控制台。
- **遮罩和进度条是模块级单例** —— `containCrud` 把两者都指向最后登记的那个盒子，所以屏上同时有两个数据页时，一个页面的加载态会画进另一个页面的盒子里。一次调用只能摆一个页面，那是落位包的规矩；两次调用照样能在列里留下两个条目。
- **提示收纳假定页面上每一条 element-ui 提示都是这个工具包的** —— 那个把 body 上的 `.el-message` 与 `.el-notification` 搬进盒子的观察器不问是谁弹的，所以将来某一行弹的提示会被搬进某个数据页的盒子里，而不是画在那一行本来的地方。
- **数据页有七个查询控件是禁用的替身** —— 那些要去解析关联记录的取值控件在构建时被换掉了，跟前一份 tgz 里一样，所以查询没法按关联属性收窄，控件画出来是灰的。把它们做出来的触发条件是第一个真需要它的用户。
- **数据页的图标画成空框** —— 没有送图标字体，所以 `TcAwesomeIcon` 渲染出来的是一个里面什么都没有的 `<i class="fa …">`。只读页面里一个都看不见；写入路径会露出来。
- **数据页的选中不会到小助手那里** —— 页面能勾选行，而它的组件在勾选变化时什么都不 emit，所以调用打开的 `selectMode` 完全留在面板里。要读它就得按定时器去轮询挂载好的实例，这一行不做这件事。
- **crud 那份 tgz 的类型是手写的** —— 里面的 `types/index.d.ts` 是对着一份 JavaScript 构建手写的，跟前一份一样，所以构建出来的组件自身属性一旦漂移，这边照样编译通过，等画这块内容时才炸。
- **没有装配快照覆盖** —— 浏览器侧的证据是针对真实组合的 Playwright 场景；快照泳道回放的是发行组合，其中不含任何 experimental 行。
- **「只有一份 Vue」这条对产物的断言在 CI 上不执行** —— `tests/client-bundle-vue.client.spec.ts` 读的是 `lib/client.js`；在 pull request 上，唯一会对这个包跑 `vitest` 的作业是覆盖率作业，它不构建，于是在那里跳过。master 的 `linux-primary` 泳道串行执行它的门禁，build 排在覆盖率门禁之后，所以那里产物同样不存在。本地、以及任何先构建的泳道里它照常执行。仓库里没有任何门禁去读一个已构建客户端产物的正文——同类的另外两个 spec，在 `client/ui-trajectory` 与 `session/session-persistence-sqlite`，在 CI 上因同一原因跳过。CI 覆盖到的是后果：Playwright 场景对着发行产物画出那个 vendored 组件。把这三条一起挂上门禁的触发器，是第一个去读已构建客户端产物的门禁出现。

**运行时不变式：** 不发布伴生入口。本包是一张渲染器表：它的 node 半边只提供一条设置路由，不追加任何会话事件，而一块内容可以画什么，由拥有目录的落位包判定。
