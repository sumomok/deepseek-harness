# @deepseek-ai/dsh-safe-binary-write

[English](README.md) | 中文

## 概述

写必须留在工作区边界内的二进制数据（截图、图像、产物）时用 `dsh-safe-binary-write`。它拒绝悬空符号链接，拒绝跟随越出允许根目录的符号链接，并把数据写进同目录的临时文件后再原子改名，以此缓解 TOCTOU 竞态。这个零依赖库面向截图恢复一类场景：在那里跟随一个符号链接就可能写到预期工作区之外。

## 使用本包

要在不跟随可能越界的符号链接的前提下，把二进制内容写进某个目录边界内时，用 `writeBinarySafe`。

### 安全写入二进制数据

```ts
import { writeBinarySafe } from '@deepseek-ai/dsh-safe-binary-write'

declare const screenshotData: Uint8Array
declare const workspaceRoot: string

await writeBinarySafe(
  '/workspace/screenshots/capture.png',
  screenshotData,
  workspaceRoot,
  { mode: 0o600 }
)
```

这个函数会：
- 校验目标路径位于允许的根目录之下
- 检查路径中没有越出根目录的符号链接
- 按需创建父目录（在根目录之内）
- 以独占创建方式写入临时文件
- 写入期间复查是否引入了新的符号链接
- 把临时文件原子改名为目标文件

### 需要预案的失败

出现以下情况时函数抛 `SymlinkContainmentError`：
- 目标路径本身是符号链接
- 路径中任一父目录是符号链接
- 某个符号链接指向允许的根目录之外
- 目标是悬空的符号链接

常规文件系统错误（EACCES、ENOSPC）原样向上抛出。任何失败都会清理临时文件。

### 写入路径

1. **词法围栏检查**：用规范化后的绝对路径校验目标在允许的根目录之下
2. **符号链接扫描**：从目标向上走到根，对每段用 `lstat` 判定是否为符号链接
3. **创建目录**：在允许的根目录之内创建父目录
4. **临时写入**：用 `wx` 标志（独占创建、不跟随符号链接）把完整数据写进同目录下一个随机后缀的临时文件
5. **终检**：改名之前再查一次符号链接
6. **原子改名**：把临时文件改名覆盖目标（目标本身是符号链接时替换该链接）

### 为什么写入仍然安全

- **不跟随符号链接** —— `lstat` 判定而不跟随；`wx` 标志在写入期间拒绝跟随；`rename` 替换被符号链接的目标而不是穿过它写
- **强制路径围栏** —— 写入前与写入中逐段检查
- **缓解 TOCTOU** —— 同目录临时文件保证改名原子；改名前的终检接住竞态
- **带调用方模式的新 inode** —— 临时文件把权限位一路带到改名之后
- **失败即清理** —— 任一步失败都删除临时文件

## 已知限制与推迟的工作

这些限制界定了本包不适用的范围。它们是本包当前的约束，不是待办清单。

- **仅二进制数据** —— 接受 `Uint8Array`（含 `Buffer`）；文本内容应使用 `dsh-atomic-write`
- **单主机操作** —— 符号链接检查在当前主机上运行；跨主机共享的网络文件系统可能看到不同的符号链接状态
- **不保证持久化** —— 不对文件或目录做 `fsync`，崩溃后这次写入可能被回退
- **残留 TOCTOU** —— 终检与系统调用之间有很窄的窗口；在本威胁模型（担心的是不可信路径而非不可信代码）下接受
- **拒绝路径中的所有符号链接** —— 保守策略；工作区内合法的符号链接也被挡住

### 开发备注

上传路径与截图恢复路径都需要让文件以已知名字出现，且要么带着它此前的完整内容，要么一个字节都没有。本包只拥有这一层字节级保证：对目标路径中符号链接的围栏检查，以及一个改名到位的临时文件。需要文本语义或冲突策略的调用方自己拥有那些决定。
